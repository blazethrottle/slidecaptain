# Q1a 종료 및 새 세션 인계

작성: 2026-09-12. 작업 저장소는 `~/Projects/slidecaptain`이다.

**종료 지점: Q0 문서 보완과 Q1a 구현의 로컬 자동화 검증을 마쳤다. 사용자는 이 시점에 /clear 후 새 세션에서 이어가기로 했다. Q1b/Q2 이후 개발을 이번 세션에서 시작하지 않는다.**

## 반드시 유지할 제품 기준

SlideCaptain의 목적은 PPTX 파일 생성이나 서식 통일이 아니라 독자가 보고의 흐름과 근거를 쉽게 이해하는 결과물이다. 사용자 제공 비교 자료의 30점 평가는 목표 품질이 아니다. 보고 논리, 근거, 강조와 정보 위계, 적절한 도식/차트, 가독성과 균형을 함께 개선해야 한다. 테스트 수와 도형/색상 수를 품질 점수로 대신하지 않는다.

목표는 AI가 논리와 표현을 설계하고, 코드가 배치를 계산하며, 실제 완성본 검수로 제출 가능 여부를 판단하는 구조다. 현재 Q1a는 그 기반이지 품질 보증의 완성이 아니다.

## 완료한 범위

- 기존 설계서, 로드맵, 디자인 묶음 계획과 5B 재개 조건을 새 품질 기준에 맞췄다.
- 구조안/장 생성에 보고 질문, 근거와 지표 비교 조건, 불확실성 보존, 표현 선택 지침을 연결했다.
- 다른 장의 초안을 제한된 문맥으로 제공하고, 사실의 근거와 구분하며 현재 장/표지/간지를 제외한다.
- 빈 출력, 누락 장과 용량 경고를 점검한다. 미구현 검수는 대상 0과 not_run으로 남긴다.
- 초안 PPTX 옆에 동일 버전의 quality.json을 기록한다. 입력 fingerprint와 실제 PPTX 해시를 연결한다.
- 빈 출력과 CLI의 final 요청을 거절한다. UI는 초안임을 밝히고 점검 기록 경로를 표시한다.

## 미완료와 재심할 전제

- 실제 AI 호출, 실앱 조작, PowerPoint 화면, 독자 이해도와 블라인드 비교는 검증하지 않았다. 읽기 품질이 개선됐다고 판정할 수 없다.
- Q1b의 검수 상세 API/UI, 검수 이력/무효화, 웹과 직접 CLI의 공통 내보내기 잠금은 미구현이다.
- Q2의 주장/근거 장부와 전체 보고 계획, Q3의 표현 모델/부분 강조/차트/복합 배치, Q4의 완성본 검수/제한된 수정, Q5의 비교 실증은 미구현이다.
- 현재 fingerprint는 deck/preset/render plan 범위다. 원문 진실성이나 변경된 자료에 대한 검수 판정의 유효성을 보장하지 않는다.
- PPTX와 점검 기록은 하나의 원자적 파일 묶음이 아니다. 게시 실패 후 남는 기록의 버전 재사용 방지는 확인했지만 웹/직접 CLI의 동시 실행 안전성까지 해결한 것은 아니다.
- CLI의 기본 프리셋은 웹의 전역 프리셋과 다를 수 있다. 이후 공통 계약과 검수 입력 고정에서 다뤄야 한다.
- 프런트 dist를 빌드했지만 기존 앱 서버를 재시작하지 않았다. 현재 실행 중인 앱이 새 백엔드를 읽었다고 가정하지 않는다.

## 승인과 보존 경계

사용자는 현재 단계의 테스트/빌드, 필요한 수정과 인계 정리를 승인했다. 실제 AI 호출의 비용/자료 전송, 배포와 커밋/푸시 승인은 포함하지 않았다. 이 세션에서 Git 명령, 커밋/푸시, 회사 자료 외부 전송을 실행하지 않았다. 현재 브랜치와 작업 트리 상태도 다시 조회하지 않았으므로 깨끗하다고 단정하지 않는다. 기존 사용자 변경을 보존한다.

회사 원문, 내부 수치와 식별정보, 비교 자료 스크린샷을 공개 저장소나 개인 위키에 넣지 않는다. 테스트에는 비기밀 합성 자료만 쓴다. 새 위키 지식 수집은 하지 않았으며, 앞선 진단의 대리지표/실제 성과 구분 원칙을 자동화 검사와 보고서 품질 판정의 분리에 적용했다.

## 다음 세션의 첫 작업

권장 대상은 **Q2의 첫 단위: 보고 질문과 주장별 근거를 중심으로 전체 보고 계획을 만드는 최소 경로**다. 먼저 해당 아키텍처 계약과 기존 Deck/구조안/생성 흐름의 호환성을 확인하고, 하나의 합성 보고서에서 입력부터 생성 계획까지 연결되는 범위로 좁힌다. 새 입력 폼이나 점수 표시만 추가하고 내용 품질 개선으로 간주하지 않는다.

Q1b의 미완료 항목을 완료로 표시하지 않는다. Q2 전체와 Q3/Q4를 한 세션에서 끝내려 하지 않는다. 첫 단위의 구현, 관련 테스트/빌드와 미완료 기록까지 마친 다음 다시 인계 가능한 경계에서 멈춘다. 실제 AI 실증이 필요하면 비용과 자료 범위를 먼저 확인한다.
