# Q2b 지표 비교 계약 종료 및 다음 세션 인계

작성: 2026-09-12. 저장소는 `~/Projects/slidecaptain`이다.

**종료 지점: 최신 Q2a 인계의 다음 권장 단위인 지표 비교 계약과 비교 불가 사유를 구현하고 테스트/빌드까지 마쳤다. 다음 인계 가능한 경계이며 Q2 전체 완료가 아니다.**

## 목적과 보존 범위

보고서의 수치가 같은 기준으로 비교되는지 확인할 수 있도록 근거의 비교 조건과 판정 사유를 계획에 연결했다. 제품 목적은 독자가 보고의 흐름과 근거를 쉽게 이해하는 결과물이다. 입력 조건 일치, 코드 검사와 테스트 수를 보고서 품질 점수로 대신하지 않는다.

시작/종료 브랜치는 `codex/phase-5b`, HEAD는 `acff346`, 원격은 `https://github.com/blazethrottle/slidecaptain.git`이다. 기존 Q1a/Q2a 미커밋/미추적 변경과 빈 스테이징을 보존했다. 작업 트리가 깨끗하지 않아 pull/브랜치 전환/머지는 하지 않았다. 커밋/푸시/배포, 실제 AI 호출과 회사 자료 전송은 수행하지 않았다. 합성 테스트만 사용했다.

Q1a/Q2a 보호 파일 16개는 작업 전 사본과 대조해 변경 0개였다. 점검/내보내기/CLI, 서비스/API/Deck, ProjectView와 StructureScreen, 이전 인계 2개가 해당한다. 이번에 함께 변경한 StoryPlan 모델/파서/화면과 기존 테스트 파일은 전체 회귀 검사로 확인했다. 시작 시 스냅샷은 임시 경로 `slidecaptain-q2b-baseline-y__y_x4_`에 있으며 장기 보존을 보장하지 않는다.

## 완료한 동작

1. 근거에 선택적 `metric_basis`를 추가했다. 지표 정의, 단위, 주체, 기간(날짜/달력 단위/집계 방식/완결 여부), 분모(해당 없음/모집단/미확인과 정의)를 구조화한다. 기존 자유 문자열 메타데이터를 비교 판정에 섞지 않는다.
2. 전체 계획이 비교할 주장 ID, 두 근거 ID와 주체/기간 비교축을 명시한다. 코드가 조건 일치, 불가 또는 정보 부족과 개별 사유를 반환한다. 없는 참조, 동일 근거, 중복 ID는 기존 형식 재시도 최대 1회 뒤 format_error로 처리한다. 조건 불일치 자체는 정상 판정이므로 추가 호출을 만들지 않는다.
3. 모델은 결과를 생성하지 않는다. 계획 저장/재읽기에서도 `comparison_results`를 입력 조건에서 다시 계산한다. 편집한 입력과 기존 계획은 보존하고, fingerprint가 달라진 계획으로 장 생성/축약을 요청하면 호출 전에 409로 거절한다.
4. 새 계획 버전은 q2b-v1이다. 기존 q2a-v1 fingerprint에서는 새 기본 필드를 제외한다. Q2a 계획에 비교 필드를 숨기면 거절한다. 실제 변경 전 합성 저장본으로 호환을 검증했다. Deck schema_version은 1을 유지한다.
5. 비교 요청/사유를 승인 저장, 다시 열기, 스냅샷 복원, 편집/undo/redo와 장 생성/축약 문맥에 전달한다. 불가/정보 부족 비교를 직접적인 우열, 증감과 차트 근거로 쓰지 말고 사유를 설명하도록 지시한다.
6. 화면은 해당 주장, 양쪽 원문 위치, 판정 사유와 비교 조건 표를 보여 준다. 조건 일치는 '입력 조건 일치'로 표시한다. 대상 0건은 미검사이며, 프런트는 비교를 자체 계산하지 않는다.

정확한 지원 범위와 계약은 [아키텍처의 Q2b 실제 계약](../architecture/2026-09-12-quality-pipeline.md), 범위/반증 검토는 [단위 계획](../plans/2026-09-12-q2b-metric-comparison.md)에 있다.

새 백엔드 계약과 프런트 화면이 없는 상태에서 회귀 실패를 먼저 확인했다. 프런트 타입 검사에서 새 필드를 빠뜨린 모의 데이터를 발견해 함께 갱신했다. 자체 코드 검토는 결측끼리의 일치, 기간 경계/집계, 분모, 판정 재계산, 옛 fingerprint와 입력 변경 후 호출 차단을 대조했다. 별도 독립 에이전트 리뷰는 수행하지 않았다.

브라우저 검수는 CUA의 `No browser is available`과 네이티브 Chrome의 `cgWindowNotFound` 오류로 완료하지 못했다. 임시 서버는 AI 프로바이더 없이 임시 프로젝트 폴더만 사용했고 검사 후 종료했다. 원래 사용 중인 앱 서버를 재시작하거나 그 앱이 새 코드를 읽었다고 확인하지 않았다. 이번 프런트 dist 빌드 자체는 완료했다.

원시 로그는 `/tmp/slidecaptain-q2b-validation.U6CdiQ`의 backend-tests.log, frontend-tests.log와 http-smoke.json에 있다. 임시 파일의 장기 보존은 보장하지 않으며 위 표가 지속되는 결과 기록이다.

## 미완료와 재심할 전제

- 비교 대상과 조건은 모델이 분류한 초안이다. 원문에 없는 정의/기간을 지어내지 않았는지, 지표의 의미가 같은지, 비교 주장을 빠짐없이 등록했는지는 검사하지 않는다. 조건 일치를 사실 검증으로 사용하면 안 된다.
- 단위 환산, 동의어/지표 온톨로지, 회계연도/이동 기간/부분 기간, 표본 크기와 구성에 대한 통계적 검수는 미지원이다. 비율의 분모 정의는 대조하지만 그 비율 자체를 재계산하지 않는다.
- 비교 불가 사유를 장 생성/축약에 전달했지만 생성된 각 문장이 이를 준수하는지 독립 검수하지 않는다. Q1a 품질 기록의 의미/근거/시각 검수는 계속 not_run이다.
- 실제 제공자의 새 날짜/비교 스키마 수용성, 비용/지연과 생성 품질은 모의 제공자로 입증되지 않는다. 실호출 전 합성 자료 범위와 호출 수를 확인한다.
- Q1b의 검수 상세/이력/무효화와 웹/CLI 공통 내보내기 잠금, Q2 계산/요약 정합성/부분 재계획과 수동 주장 편집, Q3~Q5는 미완료다.

## 다음 즉시 행동

이 인계와 Q2b 실제 계약을 읽고 변경/스테이징을 다시 확인한다. 권장 다음 단위는 **근거 ID와 산식이 연결된 결정론 계산(DerivedValue)의 최소 경로**다. 먼저 원문 값의 숫자 파싱과 단위/분모 계약을 확정하고, 합성 보고서 한 건에서 재계산 및 계산 불가 사유까지 연결한다. 비교 불가/정보 부족을 숫자 결과로 숨기지 않는다. 단위 변환, 전체 의미 검수와 부분 재계획을 한꺼번에 구현하지 않는다.

사용자 재개 예시:

> Q2b 인계를 읽고 다음 Q2 계산 태스크의 최소 범위를 확정해서 구현·테스트·빌드까지 진행해줘. 기존 변경을 보존하고 다음 인계 지점에서 멈춰줘.
