## 요약

- **CI 실패 원인**: 가짜 Claude CLI(`backend/tests/fakes/fake_claude_cli.py`)가 초기화 응답을 `{}`로 보내, D4b 뒤 모델 목록이 비고 생성 전 확인에서 작업이 막혔다. 이 시험은 POSIX 전용이라 Windows 로컬 시험에서 건너뛰었다. 가짜 CLI가 목록을 싣게 고치고, 모든 OS에서 도는 시험으로 고정했다.
- **major 2건**: 목록 조회의 제한 시간이 연결 단계까지 걸리게 고쳤다(최대 35초, 넘기면 정리를 기다리지 않음). 목록 조회를 연결 관리자의 잠금 밖으로 옮겨, 조회 중에도 상태 조회와 생성 임대 반납이 기다리지 않는다.
- **설치 CLI 실측**: 데스크톱 앱이 쓰는 설치 CLI 2.1.304에는 `opus`가 있다(동봉 CLI 2.1.247에는 없음). 기존 `opus` 사용자가 다시 골라야 하는지는 Claude Code 판에 따라 다르다.
- **화면**: 저장한 모델이 목록에 없으면 설정 화면이 "저장한 모델(opus)을 지금 Claude Code 목록에서 찾지 못했습니다. 다시 선택해 주세요."를 보인다. 모델 이름은 `Sonnet → claude-sonnet-5`처럼 보인다.

## 운용 사실

- 이 세션은 `/clear` 전 세션이 띄운 리뷰어의 보고를 받았다. 같은 범위의 리뷰어를 새로 띄웠다가 중복이라 멈췄다. 새 세션은 앞 세션이 띄운 백그라운드 작업이 있는지 먼저 확인한다.
- 문서 브랜치는 세션 임시 폴더의 `git worktree`로 고쳤다. 작업 사본의 브랜치를 바꾸지 않기 위해서다. 머지 뒤 그 worktree를 지웠다.
- 머지는 사용자의 "A" 답(질문의 선택지 A가 "두 브랜치 모두 머지")으로 세션이 로컬 `--no-ff` 머지와 push를 했다. 두 브랜치는 로드맵의 다른 줄을 고쳐 충돌이 없었다.
- 백엔드 전체 시험은 이 PC에서 약 24분 걸린다. 2026-10-21 리뷰 반영 뒤 실행은 2,976 통과, 48 건너뜀, 실패 0이다.
- 메모리가 부족하면(이 날 여유 0.9GB) Claude Code가 쉬는 동안의 백그라운드 명령을 끊는다. 이때는 시험 파일을 다섯 묶음으로 나눠 앞에서 하나씩 돌린다(묶음마다 10분 안).
