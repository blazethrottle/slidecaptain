# Q2d 계산 문구 대조 인계

작성: 2026-09-13. 저장소: `~/Projects/slidecaptain`.

**종료 지점: 계산 기준 문구와 현재 편집본의 대조를 구현하고 자동 검사와 실제 Chrome 표시를 확인했다. 기준 문구와 다른 표현은 확인 필요로 남긴다. 일반적인 의미 검수나 보고서 품질 통과는 아니다.**

## 목적과 승인 범위

사용자의 SlideCaptain 개발 재개 요청을 Q2c 인계의 다음 최소 검수 단위로 이어받았다. 원문 근거/산식과 생성된 문구를 연결하고 부호/단위/비교 기준이 다른 문장을 숫자의 단순 존재만으로 통과시키지 않는 것이 목적이다. 합성 자료만 사용했으며 실제 AI 호출, 회사 자료 외부 전송, 배포와 커밋/푸시/머지는 수행하지 않았다. 기존 사용 앱 서버는 재시작하지 않았다.

실제 저장소는 `codex/phase-5b`, 시작 HEAD는 `acff346`, 원격은 `https://github.com/blazethrottle/slidecaptain.git`이다. 기존 Q1a~Q2c와 AI 연결 작업의 미커밋/미추적 변경을 보존한다. 스테이징은 비어 있었고 작업 트리가 깨끗하지 않아 pull/브랜치 전환을 하지 않았다. 반영 대상은 기존 파일 14개 수정과 신규 파일 8개이며 삭제는 없다. 작업 시작 때 있던 나머지 파일 192개는 작업 전 사본과 동일하다. 반영 직전 별도 작업의 문서 커밋 `62d7b61`과 DiagramSpec 도입안 1개가 추가된 것을 확인했다. 기존 코드 내용은 그대로였으며 새 문서도 수정 없이 보존한다. 샌드박스 밖 원본에 반영하기 전, 별도 임시 사본에서 구현과 검증을 마쳤다.

## 완료한 동작

1. Q2c 계산으로 명시적인 대상/기준/부호/단위/기간/분모/반올림을 담은 기준 문구를 코드가 작성한다. 예: `A팀 순매출: B팀 대비 차이 +200원 (2026-01-01~2026-01-31)`. 일치한 텍스트 칸은 계산 ID, 주장 ID와 두 근거 ID로 연결한다.
2. 칸 전체의 정확한 일치만 인정한다. 부호/단위/비교 기준/기간/반올림을 바꾸거나 문구 앞뒤에 다른 주장을 붙이면 확인 필요다. 같은 문구가 여러 산식에 대응하면 임의 선택하지 않는다. 한 자리와 비ASCII 십진 숫자, 표의 중첩 셀과 수동 부제도 누락하지 않는다.
3. 입력에서 계산 결과를 다시 계산한다. 현재 자료와 계획 fingerprint에 더해 원문 파일의 해시, 행 위치와 발췌를 직접 대조한다. 클라이언트가 식별값을 다시 계산해도 틀린 원문 연결을 인정하지 않는다. 계획 없음/낡음/근거 불일치/계산 없음/대상 0건은 `not_run`이고 evaluated=0이다.
4. 생성/축약 문맥에 기준 문구를 전달한다. 보고에 적합한 경우에만 사용하고 대조 결과를 위해 억지로 넣지 않도록 지시한다. 생성 스키마, Deck 버전 1과 q2a/q2b/q2c 저장본은 유지한다.
5. `POST /api/projects/{name}/review/numbers`는 편집기의 현재 Deck을 받는다. 기존 앱 헤더를 요구하며 AI 연결/동의/호출을 쓰지 않는다. API 호출 전후 프로젝트 파일 전체의 내용이 유지되는 것을 검사했다. 초안, 스냅샷과 사용량에 쓰지 않는다.
6. 편집 화면의 **계산 문구 대조**에서 전체 초안을 검사하고 실제 문구/기준 문구/산식/자료를 표시한다. 편집과 undo/redo, 복원, 프로젝트 이동과 언마운트에 결과/진행 중 요청을 무효화하며 낡은 응답을 표시하지 않는다. 다른 앱에서 원문을 바꾸면 다시 검사해야 함을 알린다.

처음에는 백엔드/프런트 구현 부재로 검사가 실패했다. `engineering:code-review` 기준 자체 검토에서는 식별값이 재계산된 잘못된 발췌/행/원문 해시 3개 사례가 잘못 일치하는 것을 재현하고 직접 원문 대조로 수정했다. Chrome에서는 미수행 안내 뒤에 완료형 설명이 붙는 문제를 발견했고 범위 설명으로 정정했다. 이를 회귀 테스트와 실제 표시로 확인했다.

실행 로그와 작업 전 사본은 임시 폴더 `slidecaptain-q2d-zw8z0sfm`에 있다. 파일은 `backend-tests-final.log`, `frontend-tests-final.log`, `manifest.json`, `baseline/`이다. 임시 파일의 장기 보존은 보장하지 않는다. 저장소의 테스트/공유 픽스처가 지속되는 재현 근거다. 검수 서버에는 AI 제공자를 연결하지 않았고 생성한 Chrome 탭과 임시 서버를 종료했다.

## 미완료와 재심 대상

- 코드가 작성한 문구의 동일성을 대조하는 좁은 범위다. 자연스럽지만 다른 표현과 원문 수치는 확인 필요가 될 수 있다. 숫자를 글자로 적은 표현이나 일반적인 문장의 부호/인과/비교 의미를 자동 판정하지 않는다. 사용자 문장을 기준 문구로 자동 교정하지 않는다.
- 원문 위치의 실재와 산식 실행이 모델이 추출한 지표 정의/주체/기간/분모의 진실성이나 주장 타당성을 보증하지 않는다.
- Q1a 품질 기록의 evidence/narrative/visual은 계속 `not_run`이며 제출본 차단도 유지한다. 이번 대조 결과는 아직 품질 sidecar/내보내기에 통합하지 않는다. 기존 숫자 존재 경고와 검사 범위가 다르다.
- 별도 앱/탭에서 원문을 바꾸면 다시 검사할 때 감지한다. 지속적인 파일 감시와 분산 리비전 잠금은 구현하지 않았다.
- Q1b 품질 기록/이력/공통 내보내기 잠금, 자유로운 문장과 요약의 의미 검수, 부분 재계획, 단위 환산, Q3~Q5는 남아 있다. 실제 제공자의 기준 문구 채택/용량/보고 흐름과 비용은 미검증이다.

## 다음 즉시 행동

Git 상태와 이 인계를 읽고 현재 구현을 확인한다. 다음 권장 단위는 **현재 수치 대조 결과를 Q1b의 품질 기록과 내보내기에 연결하는 최소 경로**다. 대상 0건/미연결 수치/낡은 자료를 통과로 바꾸지 않고 기존 초안과 품질 기록의 대응을 유지해야 한다. 자유로운 문장의 전체 의미 검수와 자동 수정 루프는 별도 범위로 둔다.

병행 작업에서 [DiagramSpec 도입안](../plans/2026-09-13-diagram-spec-adoption.md)이 문서로 추가됐다. Q3 착수 시 이 계약 후보를 함께 확인하되 이번 Q2d 구현에 도식 엔진이 포함됐다고 해석하지 않는다.

AI 실증을 먼저 진행한다면 별도 [AI 연결 인계](2026-09-13-ai-connections-handoff.md)의 본인 로그인 완료 및 합성 자료의 제공자별 1건 생성 계획을 따른다. 이번 작업은 실제 인증 완료나 생성 성공을 입증하지 않는다.

위키 `slidecaptain`의 상태는 오래되어 저장소의 최신 인계와 현물을 우선했다. `Contract-Measure-Roundtrip-Test`의 기준을 합성 JSON의 실제 API/프런트 왕복에 적용했다. 두 본문을 읽고 읽기 영수증을 확인했다. 재사용 로그에서 현재 세션의 프로젝트 페이지 읽기는 확인했으며 왕복 테스트 페이지의 현재 세션 성공 로그는 확인되지 않았다. pages_read=2, frames_applied=1, wiki_irrelevant_justified=0, reflux=0이다. 환류는 프로젝트 업무 기록이며 위키 지식/메모리를 새로 쓰지 않았다.

공통 환경 적용/정적 설치 결과는 current, 변경 파일 0개, pending_files=[]다. 새 앱 세션의 지침 로드는 검증하지 않았다. 프로젝트 CLAUDE.md의 변경은 현재 상태/인계 포인터이며 공통 운용 기준의 개정이 아니다.
