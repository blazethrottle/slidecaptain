# Q3b 프로젝트 도식 저장과 읽기 전용 미리보기 인계

작성: 2026-09-20. 사용자의 중단 지점부터 개발 재개 요청으로 [단위 계획](../plans/2026-09-20-q3b-project-diagrams.md)을 구현하고 검증했다. 이전 공통 렌더 구현은 원본에 남아 있었으며, 이번에는 그 다음 저장/제품 연결 단위를 진행했다.

## 완료한 동작

- 기존 Deck에 `diagram` 슬롯을 추가했다. 원래 노드/관계/근거 ID/조건과 각주만 저장하며 제목/분류 라벨/부제는 기존 Chapter/Slide 필드를 사용한다. 근거의 진본은 `Structure.story_plan.evidence` 하나다.
- 저장, 재열기, ETag, 스냅샷 복원에서 의미 입력을 보존한다. 도식 Chapter와 도식 ID/슬롯은 일치해야 하며 도식 내용과 제목이 빠지면 거절한다. 근거 없는 명시적 제안만 빈 장부를 허용한다.
- 좌표/렌더 결과/검수 통과 값은 도식 저장 입력으로 받지 않는다. 저장과 렌더 전에 원래 필드를 보존해 다시 검증하므로 모델 인스턴스를 직접 훼손해도 검사 우회가 되지 않는다.
- 일반 슬라이드와 도식을 구조안 순서로 계산한다. 기존 `/api/render-plan`, 프로젝트 render-plan과 초안 export가 공통 RenderPlan을 사용한다. 실패한 도식은 422와 사유를 돌려주며 부분 페이지/PPTX를 내지 않는다.
- 편집 화면은 도식을 읽기 전용으로 표시한다. 템플릿 변환/인라인 편집/AI 재생성/축약을 차단하고 구조안에서 도식의 주제/결론/템플릿/삭제를 잠근다. 다른 장 편집과 순서 변경/저장/undo/redo는 도식과 근거를 보존한다.
- 도식이 있는 덱의 전체 구조안 AI 재생성은 장부 교체를 막기 위해 아직 제한한다. 생성 전용 타입을 분리해 planned/unplanned schema와 실제 parser가 도식을 출력 대상으로 받지 않는다. 관련 API는 서비스 lease 전에 차단한다.
- 숫자 문구 검사에는 도식의 보이는 본문/조건/관계 라벨/각주만 포함한다. ID/버전/근거 참조 문자열은 숫자 문구로 세지 않는다. 기존 전체 품질 식별값은 원문 변경도 반영한다.
- 실제 화면에서 발견한 편집 열의 최소 폭 문제를 수정했다. 배치 실패는 '내용 없음'과 구분해 안내한다.

## 호환성과 남은 범위

Deck schema_version 1과 StoryPlan 버전은 유지한다. 기존 슬롯의 직렬화는 그대로이며 구 앱은 새 template 판별자를 거절한다. 도식의 기존 근거/문구/순서/프리셋이 바뀌면 배치를 다시 계산하고 식별값도 바뀐다. 모든 semantic/browser/powerpoint/reader 검수 상태는 계속 not_run이다. 이번 합성 화면 검사는 사용자 덱의 승인 기록으로 저장하지 않았다. 실제 검수 승인 저장/만료 체계는 후속 범위다.

아직 UI에서 도식을 새로 만드는 진입점은 없다. 이번 단위는 기존 Deck API/파일에 유효한 의미 입력이 있는 프로젝트를 여는 경로다. 도식 AI 생성, 자유 편집, 원문과 관계의 의미 검수, 분기/비인접 경로, 다른 폰트/읽기 프로필, 목표 PowerPoint 앱 표시와 독자 품질은 미완료다. 실제 AI를 호출하지 않았고 새 원격 CI/Windows 실기기 검증도 수행하지 않았다. 테스트 수와 합성 화면 성공을 보고서 품질 통과로 해석하지 않는다.

## 다음 단위

도식 의미 입력의 작성/검토 UI를 최소 범위로 설계한다. 기존 Evidence 장부 안에서 노드/관계/조건/근거를 지정하고 저장 전 실패 사유와 변경 후 재계산을 보여 주는 계약을 먼저 리뷰한다. AI 생성, 전체 StoryPlan 재계획, 검수 승인 저장을 한 번에 묶지 않는다. 이번 세션에서는 다음 단위로 확장하지 않는다.
