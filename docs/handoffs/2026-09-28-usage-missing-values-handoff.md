# Claude 사용량 결측 보존 수정 인계

작성: 2026-09-28. 사용자 요청은 SlideCaptain 개발 재개다. [직전 인계](2026-09-28-quality-pilot-handoff.md)의 실제 AI 관통은 모델/호출 상한 동의가 필요한 상태이므로, 로드맵에 이월된 사용량 결측 오류를 [단위 계획](../plans/2026-09-28-usage-missing-values.md)에 따라 처리했다.

## 변경

`build_call_usage`는 SDK 모델별 토큰 키가 없으면 0을 넣고, 잘못된 모델 항목은 제외한 뒤 나머지만 더하고 있었다. 이제 각 토큰 필드에 모든 모델의 음이 아닌 정수가 명시돼 있을 때만 합계를 만든다. 키 누락/null/음수/불리언/문자열/실수는 해당 필드의 합계를 `None`으로 만들며, 정상인 나머지 필드와 실제 0은 유지한다. 모델 항목 자체가 잘못된 혼합 입력은 네 합계를 모두 미확인으로 남긴다. 모델 여러 개 중 정상 항목 하나만 남았다는 이유로 실제 모델을 추정하지 않는다.

진단 로그와 앱 반환값은 같은 합산 함수를 사용한다. SDK의 비용/시간/턴 수와 실패 응답 사용량은 보존하며 마지막 턴 `usage`를 누적 토큰의 대체값으로 쓰지 않는다. 기존 nullable API 계약을 사용하므로 OpenAPI/프런트 생성 타입은 바뀌지 않는다.

화면은 알려진 입력과 출력 값을 각각 표시하며, 빠진 값에는 미확인을 표시한다. 캐시 0은 기존처럼 생략하고 캐시 결측은 `캐시 읽기 토큰 미확인` 또는 `캐시 생성 토큰 미확인`으로 표시한다. 네 토큰이 모두 없으면 `토큰 미확인`으로 묶는다. 예를 들어 두 호출의 입력 합계가 12이고 두 번째 출력/캐시 생성 값이 빠지면, 입력 12를 유지하고 출력/캐시 생성은 미확인으로 표시한다.

기존 JSONL이나 저장된 과거 0은 수정하지 않았다. 과거 기록만으로 실제 0인지 누락값을 변환한 것인지 구분할 수 없다.

## 검증

- 실패 확인: 신규 백엔드 39개 중 38개 실패/1개 통과, 프런트 4개 중 3개 실패/1개 통과로 기존 결함을 재현했다. 모델별 서로 다른 누락 필드의 추가 회귀 1개는 이 단계 이후 작성했다.
- 수정 후 신규 백엔드 40개/프런트 4개가 통과했다. 전체 백엔드는 1,602개 통과/Windows 전용 1개 미실행, 프런트는 406개/38파일 통과, TypeScript/Vite 빌드도 통과했다.
- 고정 SDK 응답을 실제 `SubscriptionProvider`와 앱 API에 연결해 형식 재시도 뒤 응답/JSONL을 공통 픽스처와 대조했다. 프런트도 같은 픽스처의 합산과 표시를 검사한다.
- OpenAPI 재생성은 기준선과 바이트가 같고, 임시 생성 TypeScript도 현재 파일과 같다. 공개 저장소 감사에서 문제 0건을 확인했다.
- 기존 대표 합성 보고서 오프라인 관통은 완료됐고 고정 제공자 호출 2회/외부 호출 0회다. 실제 AI가 보고서를 만든 결과는 아니다.
- Chrome 실서버에서 부분 결측과 모든 토큰 0의 합성 프로젝트 2개를 구조안 생성/형식 재시도까지 실행했다. 알려진 입력 12, 출력/캐시 생성 미확인, 입력/출력 0과 캐시 0 생략을 확인했다. 부분 결측 화면의 텍스트 잘림이나 겹침은 관찰되지 않았다. 모델명은 합성 `fixture-model`이며 실제 AI 호출은 없다.

독립 계획 검토에서 필수 수정 0건, 선택 보완 2건을 반영했다. 독립 구현 리뷰는 7개 변경 파일을 대조하고 필수 잔여 0건으로 판정했다. 별도 반례는 어댑터/로그 512개, API/JSONL 20개, 프런트 합산 20개와 화면 문구 81개가 모두 통과했다. 이 수치는 전체 테스트 개수에 합산하지 않는다.

실제 SDK/CLI 호출, Windows 실기기, PowerPoint와 독자 품질은 이번 검증에 포함하지 않는다. 브라우저 합성 검사는 실제 계정 인증이나 실제 AI 생성 성공을 입증하지 않는다.

## 보존과 다음 행동

원본 `codex/phase-5b`, HEAD `a8c6d7a`의 290개 파일과 인덱스를 보존해 `codex/usage-missing-20260928` 작업본에서 개발했다. 증거는 `~/Projects/slidecaptain-work/usage-missing-20260928/`의 baseline, logs, review, runs에 있다. 원본 보존을 재확인한 뒤 이번 13개 경로만 반영했다. 기존 8개 파일에 변경을 더하고 새 5개 파일을 추가했으며, 나머지 기존 282개 파일과 스테이징을 보존했다. 결과는 `logs/applied-preservation.json`에 있다. 커밋/푸시/머지는 하지 않았다. 검사에 사용한 서버와 브라우저 탭은 종료했다.

`CLAUDE.md` 변경은 프로젝트 진본의 최신 인계 포인터 갱신이며 공통 관리 사본의 규칙 수정이 아니다. 공통 `shared-work.md`의 승인 범위, 기존 변경 보존, 검증 구분 기준과 대조했고 충돌이 없다. 환경 적용/설치 검사는 `current`, 변경 파일 0건/설치 대기 0건이었다. 새 앱 세션의 지침 로드 검증을 뜻하지 않는다.

다음 행동은 기존 합성 입력과 Claude 모델/최대 호출 수를 제시하고, 실제 호출이 승인되면 관통 도구를 실행하는 것이다. [실행 방법](2026-09-28-quality-pilot-handoff.md)을 따른다. 의미/시각/PowerPoint/독자 품질은 별도로 확인하며 사용자 품질 판정을 대신 채우지 않는다. 이번 수정을 이유로 Q3 도식 AI 생성이나 Q4 검수 승인이 완료됐다고 하지 않는다.

위키의 부분 결측/전체 결측/실제 0 구분과 부분 합계 금지 기준을 현재 SDK 어댑터와 대조했다. [[wiki:AI-Usage-Accounting-Missing-Values]] 읽은 페이지는 2개, 실제 대조한 기준은 1개이며 결론은 로드맵과 동일했다. 지식 본문과 메모리는 변경하지 않았고 규칙 적용은 `no_effect`로 기록했다. 환류는 업무 기록으로 남긴다.
