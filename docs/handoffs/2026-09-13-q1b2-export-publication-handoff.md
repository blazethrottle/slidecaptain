## 목적과 승인 범위

SlideCaptain 개발 재개 요청을 [Q1b 첫 단위 인계](2026-09-13-q1b1-export-quality-handoff.md)의 다음 최소 단위로 수행했다. 별도 프로세스가 같은 출력 폴더에서 같은 버전을 골라 PPTX나 품질 기록을 덮어쓰는 문제를 막는 것이 목적이다. 합성 자료만 사용했으며 실제 AI 호출, 회사 자료 외부 전송, 커밋/푸시/머지와 배포는 수행하지 않았다.

브랜치는 `codex/phase-5b`, 시작 HEAD는 `62d7b61`, 종료 확인 HEAD는 `a8c6d7a`, remote는 `https://github.com/blazethrottle/slidecaptain.git`이다. 작업 중 별도 변경으로 `AGENTS.md` 하나만 추가한 커밋 `a8c6d7a`가 생겼으며 이번 세션이 만든 커밋은 아니다. 해당 파일을 읽고 보존했다. 기존 Q1a~Q2d와 AI 연결 작업은 시작부터 미커밋/미추적 상태였고 스테이징은 비어 있었다. 이번 세션은 pull이나 브랜치 전환, 일괄 스테이징을 하지 않았다.

시작 파일 221개를 별도 사본으로 보존했다. 이번 수정 파일 12개를 제외한 209개는 바이트가 같고 삭제는 없다. 이번 신규 파일은 잠금 모듈, 회귀 검사, 계획과 이 인계의 4개다. 작업 중 별도로 추가된 루트 `AGENTS.md`는 읽고 보존했으며 이번 작성 파일로 집계하지 않는다. 보존 사본과 검증 스크립트는 시스템 임시 폴더의 `slidecaptain-q1b2-1w7epo9i`에 있다.

## 완료한 동작

1. `export_deck_data`가 출력 폴더 단위의 OS 잠금을 사용한다. 웹/CLI와 직접 함수 호출, 같은 프로세스의 여러 스레드가 같은 잠금에 참여한다. 다른 출력 폴더는 독립적이며 웹의 기존 프로젝트 잠금 다음에 출력 잠금을 잡는다.
2. 품질 관문을 검사하고 같은 파일 시스템의 고유 임시 폴더에서 PPTX와 품질 JSON을 먼저 완성한다. 출력 잠금은 버전 선택부터 품질 기록/PPTX 게시가 끝날 때까지만 유지한다. 대상 파일이 이미 존재하면 hard link 생성이 실패하며 기존 파일을 교체하지 않는다.
3. 버전 선택은 같은 제목의 PPTX와 품질 기록 양쪽을 본다. 높은 번호의 고아 기록도 예약된 버전이며 비슷한 다른 제목의 번호를 섞지 않는다. 두 번째 파일 게시 실패나 그 사이 강제 종료 후에도 남은 기록을 덮어쓰지 않는다.
4. 성공/예외에서 잠금을 해제하고 핸들을 닫는다. 프로세스 강제 종료 때도 잠금이 해제되는 것을 검증했다. 잠금 파일은 빈 `.slidecaptain-export.lock`으로 계속 보존한다. 5초 대기 초과는 웹 409와 CLI 종료 코드 1 및 재시도 안내다. 파일 게시 오류는 웹 422와 CLI 실패로 알린다.
5. 기존 내보내기 성공 응답, 품질 모델, Deck/StoryPlan 버전과 제출본 차단은 유지한다. 소스/덱/스냅샷/사용량은 내보내기로 변경하지 않는다. 첫 단위의 화면은 그대로 사용하며 이번에 화면 구현을 바꾸지 않았다.

## 미완료와 다음 행동

다음 최소 단위는 **내보내기 검수 이력 목록/상세 조회와 과거 기록의 유효성 표시**다. 내보낸 시점의 품질 기록은 그대로 보존하고, 조회 시 현재 입력/원문 fingerprint와 실제 PPTX SHA-256을 대조한다. 품질 기록만 남은 버전, PPTX 부재, 해시 불일치, 깨진 JSON, 옛 preflight-v1과 현재 자료가 바뀐 기록을 구분해야 한다. 파일 두 개가 존재하는 것만으로 일치/현재 유효를 판정하지 않는다. 읽기 전용 경로부터 계획하고 사용자 입력과 기존 결과 파일을 자동 수정하지 않는다.

재심할 전제는 로컬 파일 시스템의 OS 잠금과 hard link 지원이다. Windows 코드는 작성됐지만 실기기/새 CI에서 아직 실행하지 않았다. 미지원 파일 시스템에서는 오류를 알리며 안전하지 않은 복사로 우회하지 않는다. 네트워크 드라이브, 동기화 서비스, 잠금 파일 삭제/교체, 구버전 앱 동시 실행과 전원 차단 내구성을 보장하지 않는다. 강제 종료 뒤 숨김 임시 폴더는 남을 수 있으며 활성 요청 여부를 모른 채 자동 삭제하지 않는다.

CLI와 외부 편집기의 덱/원문 읽기 전체를 하나의 트랜잭션으로 만드는 것은 이번 게시 잠금의 범위가 아니다. 자유로운 문장의 의미 검수, 원문 메타데이터 해석, 요약 정합성, 자동 수정, 단위 환산, Q3~Q5와 실제 AI/PowerPoint/독자 평가는 계속 남아 있다. DiagramSpec 도입안과 AI 연결 인계도 유지한다.
