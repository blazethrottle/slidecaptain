# Claude와 Codex LUNA 직접 선택 및 실제 생성 검증 인계

작성: 2026-09-28. 사용자는 Sonnet 최대 5회 호출을 승인하고 Codex LUNA도 지원하도록 요청했으며, 자동 백업 대신 직접 선택 방식을 확정했다. 사용자가 공식 Codex 로그인을 완료했다. [계획](../plans/2026-09-28-manual-ai-selection.md), [검증 기록](../qa/2026-09-28-manual-ai-selection-pilot.md).

## 구현과 사용

AI 연결 화면에서 **Claude Sonnet** 또는 **Codex LUNA**를 누른 뒤 **선택 저장**으로 확정한다. 빠른 선택은 현재 모델 목록의 정확한 ID가 있을 때만 가능하다. 클릭만으로 저장하지 않으며 저장된 모델 복원, 생성 중 선택 잠금, 변경 후 전송 동의 재확인을 유지한다. 실패 시 다른 제공자를 자동 호출하지 않는다.

파일럿 도구는 `--provider claude|codex`를 지원한다. 기본 모델은 각각 `sonnet`, `gpt-6-luna`다. 명시한 다른 Codex 모델도 그대로 사용한다. 내부 제공자 ID `chatgpt`, API/OpenAPI, 도메인 모델과 저장 계약은 바꾸지 않았다. 준비/오프라인 모드는 인증 조회나 외부 호출을 하지 않는다. 실제 실행은 선택한 공식 어댑터만 만들고 성공과 실패 모두 연결 프로세스를 정리한다.

앱 전용 Codex 프로필은 `~/slidecaptain-projects/.slidecaptain-codex`에 유지된다. 인증 파일은 읽거나 복사하지 않았다. 별도 위치는 `--codex-home`으로 지정한다. 실제 AI 연결 화면 검사는 별도 QA 데이터 폴더를 사용했으며 사용자의 기존 모델 선택을 덮어쓰지 않았다.

Chrome 실검수에서 발견한 하단 잘림도 수정했다. `Preview` 바깥 높이를 `pageH * scale`로 맞춰 CSS 확대 후 결론과 각주가 숨지 않게 했다. 보고서 좌표와 PPTX는 그대로다.

## 실제 호출 결과

합성 자료는 접수 담당자의 요청 접수, 검토 담당자에게 전달, 검토 담당자의 검토 3문장이다. 기존 초안은 표지/수동 작성 도식/개선 검토 3장이다. 회사 자료는 전송하지 않았다.

| 선택 | 실제 모델 | 호출 수 | 결과 |
| --- | --- | ---: | --- |
| Claude Sonnet | `claude-sonnet-5` | 2 | 개선 검토 장 생성, 편집 보존 재작성, 3장 초안 PPTX까지 완료 |
| Codex LUNA | `gpt-6-luna` | 3 | 장 생성 성공. 재작성과 형식 재시도 모두 보존 계약 위반으로 거절 |

승인된 총 5회를 모두 사용했다. 호출 단위는 `provider.complete` 진입이며 실패와 재시도를 포함하고 SDK 내부 턴은 별도다. 새 실제 호출은 추가 승인 범위가 필요하다. 도구의 `--max-calls`는 실행별 제한이라 세션 누적량은 앞선 기록과 합쳐 확인해야 한다.

LUNA의 첫 재작성은 보호 근거의 `value:null`을 원문으로 바꿨다. 재시도는 값을 복원했으나 도식 장의 `claim_ids`에 세 주장을 추가했다. 원문 응답의 오프라인 재파싱으로 거절 사유를 재현했다. 재작성 전 덱과 실패 후 저장된 덱의 파싱한 JSON 전체 내용은 같으며 성공한 장 본문이 남아 있다. 보존 검사를 완화하거나 모델 간 자동 전환으로 우회하지 않았다. LUNA의 재작성과 해당 흐름의 PPTX 내보내기는 미완료다.

Sonnet의 PPTX는 3장, 파일/품질 기록 해시 일치, 편집 가능한 도식 도형을 확인했다. 제출용 내보내기는 미검수 상태에서 계속 거절된다. 산출물 상태는 `draft`다. 실제 PowerPoint 표시, 독립 의미 검수와 독자 품질 판정은 완료하지 않았다.

## 검증

- 백엔드 전체 1,615개 통과, Windows 전용 1개 미실행. 새 선택 회귀 13개는 이 수에 포함된다.
- 프런트 전체 410개/38파일 통과, TypeScript/Vite 빌드 통과. 새 선택 화면 회귀 4개는 이 수에 포함된다.
- OpenAPI/생성 TypeScript 바이트 무변경, 공개 저장소 감사 발견 0건.
- Chrome에서 미저장 선택, 명시적 저장, 새로고침 후 복원과 로그인 완료를 확인했다. 확대된 표지/일반 장/도식과 축소된 도식 작성창의 포함성 4개 중 실패 0개다. 480px/창 resize 검사는 도구가 실제 창 크기를 바꾸지 못해 미검증으로 남긴다.
- 독립 계획 리뷰, 구현 리뷰와 추가 Preview 리뷰의 필수 수정 잔여 0건. 리뷰어가 별도로 실행한 모의 실패 반례 6개와 실제 Codex 어댑터의 RPC 모의 관통 1개는 통과했으며 전체 테스트 수에 합산하지 않는다.

PowerPoint는 이 Mac에 없고 Keynote의 네이티브 앱 연결도 두 번 시간 초과로 실패했다. 브라우저 미리보기와 PPTX 구조 검사는 목표 앱 표시/편집을 대신하지 않는다. 새 Windows CI, Q3 도식 AI 생성, Q4 검수 승인과 Q5 비교도 이번 완료 범위에 포함하지 않는다.

원본은 `codex/phase-5b`, HEAD `a8c6d7a`다. 원본 295개 파일과 스테이징을 기준으로 격리 작업본 `codex/manual-ai-selection-20260928`에서 구현했다. 증거 위치는 `~/Projects/slidecaptain-work/live-pilot-20260928-cygnfscx/`다. baseline, logs, review, live, live-codex, browser에 입력/출력/사용량/화면을 보관했다. 원본 반영과 보존의 최종 판정은 `logs/applied-preservation.json`을 따른다. 커밋/푸시/머지는 하지 않는다.

다음 개발 후보는 LUNA 응답의 보호 필드 위반을 오프라인 회귀로 고정하고 재작성 지침 또는 후보 구성을 개선하는 일이다. 기존 필드 보존과 저장 거절을 유지하며 실제 재검증은 새 호출 상한을 정한 뒤 수행한다. 별도로 목표 PowerPoint에서 3장 초안을 열어 표시/편집을 확인하고 독자가 품질을 판정해야 한다. 단일 합성 사례로 제공자 품질 순위나 비용 우위를 결론내리지 않는다.

`CLAUDE.md`는 프로젝트 최신 인계 포인터만 갱신한다. 환경 설치 검사는 current, 변경 0건이었으며 새 앱 세션이 지침을 읽었다는 뜻은 아니다. 위키의 과거 프로젝트 기록은 저장소 위치와 기존 변경 보존 원칙에 참고했고 현재 결과는 로컬 코드와 실행으로 확인했다. [[wiki:slidecaptain]] 위키 본문과 메모리는 변경하지 않았다.
