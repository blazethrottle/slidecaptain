# Windows PowerPoint 검수 준비 인계

사용자 승인: 현재 개발본을 GitHub에 커밋·푸시하고 회사 Windows PC의 실제 PowerPoint 검수와 사용자 직접 품질 피드백을 준비한다. 개발 브랜치는 `codex/phase-5b`이며 main 머지·배포·추가 AI 호출은 이번 작업에 포함하지 않는다. 2026-10-01 시작, 2026-10-02 로컬 검증을 마쳤다.

## 준비한 것

- `Windows검수준비.bat`: 현재 checkout 백엔드 설치, 프런트 빌드, 별도 검수 폴더와 8870 앱·피드백 폼·파일 폴더를 연다. 충돌 포트와 Python/Node 환경 오류에서 중단한다.
- `scripts/prepare_windows_review.py`: 현재 exporter로 합성 5개/15페이지를 만든다. 템플릿 10종, 도식, 막대·열 차트, 부분 강조를 포함한다. 원본 PPTX의 SHA-256·버전·페이지 목록과 검사 당시 미커밋 여부를 기록한다. 매번 새 회차를 만들어 기존 회사 프로젝트·인증정보·평가를 보존한다.
- `scripts/windows-review-form.html`: 환경, 다섯 품질 기준, 페이지별 판정, 구체적인 수정 요청·실제 수정 시간을 JSON으로 다운로드하고 같은 회차에 복원한다. 미평가/미측정은 null, 실제 0분은 0이다. 브라우저 임시 저장은 보조다. 직접 만든 보고서의 추가 피드백 칸도 제공한다.
- [회사 PC 시작 가이드](../qa/2026-10-02-windows-powerpoint-guide.md): 최신 브랜치 준비를 에이전트에 맡기는 재개 문장, PowerPoint 전체 페이지 표시·편집·native render·피드백 보관 순서를 설명한다.

출력과 평가, 회사 데이터는 저장소의 무시된 `projects/windows-review/`에서만 관리한다. 공개 저장소에는 생성 코드와 비기밀 합성 픽스처를 제공하고 Office 파일이나 인증 프로필을 넣지 않는다. 기존 배치 인계·QA의 개인 절대 경로 두 곳은 공개용 자리표시자로 바꿨으며 외부 증거 원본은 그대로 보존했다.

## 로컬 검증

- 백엔드 전체 1,954 통과 / 1 건너뜀, 프런트 전체 532 통과, 빌드 통과.
- OpenAPI·TypeScript 재생성 전후 바이트 일치.
- 검수 준비 회귀: 5개/15페이지, 파일 해시, 편집 가능한 차트 값 1200/1000, 제출 차단 유지, 반복 실행 뒤 기존 PPTX·피드백 불변을 검사했다.
- 폼 자동 검사(jsdom): 기본 null, 실제 0분, 같은 회차 복원, 복원 직후 임시 저장, 타회차 거절, JSON 다운로드를 확인했다. 독립 리뷰에서 발견한 복원 후 임시 저장 누락을 수정하고 재검토했다.
- 독립 검토: 지정 준비 도구·폼·배치·테스트·가이드 5파일에서 차단 사항 없음. 실제 Windows 실행은 이 결과에 포함되지 않는다.

공개 파일 감사·Git diff 검사 후 선택한 개발 파일만 커밋하며 원격 반영과 CI 결과는 GitHub에서 확인한다. 이번 커밋의 CI에서도 새 배치 파일의 CRLF를 검사한다. 로컬 실행 증거와 선택 파일 해시는 저장소 밖 `publication-20261002/logs/`에 보관한다.

## 회사 PC에서 이어갈 것

실제 Windows 배치 실행·PowerPoint 열기/표시/편집·native render와 사람 품질 판정은 미실행이다. 검수 폼과 수동 검수 기록은 독립 서명 영수증이나 제출 승인으로 자동 승격하지 않는다. 이전 Q5 사람 평가 0/9와 개선 우세 미입증도 유지한다. 회사 원문은 회사 PC에 보관하고 다음 개발 세션에 전달할 피드백과 화면에서는 민감정보를 제외한다.

프로젝트 지침에 추가한 재개 포인터는 공통 `shared-work.md`의 기존 변경 보존, 미검증 분리, 승인 범위와 일치하는지 대조했다. 이 프로젝트의 CLAUDE.md는 프로젝트 정본이며 전역 관리 사본이 아니므로 위키 공통 지침이나 전역 설치는 변경하지 않았다.
