# 대표 합성 보고서 관통 도구 인계

작성: 2026-09-28. 사용자 요청은 SlideCaptain 개발 재개다. [직전 인계](2026-09-27-story-plan-rewrite-handoff.md)의 다음 행동을 [단위 계획](../plans/2026-09-28-quality-pilot.md)에 따라 실행 도구로 구체화했다. 이번에는 제품 화면이나 생성 계약을 바꾸지 않는다.

## 구현

`backend/scripts/quality_pilot.py`는 표지/업무 흐름 도식/개선 검토의 합성 3장을 준비한다. 기존 도식 픽스처를 바탕으로 일반 장 하나 생성, 저장, 계획 재작성 미리보기/적용, 렌더와 초안 PPTX/품질 기록 검사를 연결한다. 전체 구조안 생성이나 도식 AI 생성 시나리오는 아니다. 자료와 주장은 실제 회사 정보를 사용하지 않는다.

기본 모드는 외부 연결을 만들지 않고 입력만 준비한다. `--offline`은 같은 `AIConnections`/앱 API에 고정 응답을 넣는다. `--live --consent --max-calls N`은 사용자가 승인한 실제 Claude 호출용이다. 호출 상한은 실행 전체의 `provider.complete` 진입 기준이며 실패/형식 재시도/축약이 포함된다. SDK 내부 턴이나 청구 요청 수와 같은 단위가 아니다. 제안 상한 5회는 일반 장 최대 3회, 계획 재작성 최대 2회다.

각 호출 전에 실제 prompt/schema와 시작 기록을 저장한다. 실패·반환 시 앱 `CallUsage`를 변경 없이 남긴다. 기록을 저장하지 못하면 추가 호출을 중단한다. 자동 축약 차단 뒤 API가 정상 초안을 반환해도, 도구는 초안을 저장하고 실행 전체를 중단으로 기록한다. 원본 출력 폴더는 재사용하지 않는다.

## 실행 방법

저장소 backend 폴더에서 설치된 개발용 가상환경으로 실행한다. 아래 명령은 새 합성 입력만 준비하며 AI를 호출하지 않는다.

```sh
PYTHONPATH=. .venv/bin/python -m scripts.quality_pilot --output /tmp/slidecaptain-pilot-prepare
```

같은 앱 API를 고정 응답으로 검사하려면 다른 새 출력 폴더와 `--offline`을 사용한다.

```sh
PYTHONPATH=. .venv/bin/python -m scripts.quality_pilot --output /tmp/slidecaptain-pilot-offline --offline
```

실제 호출은 별도 승인 후 다음 형식을 사용한다. 기존 Claude 구독 연결을 이용하며 인증 설정은 변경하지 않는다.

```sh
PYTHONPATH=. .venv/bin/python -m scripts.quality_pilot --output /tmp/slidecaptain-pilot-live --live --consent --model sonnet --max-calls 5
```

기존 출력 경로, 입력/기록/제공자 오류 또는 상한 차단은 종료 코드 2다. 이미 저장한 산출물은 남는다. 삭제나 덮어쓰기가 필요하지 않으며 다시 검사하려면 새 출력 폴더를 사용한다. 도구 실행에는 `httpx` 등 저장소의 dev 의존성이 필요하다. Windows에서는 동일한 모듈을 `.venv\Scripts\python.exe`로 실행한다.

## 검증과 한계

새 회귀 22개가 준비/오프라인 무호출, 동의/상한 누락, 선택 ID 409와 동의 428, 최초 실패/형식 재시도/자동 축약/후속 재작성의 공유 상한, 기록 쓰기 실패, 사용량 결측, 기존 출력 보존을 검사했다. 전체 백엔드는 1,562개 통과, Windows 전용 1개 미실행이다. 호출 입력 보존 수정까지 포함한 최종 전체 실행도 1,562개 통과/1개 미실행이며 관련 22개를 별도로 확인했다.

오프라인 관통에서 후보 무저장, 재작성 후 본문 보존, 3장 PPTX 재열기, 도식의 편집 가능한 도형, 파일/품질 기록 해시와 제출본 거절을 확인했다. `TestClient`로 실제 앱 라우트를 실행한 결과이며 TCP 실서버나 브라우저 화면 검증을 뜻하지 않는다. 새 UI/OpenAPI/모델 변경은 없으므로 프런트 전체 검사는 반복하지 않았다.

실제 Claude 로그인 상태는 생성 없이 확인했다. 실제 모델 생성은 승인 대기다. PowerPoint는 이 Mac에 없으며 의미/시각/목표 앱/독자 검수는 `not_run`이다. 고정 응답과 PPTX 구조 검사로 실제 품질을 통과 처리하지 않는다.

계획 리뷰의 4항은 공유 예산, 실제 연결 선택 관문, 실패 기록과 사용량 표현에 반영했다. 독립 구현 리뷰에서 전송 prompt/schema 본문 보존 누락 1건을 반영한 뒤 필수 잔여 0건을 확인했다. 별도 반례 6개(정확히 5회 완료, 4회 중단/본문 보존, 오류 사용량, 기록 실패, 계정명 비저장)를 통과했다. 입력 저장 실패와 후속 무호출을 확인하는 독립 probe 1건도 통과했다. 신규 22개와 독립 6개, probe 1건은 전체 백엔드 수에 합산하지 않는다. 기존 `build_call_usage`의 누락 필드 0 정규화 반례는 로드맵에 이월했다. 이번 도구가 원시 SDK 결측을 복원하거나 비용을 실제 청구액으로 환산하지 않는다.
