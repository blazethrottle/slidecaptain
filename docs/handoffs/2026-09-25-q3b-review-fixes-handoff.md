## 완료한 변경

도식 확인을 시작한 뒤 작성 창을 닫고 다른 편집을 저장하면, 늦은 확인 응답의 ETag가 이후 저장의 ETag를 되돌릴 수 있었다. 화면은 이미 후보를 무시해도 API 클라이언트의 공통 저장본 식별값이 변경되어 다음 저장에 과거 If-Match를 보내게 됐다.

- `frontend/src/api/client.ts`: 요청의 If-Match 전송과 응답의 ETag 갱신을 구분했다. 읽기 전용 도식 확인은 현재 식별값을 보내지만 응답으로 저장용 식별값을 갱신하지 않는다. 덱 읽기/저장/스냅샷 복구의 기존 동작은 유지한다.
- `frontend/src/api/client.test.ts`: 확인 요청, 이후 저장 성공, 이전 확인 응답 도착, 다음 저장 순서를 재현했다. 수정 전 다음 저장의 If-Match가 과거 값으로 되돌아가 실패했고 수정 후 최신 값이 유지됐다.
- 로드맵, 품질 개발 계획과 진입 문서의 최신 인계 포인터를 갱신했다. API/모델/저장 스키마는 바뀌지 않았다.
