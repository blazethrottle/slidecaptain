# Q3b 핵심 답변의 역할과 주장 연결 안내 인계

작성: 2026-09-27. 사용자의 개발 재개 요청으로 [직전 인계](2026-09-27-q3b-independent-review-handoff.md)의 다음 후보 중 역할 제약 안내를 구현했다. [계획](../plans/2026-09-27-q3b-answer-guidance.md)에 따라 전체 재계획이나 낡은 계획 복구로 확대하지 않았다.

## 변경과 판단 근거

기존에는 유일한 답변 도식을 근거 역할로 바꾸거나 그 장만 맡는 핵심 주장을 해제하면 서버 확인 단계에서 거절됐다. 이제 입력 단계에서 이유와 유지해야 할 연결을 표시한다. 같은 주장을 다른 답변 장도 맡는 경우에는 역할이나 연결 변경을 허용한다.

- `frontend/src/editor/diagramDraft.ts`: 대상 장을 제외한 답변 역할 장들이 다루는 주장 ID의 합집합을 구한다. 이 집합에 없는 핵심 답변만 해당 도식에 남겨야 하며, 잘못된 초안은 저장 플러시/연결 확인/배치 요청 전에 차단한다.
- `frontend/src/editor/DiagramAuthoringDialog.tsx`: 역할 선택란에 사유를 설명하고 유지해야 할 주장에 표시한다. 필요한 경우 다른 역할과 필수 주장의 선택 해제를 제한한다. 이미 누락된 초기 초안은 자동 변경하지 않고 사용자가 다시 선택해 고칠 수 있다.
- `frontend/src/styles.css`: 주장별 선택지를 줄로 구분하고 연결 유지 표시를 해당 주장 아래에 둔다. 실제 Chrome의 복수 주장 화면에서 구분이 어려웠던 표시를 수정했다.
- `frontend/src/editor/DiagramAuthoringDialog.test.tsx`: 10개 회귀를 추가하고 역할 변경 성공 사례는 같은 핵심 주장을 맡는 다른 답변 장이 있는 유효한 조건으로 바꿨다.

답변 장의 개수만 세면 다른 주장만 맡는 장을 잘못 대체 수단으로 인정할 수 있다. 원본 StoryPlan의 주장별 연결 조건을 그대로 따른다. 핵심 답변 이외의 일반 주장 연결, 근거 현재성과 전체 계획 유효성은 기존 서버가 최종 검사한다. API/모델/저장/OpenAPI 계약은 바뀌지 않았다.

## 검증

| 대상 | 결과 |
|---|---|
| 새 실패 검사 | 추가 기능이 없는 기준본에서 8건 실패, 기존/대조 사례 20건 통과 |
| 관련 프런트 | 28건 통과 |
| 최종 프런트 전체 | 35파일 370건 통과 |
| 타입/빌드 | TypeScript와 Vite 통과 |
| 공개 저장소 감사 | 종료 코드 0, 발견 0건 |
| 관련 백엔드/계약 | StoryPlan, 도식 연결과 OpenAPI 검사 51건 통과 |
| 독립 리뷰 | 이번 변경 승인, 대상 5파일 중 필수 수정 0건. 독립 UI 6건 통과, 백엔드와 10,125조합 대조의 불일치 0건, 비핵심 주장 미연결의 서버 거절 1건 확인 |
| Chrome 합성 프로젝트 | 3개 시나리오 확인. 연결 확인 2건/저장 2건 모두 200, 저장본 3개의 계획 현재성 검사 통과 |

독립 리뷰 원문과 최종 5파일 해시는 `review/initial-review.md`, `review/reviewed-files.json`에 있다. 계획의 반례도 대조했으나 구현 전 계획 리뷰로 소급하지 않는다. 다른 답변 두 장이 주장을 나눠 맡아 전체를 다루는 사례는 독립 UI와 조합 대조에서 통과했다. 이 사례를 상시 회귀로 옮기자는 비차단 제안 1건은 다음 관련 테스트 정비에 이월했고 로드맵에 반영했다.

실제 Chrome 확인은 다음과 같다.

1. `single-answer`: 안내 문구, 답변 역할 유지와 필수 주장 체크 해제 제한을 확인했다.
2. `shared-answer`: 같은 주장을 다른 답변 장도 맡는 상태에서 근거 역할로 변경하고 확인/적용/저장했다. 목록으로 나갔다가 프로젝트와 작성 창을 다시 열어 근거 역할을 확인했다.
3. `partial-answer`: 다른 답변 장이 첫 주장만 맡는 상태에서 두 번째 주장만 필수로 표시됐다. 공유된 첫 주장 연결을 해제한 뒤 확인/적용/저장했고 다른 장의 답변 연결과 계획 현재성을 확인했다.

화면 검증은 제공자/계정을 구성하지 않은 임시 서버와 합성 자료만 사용했다. AI 사용량 파일은 0개이며 실제 AI를 호출하지 않았다. 브라우저 요청 중 API 실패는 0건이고 기능과 무관한 `/favicon.ico` 404가 1건 있었다. 임시 서버와 검증 탭은 종료했다.

백엔드 생산 코드가 바뀌지 않아 전체 백엔드를 반복 실행하지 않았다. 이전 전체 결과는 9월 25일의 1,501건 통과/Windows 전용 1건 미실행이며 현재 회차의 검사 수와 구분한다. 실제 AI 인증/생성, Windows 실기기, 목표 PowerPoint와 독자 품질은 이번에 검증하지 않았다.

관련 위키의 백엔드 단일 진본과 자동 검사/화면/실제 품질 구분 원칙을 기존 계획과 대조했고 같은 결론을 유지했다. [[wiki:slidecaptain]] 부모 세션은 `pages_read=1`, `frames_applied=1`, `wiki_irrelevant_justified=0`, `reflux=1`이며 읽기 로그를 확인했다. 위키 본문과 메모리는 수정하지 않았고 환류는 Ingest 제안이다.

위키 후보: 필수 역할 연결의 사전 안내에서는 역할 개수보다 각 핵심 주장을 맡는 다른 장의 합집합을 검사해야 한다. 부분 공유와 누락된 초안의 복구 경계를 함께 검사한다.
