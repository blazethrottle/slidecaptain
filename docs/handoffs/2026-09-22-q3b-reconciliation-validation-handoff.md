# Q3b 도식 연결의 저장 안정성 및 화면 검증 인계

작성: 2026-09-22. 2026-09-20 개발 재개 요청으로 [단위 계획](../plans/2026-09-20-q3b-reconciliation-validation.md)을 진행했다. 작업 중 날짜가 바뀐 뒤 원본 266개 파일의 해시와 스테이징이 시작 상태와 같음을 다시 확인했다.

## 수정한 동작

- 도식 연결 확인 전에 기존 편집의 저장을 마친다. 저장 대기/진행 중 요청을 기다리고 실패하면 확인 API를 호출하지 않는다. 작성 창의 입력은 적용 전까지 덱에 저장하지 않는다.
- 연결 확인의 412 응답도 편집기 충돌 상태로 전달한다. 창에 입력을 남기고 적용을 차단하며, 닫으면 기존 `서버 내용으로 되돌리기` 경로를 사용할 수 있다.
- 충돌 직후 대기 중인 저장과 flush가 PUT을 재시도하지 않게 했다. 다른 확인 요청에서 감지한 충돌을 늦은 저장 성공이 지우지 않는다. 복구는 진행 중 저장 체인이 끝난 뒤 서버본을 읽는다.
- 기존 도식 연결을 다시 확인할 때 StoryPlan의 원래 장 순서를 유지한다. 같은 역할/주장을 다시 확인하면 계획과 fingerprint가 바뀌지 않는다.
- 유일한 답변 장을 다른 역할로 바꾸는 등 계획 조건을 어긴 요청은 422로 거절한다. 실제 Chrome에서 발견한 내부 Pydantic 객체 노출을 제거하고 사용자에게 필요한 사유만 반환한다.

## 변경 파일

- `frontend/src/state/useDeckEditor.ts`: 확인 요청의 충돌 전달, 대기 저장 중단과 복구 순서.
- `frontend/src/editor/DiagramAuthoringDialog.tsx`, `frontend/src/screens/EditorScreen.tsx`: 저장 플러시 후 확인, 실패 시 입력 보존과 충돌 안내.
- `backend/slidecaptain/pipeline/story.py`, `backend/slidecaptain/server/app.py`: 기존 장 순서 보존과 입력을 노출하지 않는 계획 검증 오류.
- 관련 프런트 테스트 3개 파일과 `backend/tests/test_story_plan_reconciliation.py`: 실제 실패, 늦은 응답, 412/409 거절 및 덱/스냅샷 무변경을 고정했다.
