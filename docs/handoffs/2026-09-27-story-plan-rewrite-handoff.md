# 편집 보존 보고 계획 재작성 인계

작성: 2026-09-27. 사용자는 다음 기능인 보고 계획 재작성 구현 후 전체 QA를 선택했다. [직전 복구 안내](2026-09-27-q3b-stale-plan-guidance-handoff.md)에서 남긴 기능을 [계획](../plans/2026-09-27-story-plan-rewrite.md)에 따라 구현했다. 결과와 상세 증거는 [전체 QA 보고서](../qa/2026-09-27-story-rewrite-full-qa.md)를 따른다.

## 사용자 동작과 계약

저장된 보고 계획이 있는 프로젝트에서 구조안 탭의 **기존 편집을 보존하며 계획 재작성**을 사용한다. 새 질문과 지시사항으로 후보를 만들고, 본문 재검토 확인 뒤 **이 계획 적용**을 누른다. 적용 전까지 기존 계획과 스냅샷은 변하지 않는다. 기존 장 ID/제목/결론/템플릿과 슬라이드 내용은 보존하며 장 순서, 일반 장의 역할/주장/근거를 변경한다.

도식 장의 역할/주장, 직접/간접 근거와 관련 비교/산식은 그대로 유지한다. 보호 근거의 원문 전체 해시가 달라지면 발췌가 같아도 AI 호출 전에 거절한다. 장 추가/삭제, 본문 재생성이나 변경된 보호 근거 이전은 이번 계약에 없다. 적용 뒤의 `rewrite_review`는 재작성 당시 보존한 장의 이력이며 검수 승인이 아니다.

- `POST /api/projects/{name}/story-plan/rewrite`: 기존 동의/모델 선택 관문, 명시적 If-Match, 자료 현재성 검사 후 미저장 후보/기준 ETag/자료 해시 반환. 생성 동안과 직후 변경도 거절한다.
- `POST /api/projects/{name}/story-plan/rewrite/apply`: 후보의 기준 ETag와 전체 자료 해시로 다시 검사하고 보호 내용/원문/계획 fingerprint를 검증해 같은 저장 잠금 안에서 스냅샷과 덱을 저장한다.
- 입력 변경과 늦은 응답, 화면 이탈, 중복 적용을 보호한다. 412에서 후보/질문을 유지하고 적용을 막으며 기존 서버본 복구에 연결한다.
- 선택적 메타데이터가 없는 이전 계획은 null 필드를 직렬화하지 않는다. 예전 세 버전의 저장/계획/수치/품질 식별값 12개가 기준본과 같다.

주요 파일은 `pipeline/rewrite.py`, `pipeline/story.py`, `pipeline/service.py`, `models/story.py`, `server/app.py`, `StoryRewritePanel.tsx`, `StructureScreen.tsx`, `ProjectView.tsx`, `StoryPlanView.tsx`, `api/client.ts`와 생성 스키마/타입이다. 신규 상시 회귀는 백엔드 38개와 프런트 13개다.

## 검증과 리뷰

백엔드 전체 1,540개 통과/Windows 전용 1개 미실행, 프런트 402개/37파일 통과, 타입/빌드, OpenAPI/타입 바이트 일치, 줄바꿈/실행 모드와 공개 저장소 이력 감사를 확인했다. 실서버 HTTP/CLI/PPTX 검사 50개와 Chrome의 적용/재열기, 저장 충돌/복구, 390px 화면을 확인했다. 브라우저 뒤 저장본 대조 7항목도 일치했다.

구현 전 계획 리뷰의 필수 4항을 반영해 재검토를 받았다. 구현 리뷰의 공유 busy 해제, 모순된 ID 프롬프트, 조건/질문의 수치 경고 누락, 일반 문구 정규화 누락 4건을 실패 재현 후 수정했다. 브라우저에서 발견한 표 넘침도 수정했다. 독립 반례 23개와 관련 회귀 79개가 통과했고 이번 기능의 최종 18파일에 대한 필수 잔여는 0건이다. 누적 브랜치 전체의 독립 리뷰 승인은 아니다.

실제 AI와 Windows/새 CI, PowerPoint 및 독자 품질은 미검증이다. PPTX 구조 재열기와 합성 화면 결과로 실제 보고서의 의미/시각 품질을 통과 처리하지 않았다. 모든 생성은 로컬 합성 프로바이더이며 외부 AI 호출은 0회다. 검증 탭과 임시 서버는 종료했고 합성 결과는 작업 폴더에 보존했다.

재심 전제: 원문 전체 해시가 바뀐 보호 근거를 자동 갱신하는 것은 의미 검증이 아니다. 기존 본문 보존과 새 계획의 품질도 서로 다른 조건이다. 재작성 메타데이터를 현재 검수 승인 원장으로 확장하려면 저장/만료 계약부터 새로 정해야 한다.
