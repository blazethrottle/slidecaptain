# Q4a 수동 검수 기록과 현재성

작성: 2026-09-29. 개발 재개 요청에 따라 [직전 도식 AI 후보 인계](2026-09-29-diagram-ai-draft-handoff.md)의 다음 단위였던 검수 기록 저장/만료를 구현했다. [계획](../plans/2026-09-29-q4a-review-records.md), [QA](../qa/2026-09-29-q4a-review-records.md).

## 사용할 수 있는 흐름

프로젝트의 검수 이력 → 내보낸 파일 상세 → 수동 검수 기록에서 보고 흐름·근거·표현·시각·목표 PowerPoint 표시의 판정을 기록한다. 검수자, 판단 근거와 확인한 페이지가 필요하고 통과는 모든 페이지를 명시적으로 확인해야 한다. 최신 항목별 판정과 과거 기록을 함께 확인할 수 있다.

기록은 내보낸 파일의 입력 fingerprint와 실제 PPTX 해시에 묶이며 별도 파일로 추가한다. 자료/덱/프리셋/출력이 바뀌면 현재 출력에 적용할 수 없다고 표시한다. 손상된 최신 기록을 건너뛰어 과거 통과를 복원하지 않는다. 내용이 정확히 복원되면 같은 기록이 다시 현재로 표시될 수 있다. 조회 시점의 일치이며 변경 이벤트의 영구 이력은 아니다.

저장 직전에 명시적 ETag와 모든 기준을 재대조한다. 409/412에서는 입력을 보존하고 다시 기준을 확인해야 저장할 수 있다. 미저장 폼 이탈 확인, 저장 중 이탈 차단, 내보내기 대기 중 입력 잠금과 늦은 응답 보호를 연결했다. 복구/덱 읽기 실패 화면은 읽기 전용이다.

수동 통과는 검수자의 자기 신고이며 실제 렌더 확인이나 독립 검수 영수증이 아니다. 모든 항목을 수동 통과로 기록해도 산출물은 초안이며 HTTP/CLI 제출본 요청은 계속 차단된다.

## 구현과 검증

- `models/export_reviews.py`, `export/reviews.py`, 서버의 `GET/POST /api/projects/{name}/exports/{export_id}/reviews`와 이력 화면을 추가했다. 기존 Deck/StoryPlan/게시 품질 기록은 변경하지 않는다.
- 안전한 디렉터리 고정과 공통 OS 게시 잠금에서 순번을 배정하고 불변 추가한다. 파일 128KiB, 합계 8MiB, 1,000개 한도를 넘는 쓰기는 게시 전에 거절한다.
- 전체 백엔드 1,772개 통과/Windows 전용 1개 미실행, 프런트 463개/44파일, 타입/빌드, 실제 HTTP 37개와 Chrome 합성 저장/412/409/만료/복구/480px를 확인했다. 독립 백엔드 반례 3개와 프런트 경합 2개도 통과했고 필수 잔여 수정은 0건이다. OpenAPI/생성 타입 2개 파일은 재생성 전후 바이트가 같고 공개 후보 322개 파일에서 문제 0건이었다. 상세 근거와 브라우저 대화상자 도구의 검사 한계는 QA에 구분했다.
- 구현자와 독립 검토자의 역할을 나누고 반례를 수정 후 재검증했다. [[wiki:Implementer-Reviewer-Applier-Pipeline]] 사용자 품질 판정은 수행하거나 추정하지 않았으며 새 위키 지식 본문은 만들지 않았다.
