# Q3b 도식 작성/수정 UI 인계

작성: 2026-09-20. 사용자의 SlideCaptain 개발 재개 요청으로 [단위 계획](../plans/2026-09-20-q3b-diagram-authoring.md)을 구현하고 로컬 검증했다. 이전 단위는 프로젝트 의미 입력 저장/읽기 전용 미리보기다.

## 완료한 동작

- 빈 프로젝트의 편집 탭에서 새 도식 장을 만들고, 기존 도식은 별도 작성 창에서 수정한다. 제목/분류/부제/각주, 항목의 역할/내용/사실 구분/조건, 관계의 주체/대상/종류/설명과 근거를 지정한다. 내부 ID는 충돌 없이 만들고 좌표는 입력받지 않는다.
- StoryPlan.evidence의 파일/행/등록 발췌문을 보여 주고 근거 ID를 선택한다. 사실 노드와 흐름/참조 관계는 필요한 근거를 요구하며 추정/미확인 노드는 조건을 요구한다. 근거 없는 명시적 제안은 작성할 수 있다.
- 입력 중에는 기존 Deck을 수정하지 않는다. 기존 POST /api/render-plan이 전체 후보의 구조/근거 ID/배치를 검사하고 공통 Preview를 제공한다. FastAPI의 목록형 입력 오류는 메시지만 표시하고 원래 입력/내부 오류 객체를 출력하지 않는다.
- 확인 후 입력을 바꾸면 결과를 무효화한다. 늦은 응답/닫힌 창/바뀐 원본 덱/저장 충돌의 결과는 적용하지 않는다. 연결된 항목을 지우려면 관계를 먼저 삭제하도록 해 의미를 몰래 지우지 않는다.
- 적용은 한 번의 편집 이력으로 들어가고 기존 자동 저장/ETag/스냅샷/undo/redo를 사용한다. 작성 중 dirty/flush 관문으로 탭 전환/복원/내보내기/새로고침을 보호한다. 취소는 작성 중 입력만 버린다.
- 미리보기의 인라인 편집/템플릿 변환/도식 AI 생성과 전체 구조안 AI 재생성 제한을 유지한다. API/Deck schema_version/StoryPlan 버전과 저장된 계획 fingerprint를 바꾸지 않았다.

실제 화면에서 새 프로젝트의 편집 탭 진입 차단을 발견해 실패 테스트 후 수정했다. 미리보기 원래 크기가 축소 후에도 공간을 차지해 결과가 가려지는 문제는 작성 창에 페이지 비율 컨테이너를 적용했다. 좁은 화면에서는 결과로 포커스를 이동한다. 전체 제품의 모바일 사용성이나 보고서 품질을 승인한 것은 아니다.

## 미완료와 다음 단위

이번 작성 UI의 독립 리뷰가 남아 있다. 세션에서 에이전트 위임을 명시적으로 요청받지 않아 별도 에이전트를 실행하지 않았다. 로컬 테스트와 브라우저 검증은 독립 리뷰를 대신하지 않는다.

도식 추가/장 제목 변경 뒤 기존 StoryPlan fingerprint를 임의 갱신하지 않으므로 생성 전 409 경계를 유지한다. 도식이 있는 덱의 전체 구조안 AI 재생성은 계속 제한한다. 새 장을 기존 보고 계획과 연결하는 최소 갱신 계약이 다음 설계 대상이다. 기존 도식/근거/다른 장을 보존하는 경계를 먼저 검토하고 도식 AI 생성, 검수 승인 저장/만료, 분기 배치와 한 번에 묶지 않는다. 도식 장의 영구 삭제 UI는 없으며 이번 편집 이력/스냅샷 복구를 사용한다.

원문 현재성/관계 의미/PowerPoint 표시/독자 품질은 미검수다. 실제 AI 호출, Windows 실기기와 이번 변경의 원격 CI는 미수행이다. 시작 시 원격 codex/phase-5b는 a8c6d7a였고 그 커밋 CI 성공은 확인했으나 누적 미커밋 구현의 CI 증거는 아니다. 새 품질 승인 상태는 저장하지 않는다.
