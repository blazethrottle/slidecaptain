# 첫 사용 피드백 개정: 첫 구현 단위 인계

작성: 2026-10-02. 작업 브랜치 `feat/windows-feedback-revision`, 기준 커밋 `4f6a03a`. 사용자 요청은 Windows 사용 피드백을 바탕으로 개선 프로젝트를 시작하는 것이다. 전체 요구와 수용 기준은 [개정 계획](../plans/2026-10-02-windows-feedback-revision.md), 진행 상태는 [로드맵](../plans/2026-08-27-mvp-roadmap.md)에 있다. 이번 기록은 전체 개정판 완료가 아니다.

## 구현

- R09: 기존 저장 ID 세 개를 유지하고 주간, 일반 업무, 월간, 데이터 설명, 프로젝트, 결과 유형을 추가했다. 기존 연구분석은 리서치 결과 보고로 표시한다. 총 9개 선택지의 저장/재읽기, ReportBrief, OpenAPI와 TypeScript를 맞췄다. 유형별 구성과 해석 지침을 구조안, 한 장 생성, 편집 보존 재작성에 전달한다. 누락 정보 창작을 금지하고 현재 장 및 보존 계약을 우선한다.
- R15: 구조안의 `instructions` 입력을 ‘문서의 주안점 및 원하는 결과 입력’으로 표시한다. 별도 보고 질문 기능을 유지하고 호출 전달과 실패 후 입력 보존을 검증했다.
- R11 일부: 첨부 응답은 JSON/StoryDraft를 통과하지만 핵심 답변 일부가 실행 역할 장에만 연결되어 계획 검증을 통과하지 못한다. 실제 원자료가 없어 당시 최초 실패 원인은 확정하지 않았다. 엄격한 검증을 유지하면서 `answer_not_in_summary` 코드를 추가했다. 코드명은 특정 summary 템플릿 요구가 아니라 answer 역할 연결 실패를 뜻한다. 최종 구조안 실패만 비민감 코드로 화면에 전달하며 첫 실패 코드가 재시도 결과에 남지 않는다. 응답/예외 원문을 새 안내에 넣지 않고 입력 보존과 다시 생성 경로를 제공한다. 지침에도 모든 핵심 답변 ID의 장 연결 조건을 명시했다.

## 검증

- 백엔드 전체: 2,003 통과, 플랫폼 관련 3 건너뜀.
- 프런트 전체: 52파일, 543 통과. TypeScript와 Vite 빌드 통과.
- OpenAPI 현재 앱 일치, 타입 재생성, 공개 저장소 감사, diff 공백 검사 통과.
- Chromium: 9개 보고 유형, 주간 업무 저장 후 새로고침/재열기, 주안점 명칭 표시 확인. 합성 프로젝트와 화면 증거는 저장소 밖 `/workspace/.slidecaptain-tools/`에 보관했다.
- 계획 독립 리뷰의 입력란 구분 및 생성 단계별 보존 계약 조건을 반영했다. R09/R15와 R11 독립 코드 리뷰에서 필수 수정 사항 없음.
- 실제 AI 호출 0회. 실제 Windows/macOS 독립 앱, PowerPoint 표시, 실제 보고서 품질과 생성 성공률 개선은 미검증이다. 이 첫 구현 검증 시점에는 새 릴리스 게시나 원격 푸시를 하지 않았다. 이후 원격 반영 여부는 Git 이력을 따른다.
