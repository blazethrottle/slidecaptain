# Q3b 독립 리뷰와 작성 중 입력 보존 인계

작성: 2026-09-27. 사용자는 이전 인계에 남은 독립 리뷰를 위해 리뷰 에이전트 1명 사용을 승인했다. 같은 리뷰어가 최초 검토와 수정 후 재검토를 수행했다. 추가 에이전트와 실제 제품 AI 호출은 사용하지 않았다.

## 결과와 변경

검토 범위는 도식 작성 UI, 기존 StoryPlan 연결, 저장 충돌 보호와 [9월 25일 ETag 수정](2026-09-25-q3b-review-fixes-handoff.md)이다. 최초 필수 수정 1건을 해소했고 재검토의 필수 수정 잔여는 0건이다. 누적 미커밋 코드 전체나 보고서 품질에 대한 승인은 아니다.

발견한 순서는 기존 편집 변경 → 목록/탭 이동으로 저장 시작 → 응답 대기 중 새 도식 작성 → 저장 성공이다. 종전 이탈 함수는 시작 시점의 초안 상태만 확인하여 새 도식 입력을 버리고 이동했다. 내보내기 경로에서도 작성 중인 초안을 제외한 채 스냅샷/내보내기를 진행할 수 있었다.

- `frontend/src/screens/EditorScreen.tsx`: 현재 도식 초안을 ref로 보관하며 이탈 검사 시작 전과 저장 완료 뒤 모두 확인한다. 초안이 남아 있거나 저장에 실패하면 이동/복구/내보내기를 중단한다. 작성 창의 입력 확인에는 기존 저장 플러시를 계속 사용한다.
- `frontend/src/screens/ProjectView.diagramDraft.test.tsx`: 실제 ProjectView와 EditorScreen으로 6개 경로를 검사한다. 초안 내용, 편집 화면과 창 닫기 경고를 보존하고, 복구/이력/내보내기 API를 호출하지 않는지 확인한다. 명시적으로 초안을 버린 뒤에는 정상 이동한다. 기존 초안이 먼저 열린 경우도 대조군으로 남긴다.
- 로드맵 이월표, 품질 개발 계획과 최신 인계 포인터에 발견과 해소를 반영했다. 모델/백엔드/OpenAPI/저장 스키마는 변경하지 않았다.

## 실제 브라우저 확인

AI 제공자/계정을 구성하지 않은 임시 서버에 합성 자료만 넣었다. 테스트 서버의 응답을 의도적으로 보류하고 Chrome UI로 아래 순서를 수행했다.

1. 도식 연결 확인 응답을 보류한 채 작성 창을 닫고 기존 장을 저장했다. 이후 과거 확인 응답을 전달하고 다시 저장했다. 두 PUT 모두 200이며 두 번째 If-Match가 첫 저장의 새 ETag와 같았다. 화면의 저장 완료 상태를 확인했다.
2. 화면 이동을 누른 뒤 저장 응답을 보류하고 새 도식 제목을 입력했다. 저장 성공 응답을 전달해도 이동이 중단되고 제목 입력과 편집 탭이 유지됐다. 초안을 명시적으로 닫은 뒤 목록으로 이동했다.

`logs/browser-final.json`은 관측값과 실제 PUT 3건/실패 0건, 최종 덱 해시를 담는다. 작성 중 초안은 적용하지 않았으므로 저장본에 들어가지 않았다. AI 사용량 파일은 0개다. 임시 서버와 테스트 탭은 종료했다. 이 확인은 화면 동작과 저장 경계의 검사이며 PowerPoint 표시와 독자 품질 평가가 아니다.

## 보존과 다음 단계

원본 `~/Projects/slidecaptain`의 `codex/phase-5b`, HEAD `a8c6d7a` 및 빈 스테이징을 유지한다. 9월 27일 재개 시 이전 반영본 270개 파일이 원본/격리 작업본 양쪽에서 그대로임을 확인했다. 이번 변경만 해시를 대조해 반영하며 커밋/푸시/머지는 하지 않는다. 보존 근거는 `logs/applied-review-preservation.json`, 테스트와 빌드는 `logs/frontend-final.log`, `build-final.log`다. 시작 기준본과 이전 단계의 로그도 보존한다.

이번 독립 리뷰 단위는 여기서 종료한다. 다음 후보는 유일한 답변 장의 역할 제약을 미리 설명하는 개선, 낡은 계획과 도식이 함께 있는 프로젝트의 복구/재계획 UX다. 전체 StoryPlan 재계획, 도식 AI 생성, 검수 승인 저장/만료, 자유 토폴로지, 실제 AI 계정/생성, Windows 실기기와 목표 PowerPoint/독자 품질은 별도 미구현 또는 미검증이다. 자동으로 다음 단위를 구현하지 않는다.

리뷰의 발견/판정은 대화와 임시 파일에만 두지 않고 이 인계와 로드맵에 반영했다. [[wiki:Agent-Output-Persistence]] 이전 프로젝트 지식과 이번 영속화 원칙은 기존 절차와 같은 결론으로 적용했다. 이 작업에서 부모 세션의 직접 읽기는 `pages_read=2`, `frames_applied=2`, `wiki_irrelevant_justified=0`, `reflux=1`이다. 위키 본문/메모리는 변경하지 않았고 환류는 Ingest 제안이다.

위키 후보: 비동기 이탈 검사에서는 저장 응답 이후의 현재 초안도 확인해야 한다. 저장 시작 전후에 작성 창을 여는 순서를 바꾸고 정상 대조군을 두어 초안 보존과 이탈 허용을 각각 검증한다.
