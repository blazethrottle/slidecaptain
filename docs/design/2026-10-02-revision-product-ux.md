## 1. 목표와 결정

사용자가 자료와 보고 목적을 정하면, 목적에 맞는 구성을 만들고 편집 가능한 PPTX까지 이어지는 독립 앱을 제공한다. 핵심은 보고 목적에 맞는 내용, 알기 쉬운 진행 상태, 실패해도 잃지 않는 작업이다.

- Windows와 macOS를 같은 기능 수준으로 개발한다. 브라우저 탭을 열어 앱을 사용하는 방식에서 전용 앱 창으로 전환한다. 제공자 로그인은 공식 시스템 브라우저에서 한다.
- 보고 목적, 자료, 구성, 편집, 검토와 내보내기의 다섯 작업 화면을 둔다. 단계를 다시 오갈 수 있으며 끝까지 순서대로 통과해야만 편집할 수 있는 잠긴 마법사로 만들지 않는다.
- 생성 버튼은 각 화면에 하나의 주된 행동으로 표시한다. 상세 AI 토큰/비용 문구, JSON, 내부 오류 코드는 기본 화면에서 제거한다.
- 계정 연결 시 AI 자료 전송 동의를 한 번 받는다. 같은 계정의 같은 전송 범위에서는 매번 팝업을 띄우지 않는다. 이후 상단에 현재 제공자와 계정을 지속 표시한다.
- 기본 디자인은 밝은 업무용 작업 화면이다. 짙은 남색을 주 행동에, 청록색을 저장/완료에 사용한다. 상태를 색만으로 전달하지 않는다.

## 2. 현재 제품에서 해결할 문제

현재는 자료 탭에 보고 정보와 파일 조작이 함께 있고, 프로젝트 내 버튼들이 모두 비슷한 형태다. 사용자는 현재 단계, 저장 여부와 미완료 항목을 한눈에 구분하기 어렵다. AI 연결은 Claude 별칭을 고정 표시하며 Effort와 여러 프로필을 다루지 않는다. 최초 실패 안내는 JSON 원문 확인을 요구했고 긴 사용량 문구가 작업 화면을 차지했다. 자료는 md/txt/csv/xlsx이며 생성 자료 합계는 10만 자 제한이다. 현재 배포본은 Python과 최초 인터넷 설치가 필요하다.

첫 구현 단위에서 보고 유형 선택/지침, 주안점 명칭, 일부 생성 실패 사유 전달을 추가했지만 아래 전체 경험은 아직 구현 전이다.

## 3. 정보 구조와 기본 배치

```text
┌ 프로젝트 목록  /  10월 주간 업무 보고         저장됨 14:32    Claude · 회사 계정 ┐
│ 작업 단계          │ 화면 제목 / 짧은 목적 설명                  │ 다음 할 일   │
│ 1 보고 목적  ✓    │                                            │             │
│ 2 자료       ✓    │ 현재 작업 영역                             │ 필요한 경우 │
│ 3 구성   작성 중  │ 입력 / 자료 미리보기 / 장 구성 / 편집 캔버스 │ 열리는 도움 │
│ 4 편집    시작 전 │                                            │             │
│ 5 검토·내보내기   │                                            │             │
│                  ├────────────────────────────────────────────┴─────────────┤
│ AI 연결 및 설정  │ 취소 / 이전 작업                         주요 행동 버튼   │
└──────────────────┴──────────────────────────────────────────────────────────┘
```

좌측 내비게이션은 216px, 본문은 유동 폭으로 한다. 기본 창은 1280×900 수준을 기준으로 설계하되 1024×720 및 200% 확대에서 핵심 행동이 가려지지 않게 한다. 좁은 창에서는 내비를 접고 보조 패널을 드로어로 전환한다. 입력 화면은 읽기 폭을 제한하고, 편집 화면은 캔버스에 남는 공간을 준다. 작은 버튼을 한 줄에 계속 늘리지 않는다.

상단의 저장 상태는 현재 프로젝트 기준이다. 계정/모델 변경은 AI 설정 드로어를 연다. 진행 중 작업은 화면을 바꿔도 상단 작업 표시에서 다시 찾을 수 있다. 기본 화면에 항상 도움 패널을 띄워 공간을 차지하지 않는다.

## 4. 상태와 시각 규칙

| 의미 | 표시 | 색/모양 | 전환 기준 |
|---|---|---|---|
| 현재 보고 있는 단계 | 선택 막대, 단계 이름 강조 | 남색 바탕/옅은 남색 영역 | 클릭으로 이동 |
| 시작 전/미지정 | 빈 원 + 시작 전 | 중립 회색 | 아직 유효한 입력/결과 없음 |
| 작성 중/미저장 | 연필 + 변경사항 있음 | 황갈색 | 로컬 변경이 저장본과 다름 |
| 저장 중 | 회전 표시 + 저장 중 | 중립색 | 저장 응답 대기 |
| 저장됨 | 체크 + 저장됨 | 청록색 | 서버가 현재 리비전 저장 확인 |
| 단계 준비됨 | 체크 + 준비됨 | 청록색 | 아래 단계별 입력/결과의 준비 조건 충족 |
| 확인 필요/자료 변경 | 느낌표 + 확인 필요 | 황갈색 | 부분 추출, 낡은 구성, 미확인 항목 |
| 실행 실패 | 오류 아이콘 + 조치 문구 | 붉은색 | 수행 실패, 성공한 결과는 유지 |
| 생성 중 | 단계 이름 + 진행 표시 | 남색 | 실제 작업 상태 수신 |

화면 선택과 단계 완료는 별개다. 저장됨은 보고 품질 통과를 뜻하지 않는다. 구성 준비됨, 자료 최신 여부, 편집 저장, 검수 상태도 각각 표시한다. 자료/보고 유형을 바꾸면 영향을 받는 구성과 검토 상태만 확인 필요로 바뀌고 기존 내용은 남는다.

단계별 준비 조건은 다음과 같다. 보고 목적은 제목과 유형 등 최소 입력이 저장된 상태, 자료는 이번 생성에 포함한 자료의 추출이 끝나고 확인 필요 항목을 사용자가 처리한 상태, 구성은 현재 입력에 맞는 유효한 후보를 사용자가 적용한 상태, 편집은 선택한 장의 작성이 끝나고 변경이 저장된 상태다. 검토/내보내기는 단일 완료 체크로 합치지 않고 자동 검사, 사람 검토, 파일 저장 상태를 각각 표시한다. 예를 들어 ‘저장됨 / 구성 업데이트 필요 / 6장 중 1장 실패 / 초안 내보내기 가능’이 동시에 성립할 수 있다.

디자인 토큰 초안: 배경 `#F4F6F8`, 패널 `#FFFFFF`, 본문 `#172B4D`, 보조 `#526174`, 경계 `#D9E0E7`, 주 행동 `#244C83`, 완료 `#176B55`, 주의 `#8A5700`, 오류 `#B42318`. 본문 15~16px, 제목 24~28px, 입력 높이 40px 이상, 주요 버튼 44px, 여백 8/16/24/32px, 모서리 8~12px를 기준으로 한다. 실제 조합의 대비는 구현 전 AA 기준으로 검사한다. 키보드 초점은 2px 이상 선으로 표시하고 움직임 감소 설정을 따른다.

## 5. 화면별 설계

### A. 프로젝트 홈

최근 프로젝트를 제목, 보고 유형, 마지막 저장 시각, 다음 할 일로 표시한다. ‘새 보고서’, ‘기존 프로젝트 열기’를 주 행동으로 둔다. AI가 연결되지 않아도 프로젝트 열기, 자료 준비, 수동 편집은 가능하다. AI 연결은 생성이 필요한 시점에 유도한다.

### B. 보고 목적 (R09)

보고 유형은 주간 업무, 일반 업무, 월간, 데이터 설명, 리서치 결과, 프로젝트, 결과 보고, 승인요청, 전략기획, IR Pitch Deck의 10종을 드롭다운으로 제공한다. 왼쪽에 드롭다운과 선택한 유형의 설명·추천 구성을, 오른쪽에 해당 유형의 슬라이드 예시 화면을 배치한다. 선택 즉시 유형의 대표 페이지 전체를 바꾸며 문구만 교체한 같은 레이아웃을 재사용하지 않는다. ‘크게 보기’로 페이지를 확대해 확인할 수 있다. 좁은 창에서는 드롭다운 아래에 예시 화면을 배치한다. 예시는 합성 자료이며 실제 생성 결과처럼 표시하지 않는다. 기본 제목/보고자/독자와 ‘이 보고서에서 전달할 핵심 내용’을 먼저 받고 세부 항목은 유형에 따라 펼친다.

| 유형 | 목적과 구성 패턴 | 추가로 받는 정보 | 검토할 누락 |
|---|---|---|---|
| 주간 업무 | 이번 주 요약 → 실적/계획 차이 → 이슈/지원 요청 → 다음 주 | 보고 기간, 계획 또는 이전 보고서(선택) | 기간, 지연 원인과 다음 행동 |
| 일반 업무 | 업무 현황 → 수행 내용 → 주요 이슈 → 후속 행동 | 대상 업무, 공유 목적 | 완료/진행/예정 혼동 |
| 월간 | 월간 요약 → 목표 대비 실적 → 전월 변화 → 다음 달 | 대상 월, 목표/비교 기준(선택) | 기간과 비교 기준 불일치 |
| 데이터 설명 | 질문 → 지표/범위 → 관측 결과 → 해석/한계 | 주요 지표, 기간과 대상 | 단위/분모/모집단/해석 범위 |
| 리서치 결과 | 조사 질문 → 방법/범위 → 발견 → 시사점/한계 | 조사 질문, 범위 | 출처 충돌과 근거 밖 결론 |
| 프로젝트 | 목표/범위 → 진척/마일스톤 → 위험/결정 → 다음 단계 | 프로젝트, 기준일, 주요 마일스톤 | 일정/실적 혼동과 결정 필요 사항 |
| 결과 보고 | 목표/평가 기준 → 수행/산출 → 달성 여부 → 교훈/후속 | 활동 범위, 목표와 평가 기준 | 목표 없는 달성 판정 |
| 승인요청 | 요청 → 배경 → 대안/추천 → 실행/위험 | 결정할 질문, 대안(선택) | 추천 근거와 승인 범위 |
| 전략기획 | 결론 → 현황/변화 → 방향/근거 → 실행 순서 | 목표, 검토 기간 | 가설과 확정 사실 혼동 |
| IR Pitch Deck | 문제 → 해결책/제품 → 시장 → 사업 모델 → 성과 → 성장 전략 → 팀 → 투자 요청/자금 사용/마일스톤 | 투자 단계, 독자, 투자 요청과 사용 계획(선택) | 시장 규모·실적·전망의 출처, 투자 조건과 가정 |

대표 페이지의 표현 차이를 다음과 같이 설계한다. 이는 유형의 특징을 전달하는 예시이며 해당 유형의 모든 장을 같은 레이아웃으로 생성한다는 뜻이 아니다. 모든 예시 수치와 인용은 합성 자료다.

| 유형 | 대표 페이지 | 시각적 특징 |
|---|---|---|
| 주간 업무 | 이번 주 업무 현황 | 완료/진행/지원 필요 상태 보드와 다음 주 우선순위 띠 |
| 일반 업무 | 업무 흐름과 병목 | 접수→검토→처리→완료 프로세스, 병목과 후속 조치 |
| 월간 | 목표 대비 실적 | KPI 타일, 월별 추이 막대, 목표 대비 달성률 |
| 데이터 설명 | 지표의 관계와 해석 | 산점도, 관측값 강조, 관계 해석과 한계 |
| 리서치 결과 | 발견과 근거 | 핵심 발견을 강조한 영역, 인터뷰 인용, 시사점 연결 |
| 프로젝트 | 일정과 마일스톤 | 간트 일정표, 현재 시점선, 위험·결정 요청 |
| 결과 보고 | 목표 대비 결과 | 목표/실제 결과 대조, 달성률, 교훈과 후속 조치 |
| 승인요청 | 대안 비교와 승인 범위 | 기준별 비교표, 추천 열 강조, 승인 요청 띠 |
| 전략기획 | 전략과 실행 로드맵 | 전략 방향 띠, 기반→반복→확장의 단계별 실행 경로 |
| IR Pitch Deck | 제품 가치와 성장 기회 | 짙은 배경의 제품 히어로, 성장 개념 곡선과 투자 메시지 |

없는 정보는 미정으로 저장하며 AI가 기간/성과/담당을 만들지 않는다. 모든 항목을 필수로 바꾸지 않는다. 생성을 막을 정도의 누락만 버튼 근처에서 설명하고, 비필수 누락은 구성 후보의 확인 필요 항목으로 남긴다. 보고 유형 변경 시 기존 구성/본문을 보존하고 재검토가 필요한 범위를 알려 준다.

### C. 자료 (R08/R10/R13)

‘파일 추가’, ‘폴더에서 선택’, ‘텍스트 붙여넣기’의 세 입력을 같은 위치에 둔다. 드래그 앤드 드롭도 지원한다. 폴더를 선택하면 대상 파일, 하위 폴더 포함 여부, 형식/크기/중복을 미리 보고 가져올 항목을 고른다. 최근 폴더는 기억하되 앱 시작 시 자동으로 다시 읽지 않는다.

자료 행에는 원래 파일명, 형식, 추출 상태, 이번 생성에 포함 여부, 짧은 문제 설명을 보여 준다. PDF는 페이지, PPTX는 슬라이드, DOCX는 절/문단/표, HWP는 절/문단 등 원문 위치를 유지한다. 한 파일이 실패해도 성공한 파일은 남는다. 자세한 미리보기에서 추출 텍스트와 원문 위치를 확인할 수 있다.

텍스트 붙여넣기는 제목(자동 제안 가능)과 큰 편집 영역으로 바로 시작한다. 사용자는 빈 파일을 먼저 만들 필요가 없다. 입력 자동 저장 상태와 글자 수를 표시한다. 긴 입력의 보관 용량과 AI에게 보내는 양을 구분한다. 긴 자료를 조용히 잘라 보내지 않고 자료별 포함/제외 또는 범위 선택을 제공한다. 1차 목표는 20만 자 입력의 저장/복구이며 기기 성능 측정 후 상향한다. 현재 생성 10만 자 제한을 단순 삭제하지 않고 문맥 선택/분할 분석을 검증한 뒤 모델별 한도로 전환한다.

원본은 기본적으로 프로젝트 자료 저장소에 복사하여 변경하지 않는다. 외부 파일이 변경되면 ‘변경 감지 → 차이 확인 → 새 리비전 가져오기’를 사용하고 기존 추출/구성은 덮어쓰지 않는다. 첫 버전은 수동 새로 읽기로 변경 확인하며 자동 감시는 후속이다. 폴더 위치가 사라져도 가져온 복사본으로 작업할 수 있다.

### D. 구성 (R11/R15)

‘문서의 주안점 및 원하는 결과 입력’과 목표 분량을 상단에 둔다. 보고 목적에서 입력한 핵심 내용은 연결해 보여 주고 동일 내용을 다시 입력하도록 강요하지 않는다. ‘핵심 답변과 근거를 계획’하는 기존 보고 질문 기능은 유지하되 질문형/상태 공유형 보고 모두 사용할 수 있게 설명한다.

생성 전에는 선택 자료 수와 현재 모델/Effort를 한 줄로 확인하고 ‘구성 만들기’를 누른다. 장 구성 후보는 표보다 카드 목록 중심으로 제목, 이 장의 역할, 핵심 내용, 근거 유무를 보여 준다. 상세 근거와 기술 검증 결과는 펼쳐 본다. 순서 변경/제목 수정/장 삭제가 가능하고 변경 영향은 적용 전에 알려 준다. ‘이 구성으로 슬라이드 작성’을 주요 행동으로 둔다.

실행 중 표시 예: ‘자료 확인 중 → 구성 생성 중 → 연결 확인 중’. 완료된 단계와 경과 시간을 표시하며 예상 시간이 측정되지 않았다면 가짜 백분율/남은 시간을 쓰지 않는다. 취소 버튼과 다른 화면으로 이동할 방법을 제공한다.

실패 안내는 ‘무슨 일이 생겼는가 / 무엇이 보존됐는가 / 지금 할 수 있는 일’의 세 요소를 갖는다. 입력 누락은 해당 입력으로 이동, 계정 만료는 연결 설정, 출력 연결 오류는 같은 입력 재시도를 제안한다. 실패한 응답 원문은 기본 화면에 쏟지 않고 진단 상세에서 사용자가 펼친다. 형식 재시도는 현재처럼 1회 상한을 유지하며 단순 JSON 재출력과 의미 변경을 구분한다. 주장을 자동 이동하거나 실패한 계획을 성공으로 저장하지 않는다.

### E. 편집

왼쪽 장 목록, 가운데 캔버스, 오른쪽 선택 항목 속성을 사용한다. ‘직접 수정’을 누르면 캔버스의 요소를 선택할 수 있고 버튼은 ‘수정 완료’로 바뀐다. 완료는 편집 모드 종료이며 프로젝트 저장 완료 표시와 구분한다.

- 텍스트를 더블클릭하거나 선택 요소의 텍스트 입력란으로 내용을 변경한다. 글자 크기와 색을 속성 패널에서 즉시 바꾼다.
- 도형은 본체 또는 이동 손잡이를 드래그한다. 텍스트도 이동 손잡이로 옮긴다. 가로/세로 위치 입력과 방향키 이동을 함께 제공한다. Shift+방향키는 큰 단위 이동이다.
- 선택 요소 삭제 버튼 또는 Delete로 불필요한 텍스트/도형을 제거한다. 되돌리기/다시 실행은 텍스트 수정, 이동, 서식 변경, 삭제를 복구한다. 인라인 입력 중에는 브라우저의 텍스트 되돌리기를 유지한다.
- 키보드 포커스가 바뀌면 선택 대상도 함께 바뀐다. 반복 더블클릭은 진행 중 편집의 이전 내용을 잃게 하지 않는다. 위치는 슬라이드 경계 안에서 이동한다.
- 직접 수정 모드 종료나 단계 이동으로 입력을 버리지 않는다. 시안은 한 장의 메모리 편집만 지원하며 새로고침 시 초기화한다. 실제 저장/장별 편집/PPTX 반영은 제품 구현에서 완료해야 한다.

제품에서는 수정한 요소를 안정적인 ID와 사용자 변경 정보로 보존한다. 다시 생성할 때 직접 수정한 문구와 위치·색·크기를 조용히 덮어쓰지 않고 후보와 현재본을 비교해 적용하게 한다. 필수 내용이나 근거의 표시를 삭제하면 해당 내용/표시 검토를 최신 통과로 유지하지 않는다. 삭제 요소를 자동으로 다시 채우거나 AI가 수치를 새로 만들지 않는다. 자세한 저장 계약은 [직접 수정 데이터 계약](../architecture/2026-10-02-desktop-revision.md#10-직접-수정-데이터-계약-r16)을 따른다.

근거와 경고는 현재 선택한 장에 연결하여 펼친다. 특정 장 생성 실패는 성공한 다른 장을 되돌리지 않고 해당 장에서 다시 시도한다.

### F. 검토와 내보내기

‘확인할 항목’, ‘내보낸 파일’, ‘검토 기록’을 한 화면에서 연결한다. 수치/출처/분량의 자동 검사와 실제 PowerPoint 표시/사람 판단을 구분한다. 초안 내보내기는 항상 초안임을 알리고, 기존 제출본 자격 검증은 유지한다. 폴더 선택 대화상자로 저장 위치를 정하고 ‘파일 열기’, ‘저장 폴더 열기’를 제공한다. 저장 취소/권한 부족/열려 있는 파일 때문에 실패하면 기존 파일을 보존한다.

### G. AI 연결과 추천 (R03~R07/R14)

전역 드로어의 순서는 계정 → 현재 작업 → 모델/Effort → 적용이다. 회사/개인 같은 계정 별칭을 등록하고 제공자가 확인해 준 신원을 함께 표시한다. 확인할 수 없는 신원을 별칭만으로 인증 완료처럼 보이지 않게 한다. 계정 추가와 전환, 로그아웃을 별도 행동으로 둔다. 작업 중인 호출은 시작 시 계정/모델/Effort에 고정하고 변경은 다음 작업부터 적용한다.

로그인 버튼은 ‘Claude 계정 연결’, ‘ChatGPT 계정 연결’이다. 아래에 ‘Google 계정은 공식 로그인 화면에서 선택할 수 있습니다’라고 안내하되 제공자가 해당 경로를 제공하는 경우에만 표시한다. 앱이 직접 Google 로그인 폼을 만들거나 제공자 공식 페이지를 모방하지 않는다.

모델에는 버전이 확인된 표시명과 모델 ID를 함께 제공한다. 조회된 후보, 계정 사용 확인, 현재 실제 호출 모델은 다른 정보다. 별칭만 확인되면 ‘정확한 버전 확인 필요’로 표시하며 Opus라는 이름에서 5.5를 추측하지 않는다. 조회 실패 시 마지막 확인 목록과 확인 시각을 표시하고 사용할 수 있는지 검증되지 않은 후보를 자동 선택하지 않는다.

Effort는 제공자/모델이 지원하는 값만 노출한다. 추천에는 목적에 맞는 이유 한 문장과 적용 버튼을 둔다. 사용자 요청에 따라 모델/Effort의 추천 근거·한계 상세 보기 UI는 제거한다. 사용자가 지정한 모델/Effort를 자료 또는 보고 유형 변경 때 자동으로 덮어쓰지 않는다. 추천을 다시 제안하고 사용자가 적용하게 한다. 앱 최초 선택이 비어 있을 때만 사용 가능한 추천 후보를 미리 선택할 수 있다.

## 6. 원하는 결과와 모델 추천 설계

‘원하는 결과’는 다음 네 가지로 제공한다. 이 항목은 품질 등급이 아니라 보고서가 달성할 목적이다.

| 선택지 | 목적 | 입력과 추천 동작 |
|---|---|---|
| 사실 및 데이터 중심 보고서 | 확인된 사실, 수치와 해석 전달 | 기본 선택. 작업 종류에 맞는 정리/분석 후보 제안 |
| 사업 기획안 | 사업의 논리, 실행 계획과 검증할 가설 정리 | 구성과 실행 논리를 함께 다루는 후보 제안 |
| 투자자 및 의사결정자 설득 | 가치, 근거, 대안과 요청을 연결 | 메시지와 의사결정 논리를 다루는 후보 제안 |
| 기타 (직접 입력) | 사용자가 설명하는 목적 | 선택 시 텍스트 입력란 노출. 입력을 보존하며 모델/Effort는 직접 선택 |

기타는 비어 있으면 적용 버튼 근처에서 입력을 요청한다. 다른 선택지로 잠시 전환해도 작성한 내용을 보존한다. 목적 또는 작업 변경이 직접 선택한 모델/Effort를 덮어쓰지 않으며 추천은 적용 버튼을 눌렀을 때만 선택값에 반영한다. 보고 유형과 원하는 결과는 서로 다른 축이다. IR Pitch Deck을 고른 뒤에도 사실 전달 등 다른 목적을 선택할 수 있고 설득형을 강제로 지정하지 않는다.

내부 추천 카탈로그의 출처는 사용자가 지정한 [modeltest-claudecode 가이드](https://github.com/blazethrottle/modeltest-claudecode/blob/b68b2bd7c917a62cc1d243ac338060ee2d41cf0d/docs/06-model-guide.md)와 같은 커밋의 `docs/03-model-effort-grid.md`다. 기존 연구의 품질 축을 새 목적 선택지의 실측 결과로 간주하지 않는다. 다음은 설계 시안의 초기 정책이며 목적별 우열이나 SlideCaptain에서 검증한 성능 순위를 뜻하지 않는다.

| 현재 작업 | 사실 및 데이터 중심 | 사업 기획안 / 설득 | 적용 조건 |
|---|---|---|---|
| 정해진 형식의 슬라이드 | Sonnet 5.5 / medium | Opus 5.5 / medium | 형식이 이미 정해진 작업 |
| 메시지 구성부터 맡기기 | Opus 5.5 / low | Opus 5.5 / high | 질문과 자료 범위 확인 |
| 복수 자료 분석 | Opus 5.5 / medium | Opus 5.5 / high | 제공 자료의 분석·종합 |
| 장문 자료 요약 | Sonnet 5.5 / medium | Opus 5.5 / high | 별도 요약 작업과 원문 위치 유지 |

측정 날짜·작업 종류·표본·한계·출처는 내부 카탈로그에 보존하고 사용자 화면의 상세 보기로 노출하지 않는다. 실측 근거와 실제 가용 모델 버전이 맞지 않으면 추천을 보류한다. 미측정 새 버전에 기존 추천을 자동 승계하지 않는다. 제품의 모델 ID는 설치된 공식 도구의 정확한 모델 정보와 대조해 확정한다. ChatGPT는 모델/Effort 직접 선택을 제공하고 실측 기반 추천은 후속으로 둔다. 기본 화면에 긴 비용/토큰 문구를 두지 않는다.

## 7. 저장, 동의와 긴 작업

- 보고 목적과 텍스트는 짧은 지연 뒤 자동 저장하되 ‘저장됨’은 서버 확인 후 표시한다. 저장 중 이탈/종료는 완료를 기다리거나 실패 시 복구 가능한 로컬 임시본을 남긴다. 기존 ETag 충돌과 미저장 보호를 유지한다.
- 생성 중 화면 이동과 편집은 허용한다. 실행 시작 후 관련 목적/자료 포함 범위/본문이 바뀌면 도착한 후보는 ‘이전 입력 기준’으로 보관하고 자동 적용하지 않는다. 현재 리비전과 맞지 않으면 적용을 차단하고 ‘후보 보기 / 현재 입력으로 다시 생성’을 제공한다. 이전 입력을 복원하는 선택은 별도 스냅샷 비교를 거치며 현재 편집을 버리지 않는다.
- 다른 창/앱이 같은 프로젝트를 바꾼 경우 충돌을 표시하고 양쪽 내용을 보존한다. 임의 덮어쓰기나 자동 병합을 하지 않는다. 초기 독립 앱은 동일 프로젝트 편집창을 한 개로 제한한다.
- 최초 계정 연결 때 전송 대상, 자료/초안 범위, 자동 형식 재시도 범위를 설명한다. 동의는 제공자+확인된 계정/프로필+고지 버전+범위에 연결해 로컬에 저장한다. 같은 계정의 모델/Effort 변경만으로 다시 묻지 않는다. 새 계정/제공자나 전송 범위 확대 때만 해당 설정 화면에서 갱신한다.
- 동의 철회는 앞으로의 전송과 아직 시작하지 않은 재시도를 막고 진행 중 작업에 취소를 요청한다. 이미 보낸 자료를 회수했다고 안내하지 않는다.
- 창 닫기는 저장되지 않은 변경 또는 실제 실행 작업이 있을 때만 확인한다. macOS 창 닫기와 앱 종료, Windows 창 닫기를 구분하며 남은 작업을 사용자가 볼 수 없는 상태에서 계속 돌리지 않는다. 첫 버전은 마지막 작업창 닫기 시 ‘계속 작업 / 취소 후 닫기’다. 앱 강제 종료 뒤에는 완료 여부 불명 상태로 복구하고 자동 재호출하지 않는다.

> 2026-10-08 정정(D2b 계획 2.6절, 사용자 결정): 첫 항목의 "실패 시 복구 가능한 로컬 임시본"은 구현하지 않고 로드맵 방치 확정으로 올렸다. "완료를 기다린다" 갈래는 이탈 경고와 닫기 대화 상자가 맡는다. 같은 계획은 웹 모드 탭 닫기 뒤의 작업 계속과 생성 중 편집 허용을 D3로 넘겼다.

## 8. 디자인 검증과 산출물

[화면 설계 시안](2026-10-02-revision-wireframe.html)은 합성 데이터로 만든 상호작용 가능한 설계 검토 자료다. 실제 파일 접근, 저장, 인증 또는 AI 기능은 수행하지 않는다. 프로젝트 단계 이동, 목적 선택, AI 설정, 자료 입력 방식, 실패 상태 예시를 비교할 수 있게 한다.

사용자 흐름 검증은 기존 0.2.0과 같은 합성 과제로 수행한다. 목표는 ① 현재 단계/저장/오류 상태 구별 ② 자료 추가 전에 파일명을 만들 필요 없음 ③ 같은 계정에서 재시작 후 반복 동의 없음 ④ 실패 후 입력 재작성 없이 재개 ⑤ 선택한 보고 유형의 내용 차이 이해 ⑥ 계정/모델/Effort 적용 여부 확인이다. 클릭 수, 작업 시간, 잘못된 행동과 도움 요청을 기록한다. 구체적인 개선 비율은 측정 전 약속하지 않는다.

기본 설계 선택은 밝은 화면, 다섯 작업 단계, Windows/macOS 동시 지원, 계정별 한 번 동의, Claude 근거 추천이다. 별도 확인 없이는 계정 자격 증명이나 회사 원자료를 예시/시안/공개 저장소에 넣지 않는다.

## 9. 설계 검토 결과

2026-10-02 독립 제품 검토의 세 항목을 반영했다. 저장/단계 준비 조건을 분리했고, 생성 중 입력이 바뀐 후보의 보존/적용 차단 규칙을 확정했으며, 시안에 전역 작업 상태와 취소 요청/완료/완료 불명 상태를 추가했다. 보완 재검토에서 추가 중요 지적은 없었다. 독립 기술 검토도 구현 착수를 막는 설계 결함을 발견하지 않았으나 D1의 공식 기능과 설치/추출 검증은 미실행이다.

최초 시안은 Chromium에서 9개 목적/5개 화면, 추천 명시 적용과 직접 선택 보존, 텍스트 입력 흐름, 실패 상태, 다른 화면에서도 유지되는 작업 상태와 취소 요청/완료 불명 예시를 확인했다. 1440/1024/512px 폭에서 페이지 가로 넘침이 없고 스크립트 오류가 없었다. 512px는 1024px 화면의 확대 상황에 대응하는 좁은 폭 검사이며 OS 확대/보조기기 접근성 실증을 대체하지 않는다. 주요 본문/보조/주행동/완료/주의/오류 색 조합은 4.5:1 이상의 텍스트 대비를 확인했다. 실제 로그인, AI 호출, 파일 가져오기와 독립 앱 설치 시험은 수행하지 않은 설계 시안이다.

후속 수정 시안은 Chromium에서 IR 포함 10종의 드롭다운·유형별 예시 전환과 유형별 입력 보존을 검증했다. 원하는 결과 네 선택지, 기타 입력 표시/빈 값 확인/전환 후 보존/적용, 추천 상세 보기 제거와 수동 모델/Effort 선택 보존도 확인했다. 1440/1024/512px에서 다섯 화면 및 설정 대화상자 가로 넘침과 스크립트 오류는 없었다. 독립 수정 리뷰에서 추가 결함은 없었으며 제품 구현과 실기기 검증은 후속이다.

대표 페이지/직접 수정 후속 검증: Chromium에서 10종의 서로 다른 시각 구조와 확대 보기, SVG 텍스트의 페이지 경계, 인라인/패널 텍스트 편집, 글자 크기/색, 실제 포인터 도형 이동, 위치 경계, 삭제/되돌리기/다시 실행, 방향키 이동과 화면 전환 후 보존을 확인했다. 1440/1024/512px에서 10종과 다섯 화면/편집 모드의 가로 넘침 및 스크립트 오류는 없었다. 독립 리뷰의 포커스/수정 대상 불일치와 반복 더블클릭의 원문 이력 손실을 수정하고 회귀를 확인했다. 이는 시안 동작이며 실제 장 저장·AI 재작성·PPTX 출력·양 OS 사용성 검증 완료가 아니다.
