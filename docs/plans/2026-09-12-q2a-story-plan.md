# Q2a: 보고 질문에서 근거가 연결된 생성 계획까지

작성: 2026-09-12. [Q1a 인계](../handoffs/2026-09-12-q1a-validation-handoff.md)의 다음 첫 태스크만 수행한다. 기존 미커밋 Q1a 변경을 보존하며 커밋, 푸시, 배포와 실제 AI 호출은 이번 범위에 포함하지 않는다.

## 범위와 완료 조건

기존 구조안 생성 요청에 선택적 `brief`를 추가한다. 질문이 없으면 기존 생성 계약을 유지한다. 질문이 있으면 한 번의 구조화 호출로 주장, 근거 위치, 핵심 답변의 주장 ID, 장별 역할과 주장 연결, 미확인 질문을 생성한다. 기존 형식 재시도 1회와 동의/사용량 경로를 재사용한다.

`Structure.story_plan`은 선택적 메타데이터다. 원문 발췌와 자료 리비전은 서버가 실제 UTF-8 추출 텍스트에서 만든다. 사실 주장은 근거 ID가 필요하고, 추정과 미확인은 조건을 남긴다. 원문 위치, 참조 ID, 핵심 답변과 장의 연결을 코드로 검증한다. 계산, 비교 가능성의 의미 판단, 독립 내용 검수는 후속 Q2 범위다.

계획은 보고 정보, 구조안, 자료 집합과 계획 내용에 바인딩한다. 편집/저장/복원은 계획을 보존하며, 입력이 달라진 뒤 장 생성/축약을 요청하면 외부 호출 전에 재계획을 요구한다. 스키마 버전 1과 기존 템플릿/편집 계약은 유지한다.

화면에는 보고 질문 입력과 계획의 답변/근거/미확인 사항을 최소한으로 표시한다. 구조안 승인과 순차 장 생성, 저장, 다시 열기까지 계획이 전달되어야 한다.

## 구현 전 반증 검토

- 모델의 발췌를 원문으로 믿으면 정상 형식의 허위 근거가 통과한다. 발췌와 SHA-256은 코드가 만들고 범위를 벗어난 위치는 재시도 후 실패시킨다.
- 기존 문자열 정규화는 자료 파일명과 발췌를 바꿀 수 있다. 계획 응답은 원문 식별자를 보존하고 생성 문구만 정규화한다.
- 프런트가 승인 시 `chapters`만 새 객체에 담으면 선택적 메타가 사라진다. 승인과 수동 편집, 재생성, 저장 왕복을 검사한다.
- 장을 수동 편집한 뒤 옛 계획을 적용하면 주장 연결이 어긋난다. 계획은 보존하되 낡은 계획을 사용하는 생성은 거절한다. 자동 부분 재계획은 후속 범위다.
- 원문 위치가 존재해도 주장의 진실성이나 지표 비교 가능성이 입증되지는 않는다. 이 검증을 내용 검수 통과로 표시하지 않는다.

설치된 `superpowers`와 `requesting-code-review` 스킬 검색 결과는 각각 0건이다. 사용 가능한 `engineering:code-review` 기준으로 자체 검토하며, 독립 에이전트 리뷰를 수행했다고 기록하지 않는다.

## 검증과 종료

비기밀 합성 자료로 입력 → 계획 생성 → 승인 저장 → 재읽기 → 장 생성/축약 전달을 검증한다. 잘못된 근거/연결, 재시도 상한, 낡은 계획의 호출 차단, 레거시 호환을 테스트한다. OpenAPI와 TypeScript를 함께 갱신하고 백엔드/프런트 테스트와 화면 빌드를 수행한다. 결과와 미완료 사항을 진본 로드맵 및 새 인계문서에 기록한 뒤 멈춘다.

## 실행 결과

2026-09-12에 위 범위의 구현과 로컬 자동화 검증을 완료했다. 백엔드 987개 중 실패 0개, 프런트 257개 중 실패 0개(24개 파일), tsc와 Vite 빌드, OpenAPI와 생성 타입 일치 검사를 통과했다. 새 테스트는 백엔드 33개와 프런트 5개다.

실패부터 확인한 경로는 계획 모델/생성 연결, 프런트 메타데이터 유실과 질문 입력, 자체 검토의 Brief 지시 충돌/표지에만 연결한 주장이다. API 합성 픽스처의 생성 상태 코드(201), 허용 파일명, 스냅샷 정렬 방향도 실제 계약에 맞춰 고쳤다. 별도 독립 에이전트 리뷰는 수행하지 않았다.

코드 검토에서 확인한 Q2 후속 범위와 실제 AI/PowerPoint 미검증 상태는 로드맵 이월 항목에 반영했다. [종료 인계](../handoffs/2026-09-12-q2a-story-plan-handoff.md)를 다음 작업의 출발점으로 삼는다.
