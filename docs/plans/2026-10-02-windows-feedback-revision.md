# Windows 첫 사용 피드백 기반 개정 프로젝트

> 2026-10-02 사용자 시안 수정 요청 반영: IR Pitch Deck, 보고 유형 드롭다운과 옆 예시 화면, 원하는 결과 네 가지 및 기타 직접 입력, 추천 근거·한계 보기 제거. 이 시안 변경 자체는 제품 구현 완료를 뜻하지 않는다. 이후 사용자 계속 진행 요청으로 D1 독립 앱 기반을 구현했으며 [D1 인계](../handoffs/2026-10-02-desktop-d1.md)의 범위/미확인 관문을 따른다.

작성: 2026-10-02. 사용자가 Windows에서 직접 실행한 뒤 제공한 개선 목록과 개선 프로젝트 착수 요청을 반영한다. 요구사항 등록은 구현 완료를 뜻하지 않는다. 첨부 원문과 실패 응답에는 업무 자료가 포함되어 있어 공개 저장소에 복사하지 않는다. 회귀 검증에는 합성 자료만 사용한다.

> 2026-10-02 추가 시안 수정: 동일한 3열 텍스트 예시는 보고 형식의 특징을 전달하지 못한다는 사용자 피드백으로 10종의 대표 페이지를 서로 다른 시각 구조로 교체했다. 편집 탭에는 직접 수정과 실행 취소/다시 실행을 추가했다. 아래 구현 계약은 제품의 후속 목표이며 이번 동작은 메모리 기반 시안이다.

## 전체 설계 수립 (2026-10-02 후속 요청)

사용자 요청에 따라 추가 기능 구현보다 전체 계획과 UI/UX 설계를 먼저 수립했다. [제품과 화면 설계](../design/2026-10-02-revision-product-ux.md), [독립 앱과 구현 단계](../architecture/2026-10-02-desktop-revision.md), [상호작용 화면 시안](../design/2026-10-02-revision-wireframe.html)을 현재 개정판의 설계 기준으로 삼는다. 아래 첫 단위 구현 결과와 전체 목표 설계는 구분한다.

설계 결정: Windows/macOS 동시 지원, Electron/React/Python 기본안, 다섯 작업 단계, 독립적인 저장/진행/검토 상태, 계정별 최초 AI 동의, 작업과 원하는 결과 유형 기반 Claude 추천, 파일/폴더/텍스트 통합 입력이다. 공식 프로필/모델/Effort 지원, 양 OS 설치본과 HWP 추출은 D1 기술 검증 관문이다. 전체 일정은 이 관문 이후 산정한다.

## 목표와 작업 순서

가장 높은 우선순위는 보고 목적에 맞는 문서 구성이다. 드롭다운 항목만 늘리지 않고 저장 계약, 구조안과 장 생성의 지침, 기존 문서 호환성을 함께 확장한다. 이어 생성 실패의 원인과 복구 경험, 자료 입력, AI 연결, 독립 앱과 전체 상태 디자인을 진행한다. 실제 AI 호출과 Windows 설치본 검증은 실행 증거가 있을 때만 완료로 기록한다.

## 첫 구현 단위: 보고 목적

기존 `research`, `approval`, `strategy` 저장값은 유지한다. `research`는 리서치 결과 보고로 표시한다. `weekly`, `business`, `monthly`, `data`, `project`, `results`를 추가한다. 새 ID는 백엔드 ReportType, OpenAPI, 프런트 타입에 함께 반영한다.

| 유형 | 구성과 강조점 |
|---|---|
| 주간 업무 | 보고 기간, 이번 주 실적, 계획 대비 차이, 장애/지원 요청, 다음 주 계획 |
| 일반 업무 | 업무 목적, 현재 현황, 수행 내용, 이슈, 후속 행동 |
| 월간 | 대상 월, 목표와 실적, 전월/계획 대비 변화, 원인과 한계, 다음 달 계획 |
| 데이터 설명 | 질문, 지표 정의와 단위·기간·분모, 관측 결과, 해석과 한계 |
| 리서치 결과 | 조사 질문, 범위와 방법, 발견, 근거와 한계, 시사점 |
| 프로젝트 | 목표와 범위, 마일스톤/진척, 일정·자원·리스크, 필요한 결정, 다음 단계 |
| 결과 | 당초 목표와 평가 기준, 수행과 산출, 달성 여부, 차이 원인, 교훈과 후속 조치 |

누락된 기간·담당·실적을 만들지 않는다. 정기/설명 보고를 억지로 승인 요청이나 전략 제안으로 바꾸지 않는다. 세부 템플릿은 자료에 맞게 선택한다. 첫 단위에서는 구조안 및 장별 생성 지침, 편집 보존 재작성 지침에도 유형을 전달한다. 전체 구성 지침은 문맥이며, 장 생성에서는 지정한 한 장만 채우고 재작성에서는 기존 장 ID·제목·본문 보존 계약을 우선한다. 유형 변경 시 기존 계획의 현재성 검사는 유지한다.

R15는 `StructureScreen.instructions` textarea의 label과 aria-label을 변경한다. 별도의 `decision_question` 입력은 유지한다. 입력한 주안점이 `generateStructure.instructions`로 전달되고 실패 뒤에도 남는지 검증한다.

수용 검증은 새 유형의 저장/재읽기, 기존 세 유형의 호환, 유형별 구조안·장 생성·재작성 지침 전달, 프런트 선택과 저장, OpenAPI/타입 일치, 기존 계획 현재성 회귀, 화면 빌드다. 실제 보고 품질 향상은 AI 생성과 Windows 사용자 재검증 전까지 미확인이다.

## 검토와 진행 기록

R11의 첫 단위도 포함한다. 구조안 최종 검증 실패에 비민감 오류 코드(`answer_not_in_summary` 또는 `invalid_response`)를 반환한다. 구체적인 회사 자료나 예외 원문을 오류 안내에 넣지 않는다. 답변 장 연결 오류에서는 사용자가 입력을 잘못했다고 안내하지 않고 AI가 만든 구성의 연결 문제와 입력 보존을 설명한다. 성공 시 오류 코드는 비우고, 재시도 성공/서로 다른 두 번의 실패/재시도 상한을 검사한다. 다른 생성 기능의 반환 계약은 유지한다. 생성 지침에는 모든 핵심 답변이 answer 역할 장에도 연결되어야 한다고 명시한다. 자동 수정과 검증 완화는 하지 않는다.

- 계획 확정 전 독립 반례 검토를 수행한다. 이후 첫 구현 단위의 코드와 회귀를 독립 검토한다.
- 생성 실패의 첨부 응답은 로컬에서만 검사하며 실제 원자료가 없으면 근거 위치 검증을 완료로 주장하지 않는다.
- 독립 진단에서 첨부 JSON/StoryDraft 검증은 통과했지만 일부 핵심 답변이 action 역할 장에만 연결되어 StoryPlan의 답변 장 배치 계약을 위반함을 확인했다. 실제 원자료가 없으므로 당시 최초 실패 원인은 확정하지 않았다. R11에서 실패 사유 전달과 해당 연결 조건의 합성 회귀를 다루며 검증을 약화하거나 주장을 자동 이동하지 않는다.
- 2026-10-02 접근 진단 정정: `.git`이 없는 주소의 인증 실패를 저장소 권한 문제로 오판했다. `https://github.com/blazethrottle/modeltest-claudecode.git`으로 `ls-remote`와 복제가 성공했고 기준 커밋은 `b68b2bd7c917a62cc1d243ac338060ee2d41cf0d`다. README와 `docs/06-model-guide.md`를 읽었다. GitHub API는 환경 프록시에서 CONNECT 403이지만 Git 읽기는 정상이며 사용자 권한 변경은 필요하지 않다. 같은 환경에서는 정식 `.git` 주소로 접근한다.
- 외부 게시, 릴리스 발행, 실제 AI 계정 사용은 아직 실행하지 않았다.

## 첫 구현 단위 결과

2026-10-02: 위 R09/R15와 R11의 한정된 사유 안내를 구현했다. 백엔드 전체 2,003 통과/플랫폼 관련 3 건너뜀, 프런트 전체 543 통과, TypeScript/Vite 빌드, OpenAPI 일치, 공개 저장소 감사, diff 공백 검사를 통과했다. 독립 코드 리뷰 두 건에서 수정이 필요한 결함은 발견되지 않았다. Chromium에서 9개 유형 표시, 주간 업무 보고 저장/새로고침 후 재열기와 주안점 명칭을 검증했다. R09 회귀는 모든 유형의 API 저장/재읽기와 기존 보호 도식 포함 재작성 보존, 유형 변경 시 계획 현재성 무효화를 검사한다. 실제 AI 호출은 0회다.

제보 응답의 연결 오류가 발생하지 않도록 생성 지침을 구체화했지만 실제 제공자의 응답 성공률 향상을 입증한 것은 아니다. 원자료 없이 당시 최초 오류를 확정하지 않았다. 자동 의미 수정과 Windows/macOS 실기기 품질 검증은 남아 있다. 전체 프로젝트의 후속 단위와 재개 순서는 [인계](../handoffs/2026-10-02-windows-feedback-first-batch.md)를 따른다.
