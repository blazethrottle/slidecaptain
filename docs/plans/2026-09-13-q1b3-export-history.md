# Q1b 세 번째 단위: 내보내기 검수 이력 조회

작성: 2026-09-13. 개발 계속 진행 승인을 최신 Q1b 두 번째 단위 인계의 다음 작업으로 수행한다.

## 범위와 종료 조건

프로젝트의 exports 폴더에서 기존 제목을 포함한 버전별 PPTX와 품질 기록을 읽고, 목록과 상세 API 및 화면을 제공한다. 저장 당시 점검 결과를 보존하면서 조회 시점의 현재 저장된 덱/프리셋/원문 식별값과 실제 PPTX SHA-256을 대조한다. 파일 일치가 내용/시각 검수 통과나 제출 승인을 의미하지 않도록 표시한다.

1. 목록은 파일 쌍의 합집합이다. 품질 기록만 있는 버전, PPTX만 있는 버전, 깨진 JSON과 구형 preflight-v1도 누락하지 않는다. 제목 변경 이전 파일도 포함한다. 파일 수정 시각으로 정렬하고 이것을 내보낸 시각으로 부르지 않는다. 페이지 크기에 상한을 두며 선택한 페이지의 파일만 대조한다.
2. 기록 상태, PPTX 일치 상태와 현재 입력 일치 상태를 독립 필드로 제공한다. 한 문제가 다른 문제를 숨기지 않는다. preflight-v1은 읽되 원문을 포함한 현재 식별값과 비교 가능한 것으로 취급하지 않는다. 지원하지 않는 기록 버전, 해시 결손과 읽기 실패는 확인 불가다.
3. GET 조회는 덱, 원문, 스냅샷, 사용량, 내보낸 파일과 잠금 파일을 만들거나 수정하지 않는다. 현재 자료 읽기 실패에도 과거 기록은 열 수 있고 현재 자료 대조만 확인 불가로 표시한다. exports 폴더 읽기 실패는 빈 목록으로 숨기지 않는다.
4. 파일 ID는 직접 자식의 내보내기 이름으로 제한한다. 경로 이동, exports 폴더 심볼릭 링크, 파일 심볼릭 링크와 비정규 파일을 따라 읽지 않는다. JSON 읽기 크기에 상한을 두고 PPTX 해시는 스트림으로 계산한다. 읽는 동안 파일이 변경되면 일치 판정을 내리지 않는다.
5. 현재 입력 스냅샷은 기존 프로젝트 잠금 안에서 한 번 계산한다. 두 파일의 게시가 단일 원자 동작은 아니므로 조회는 시점 관측이며, 진행 중이거나 외부 프로그램이 변경한 경우 재조회로 확인한다. GET으로 게시 잠금을 새로 만들지 않는다. 외부 원문 편집 전체를 하나의 트랜잭션으로 보장하지 않는다.
6. 화면은 별도 검수 이력 탭으로 제공한다. 기존 탭 이탈 저장 관문을 사용하며 저장 실패 시 이동하지 않는다. 목록/상세 요청의 이전 응답이 다른 프로젝트나 선택을 덮지 않도록 한다. 새로고침, 오류와 빈 목록, 이전/다음 페이지를 제공하고 조회 시각 및 저장본 기준임을 표시한다.
7. 상세는 저장 당시 결과라는 설명과 현재 대조 결과를 함께 표시한다. 기존 내보내기 성공 안내 컴포넌트의 성공 문구를 손상/누락된 이력에 재사용하지 않는다. AI 호출이나 자동 수정은 없다.

## 검증과 인계

구현 전 API의 목록/상세 부재와 UI 부재를 실패 검사로 확인한다. 정상 내보내기 응답/저장 JSON/실제 PPTX/이력 상세를 왕복 대조하고 덱/원문/프리셋 변경 및 복원, 고아 파일, 손상, 구형/미지원 기록, 권한 오류, 경로 경계와 파일 보존을 검사한다. 화면의 낡은 응답과 이탈 저장, 전체 회귀, OpenAPI/TypeScript 재생성, 빌드 및 가능하면 실제 브라우저 표시까지 확인한다.

계획과 구현은 독립 검토 후 발견을 반영한다. 현재 누적 미커밋 변경과 비어 있는 스테이징을 보존하며 이번 단위 구현/검증/인계에서 멈춘다. 실제 AI 생성, Windows 실기기, PowerPoint 및 독자 평가는 별도 미검증으로 남긴다.

독립 계획 리뷰 3건 반영(2026-09-13): 덱 파일 부재/손상과 복구 화면에서도 이력에 접근한다. 원시 JSON의 버전을 필수로 확인하고 SHA-256 형식을 검사해 생성 모델의 기본값으로 결손을 보충하지 않는다. 기존 exporter가 허용한 괄호, 점 시작과 연속 점 제목은 이력에서도 허용하며 프로젝트/자료의 이름 제한을 재사용하지 않는다.

## 구현 중 발견과 수정

- 경로를 검사한 뒤 이름으로만 파일을 열면 exports를 잠깐 외부 링크로 바꾼 경우 외부 기록을 읽을 수 있었다. 실패 재현 후 POSIX 디렉터리 fd 고정으로 수정했다. Windows는 네이티브 핸들을 유지하며 실제 파일 핸들/목록 항목의 최종 경로를 확인한다. 이름 변경 방지만으로 junction 제어가 충분하다고 가정하지 않는다. 근거와 플랫폼별 미검증은 [아키텍처 실제 계약](../architecture/2026-09-12-quality-pipeline.md)의 해당 절을 따른다.
- 자료 탭의 저장 관문은 보고 정보만 처리해 미저장 본문을 버릴 수 있었다. 본문 수동 저장을 요구하고 보고 정보 저장 전후로 확인한다. 늦은 자료 읽기가 현재 편집을 덮거나 이전 자료 저장 응답이 다른 자료의 dirty 상태를 지우지 않도록 요청 소유권을 검사한다. 독립 재현과 회귀 테스트로 수정 전 실패/수정 후 통과를 확인했다.
- 스냅샷 복구 화면 위에서 이력을 선택한 것처럼 표시되는 상태를 막았다. 화면 확인 중 발견한 점검 표의 좁은 열 간격과 성공적인 이탈 후 남은 오류 배너도 수정했다.

최종 독립 구현 재검토: 추가 필수 수정 없음. 백엔드 1,258개 통과/Windows 전용 1개 미실행, 프런트 312개 통과와 OpenAPI/타입/빌드 검증. 실제 Chrome 합성 프로젝트의 정상/누락/변조/손상/복구 필요/저장 보호 흐름을 확인했다. [인계](../handoffs/2026-09-13-q1b3-export-history-handoff.md)에 파일 보존과 다음 단위를 기록하며 여기서 멈춘다.
