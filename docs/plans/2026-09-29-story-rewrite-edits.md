# 보고 계획 재작성의 보호 필드 출력 분리

작성: 2026-09-29. 개발 재개 요청에 따라 최신 인계의 LUNA 재작성 실패를 처리한다. 실제 호출 기록에서는 보호 근거의 null 값 변경과 보호 도식의 주장 추가가 각각 거절됐다. 기존 승인 5회는 모두 소진했으며 이번 기본 검증은 외부 호출 없이 수행한다.

## 변경 계약

1. AI 전용 응답에 `chapter_order`를 추가한다. 기존 모든 장 ID를 정확히 한 번 포함하고, `chapters`에는 보호 도식 외의 모든 장 연결만 출력한다. 누락, 중복, 추가 ID는 거절한다. 기존 Deck/API/저장 모델은 유지한다.
2. `evidence`, `claims`, `comparisons`, `derivations`에는 보호되지 않은 항목만 출력한다. 보호 ID를 재출력하면 동일한 값이라도 거절한다. `comparisons.claim_id`가 보호 주장인 신규 비교와 `derivations.comparison_id`가 보호 비교인 신규 산식도 거절한다. 일반 장이 보호 근거/주장의 ID를 참조하거나, 일반 주장이 보호 근거를 이용해 새 비교와 산식을 만드는 것은 허용한다.
3. 서버가 현재 저장본의 보호 도식 연결, 주장, 근거, 비교와 산식을 그대로 합친다. 보호 근거는 도식 주장의 간접 참조와 도식 노드/간선의 직접 참조를 모두 포함한다. 각 출력 목록의 중복 ID는 사전 병합 전에 거절한다. AI 출력의 보호 필드를 덮어써서 오류를 숨기거나 과거 실패 응답을 자동 변환하지 않는다. 보호 근거의 원문 해시/위치/발췌 검증과 최종 `validate_rewrite`는 유지한다.
4. 프롬프트에서 읽기 전용 문맥과 출력 계약을 구분한다. 기본 스토리 계획의 `chapters` 계약이 재작성 출력과 충돌하지 않도록 필요한 공통 입력만 재사용한다. 기존 본문은 근거가 아니며 새 계획의 본문 재검토 표시는 계속 유지한다.
5. 보호 도식만 있는 경우 편집할 주장/장 연결의 빈 목록을 허용한다. 병합한 최종 StoryPlan은 기존의 참조/핵심 답변/비교/계산 검사를 모두 통과해야 한다. 미연결 주장을 임의로 삭제하지 않는다.
6. 미리보기 무저장, 적용 시 ETag/전체 자료 식별값 재검사, 1회 형식 재시도와 사용량/동의/모델 선택 관문은 그대로 유지한다. 오프라인 관통 도구의 고정 응답도 새 계약을 사용한다.

## 검증과 재심할 가정

- 실제 실패 응답의 보호 값 변조/도식 주장 확장을 합성 회귀로 고정한다. 새 응답의 보호 ID 재출력과 적용 후보 변조를 모두 검사한다. 원시 LUNA 응답 재생은 별도 오프라인 증거로 남긴다.
- 정상 경로는 보호 도식만 있는 경우, 일반 장과의 혼합, 보호 근거 재사용, 장 순서 변경, 신규 근거와 비교/산식, 기존 계획 3개 버전의 호환성을 검사한다.
- 누락/중복/없는 ID, 보호 비교/산식 추가, 미연결 주장, 원자료 변경, 생성 중/적용 전 저장 충돌에서 덱/스냅샷이 보존되는지 확인한다.
- 관련 테스트의 수정 전 실패, 수정 후 백엔드 전체, OpenAPI/생성 타입 무변경, 프런트 전체/빌드와 공개 저장소 감사, 합성 3장 API/PPTX 관통을 확인한다.
- 코드/프롬프트 계약 개선은 LUNA의 실제 응답 성공을 입증하지 않는다. 새 실제 호출과 PowerPoint/독자 품질은 별도 증거가 필요하다. 보호 범위를 줄이거나 형식 검사를 완화하지 않는다.

## 보존과 검토

원본 `codex/phase-5b`, HEAD `a8c6d7a`의 299개 파일과 Git 인덱스를 기준으로 별도 작업본에서 구현한다. 원본 반영 전에 파일별 변경 유무를 다시 대조하고 이번 변경만 반영한다. 커밋/푸시는 하지 않는다.

사용자가 리뷰 에이전트 1명 사용을 승인했고 이후 필요한 서브에이전트/멀티에이전트 사용을 지속 승인했다. 독립 계획 검토에서 구현을 막는 설계 결함은 없었으며 비교/산식 참조 경계, 중복 ID 사전 검사, 노드/간선 전용 근거 보호의 3항을 구체화했다. 구현 후 같은 에이전트로 독립 리뷰를 진행한다.

## 실행 결과

독립 계획의 3항과 구현 리뷰의 문구 보완 1건을 반영했다. 필수 수정 잔여 0건이며 전체 백엔드 1,646개/프런트 410개, 타입/빌드와 생성 계약 동일성을 확인했다. 사용자가 새로 승인한 LUNA 최대 3회로 실제 장 생성/재작성/초안 PPTX까지 완료했다. 재작성 첫 후보의 답변 역할 위반을 1회 재시도로 해소했고 해당 사례를 API 회귀로 추가했다. 기존 승인과 새 승인 예산은 모두 소진했다. 상세 근거와 미검증 경계는 [검증 기록](../qa/2026-09-29-story-rewrite-edits.md)을 따른다.
