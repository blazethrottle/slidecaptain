# Q3b 프로젝트 도식 저장과 읽기 전용 미리보기

작성: 2026-09-20. 이전 단위는 `2026-09-13-q3b-diagram-render-handoff.md`이며, 사용자 재개 요청에 따라 다음 저장/연결 단위만 진행한다.

## 목적과 범위

도식 의미 입력을 기존 `deck.json`에 보존하고 저장/재열기/스냅샷 복원 뒤 기존 편집 화면에서 같은 도식을 볼 수 있게 한다. 기존 RenderPlan 계산과 PPTX 소비자를 연결하며 전체 덱의 초안 내보내기에서도 도식을 누락하지 않는다. UI에서 새 도식을 작성하거나 AI로 생성하는 기능은 후속 단위다. 이번 단위의 도식 입력은 기존 Deck API/파일 경로로 검증한다.

## 계약

- `TemplateName`과 `Slots`에 `diagram`을 추가한다. `DiagramSlots`는 `template`, `diagram`(원래 의미 필드), `footnote`만 저장한다. 제목은 기존 Chapter.topic, 분류 라벨과 부제는 기존 Slide 필드다. 도식 ID는 chapter_id와 같아야 한다.
- 도식 Chapter에는 반드시 같은 ID의 DiagramSlots가 있어야 하며 제목은 비어 있을 수 없다. 기존의 아직 생성하지 않은 일반 장과 구별해 도식 페이지가 조용히 누락되지 않게 한다.
- 근거의 진본은 기존 `Structure.story_plan.evidence`다. 도식마다 별도 근거 장부를 복제하지 않는다. 근거가 필요한 도식은 장부 없이는 저장할 수 없다. 명시적 제안만으로 구성한 도식은 빈 장부로도 검증할 수 있다.
- `DiagramInput`은 엄격한 의미 필드와 그래프 구조를 검증한다. 기존 `DiagramSpec`은 이를 상속하고 기존 파서의 근거 장부 검증을 유지한다. Deck 전체 검증에서 모든 도식을 `parse_diagram_spec`으로 재검증한다. 렌더에서도 현재 입력을 재검증한다. 좌표/렌더 결과/검수 필드는 도식 저장 계약에서 거절한다.
- Deck schema_version 1과 StoryPlan 버전을 유지한다. 기존 슬롯의 직렬화는 바뀌지 않는다. 구 앱은 새 template 판별자를 거절하므로 조용히 일반 슬라이드로 읽거나 도식 내용을 지우지 않는다. 레거시 저장본/품질 fingerprint는 동일해야 한다.
- 렌더 순서와 페이지 번호는 기존 구조안 순서를 따른다. 저장된 도식을 `build_diagram_render_plan`에 전달하고 같은 SlidePlan을 Preview/PPTX에서 사용한다. 배치 불가는 422의 구체적 사유로 반환하며 부분 도식을 만들거나 내보내지 않는다.
- 스타일 생성 함수를 공통 모듈로 옮겨 engine과 diagram_page의 순환 import를 피한다. 저장/렌더 경계는 model_dump가 버릴 수 있는 우회 추가 필드까지 재검증하고, 실패하면 저장/스냅샷을 쓰지 않는다.
- 도식 변경/근거 변경/제목/공통 문구/페이지 순서/프리셋 변경은 재계산과 fingerprint 변경으로 이어진다. 모든 의미/화면/PowerPoint/독자 검수는 계속 not_run이다. 실제 원문 현재성/의미 검수는 기존 품질 게이트의 미수행 표시를 유지한다. 미리보기 성공은 승인 상태가 아니다.

## 편집과 생성 경계

- 기존 도식 장을 선택/재정렬/저장/복원할 수 있다. 도식 자체와 주제/템플릿은 읽기 전용으로 표시해 의미 입력이 기존 슬롯 편집이나 변환 경로에서 소실되지 않게 한다. 일반 슬라이드 편집, 전역 디자인 변경과 undo/redo는 계속 가능하다.
- 구조안 화면에서 기존 도식의 주제/결론/템플릿/삭제를 비활성화하고 현재 유형을 표시한다. 새 도식 생성 선택지는 제공하지 않는다. 도식 없는 일반 구조안의 기능은 유지한다.
- 도식 AI 재생성/축약과 도식 포함 덱의 전체 구조안 AI 재생성을 UI/API에서 차단한다. 전체 구조안 승인이 기존 의미 입력과 단일 근거 장부를 교체하기 때문이다. 생성 전용 template/Chapter를 분리해 planned/unplanned 생성 스키마와 응답 parser 모두 diagram을 거절한다. 해당 요청은 서비스 초기화/로그인 lease/외부 프로바이더 호출 전에 422로 거절하며 직접 서비스의 장 생성/축약도 차단한다.
- 숫자 검사에는 실제 보이는 도식 문구(본문/조건/관계 라벨/각주/공통 문구)만 수집한다. ID/버전/근거 참조 문자열은 숫자 문구로 오인하지 않는다.

## 검증 순서

1. 저장 왕복, 근거 참조 거절, ID 불일치, 렌더/검수 입력 거절, 혼합 덱 페이지 순서와 페이지 번호, 프리셋/문구/근거 변경 fingerprint, blocked/422, 초안 PPTX와 제출본 차단에 실패 테스트를 먼저 둔다.
2. 프런트는 읽기 전용 표시, 재생성/변환 차단, 구조안 보존, undo/redo와 저장 요청에 의미 입력이 남는지 확인한다. 기존 지연 응답 무효화 계약을 유지한다.
3. OpenAPI/TS 생성, 관련 회귀 및 전체 테스트/빌드, 공개 저장소 감사, 독립 구현 리뷰를 수행한다. 실제 브라우저와 PowerPoint는 수행한 항목만 기록한다.
4. 원래 프로젝트 파일의 시작 해시를 확인한 뒤 이번 변경만 적용한다. 기존 미커밋/스테이징을 보존하고 인계와 로드맵을 갱신한다. 다음 단위로 자동 확장하지 않는다.

## 계획 리뷰 반영 (2026-09-20)

독립 리뷰에서 지적한 도식 슬롯 역방향 검증, 전체 구조안 재생성의 장부 교체, 렌더 순환 import, 서비스 lease 이전 차단, 생성 전용 schema/parser 분리의 다섯 항목을 위 계약과 검증에 반영했다. 재개 시점 전체 회귀는 백엔드 1,456개 통과/1개 미실행과 프런트 316개 통과다. 구현 전 신규 테스트는 20개 중 14개가 예상대로 실패하고 6개가 현재의 미지원 판별자 거절로 통과했다. 후자의 개별 거절 이유는 구현 후 다시 검사한다.

## 구현 결과 (2026-09-20)

구현과 독립 리뷰를 완료했다. 일반 장에 도식 축약 본문을 보내는 우회도 lease 전에 차단하며 실패 회귀를 남겼다. 실제 화면에서 편집 열이 넓어지는 문제와 배치 실패를 내용 없음으로 표시하던 안내를 수정했다. 최종 백엔드 1,486개/프런트 323개와 타입/빌드가 통과했고 Windows 전용 1개는 미실행이다. 기존 저장본과 품질 fingerprint 3개를 유지했고 실제 브라우저 정상/배치 불가 프로젝트를 확인했다.
