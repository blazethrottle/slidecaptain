# Q3b 핵심 답변의 역할과 주장 연결 안내

작성: 2026-09-27. 최신 독립 리뷰 인계의 후속 후보 중 역할 제약 안내를 진행한다. 기존 누적 변경을 복제한 격리 작업본에서 구현하며 실제 AI 호출, 커밋/푸시와 전체 재계획은 포함하지 않는다.

## 목적과 범위

핵심 답변 주장은 최소 한 답변 역할 장에 연결되어야 한다. 유일한 답변 도식을 다른 역할로 바꾸거나 필수 주장을 해제할 때 서버에서야 사유를 알게 되는 경로를 개선한다.

- 대상 장을 제외한 다른 답변 장의 주장 ID를 대조하여 이 도식에 남겨야 하는 핵심 주장을 계산한다. 단순히 답변 장 개수를 세지 않는다.
- 역할 선택란에서 제약을 설명하고 해당 주장에 표시한다. 다른 답변 장이 같은 주장을 다루는 경우에는 역할/주장 변경을 허용한다.
- 필수 연결을 해제하는 선택을 제한하되, 이미 누락된 초안은 사용자가 다시 선택해 고칠 수 있어야 한다. 역할과 주장을 자동으로 바꾸지 않는다.
- 확인 함수도 잘못된 초안을 차단하여 저장 플러시, 연결 확인과 배치 API가 호출되지 않도록 한다. 백엔드의 최종 StoryPlan 검증은 유지한다.
- 기존 저장, fingerprint, OpenAPI, AI 동의와 응답 순서 보호 계약은 변경하지 않는다.

## 반례와 검증

1. 답변 장이 둘이어도 서로 다른 핵심 주장을 맡으면 각 연결을 유지해야 한다.
2. 같은 주장이 근거/맥락 장에만 남는 경우는 답변 연결을 대체하지 않는다.
3. 복수 답변 장이 모든 핵심 주장을 함께 다루면 변경을 막지 않는다.
4. 핵심 답변이 아닌 주장의 일반 장 연결 규칙은 서버가 계속 판정한다. 이 안내를 전체 보고 계획의 사전 승인으로 표시하지 않는다.
5. 새 도식/보고 계획 없는 도식의 기존 작성 흐름을 보존한다.
6. 이미 누락된 초안, 입력 수정 뒤 과거 성공 무효화와 기존 서버 거절을 검사한다.

실패 테스트부터 작성한다. 프런트 전체/타입/빌드, 관련 백엔드 계약 검사, 실제 Chrome 합성 프로젝트 확인을 구분해 기록한다. 독립 리뷰는 실제 수행 결과만 기록하며 누적 코드 전체나 제출 품질 검수로 확장하지 않는다.
