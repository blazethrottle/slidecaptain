# Q3b 현재 자료와 맞지 않는 보고 계획의 복구 안내

작성: 2026-09-27. 사용자가 최신 상태 확인 뒤 승인한 다음 개발 단위다. 대상은 현재 보고 계획으로 도식을 확인하거나 장을 생성할 수 없는 경우의 안내와 입력 보존이다. 전체 재계획, 도식 AI 생성과 자동 자료 복원은 포함하지 않는다.

## 확인한 문제

`StaleStoryPlan`은 다른 충돌과 같은 HTTP 409이며 오류 문자열만 반환한다. 화면은 이를 그대로 표시하여 도식이 있는 프로젝트에도 구조안 재생성을 권하지만, 구조안 화면은 저장된 도식 보존을 위해 전체 재생성을 막는다. 도식 작성 창은 오류 뒤 입력을 유지하지만 창을 닫기 전 보관 방법과 가능한 후속 행동이 명확하지 않다. 구조안 화면의 도식 읽기 전용 설명도 편집 탭의 작성/수정 기능과 맞지 않는다.

## 구현 범위

- 서버의 기존 409/문자열 detail을 유지하면서 `code: stale_story_plan`을 추가한다. API 클라이언트는 선택적 오류 코드를 보존하고 상태와 코드가 모두 일치할 때만 복구 안내를 선택한다. 일반 409, AI 연결 변경, 412 저장 충돌과 네트워크 오류를 섞지 않는다.
- 도식 작성, 일반 장 생성/축약과 구조안 화면에서 같은 복구 원칙을 안내한다. 서버의 판정과 기존 fingerprint/근거 검증은 변경하지 않는다.
- 이전 자료와 보고 정보/장 구성을 정확히 복원할 수 있으면 복원 후 다시 확인할 수 있다. 스냅샷 복원만으로 원자료가 복구된다고 안내하지 않는다.
- 저장된 도식이 있으면 전체 재계획의 미지원 상태를 설명한다. 새 자료로 다시 만들어야 하면 기존 프로젝트를 보존하고 별도 프로젝트에서 작업하도록 안내한다. 저장된 도식이 없으면 기존 구조안 재생성 경로를 안내한다. 아직 적용하지 않은 새 도식을 저장된 도식으로 세지 않는다.
- 도식 작성 창의 입력과 선택을 오류/재시도/일반 편집 뒤에도 유지한다. 배치 확인 성공 전 적용을 차단하며, 복구가 확인되지 않았는데 안내를 통과 상태로 바꾸지 않는다.
- 작성 내용을 사람이 읽을 수 있는 보관용 텍스트로 제공한다. 복사 성공/실패를 구분하고 실패하면 직접 선택할 수 있게 한다. 창을 닫거나 새로고침하면 미적용 입력이 사라지며 보관 텍스트의 자동 불러오기는 지원하지 않음을 밝힌다. 근거 ID만으로 새 프로젝트에서 연결이 복원된다고 주장하지 않는다.
- 화면 안내와 보관은 자료/덱/스냅샷을 자동 변경하거나 AI 호출을 시작하지 않는다. 구조안 화면에서는 도식 수정의 실제 진입점이 편집 탭임을 안내한다.
- 정적 도움말은 현재 계획이 유효하지 않다는 판정과 구분한다. 순차 생성에서 낡은 계획 오류가 발생하면 남은 장을 보류하고 이미 성공한 결과는 유지한다.

## 검증할 반례

1. 자료 변경 후 기존 도식 확인이 실패해도 제목/노드/관계/역할/주장 선택과 저장본이 유지된다.
2. 다른 409 및 412에 보고 계획 복구 안내를 잘못 표시하지 않는다.
3. 같은 초안으로 자료를 원래대로 복원한 뒤 다시 확인하면 적용할 수 있다. 확인 응답이 늦게 도착하거나 입력/원본이 바뀌면 기존 무효화 규칙을 유지한다.
4. 저장된 도식이 없는 프로젝트의 새 도식 실패는 기존 구조안 생성 경로를 안내한다.
5. 복사가 실패해도 성공이라고 표시하지 않고 보관 텍스트와 초안을 유지한다. 복사 대기 중 입력이 바뀌면 현재 내용이 복사됐다고 하지 않는다.
6. 복구 안내를 표시하려고 저장/복원/AI 호출을 추가하지 않는다. 일반 장의 생성 오류와 구조안 안내도 실제 지원 범위와 일치한다.
7. 여러 답변 장이 핵심 주장을 나누어 맡는 기존 비차단 리뷰 사례를 관련 프런트 회귀에 포함한다.

## 작업과 완료 기준

원본 274개 파일과 인덱스를 보존한 격리 작업본에서 실패 재현을 먼저 작성한다. 계획의 독립 검토와 구현 후 독립 리뷰를 분리한다. 관련 검사, 프런트 전체/타입/빌드, 백엔드 전체 및 OpenAPI/생성 타입 일치와 공개 저장소 감사를 확인한다. 임시 서버와 합성 자료로 실제 Chrome의 실패 후 입력 보존, 복구 후 재확인과 안내를 검사한다. 실제 AI/PowerPoint/독자 품질은 이번 범위가 아니다.

최종 변경 파일만 원본 시작 해시와 대조해 반영하고 누적 변경과 스테이징을 보존한다. 로드맵, 품질 개발 계획과 최신 인계를 갱신하며 커밋/푸시/머지는 수행하지 않는다.

## 실제 검토 순서와 보완 (2026-09-27)

사용자가 리뷰 에이전트 1명을 허용한 시점이 초기 구현 이후였으므로 구현 전 독립 계획 리뷰는 수행하지 못했다. 초기 변경과 계획을 함께 독립 검토한 뒤 입력 초점 이동과 정적 도움말의 거짓 경고 2건을 실패 테스트로 재현하고 수정했다. 후속 Chrome 검증의 긴 안내/보관 내용 때문에 복사 버튼이 고정 영역 밖에 가려지는 문제는 오류 상태에서만 고정 배치를 해제해 해결했다. 같은 에이전트가 수정 후 재검토했다. 실행 결과, 승인 범위와 미완료는 [인계](../handoffs/2026-09-27-q3b-stale-plan-guidance-handoff.md)에 남긴다.
