# 편집을 보존하는 보고 계획 재작성과 전체 QA

작성: 2026-09-27. 사용자는 다음 기능인 보고 계획 재작성 구현 후 전체 QA를 승인했다. 기존 279개 파일과 빈 스테이징을 보존한 별도 작업본에서 구현한다.

## 계약

1. 기존 보고 계획이 있는 덱에서 새 보고 질문과 지시사항으로 AI 재작성 후보를 만든다. 기존 장 ID, 장 제목/결론/템플릿, 모든 슬라이드/도식 내용과 보고 정보는 그대로 보존한다. 기존 장의 순서와 일반 장의 역할/주장/근거를 다시 계획한다. 모든 기존 ID를 정확히 1:1로 대응시키고 Structure/StoryPlan 순서를 일치시키며 source_refs는 새 주장 근거에서 재계산한다. 장 추가/삭제와 본문 재생성은 이 기능에 포함하지 않는다.
2. 저장된 도식 장의 역할/주장 연결, 그 주장, 직접 참조 및 주장 경유 근거, 연결된 비교와 산식은 보존한다. 보호 근거의 원문 전체 해시/위치/발췌가 달라졌으면 AI 호출 전에 거절한다. 같은 발췌만 남았다는 이유로 revision을 갱신하지 않는다. 보호 대상이 아닌 자료 변경과 새 자료는 새 근거로 재계획할 수 있다.
3. 미리보기는 덱/스냅샷을 저장하지 않는다. 생성의 동의/모델 선택/사용량 계약을 기존 관문으로 유지한다. 외부 실호출 검증은 별도이며 이번에는 합성 프로바이더만 사용한다.
4. 미리보기 시작 시 저장본 ETag와 전체 원자료 식별값을 붙잡는다. 생성 중 변경되면 후보 적용을 막는다. 적용 API는 두 식별값, 내용 보존, 보호 근거, 모든 원문 발췌와 계획 fingerprint를 다시 검사하고 같은 저장 잠금 안에서 스냅샷과 덱을 저장한다. 식별값이 없으면 거절한다. 적용 요청은 미리보기의 base_etag를 명시적으로 보내며 전역 ETag 캐시로 대체하지 않는다.
5. 후보를 읽고 사용자가 적용하기 전에는 현재 계획을 바꾸지 않는다. 입력 변경/재요청/프로젝트 변경/창 이탈로 낡은 응답을 적용할 수 없게 한다. 생성/적용 중 탭 이동과 다른 저장 경로를 잠그고 미적용 후보를 버릴 때 확인한다. 저장 충돌 412는 기존 서버본 복구 경로에 연결한다.
6. 기존 본문은 새 계획에 맞춰 자동 변경되지 않는다. 후보와 적용 후에 본문 전체의 재검토 필요를 명시한다. 재작성 이력을 계획의 선택적 메타데이터에 보존하고 품질 승인이 아님을 표시한다. 예전 계획의 fingerprint/직렬화 호환성을 유지한다. null 메타데이터는 모델 직렬화에서 제외해 저장/수치/품질 식별값도 보존한다. 서버가 재작성 당시 보존한 슬라이드 ID를 산출하며, 이후 장 삭제/편집을 추적하는 현재 검수 원장으로 사용하지 않는다.

## 검증과 반례

- 기존 계획 3개 버전, 일반 장/도식 혼합, 슬라이드 내용 동일성, 보호 근거/주장/비교/계산 동일성, 순서와 질문 변경, 현재 자료로의 근거 재선정.
- 존재하지 않는/중복/누락 장, 보호 ID 의미 변경, 원문 해시만 갱신, 변조 발췌, 입력 초과, 형식 재시도, 동의/선택/사용량, 생성 시작 전/중/적용 전 자료 및 덱 변경.
- 미리보기/취소/거절 시 덱/스냅샷 불변, 적용/복구 왕복, 늦은 응답/입력 변경/탭 이동과 새로고침 경고, 412 복구, 적용 요청 실패 후 후보 보존.
- 독립 계획 리뷰 후 구현, 독립 구현 리뷰와 필요 수정 후 재검토. 전체 백엔드/프런트/타입/빌드/OpenAPI/생성 타입/공개 이력 감사, 실서버 API/브라우저, 합성 PPTX 내보내기와 재열기.
- 실제 AI, Windows 기기/새 CI, 목표 PowerPoint와 독자 품질은 실행 근거 없이는 통과로 보고하지 않는다. 기존 코드 전체 QA와 신규 기능 검증 범위를 별도 기록한다.

## 재심할 가정

- 보호 도식의 근거가 바뀐 경우 자동 재연결은 안전하지 않다. 첫 단위는 차단하며, 근거를 명시적으로 재확인/이전하는 기능은 후속이다.
- 기존 본문이 새 주장을 뒷받침하는지는 구조 검사로 입증하지 못한다. 본문 재검토 표시를 영속화하고 제출본 관문을 완화하지 않는다.
- AI가 기존 장 범위만으로 요청에 답할 수 없으면 미확인 질문에 남겨야 하며 장을 조용히 추가/삭제하지 않는다.

## 독립 계획 리뷰 반영

독립 리뷰의 장 ID/순서/source_refs, 명시적 ETag, 이전 직렬화 소비자 호환, 재작성 당시 보존 대상의 서버 산출 4항을 구현 전에 반영했다. 보호 근거 원문 hash가 달라지면 거절한다는 반례도 채택했다. 리뷰 원문은 작업본 상위 review/initial-plan-review.md에 둔다.

## 구현과 최종 검증

구현 전 계획의 필수 수정 4항을 반영한 뒤 재검토를 받았다. 구현 후 독립 리뷰의 busy 소유권, 기존 ID 지침 충돌, 조건/질문 수치 대조와 선택적 정규화 4건을 수정했다. 브라우저의 390px 표 넘침도 수정하고 최종 18개 코드/테스트 파일을 재검토했다. 필수 잔여는 0건이다.

전체 백엔드 1,540개 통과/Windows 전용 1개 미실행, 프런트 402개/37파일, 타입/빌드, 생성 계약 일치, 공개 저장소/이력 감사와 HTTP/CLI/PPTX 50개 검사를 통과했다. 독립 반례 23개 및 예전 계획 세 버전의 식별값 12개 대조, Chrome 성공/충돌/좁은 화면과 저장본 검증을 완료했다. [QA 보고서](../qa/2026-09-27-story-rewrite-full-qa.md)와 [인계](../handoffs/2026-09-27-story-plan-rewrite-handoff.md)에 미검증과 증거를 남겼다. 외부 AI 호출은 0회이며 실제 AI/Windows/PowerPoint/독자 품질은 통과로 표시하지 않는다.
