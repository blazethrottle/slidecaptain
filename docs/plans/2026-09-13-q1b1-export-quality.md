# Q1b 첫 단위: 내보낸 초안과 계산 문구 대조 기록

작성: 2026-09-13. Q2d 인계 이후 개발 재개 승인을 따른다.

## 범위와 종료 조건

내보내기에 사용하는 덱, 프리셋, 렌더 계획과 현재 원문으로 계산 문구를 다시 대조한다. 결과를 같은 버전의 PPTX와 `.quality.json`에 연결하고 API 응답과 화면에 표시한다. CLI의 `quality`와 `export`도 덱 옆 `sources/`를 같은 디코딩 규칙으로 읽는다. 기존 점검 기록은 읽을 수 있게 유지하고 Deck와 StoryPlan 저장 버전은 변경하지 않는다.

문구 일치는 계산 문구 대조 항목의 통과만 뜻한다. 미연결 문구는 확인 필요이며 계획 없음, 낡은 자료, 계산 없음과 대상 0건은 미수행이다. 의미, 보고 흐름, 시각과 PowerPoint 검수는 계속 미수행이다. API와 CLI의 제출본 요청은 공통 관문에서 거절한다. 기존 초안, 스냅샷과 사용량은 검사로 바꾸지 않는다.

합성 자료에서 API 응답, 저장 기록, 실제 PPTX 바이트와 CLI 결과를 왕복 대조한다. 정상, 부호 오류, 자료 변경, 대상 0건, 재열기와 복원, 원문 읽기 실패와 게시 실패를 검증하고 프런트 표시, 전체 회귀와 빌드를 확인한 뒤 인계한다.

## 구현 전 검토

- 편집 화면에서 받았던 판정이나 클라이언트가 보내는 판정을 재사용하면 오래된 결과가 게시될 수 있다. 내보내는 서버 입력으로 매번 다시 계산한다.
- 품질 식별값에 원문 내용의 식별값을 포함한다. 원문 변경 후 덱이 같아도 이전 결과와 구분한다.
- API 응답은 실제 게시한 기록을 돌려준다. 발표 파일과 기록의 버전 및 PPTX SHA-256이 같아야 한다.
- 수치 대조의 통과를 evidence 전체의 통과로 바꾸지 않는다. 미수행 항목의 대상과 실패 수는 0이며 실제 미연결 칸 수는 수치 상세에 남긴다.
- 파일 읽기 실패는 자료 없음으로 감추지 않는다. 기존 초안과 게시물을 보존하며 오류로 알린다.
- 화면은 결과를 '내보낸 초안'의 기록으로 표시한다. 이후 편집본의 현재 판정으로 표시하지 않는다.

이는 구현자의 사전 검토다. 독립 리뷰와 실제 보고서 품질 평가는 별도다. Q1b의 전체 검수 이력 탐색과 웹/CLI 프로세스 간 공통 잠금은 다음 단위로 남기며 이번 작업에서 동시 게시 안전성을 확장했다고 주장하지 않는다.
