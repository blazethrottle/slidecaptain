## 가정 (적대 리뷰가 검증한 것)

1. **원본과 추출본을 분리한다.** 원본 바이트는 `projects/<이름>/uploads/<파일명>.xlsx` 에 그대로 보존하고, AI 입력은 `sources/<파일명>.xlsx.md` 라는 UTF-8 텍스트다. 프롬프트 조립(`_load_sources`)은 `sources/` 만 읽으므로 원본은 AI 에 가지 않는다. 같은 이름을 다시 올리면 둘 다 덮어쓴다(기존 텍스트 업로드의 `overwrite` 규약과 같다). 설계서 3.1 의 종전 서술(`sources/<원본파일명>.txt`)은 이 규약으로 정정한다(문서 정정 절).
2. **추출은 openpyxl 일반 모드로 두 번 읽는다.** `data_only=False` 로 수식을, `data_only=True` 로 저장된 계산값을 얻는다. 읽기 전용 모드(`read_only=True`)는 쓰지 않는다: 실측(2026-09-04, openpyxl 3.1.5)에서 읽기 전용 워크시트에는 `merged_cells` 와 `dimensions` 속성이 없고 셀에 `hyperlink` 속성도 없어 병합과 링크를 추출할 수 없다(수식 판정 `data_type == "f"` 만 된다). 일반 모드 두 번 읽기는 셀 1만 개 0.06초, 10만 개 0.69초, 최대 메모리 약 130MB(셀 개수 기준) 이고, 텍스트가 많은 파일은 셀 수보다 압축 해제 크기 상한이 먼저 걸리며 그 경계(한국어 약 770만 자, 선언 크기 48.6MB)에서 두 번 로드의 최대 메모리는 약 100MB 다(적대 리뷰 실측). 저장된 계산값은 파일을 마지막으로 저장한 프로그램이 계산한 값이며 앱은 재계산하지 않는다. 캐시가 비어 있으면 "계산값 없음" 으로 표시한다(마스터 플랜 "틀렸을 가능성" 3항). 새 의존성 `openpyxl` 을 `backend/pyproject.toml` 에 추가한다. 이 Mac 의 작업공간은 main 클론의 가상환경을 빌려 쓰므로 그 가상환경에 `uv pip install --python <venv>/bin/python openpyxl` 로 따로 설치한다(설치 완료. CI 는 새로 설치하므로 무관).
3. **추출본 형식은 시트별 "값이 있는 셀만 행 단위로 나열"** 이다(1차 리뷰 critical 반영: 빈 셀까지 그리는 마크다운 표는 서식만 잡아 둔 넓은 빈 범위가 글자 수 상한을 잠식해 실제 데이터를 잘라냈다. 실측: 값 4개짜리 시트가 표 형식 91,831자 대 목록 형식 53자). 규칙:
   - 시트마다 `## 시트: <이름> (값 범위 A1:F120, 값 셀 348개)` 제목. 범위는 `ws.dimensions` 가 아니라 **값이 있는 셀만으로 다시 계산한 범위** 다(서식만 있는 셀은 제외). 시트 이름의 줄바꿈과 캐리지리턴은 공백으로 바꾼다.
   - 값이 있는 행마다 한 줄: `행 5: A=매출 | B=1234 | D=[자세히](https://…)`. 값이 없는 행과 셀은 쓰지 않는다(행 번호와 열 문자가 원본 위치를 가리키므로 빈 자리를 채울 필요가 없다).
   - 수식 셀은 `B==SUM(B2:B8) → 1234` 처럼 수식과 계산값을 함께(2026-09-04 정정: 종전 예시 `B9==` 는 열과 행을 함께 쓴 것처럼 읽혀 같은 절의 일반 규칙과 어긋났다. 토큰 키는 열 문자만 쓰고 행 번호는 행 접두사가 가리킨다. B1 리뷰), 계산값이 없으면 `→ (계산값 없음)`. 하이퍼링크 셀은 `[표시 텍스트](URL)`. 병합 범위는 시트 제목 아래 `병합: B2:D2, A7:C7` 한 줄로 적고 값은 왼쪽 위 셀에만 있다.
   - 값 표기: 문자열은 그대로(백슬래시를 `\\` 로 먼저, 파이프를 `\|` 로, 줄바꿈은 공백으로 바꾸고 그 건수를 `notes` 에 남긴다). 정수는 정수로, 실수는 openpyxl 이 준 그대로(`3.5`). `3.0` 처럼 정수와 같은 실수는 원본 XML 에 소수점이 있을 때만 float 로 오며(openpyxl 은 자기가 저장할 때 `3.0` 을 `<v>3</v>` 로 정규화한다. 2차 리뷰 실측), 그 경우 `3.0` 을 지우지 않는다. 실제 Excel 이 그런 값을 어떻게 저장하는지는 파일럿 원본으로 확인한다("틀렸을 가능성"). 날짜와 시각은 값 타입과 `number_format` 으로 구분한다: 값이 `datetime` 이고 서식에 `h`, `s`, `:` 가 없으면 날짜만 `2026-09-04`, 있으면 `2026-09-04T09:05:00`, 값이 `time` 이면 `09:05:00`(`mm:ss` 서식도 `time` 으로 온다. 실측), 값이 `timedelta`(경과시간 서식 `[h]:mm`, `[mm]:ss`)면 총 시간 기준 `30:05:00` 으로 쓴다(`cell.is_date` 는 셋 다 참이라 타입으로 가른다). 불리언은 `참`/`거짓`. 퍼센트 서식(`%` 포함)은 서식의 `0.00%` 자릿수(정규식 `0(\.0+)?%`)만큼 `0.153 (15.3%)` 로 병기한다. 통화는 서식 문자열에서 로케일 마커 `[$…-412]` 안의 기호를 꺼내고(`$` 자체는 마커 문법이므로 마커 밖의 `$` 만 통화로 본다) 따옴표 리터럴(`"원"`)과 대조해 `₩`, `$`, `€`, `£`, `¥`, `원`, `KRW`, `USD`, `EUR`, `GBP`, `JPY` 가 있으면 `1234 (₩)` 로 병기한다.
   - 숨김 시트(`sheet_state` 가 `hidden` 또는 `veryHidden`)는 **제외** 하고 파일 머리에 `숨김 시트 2개 제외: 내부검토, 구버전` 으로 이름만 적는다(작성자가 숨긴 내용을 사용자가 모르는 채 AI 에 보내지 않는다. 고지 취지와 일치).
   - 파일 머리에 `# XLSX 추출: <파일명>`, 추출 시각, 시트 수(보이는 시트), 적용된 한계와 `notes` 목록. 이 형식은 사람이 읽고 AI 가 "시트 매출 행 5 B열" 로 인용할 수 있게 하는 것이 목적이지 원본 재현이 아니다.
4. **상한 5종은 서버가 강제하고 추출본에 표시한다.** 로드 전 검사 2종: 압축 해제 총 크기 50MB(zip 항목의 선언 크기 합. 선언 크기를 거짓으로 줄인 항목은 `zipfile` 이 CRC 불일치로 `BadZipFile` 을 내므로 우회되지 않는다. 적대 리뷰 실측)와 **셀 요소 수 400,000개**(zip 안 `xl/worksheets/*.xml` 항목을 통째로 읽어 `<c ` 출현 수를 센다. 2026-09-04 정정: 종전 표기 "스트리밍" 은 구현과 달랐다. 총량이 50MB 상한 안이라 청크 경계에서 매치가 끊기는 문제를 피하는 전체 읽기를 택했다. 최종 리뷰 gd-2. 서식만 있고 값이 없는 셀 100만 개짜리 파일이 선언 크기 34MB 로 크기 상한을 통과한 채 로드에 4.5초와 1.16GB 를 쓴 실측에 대한 방어. 값 셀 상한은 로드 뒤에야 셀 수 있어 로드 비용을 막지 못한다). 둘 다 422 로 거절한다. 로드 후 검사 3종: 보이는 시트 30개, 값 셀 200,000개, 추출 글자 수 60,000자(자료 전체 상한 100,000자 안에 다른 자료가 들어갈 여지를 남긴다). 크기 상한 초과는 422 로 거절하고, 시트와 셀과 글자 수 상한은 초과분을 잘라내되 추출본 머리와 잘린 자리에 `(한계: 시트 31개 이후 생략)`, `(한계: 60,000자 초과분 생략. 시트 손익 행 412 부터)` 처럼 **어디서 잘렸는지** 남기고 응답에도 `truncated` 를 돌려준다. 값이 있는 셀만 쓰므로 잘림은 실제 데이터에서만 일어나며 그 위치가 표시된다. 글자 수는 행을 쓸 때마다 세고, **한 행이 남은 한도를 넘으면 그 행에서 완전한 `열=값` 쌍만 한도까지 남기고 생략한 열 문자를 `notes` 에 적는다**(파이프 중간에서 끊긴 조각이 열 참조로 오인되지 않게. 2차 리뷰). 업로드 본문 상한 5MB(기존)는 XLSX 에 대해 20MB 로 올린다.
5. **AI 전송 고지는 브라우저 탭 단위이고 서버가 헤더로 확인한다.** 화면은 `sessionStorage` 키(`slidecaptain.ai-consent`)로 동의를 기억한다(탭을 닫으면 사라지고 새로고침에는 남는다. 설계서 2.6 의 3항. 브라우저의 탭 복제는 `sessionStorage` 를 복사하므로 그 탭은 다시 묻지 않는다). 동의 전 첫 AI 호출은 공통 관문(클라이언트 모듈 `aiGate`)이 가로채 고지 화면을 띄우고, 확인하면 저장 뒤 호출을 이어가고 취소하면 호출 없이 "취소했습니다" 로 끝난다. 동의한 탭의 모든 AI 요청은 `X-AI-Consent: SlideCaptain` 헤더를 붙이고, 서버의 생성 3종 라우트는 이 헤더가 없으면 428 과 한국어 안내로 거절한다. 서버 검사는 **화면 코드가 헤더 부착 자체를 잊는 사고만 막고, 헤더를 하드코딩해 동의 절차를 우회하는 코드 버그까지는 막지 못한다**(안전망이지 인증이 아니다). 형식 재시도와 자동 축약은 같은 서버 호출 안에서 일어나므로(`GenerationService` 의 `_call_with_format_gate` 와 축약 재생성, 적대 리뷰 확인) 별도 확인 없이 최초 고지의 범위에 포함된다(설계서 2.6).
6. **고지 문구는 설계서 2.6 의 사실 1, 2, 3, 4, 6 을 옮긴다.** 5항(향후 지표 수집 시 사전 고지)은 아직 시행되지 않은 미래 약속이라 화면에서 뺀다. 문구 시안:
   > **AI 에게 자료를 보냅니다**
   > 구조안 생성, 장 생성과 다시 생성, 축약을 누르면 이 프로젝트의 입력 자료 원문(엑셀 추출본 포함), 보고 정보, 지시사항, 기존 초안이 AI 제공자 **<provider> (<model>)** 에게 전송됩니다. 형식 오류로 자동 재시도하거나 분량 초과로 자동 축약할 때도 같은 범위가 다시 전송됩니다.
   > 프로젝트 파일은 이 PC 의 프로젝트 폴더에만 저장되고, 이 앱은 문서 내용이나 사용 기록을 다른 분석 서버로 보내지 않습니다.
   > 제공자가 전송된 내용을 보관하거나 학습에 쓰는지는 이 앱이 단정하지 않습니다. 제공자의 정책을 확인해 주세요.
   > 이 확인은 지금 연 브라우저 탭에서만 유효하며, 탭을 닫고 다시 열면 다시 묻습니다.

## 이 계획이 틀렸을 가능성

- 행 단위 목록 형식은 열이 많은 시트의 표 구조를 AI 가 머리글 행과 대조해 이해해야 한다(표 형식보다 한 단계 간접적). 머리글이 3행에 있는 실무 표에서 머리글 행을 특별 표시하지 않으며, A열만 있는 세로 목록 1,000개는 행 접두사 반복 때문에 표 형식보다 76% 길다(2차 리뷰 실측). 파일럿에서 AI 가 열을 잘못 대응시키거나 글자 수가 부족한 관측이 나오면 밀도가 높은 시트의 표 형식과 머리글 행 감지(`머리글: 행 3`)를 도입한다.
- `3.0` 과 `3` 의 구분은 원본 XML 에 소수점이 있을 때만 가능하다. 실제 Excel 은 값을 IEEE 754 로 저장하고 소수 표시는 서식이 맡으므로 `3.0` 입력이 `<v>3</v>` 로 저장될 가능성이 높다(2차 리뷰 추정). 그 경우 정밀도 정보는 서식(`0.0`)에만 있으며, 필요해지면 서식의 소수 자릿수로 강제 포맷하는 규칙을 검토한다.
- 숨김 시트를 제외하면 보이는 시트의 수식이 숨김 시트를 참조할 때 계산값만 남고 근거는 사라진다. 사용자가 숨김 시트를 포함시키는 경로는 없다. 파일럿에서 필요가 나오면 업로드 옵션으로 연다.
- 글자 수 60,000자 상한이 실무 표(8개 시트)에 부족할 수 있다. 값 셀만 쓰므로 종전 예상보다 여유가 크지만, 자료 전체 상한(100,000자)과의 관계는 5B 파일럿에서 실측으로 조정한다. 상한 값은 `XlsxLimits` 한 곳에 있다.
- 같은 이름의 큰 XLSX 를 다시 올리면 덮어쓰기 확인 흐름(먼저 `overwrite=false`, 409 면 확인 뒤 재전송) 때문에 추출이 두 번 일어난다. 로컬 1인 앱이라 허용하고, 느리다는 관찰이 나오면 존재 여부만 먼저 묻는 경로를 둔다.
- `sessionStorage` 가 막힌 환경(일부 비공개 모드)에서는 새로고침마다 다시 묻는다. 탭 복제는 동의를 복사한다. 둘 다 설계서 2.6 의 3항과 완전히 같지는 않으며 파일럿에서 문제되면 저장 위치를 재검토한다.
- 서버의 428 검사는 curl 같은 외부 도구의 생성 호출을 막는다. 외부 도구로 생성을 돌릴 계획이 없고, 필요하면 헤더를 붙이면 된다.
- 계산값 캐시가 비어 있는 파일은 숫자가 전부 "(계산값 없음)" 이 되어 자료로 쓸모가 없다. 추출본 머리와 업로드 안내에 "엑셀에서 열어 다시 저장해 주세요" 를 적는다.
- 확장자만 xlsx 인 xlsb 위장 테스트 픽스처는 실제 Excel 이 만든 xlsb 바이트가 아니라 `[Content_Types].xml` 이 xlsb 콘텐츠 타입을 선언하도록 직접 구성한 zip 이다(이 Mac 에 Excel 이 없다). 예외 재매핑이 포괄 예외라 동작에는 문제가 없지만, 진짜 xlsb 파일이 확보되면 한 번 더 돌려 본다 (B1 구현자 미해결, 2026-09-04).
