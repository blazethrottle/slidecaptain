# Claude와 Codex LUNA 직접 선택

작성: 2026-09-28. 사용자는 Sonnet 최대 5회 실호출을 승인한 뒤 Codex LUNA도 사용할 수 있게 요청했고, 후속 질문에서 직접 선택 방식을 확정했다. Sonnet 관통은 2회로 완료했다. 남은 호출 예산을 새 제공자마다 다시 부여하지 않는다.

## 범위

- 기존 AI 연결 화면의 서비스/모델 선택과 저장 경로를 사용한다. `Claude Sonnet`, `Codex LUNA` 빠른 선택은 화면의 미저장 선택만 바꾸며 `선택 저장`으로 확정한다. 설치된 제공자 목록에 정확한 모델 ID가 있을 때만 활성화한다. 조회 실패/누락 시 사유를 표시하고 다른 모델로 대체하지 않는다.
- 저장된 서비스/모델을 초기값으로 유지한다. 생성 중 선택 잠금과 기존 전송 동의 무효화, 선택 ID의 409 보호를 유지한다. 실패 시 자동으로 다른 제공자를 호출하지 않는다.
- `quality_pilot.py`에 `--provider claude|codex`를 추가한다. 앱 내부 ID는 기존 `claude|chatgpt`를 유지한다. 선택한 제공자의 기본 모델은 각각 `sonnet`, `gpt-6-luna`이며 명시한 모델을 변경하지 않는다. Codex는 기존 공식 어댑터와 전용 프로필을 사용한다. 프로필 경로는 `--codex-home`으로 지정할 수 있고 기본값은 앱 기본 데이터 폴더의 `.slidecaptain-codex`다.
- 준비/오프라인 모드는 두 제공자 모두 인증 조회와 외부 호출을 하지 않는다. 실제 실행은 전송 동의, 공유 호출 상한, 현재 모델 목록과 로그인/선택 검사를 거친다. 요청한 제공자/모델과 실제 사용량을 기록하고 인증정보는 복사하지 않는다.
- 도메인 모델, OpenAPI와 저장 계약은 변경하지 않는다. 원본 295개 파일과 스테이징은 보존한 작업본에서 개발하고 이번 변경 경로만 반영한다. 커밋/푸시/머지는 하지 않는다.

## 검증

실패 테스트로 빠른 선택의 미저장 상태/명시 저장/기존 선택 복원/모델 누락/생성 중 잠금을 확인한다. 도구에서는 Codex 선택 전달, 양쪽 오프라인 무호출, 로그인/모델 불일치의 무호출 차단, 공통 예산과 프로필 정리, 잘못된 제공자/모델 거절을 검사한다. 기존 연결/도구/프런트 회귀와 타입/빌드, OpenAPI 무변경을 확인한다. 계획과 구현을 독립 검토하고 실제 브라우저에서 선택 흐름을 확인한다.

실제 Codex `model/list`에서 `gpt-6-luna`를 확인했다. 계획 당시 앱 전용 프로필은 로그인되지 않았고, 이후 사용자가 공식 로그인과 본인 인증을 완료했다. 공식 모델 문서와 app-server 문서도 대조했다. 실제 LUNA 생성, SDK 비용과 실청구액, PowerPoint 표시와 독자 품질은 각각 검증 근거가 있을 때만 완료로 기록한다.

독립 계획 리뷰에서 필수 수정은 0건이었다. 제안에 따라 이후 실제 검증은 남은 예산 3회 이하를 명시하고, 실패 경로에서도 공식 연결 프로세스를 종료한다. 실행 도구의 상한은 실행별이며, 세션 누적 상한은 이미 완료한 실행 기록과 함께 대조한다.

공식 근거: https://developers.openai.com/api/docs/models/gpt-6-luna , https://learn.chatgpt.com/docs/app-server

## 실제 관통에서 추가된 수정 범위

2026-09-28 Chrome의 1920px 창에서 기존 미리보기를 1.42083배 확대하면 화면은 767.25px 높이인데 바깥 틀은 540px에 고정돼 있었다. `overflow:hidden`으로 하단 결론/각주가 잘렸으며, 실제 각주의 상단 945.72px가 틀의 하단 800.88px 밖에 있었다. `Preview`의 바깥 높이를 확대 비율에 맞춘다. 보고서 좌표/폰트/PPTX는 바꾸지 않는다. 수정 전 브라우저 포함 검사 실패를 기록하고 수정 후 같은 검사와 세 장 화면을 확인한다.

LUNA 실제 실행은 장 생성 1회와 재작성 2회를 사용했다. 첫 후보는 보호 근거의 `value:null`을 원문 문자열로 바꿨고, 재시도 후보는 값을 복원했으나 보호 도식의 `claim_ids`를 확장해 거절됐다. 기존 보존 검사를 유지하고 생성 본문을 보관한다. 총 5회 상한을 모두 사용했으므로 실제 재시도를 추가하지 않는다. 선택 기능/장 생성 성공과 편집 보존 재작성 미완료를 구분한다.

추가 수정의 독립 계획/구현 리뷰는 필수 수정 0건이었다. 확대된 세 장과 축소된 작성창의 포함성 4개를 확인했고 프런트 전체 410개/38파일, TypeScript/Vite를 다시 통과했다. 창 크기 재설정 도구가 실제 크기를 바꾸지 못해 480px와 창 resize는 이번 검증으로 세지 않는다. 최종 상태와 재개 조건은 [인계](../handoffs/2026-09-28-manual-ai-selection-handoff.md)를 따른다.
