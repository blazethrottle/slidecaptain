# Q1b 두 번째 단위: 웹과 CLI의 내보내기 게시 잠금

작성: 2026-09-13. 개발 재개 요청을 Q1b 첫 단위 인계의 다음 작업으로 수행한다.

## 범위와 잠금 순서

웹과 CLI가 같은 출력 폴더에 내보내더라도 각 요청의 PPTX와 품질 기록이 서로 다른 버전을 사용해야 한다. 기존 덱, 원문, 스냅샷, 사용량과 내보낸 파일을 보존한다. 저장 계약과 응답 구조는 유지한다.

1. 기존 웹 프로젝트 잠금 안에서 덱과 원문을 읽는다. CLI는 읽은 입력을 사용한다. 편집 저장 전체의 프로세스 간 트랜잭션은 이번 범위가 아니다.
2. 품질 관문을 검사한 뒤 출력 폴더 안의 고유 임시 디렉터리에 두 파일을 완성한다. 같은 파일 시스템에서 게시해 다른 디스크로의 복사 중간 파일을 노출하지 않는다.
3. 공통 exporter가 출력 폴더의 `.slidecaptain-export.lock`을 OS 파일 잠금으로 잡는다. 잠금 순서는 웹 프로젝트 잠금 다음 출력 폴더 잠금이며, 역순으로 프로젝트 잠금을 잡는 경로를 만들지 않는다. 다른 출력 폴더는 독립적으로 진행한다.
4. 잠금 안에서 PPTX와 품질 기록 양쪽의 최대 버전 뒤를 선택하고, 품질 기록 다음 PPTX를 게시한다. 완성한 임시 파일의 hard link를 생성하므로 이미 존재하는 목적지는 교체하지 않는다. 두 경로의 동시 생성은 원자적이지 않다.
5. 성공과 예외에 잠금을 해제하고 파일 핸들을 닫는다. 잠금 파일은 삭제하지 않는다. 프로세스 강제 종료도 OS 잠금이 해제되며 오래된 PID를 근거로 파일을 지우지 않는다. 게시 임계 구간의 대기는 최대 5초이고, 초과하면 웹은 409와 재시도 안내, CLI는 실패 종료 코드 1을 돌려준다.

## 실패 조건과 검증

- 두 별도 프로세스의 웹 API/CLI를 버전 선택 구간에서 겹치게 한다. 두 응답, 게시된 실제 PPTX, 품질 JSON, 입력 fingerprint와 PPTX SHA-256을 대조한다. 동일 프로세스의 직접 exporter 호출도 검사한다.
- 첫 파일 게시 실패는 새 결과를 남기지 않는다. 두 번째 게시 실패는 품질 기록만 남기고 그 버전을 재사용하지 않는다. 기존 파일은 바이트가 같아야 한다.
- 잠금 보유 프로세스를 버전 선택 직후 또는 품질 기록 게시 직후 종료하고 다음 프로세스의 성공과 버전 보존을 확인한다. 강제 종료가 남긴 숨김 임시 폴더는 다른 프로세스의 작업일 수 있으므로 자동 삭제하지 않는다.
- 목적지에 파일이 끼어드는 상황, 높은 번호의 고아 기록, 이름이 비슷한 다른 제목과 한글/공백 경로를 검사한다. 출력 폴더 별칭도 동일한 잠금을 사용해야 한다.
- 잠금 오류와 지원하지 않는 파일 시스템은 성공으로 처리하지 않는다. 파일 열기/잠금의 시스템 오류는 대기 시간 초과와 구분한다. 웹 파일 게시 실패는 422와 재시도 안내이며 기존 문자열 detail 계약을 유지한다.
- 기존 품질 관문, 최종 제출 차단, 저장 보존과 API 계약을 회귀 검사한다. 자동 검사는 실제 AI/PowerPoint/독자 평가를 대신하지 않는다.

## 구현 전 검토와 경계

파일 존재만으로 잠그는 방식은 강제 종료 뒤 영구 대기를 만들고, 해제 시 파일 삭제는 서로 다른 inode를 잠그는 경합을 만든다. 열린 파일에 OS 잠금을 사용하고 파일을 계속 보존한다. 출력 경로를 받는 공통 함수에 두어 CLI의 사용자 지정 출력 폴더도 포함한다.

macOS/POSIX는 `flock`, Windows는 파일 시작 위치의 1바이트 `msvcrt.locking`을 사용한다. Windows는 EOF 이후 범위도 잠글 수 있어 잠금 파일에 내용을 쓰지 않는다. 근거는 [Python fcntl](https://docs.python.org/3.13/library/fcntl.html), [Python msvcrt](https://docs.python.org/3.13/library/msvcrt.html), [Microsoft locking](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/locking?view=msvc-170)이다. 게시에는 [os.link](https://docs.python.org/3.13/library/os.html#os.link)를 사용한다. [Windows hard link 지원](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createhardlinkw)에 따라 NTFS 등 지원 파일 시스템이 필요하며, 미지원 환경에서 덮어쓰는 복사로 우회하지 않는다.

이는 구현자의 사전 검토다. 독립 에이전트 리뷰는 수행하지 않았다. 네트워크 드라이브/동기화 서비스/외부 프로그램이 잠금 파일이나 폴더를 교체하는 상황, 전원 차단 내구성, 오래된 앱 버전과 동시 실행은 보장 범위가 아니다. 전체 검수 이력 목록과 현재 입력 대비 과거 기록 유효성 표시는 다음 단위다.
