# 대표 합성 보고서 관통 실행 도구

작성: 2026-09-28. 최신 보고 계획 재작성 인계의 다음 행동인 실제 제공자 관통 검증을 준비한다. 사용자 요청은 SlideCaptain 개발 재개다. 현재 승인 범위에서 실행 도구와 로컬 검증을 완성하고, 실제 호출은 입력/모델/상한을 보여준 뒤 별도 동의를 받아 실행한다.

## 범위와 완료 조건

- 기존 합성 도식 픽스처에서 표지/도식/개선 검토의 3장 보고서를 준비한다. 실제 회사 자료나 사용자 프로젝트를 읽지 않는다. 도식은 직접 작성된 입력이며 AI 도식 생성 성공으로 세지 않는다.
- `backend/scripts/quality_pilot.py`의 기본 동작은 입력 준비만 수행한다. `--offline`은 고정 응답으로 같은 앱 API를 실행한다. `--live --consent --max-calls N`은 지정한 Claude 모델로 실행한다. 첫 단위의 제공자는 Claude로 한정한다.
- 일반 장 하나 생성/명시적 저장 → 편집 보존 계획 재작성 미리보기/적용 → 렌더 계획/초안 PPTX/품질 기록 재열기를 순서대로 실행한다. 신규 전체 구조안 생성은 이번 시나리오에 없다.
- 호출 상한은 프로바이더의 `complete` 직전에 차감하며 실패, 형식 재시도, 자동 축약을 모두 센다. 기본 승인 제안은 최대 5회다(장 생성 최대 3회 + 재작성 최대 2회). SDK 내부 턴/실제 요청 수와는 다른 수치임을 명시한다. 중단 시 이미 저장한 초안과 사용량/실행 기록을 보존한다.
- 요청 표식/AI 동의/선택 식별값과 ETag를 기존 앱 경로로 전달한다. 재작성 적용 전후의 본문/도식 보존과 후보 무저장을 확인한다. 같은 실행 폴더 재사용은 거절한다.
- 앱의 `CallUsage`를 변경 없이 보존하고 없는 사용량 객체는 null로 둔다. 실제 모델과 요청 모델을 구분한다. 원시 SDK 값과 앱 정규화 값의 동일성은 별도 검사이며, 이번 도구가 보증하지 않는다. 실행 완료와 의미/시각/PowerPoint/독자 품질은 별도 상태로 기록한다.
- 실제 전송 입력, 덱, 단계별 결과, 렌더 계획, 사용량과 해시를 신규 로컬 출력 폴더에 남긴다. 인증정보와 계정명은 저장하지 않는다.

## 검증

먼저 실패 테스트로 기본 무호출, 실호출 동의/상한 누락 거절, 재시도/축약을 포함한 상한 준수, 공급자 실패 시 기록/초안 보존, 기존 출력 보호를 확인한다. 오프라인 관통에서는 실제 앱 API, 3장 PPTX/품질 sidecar 해시와 도식 편집 요소, 제출본 차단을 확인한다. 독립 계획 리뷰와 구현 리뷰를 수행하고 관련 회귀/전체 백엔드 검사와 공개 저장소 감사를 실행한다. 제품 프런트 계약을 변경하지 않으면 프런트 전체 검사는 반복하지 않는다.

## 한계와 재심 전제

- Claude 로그인 상태 확인은 생성 성공의 증거가 아니다. 현재 공식 CLI 상태는 구독 로그인으로 확인했다.
- PowerPoint가 이 Mac에 없으므로 python-pptx 재열기는 목표 앱 표시를 입증하지 않는다.
- 고정 응답 통과는 실제 AI의 구조화 응답 수용성이나 의미 품질을 입증하지 않는다. 실제 호출 승인이 없으면 대기 상태로 정확히 남긴다.
- 원본 286개 파일과 스테이징을 보존한 별도 작업본에서 개발하며, 검증 뒤 이번 경로만 원본에 반영한다. 커밋/푸시/머지는 하지 않는다.

## 독립 계획 리뷰 반영 (2026-09-28)

리뷰에서 지적한 선택 관문 우회를 막기 위해 모의/실제 모두 `AIConnections`를 사용한다. 자동 축약에서 `ProviderError`를 처리해 기존 초안을 반환하더라도 전송 전 차단이 있으면 실행 전체는 중단으로 기록하고 본문만 보존한다. 시도한 호출과 전송 전 거절은 서로 다른 수치로 기록한다. 현 `build_call_usage`는 일부 SDK 필드 누락을 0으로 정규화하므로, 도구가 원시 SDK 값 보존을 주장하지 않도록 범위를 바로잡았다. 이 기존 회계 경계는 로드맵 이월에 남긴다.

## 구현과 로컬 검증 결과

신규 회귀 22개와 최종 전체 백엔드 1,562개 통과/Windows 전용 1개 미실행, 별도 독립 반례 6개를 확인했다. 구현 리뷰에서 호출별 prompt/schema 보존 누락을 수정한 뒤 필수 잔여 0건으로 판정받았다. 오프라인 3장 API/PPTX 관통을 완료했으며 실제 호출은 승인 대기다. 상세 결과와 실행 방법은 [인계](../handoffs/2026-09-28-quality-pilot-handoff.md)를 따른다.
