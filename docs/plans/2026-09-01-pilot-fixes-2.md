# 파일럿 소형 개선 묶음 2 계획서 (2026-09-01)

> 실전 파일럿 관찰 6, 7(2026-09-01, 사용자 지시)의 구현 계획이다. 묶음 1([2026-09-01-pilot-fixes-bundle.md](2026-09-01-pilot-fixes-bundle.md)) 위에서 분기한 브랜치 `feature/pilot-fixes-2`에서 진행한다.
> 관찰 6: 표지에 피보고자 이름이 들어가는 것은 부적절하다. 표지에는 보고하는 사람 또는 부서가 들어가고, 피보고자 이름은 문서에 적지 않는 것이 기본값이어야 한다.
> 관찰 7: 편집 탭에서 장 주제와 템플릿이 한 줄로 이어져 있어 혼동된다. 각 입력 항목이 독립된 항목임을 직관적으로 알 수 있게 나누고, 다른 탭의 같은 패턴도 모두 고친다.

## 태스크 A: 표지에 보고자, 피보고자는 문서에 미표기

현재 구조: 표지 슬롯 `CoverSlots(title, subtitle, date, audience)`를 AI가 채우고, 프롬프트의 "피보고자: ..." 줄을 보고 `audience`에 그대로 적는다(`templates.py`가 표지 하단 y=452에 렌더). 메타의 `audience`(피보고자)는 구조안과 장별 프롬프트에 문체와 상세 수준의 기준으로도 쓰인다.

변경:
- 데이터 모델: `CoverSlots.audience`를 없애고 `presenter: str = ""`(보고자: 이름 또는 부서)를 둔다. `DeckMeta`에 `presenter: str = ""`를 추가하고 `audience`는 유지한다(프롬프트 전용). 덱 모델은 여분 필드를 무시하므로 기존 deck.json의 표지 `audience` 값은 읽을 때 버려지고 스키마 버전은 올리지 않는다(기본값이 있는 필드 추가와 제거만 있다).
- 표지 렌더: 프레임 이름 `{장ID}:audience` → `{장ID}:presenter`, 위치와 서체는 그대로.
- 보고자 값의 진본은 메타다("AI는 내용만, 배치는 코드가": 보고자는 내용이 아니라 문서 메타). 장별 생성과 축약이 끝난 표지 슬롯의 `presenter`는 서비스가 `deck.meta.presenter`로 덮어쓴다(AI가 무엇을 적었든). 사용자가 편집 화면에서 표지의 보고자 글을 직접 고치면 그 값이 저장되고, 표지를 다시 생성하면 메타 값으로 돌아간다.
- 프롬프트: 보고 정보 블록에 "보고자(표지 표기): ..." 줄을 추가하고, 구조안과 장별 프롬프트 공통 규칙에 "피보고자는 문체와 상세 수준을 맞추는 기준으로만 쓰고, 표지와 본문 어디에도 피보고자의 이름이나 직함을 적지 않는다"를 넣는다. 수치 대조 면제 필드는 `{"date", "presenter"}`.
- 화면: 자료 탭 보고 정보에 "보고자 (이름 또는 부서, 표지에 표기)" 입력을 추가하고, 피보고자 입력에는 "(문서에 적히지 않고 문체와 상세 수준을 맞추는 데만 씁니다)" 안내를 붙인다. 편집기의 표지 인라인 편집은 슬롯 이름 `presenter`를 다룬다(`slotOps.ts`, `templateSwitch.ts`).
- 기존 덱의 표지: 이미 생성된 표지 슬롯에는 보고자가 비어 있게 된다. 보고 정보에서 보고자를 넣은 뒤 표지 장을 다시 생성하거나 편집기에서 직접 적는다(자동 갱신은 하지 않는다: 편집 중인 표지를 메타 저장이 몰래 바꾸지 않기 위해서다).

테스트: `test_layout_engine`(presenter 프레임), `test_generation_service`(표지 결과의 presenter가 메타 값으로 덮어써짐, AI가 다른 값을 적어도 동일 / date와 presenter는 수치 대조 면제), `test_prompts`(보고자 줄과 미표기 규칙이 두 프롬프트에 있고 피보고자 줄도 유지), `test_deck_schema`(표지 슬롯에 옛 `audience` 키가 있는 deck.json을 읽어도 오류 없이 presenter가 빈 값). 프런트: `slotOps.test`(presenter 인라인 편집), `SourcesScreen.test`(보고자 입력이 `meta.presenter`로 저장), 표지 픽스처 갱신, 타입 재생성.

문서: 설계서 3절 메타 항목에 날짜를 단 정정(보고자 추가, 피보고자 미표기 원칙, 표지 슬롯 이름 변경), 로드맵 이월표에 관찰 6 등재와 처리 완료.

## 태스크 B: 입력 항목을 각각 한 줄로 (전 탭)

현재: 라벨과 입력이 인라인으로 흘러 한 줄에 여러 항목이 이어진다. 묶음 1에서 구조안 화면에만 `.field` 세로 배치를 넣었다.

변경:
- `styles.css`의 `.structure-screen .field`, `.actions` 규칙을 전역 `.field`, `.actions`로 승격한다(구조안 화면은 그대로 적용됨).
- 적용 지점: 자료 탭 보고 정보(제목, 유형, 보고자, 피보고자 각각 `.field`, 저장 버튼은 `.actions`) / 자료 탭 "새 자료 이름"(라벨 있는 `.field` 안에 입력과 버튼) / 목록 화면 새 프로젝트(이름, 제목 `.field`, 만들기 `.actions`) / 편집 탭 속성 패널(장 주제, 템플릿 `.field`) / 편집 탭 장 목록(주제 줄 아래에 "템플릿: 표지"를 별도 줄로) / 생성 패널(지시사항 `.field`, 버튼 `.actions`) / 디자인 패널(각 값 `.field`).
- 손대지 않는 곳: 구조안 장 구성 표(표 머리글이 있어 이미 구분됨), 복구 화면 목록(항목당 시각 + 버튼 1개).

테스트: `ProjectList.test`(이름과 제목 입력의 `.field` 조상이 다름), `SourcesScreen.test`(제목, 유형, 보고자, 피보고자 네 입력의 `.field` 조상이 서로 다름), `PropertyPanel.test`(장 주제와 템플릿), `ChapterList.test`("템플릿: 표지"가 별도 요소로 표시). 기존 테스트는 `aria-label` 기반이라 유지된다.

## 실행 순서

태스크 B(화면, 설계 판단 없음) → 태스크 A(모델과 프롬프트) → 타입 재생성 → 커밋별 독립 리뷰 → 브랜치 최종 리뷰 → 관통(8766 임시 서버: 보고자가 표지에 나오고 피보고자가 나오지 않는지 실호출 1회로 확인) → 화면 빌드.

## 이 계획이 틀렸을 가능성

- 프롬프트 규칙만으로는 AI가 본문에 피보고자를 언급하는 것을 100% 막지 못한다. 표지는 서비스가 덮어써 확실히 막지만, 본문 언급은 관찰 대상으로 남긴다(파일럿 관찰지 기록 3).
- "보고자"가 메타에만 있고 표지 자동 갱신이 없어서, 보고자를 나중에 입력한 사용자는 표지를 다시 생성해야 한다. 자료 탭 안내 문구로 알린다.
