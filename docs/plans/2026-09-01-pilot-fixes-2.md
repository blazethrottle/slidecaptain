## 태스크 A: 표지에 보고자, 피보고자는 문서에 미표기

현재 구조: 표지 슬롯 `CoverSlots(title, subtitle, date, audience)`를 AI가 채우고, 프롬프트의 "피보고자: ..." 줄을 보고 `audience`에 그대로 적는다(`templates.py`가 표지 하단 y=452에 렌더). 메타의 `audience`(피보고자)는 구조안과 장별 프롬프트에 문체와 상세 수준의 기준으로도 쓰인다.

변경(메타에서 직접 렌더):
- 데이터 모델: `CoverSlots.audience`를 제거한다(대체 필드 없음). `DeckMeta`에 `presenter: str = ""`(보고자: 이름 또는 부서)를 추가하고 `audience`는 유지한다(프롬프트 전용). 덱 모델은 여분 필드를 무시하므로 기존 deck.json과 스냅샷의 표지 `audience` 값은 읽을 때 버려진다. 스키마 버전은 올리지 않는다(기본값이 있는 필드 추가와 무시되는 필드 제거뿐이고, 로더가 정확히 일치하는 버전만 허용하므로 올리면 파일럿 덱 전부가 읽히지 않는다. 설계서 3.2에 이 판정 기준을 날짜와 함께 명시).
- 표지 렌더: `build_slide(..., presenter: str = "")`에 메타의 보고자를 넘겨 프레임 `{장ID}:presenter`(종전 audience 자리, 서체와 위치 동일)에 그린다. 장 제목을 구조안의 `topic`에서 그리는 기존 방식과 같다. 따라서 보고 정보에서 보고자를 고치면 표지가 바로 바뀌고, 표지 재생성이 필요 없다.
- 편집기: 표지의 보고자 칸을 인라인 편집하면 `deck.meta.presenter`를 고친다(장 제목 인라인 편집이 구조안을 고치는 것과 같은 분기, `slotOps.ts`). 템플릿 전환의 표지 기본 슬롯에서 audience를 뺀다.
- AI: 표지 응답 스키마에서 보고자와 피보고자 칸이 사라지므로 AI는 채울 수 없다. 프롬프트에 보고자를 주지 않는다(줄 자체를 넣지 않아 topic이나 conclusion에 새어들 경로를 만들지 않는다). 문체 규칙에 "피보고자는 문체와 상세 수준을 맞추는 기준으로만 쓴다. 보고 정보의 피보고자 항목 값을 표지, 제목, 호칭, 인사말에 옮겨 적지 않는다. 요청사항은 '승인 요청'처럼 대상을 호칭하지 않고 쓴다"를 넣고, 템플릿 안내의 "표지 (제목, 부제, 날짜, 보고 대상)"를 "(제목, 부제, 날짜). 보고자는 보고 정보에서 자동으로 채워진다"로 고친다. 수치 대조 면제 필드는 `{"date"}`.
- 화면: 자료 탭 보고 정보에 "보고자 (이름 또는 부서. 표지에 표기됩니다)" 입력을 추가하고, 피보고자 입력에 "(문서에 적히지 않고 문체와 상세 수준을 맞추는 데만 씁니다)" 안내를 붙인다.
- 견본 `backend/samples/sample_deck.json`: 표지 슬롯의 audience 키를 제거하고 메타에 보고자를 넣는다(회귀 export 견본의 표지 넷째 줄이 비지 않게).
- "디폴트"의 예외: 피보고자를 굳이 표기하고 싶은 경우의 토글은 두지 않는다. 표지 텍스트 직접 편집으로 대체한다.

테스트: `test_layout_engine`(메타의 보고자가 `:presenter` 프레임에 그려지고 `:audience` 프레임이 없으며 피보고자 문자열이 표지에 없음), `test_generation_service`(AI 응답에 audience나 presenter 키가 있어도 표지 슬롯은 제목, 부제, 날짜만 가짐 / date는 수치 대조 면제), `test_prompts`(두 프롬프트에 피보고자 줄은 있고 미표기 규칙이 있으며 보고자 값과 "보고 대상" 문구는 없음), `test_deck_schema`(옛 audience 키가 든 deck.json 로드 시 무시, 메타 presenter 기본 빈 값). 프런트: `slotOps.test`(presenter 인라인 편집이 메타를 고치고 슬롯은 불변), `templateSwitch.test`(표지 전환 결과에 제목, 부제, 날짜만), `SourcesScreen.test`(보고자 입력이 `meta.presenter`로 저장, 피보고자 안내 표시, 네 입력의 세로 배치).

실행 순서(리뷰 발견 3): 모델 변경 → `scripts/dump_openapi.py` → `npm run generate-types` → 생성 타입이 기본값 필드도 필수로 만들므로 메타 픽스처 전부(12곳)에 `presenter: ""` 추가와 표지 슬롯 픽스처 3곳에서 audience 제거 → `tsc --noEmit`.

문서: 설계서 3.2(스키마 버전 판정 기준), 3절 메타 항목, 3.4 템플릿 표의 표지 행, 4.2 수치 대조의 "보고 대상" 문구에 날짜를 단 정정. 로드맵 이월표에 관찰 6, 7 등재(처리 완료)와 "빈 텍스트 슬롯(각주, 표지 date/audience)" 행의 정정.

## 태스크 B: 입력 항목을 각각 한 줄로 (전 탭)

현재: 라벨과 입력이 인라인으로 흘러 한 줄에 여러 항목이 이어진다. 묶음 1에서 구조안 화면에만 `.field` 세로 배치를 넣었다.

변경:
- `styles.css`의 `.structure-screen .field`, `.actions` 규칙을 전역 `.field`, `.actions`로 승격한다(구조안 화면은 그대로 적용됨). 입력은 폭 100%(숫자와 색 입력 제외), 버튼은 `.actions` 행.
- 적용 지점: 자료 탭 보고 정보(제목, 유형, 보고자, 피보고자 각각 `.field`, 저장 버튼은 `.actions`) / 자료 탭 "새 자료 이름"(라벨 있는 `.field`와 `.actions`) / 자료 탭 선택 자료의 내용 편집(`textarea`를 `.field`, 저장 버튼 `.actions`. 태스크 B 리뷰 발견) / 목록 화면 새 프로젝트(이름, 제목 `.field`, 만들기 `.actions`) / 편집 탭 속성 패널(장 주제, 템플릿 `.field`) / 편집 탭 장 목록(주제 줄에 상태 배지, 그 아래 "템플릿: 표지" 별도 줄) / 생성 패널(지시사항 `.field`, 버튼 `.actions`) / 디자인 패널(각 값 `.field`. 접힘 기본이라 세로 적층으로 충분).
- 손대지 않는 곳: 구조안 장 구성 표(표 머리글이 있어 이미 구분됨), 복구 화면 목록(항목당 시각 + 버튼 1개), 미리보기 인라인 편집기.

테스트: `ProjectList.test`(이름과 제목 입력의 `.field` 조상이 다름), `SourcesScreen.test`(보고 정보 입력들의 `.field` 조상이 서로 다름, 자료 내용 영역도 `.field`와 `.actions`), `PropertyPanel.test`(장 주제와 템플릿), `ChapterList.test`("템플릿: ..."이 별도 요소, 상태 배지는 주제 줄, 접근성 이름에 공백), `GeneratePanel.test`(`.field`와 `.actions`). 기존 테스트는 `aria-label` 기반이라 유지된다.

태스크 B(화면, 설계 판단 없음) → 태스크 A(모델과 프롬프트) → 타입 재생성 → 커밋별 독립 리뷰 → 브랜치 최종 리뷰 → 관통(8766 임시 서버: 보고자가 표지에 나오고 피보고자가 나오지 않는지 실호출 1회로 확인) → 화면 빌드.

## 이 계획이 틀렸을 가능성

- 프롬프트 규칙만으로는 AI가 본문에 피보고자를 언급하는 것을 100% 막지 못한다. 표지는 슬롯 자체가 없어 확실히 막히지만, 본문 언급은 관찰 대상으로 남긴다(파일럿 관찰지 기록 3).
- 빈 보고자(미입력)면 표지 넷째 줄이 빈 채로 나간다. 자료 탭의 보고자 입력 안내가 유일한 유도 장치다.
