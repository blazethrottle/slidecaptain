# 벤치마크 대비 디자인 격차 분석과 재설계 계획 (2026-09-07)

> 단계 5B 파일럿 2건을 윈도우 PC에서 진행한 사용자가 공통되고 치명적인 문제를 보고했다: **결과물에 표와 불릿 외에 디자인 요소가 거의 없다.** 플로우차트와 도식을 지시했는데도 반영되지 않았다.
> 사용자가 벤치마크 5건(사람이 만든 보고 덱)을 제시했다. 이 문서는 그 벤치마크를 기계적으로 분석해 격차를 수치로 확정하고, 원인을 규명하고, 재설계 범위를 정한다.
> **회사 자료 취급**: 벤치마크 원본은 로컬(`~/.claude/uploads/`)에만 두고 저장소에 넣지 않는다. `.gitignore`가 오피스 파일과 PDF를 위치와 무관하게 막는다. 이 문서에는 **추상화한 디자인 패턴과 수치만** 옮기고 회사 이름, 제품명, 사업 내용은 옮기지 않는다.

## 1. 격차 (실측)

같은 화면 규격(960 x 540pt)과 같은 폰트(Noto Sans KR)를 쓰는데도 밀도가 다르다.

| 항목 | 파일럿 산출물 | 벤치마크 | 배수 |
|---|---|---|---|
| 슬라이드당 도형 수 | 2 ~ 5 | 3 ~ 38 (평균 18) | 약 4배 |
| 도형 종류 | 텍스트 상자, 사각형, 표 | 사각형 263, 둥근 사각형 60, 선 9, 그림 2, 표 4 | |
| 채움색 종류 | **1종** (`EEF3F9`) | **12종 이상** | 12배 |
| 글자 크기 단계 | 4단계 (9, 12, 20, 24) | 7단계 이상 (8, 9, 10, 11, 12, 13, 14, 16, 20, 21, 22, 23) | |
| 도식 요소 | 없음 | 번호 배지, 카드, 알약 라벨, 프로세스 행, 연결선, 좌우 매트릭스 | |

**핵심 수치 하나**: 파일럿 18장짜리 덱 전체의 채움색이 **한 종류**다. 벤치마크는 한 장 안에서 색으로 상태와 우선순위와 분류를 구분한다.

## 2. 원인 (지시가 무시된 것이 아니다)

사용자는 "분명히 지시했는데 구현이 안 됐다"고 보고했다. 코드를 확인한 결과 **AI가 지시를 무시한 것이 아니라 지시를 표현할 자리가 없다.**

현재 덱 스키마의 템플릿은 여섯 개뿐이다.

```
TemplateName = Literal["cover", "summary", "bullet_box", "table", "compare2", "divider"]
```

즉 표지, 요약, 불릿 상자, 표, 2단 비교, 간지가 전부다. **플로우차트, 프로세스, 카드 묶음, 번호 단계, 강조 밴드를 담을 슬롯 자료형이 없다.** 생성 파이프라인은 이 스키마로 구조화 출력을 강제하므로, AI가 도식을 만들려 해도 스키마에 맞지 않아 버려지거나 불릿으로 눌린다.

**따라서 프롬프트를 고쳐서는 해결되지 않는다.** 자료형과 레이아웃 엔진과 PPTX 라이터를 함께 늘려야 한다.

## 3. 벤치마크의 디자인 언어 (추상화)

### 3.1 색 역할

| 역할 | 값 | 쓰임 |
|---|---|---|
| 기본 잉크 | `1B2A3A`, `24384A`, `27405A` | 제목, 어두운 카드 바탕 |
| 강조 1 | `0E8C7F` (청록) | 아이브로우, 1순위 배지, 긍정 지표 |
| 강조 2 | `C8860B` (호박) | 2순위 배지, 주의, 일정 강조 |
| 위험 | `C0473B` | 경고 |
| 긍정 | `2E9E5B` | 달성 |
| 바탕 1 | `EAF2F1` (연청록) | 강조 밴드, 카드 안쪽 |
| 바탕 2 | `F4F6F7` (연회색) | 중립 밴드, 알약 |
| 바탕 3 | `FBF3E6` (크림) | 강조 2 계열 바탕 |

**규칙**: 강조색은 같은 슬라이드 안에서 **순서나 분류를 뜻한다.** 장식이 아니다. 세 카드가 청록, 남색, 호박이면 그것이 우선순위나 트랙 구분이다.

### 3.2 타이포 계층

| 단계 | 크기 | 쓰임 |
|---|---|---|
| 아이브로우 | 10 ~ 11pt, 강조색, 굵게 | 제목 위 한 줄 분류 라벨 |
| 제목 | 20 ~ 23pt, 굵게 | 슬라이드 제목. 괄호 부제는 같은 줄에 작게 |
| 부제 | 13 ~ 14pt, 연한 잉크 | 제목 아래 한 문장 |
| 본문 | 12 ~ 13pt | 카드와 표 안 |
| 캡션 | 8 ~ 9pt | 각주, 출처, 푸터 |

### 3.3 되풀이되는 배치 원형 8종

관측한 슬라이드 36장에서 추출했다. 왼쪽 여백은 예외 없이 **50pt**이고, 전폭 요소는 **857 ~ 860pt**다.

| # | 원형 | 구조 | 관측 빈도 |
|---|---|---|---|
| 1 | **아이브로우 + 제목 + 부제** | y30 전폭 라벨, y54 전폭 제목, 그 아래 한 문장 | 거의 모든 슬라이드 |
| 2 | **강조 밴드** | 전폭 둥근 사각형(연회색), 안에 한 문장. 핵심구는 굵게와 밑줄 | 슬라이드 절반 |
| 3 | **카드 3열** | 폭 245 ~ 275pt 카드 3개. 테두리 또는 어두운 채움. 알약 배지 + 제목 + 본문 + 색 라벨 꼬리 | 6회 |
| 4 | **카드 2열 2행** | 폭 약 600pt 카드 4개. 번호 원형 배지 + 제목 + 인용 한 줄 + 오른쪽 쪽수 | 2회 |
| 5 | **번호 프로세스 행** | 전폭 행 5 ~ 6개. 왼쪽 번호 원형(색은 단계), 제목 + 부제, 오른쪽 회색 알약(소요) + 색 알약(시점) | 3회 |
| 6 | **좌우 매트릭스** | 왼쪽 분류 셀(파스텔 채움) + 가운데 대표 항목(점 표식 + 굵은 제목) + 오른쪽 나열 | 2회 |
| 7 | **표 강조 머리** | 표 머리 행을 분류색으로 채우고 본문 행은 파스텔 교차 | 5회 |
| 8 | **각주 줄과 푸터** | 하단 왼쪽 기울임 각주(출처와 단서), 오른쪽 덱 이름과 쪽수 | 모든 슬라이드 |

### 3.4 연결선

선 도형은 슬라이드당 3 ~ 6개로 적다. 화살표로 이어붙인 전형적인 플로우차트보다 **행과 열의 반복 배치로 흐름을 표현**하고, 선은 단계 사이를 잇는 보조로만 쓴다. 즉 필요한 것은 자유 도식 편집기가 아니라 **정해진 배치 원형 몇 가지**다.

## 4. 재설계 범위 제안

### 4.1 새 템플릿 5종 (자료형과 레이아웃과 라이터를 함께)

| 템플릿 | 담는 것 | 근거 원형 |
|---|---|---|
| `process` | 번호 붙은 단계 3 ~ 6개. 각 단계는 제목, 부제, 보조 라벨 2개 | 원형 5 |
| `cards` | 카드 2 ~ 4개. 각 카드는 배지, 제목, 본문, 꼬리 라벨. 강조 카드 1개 지정 가능 | 원형 3, 4 |
| `matrix` | 왼쪽 분류 + 대표 항목 + 나열. 행 3 ~ 6개 | 원형 6 |
| `callout` | 전폭 강조 문장 1 ~ 3줄. 다른 템플릿 위에 얹는 보조 슬롯으로도 쓴다 | 원형 2 |
| `timeline` | 시점이 붙은 항목 4 ~ 8개를 가로 또는 세로로 | 원형 5의 변형 |

### 4.2 모든 템플릿 공통으로 더할 것

- **아이브로우**와 **부제** 슬롯 (원형 1)
- **각주 줄**과 **푸터** (원형 8)
- 강조색 역할 6종을 프리셋으로 승격 (3.1의 표)
- 타이포 5단계를 프리셋으로 승격 (3.2의 표)

### 4.3 AI 생성 계약

새 템플릿마다 **용량 계약**(단계 수 상한, 카드 글자 수 상한)을 프롬프트에 넣고, 레이아웃 실측과 왕복 테스트로 고정한다. 기존 계약이 22 ~ 35% 과다 약속했던 사고가 있으므로 [[Contract-Measure-Roundtrip-Test]] 규칙을 그대로 적용한다.

또한 **AI가 템플릿을 고르게** 해야 한다. 지금은 구조안 단계에서 장별 템플릿을 정하는데, 선택지가 여섯이라 대부분 `bullet_box`로 수렴한다. 선택지를 늘리고 "어떤 내용일 때 어떤 템플릿" 기준을 프롬프트에 명시한다.

### 4.4 범위 밖

네이티브 차트(`이월표`의 차트 템플릿 항목), 그림 삽입, 자유 도형 편집, 애니메이션. 이번에는 **배치 원형으로 표현되는 도식**까지만 한다.

## 5. 5B 파일럿과의 관계

이 문제는 계획서 5B-3의 판정으로는 **완주를 막는 결함에 준한다.** 앱은 끝까지 돌지만 산출물이 제품의 목적을 달성하지 못하므로, 같은 상태로 3건째를 돌려도 같은 사실을 한 번 더 확인할 뿐이다.

**제안**: 파일럿을 2건에서 중단하고, 이 재설계를 마친 뒤 3건을 새 빌드로 다시 센다. 계획서가 blocker에 대해 정한 처분과 같다.

2건에서 이미 얻은 관찰(디자인 격차, 그 밖의 불편)은 관찰지에 남기고 재설계의 입력으로 쓴다.

## 6. 이 분석이 틀렸을 가능성

1. **벤치마크 3건 중 2건이 파일럿 산출물이었다.** 사람이 만든 벤치마크는 실질 1건과 PDF 2건이다. 표본이 적어 원형 8종이 이 조직의 관례인지 이 문서 작성자 한 사람의 습관인지 가르지 못한다. 사용자 확인이 필요하다.
2. **밀도가 곧 품질은 아니다.** 도형 수가 4배라는 것이 4배 좋다는 뜻은 아니다. 다만 색 한 종류와 도식 0개는 선택의 결과가 아니라 표현 수단의 부재이므로, 격차 자체는 실재한다.
3. **AI가 새 템플릿을 잘 고를지는 미지수다.** 선택지를 늘리면 오히려 부적절한 템플릿을 고를 수 있다. 재설계 뒤 실호출로 확인해야 하며, 이것이 다음 파일럿의 관측 항목이 된다.
4. **PDF 2건은 PPTX 원본이 아니라 출력물이다.** 그 안의 기하 수치는 렌더 결과에서 눈으로 읽은 것이라 PPTX에서 뽑은 수치보다 정확도가 낮다.
