# DB-6/7 템플릿 편집과 전환 보존

작성 2026-09-30. [품질 중심 계획](2026-09-12-quality-first-rebuild.md)의 기존 DB-6/7 잔여를 처리한다. 신규 표현 모델·차트·의미 검수와 실제 PowerPoint/독자 품질 완료 선언은 별도다.

## 편집 계약

기존 신규4종 모델/배치를 변경하지 않고 속성 패널을 연결한다. 카드 2~4개, 단계와 매트릭스 3~6개, 단계 보조 라벨 0~2개를 지킨다. 중첩 본문/배지/꼬리/부제/대표 항목과 비어 있는 선택 필드도 추가·수정·삭제할 수 있다. 카드 강조/불릿 들여쓰기와 callout 색 역할도 편집한다. 기존 6종·도식 편집 경로는 유지한다. 아이브로우/페이지 부제는 slide 수준이며 표지의 slots.subtitle와 별개다.

## 보존 매트릭스

전환은 원본에서 결론·불릿·각주를 추출한 뒤 대상에 배치한다. 아래 두 표의 조합이 10×10 전환 규칙이다. 같은 템플릿은 slots 전체를 그대로 유지한다. 공통 slide 아이브로우/부제, 장 ID/주제, DeckMeta와 StoryPlan은 모든 전환에서 보존한다. 도식은 별도 의미 입력 계약으로 작성하며 이 전환에 포함하지 않는다.

| 원본 | 결론으로 추출 | 불릿으로 추출 | 각주로 추출 | 항상 손실 안내 |
|---|---|---|---|---|
| cover | 없음 | 없음 | 없음 | 표지 내용 전체 |
| summary | conclusion | points와 level | 없음 | 없음 |
| bullet_box | conclusion | bullets와 level | footnote | 없음 |
| table | 없음 | 없음 | footnote | 표 내용 전체 |
| compare2 | conclusion | 왼쪽 후 오른쪽 bullets와 level | 없음 | 좌우 소제목 |
| divider | 없음 | 없음 | 없음 | 간지 내용 전체 |
| callout | text | 없음 | 없음 | 강조 색 역할 |
| cards | 없음 | 카드 순서대로 bullets와 level | 없음 | 배지/소제목/꼬리, 설정된 카드 강조 |
| process | 없음 | 단계 heading, level=0 | 없음 | subtitle와 notes |
| matrix | 없음 | category, level=0 | 없음 | primary와 items |

| 대상 | 보존 위치 | 손실 안내 |
|---|---|---|
| cover | 빈 표지 생성 | 추출 결론/불릿/각주 |
| summary | 결론, points | 각주 |
| bullet_box | 결론, bullets, 각주 | 원본 고유 필드 |
| table | 빈 2열 표, 각주 | 결론/불릿 |
| compare2 | 결론, 모든 불릿을 왼쪽에 배치하고 오른쪽은 비움 | 각주 |
| divider | 빈 간지 생성 | 결론/불릿/각주 |
| callout | 결론을 text, 기본 surface1 | 불릿/각주 |
| cards | 불릿을 최소 2카드로 반분 | 결론/각주 |
| process | 최대 6불릿을 heading으로 옮기고 3개까지 빈 항목 보충 | 결론/각주/초과 항목/옮긴 들여쓰기 |
| matrix | 최대 6불릿을 category로 옮기고 3개까지 빈 항목 보충 | 결론/각주/초과 항목/옮긴 들여쓰기 |

손실이 있으면 적용 전에 목록을 표시하고 취소할 수 있다. 새 문자열/근거를 자동으로 만들어 의미 손실을 감추지 않는다. 일반 템플릿 간 전환은 표현 선택이며 내용의 의미 검수 승인이 아니다.

## 전환 저장과 복구

명시적 전환 handler는 미저장 내용을 먼저 flush하고 해당 시점의 deck identity와 선택 장을 다시 확인한다. 대기 중 편집 화면과 키보드 undo를 잠그고 중복 전환을 거절한다. 늦은 이벤트가 새 편집을 발생시키더라도 identity가 바뀌면 전환을 적용하지 않는다. 저장 실패/412이면 기존 템플릿과 입력을 유지한다.

전환 적용은 `apply(edit, {snapshot: true})`를 사용한다. 다음 성공 저장에서 기존 서버 저장본의 영속 스냅샷을 남기며, 일반 텍스트 편집마다 스냅샷을 늘리지 않는다. 전환 뒤 저장 실패는 기존 저장 실패 상태와 재시도 계약을 따른다. 메모리 undo/redo도 유지한다.

## 검증

항목 최소/최대, 빈 선택 필드/강조/라벨 상한, 손실 취소, 100개 전환의 개수·공통 정보·원본 보존, 미저장 flush→스냅샷, 412 입력 보존, 중복 요청과 늦은 응답/새 편집 보존, 일반 편집의 스냅샷 비확대를 검증한다. 전체 프런트와 타입/빌드 결과는 배치 인계에 기록한다. 백엔드 모델/레이아웃/렌더 계약은 수정하지 않았다. 실AI/목표 PowerPoint/독자 판정은 수행하지 않는다.


## 구현·독립 검토 상태 (2026-10-01)

DB-6/7의 위 편집·100개 전환 계약과 로컬 회귀를 구현했다. 전환 전 flush와 저장본/선택 장 재검사, 중복·대기 중 편집 차단, 손실 취소와 412 입력 보존을 검증했다. snapshot 요청/성공 소비를 세대로 기록하여 시작한 PUT이 이후 요청을 조용히 소비하지 않게 했으며, 독립 경합 반례를 재검사했다. 부분 강조와 차트가 다른 템플릿 전환에서 사라지면 손실을 안내하고 같은 템플릿에서는 보존한다.

이 완료는 편집·저장 계약 범위다. DB-8의 실제 AI 표현 선택/목표 PowerPoint/독자 품질은 미완료이며 현재 외부 측정과 최종 전체 검사 결과는 [일괄 기록](2026-09-30-remaining-batch.md)을 따른다.
