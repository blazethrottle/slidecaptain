## 1. 사용자 결정과 이 세션의 해석

2026-10-20 세션 보고에서 결정 다섯 건(머지, (16), (17), (18), (19) 확인 질문)을 대안과 추천을 붙여 물었고, 사용자가 "추천대로 승인"으로 답했다. 다섯 건 가운데 네 건에는 추천이 기록돼 있다. 아래는 그 추천을 실행할 때 세션이 정한 세부 해석이다. 사용자가 세부까지 고른 것이 아니므로, 바꿀 필요가 있으면 이 절을 정정한다.

1. **머지(A, CI 성공 뒤 main 머지)**: 문서 커밋 `e57853a`의 CI 성공(run 39353754362, 양 OS)을 확인하고 로컬 머지를 시도했다. Claude Code 자동 승인 검사기가 "리뷰 없는 머지"로 거절했다. 세션은 우회하지 않고 PR #3(`fix/c3-bar-axis-room` → main)을 열었다. 머지는 사용자가 PR에서 하거나 세션에 머지를 직접 지시할 때 한다. 그동안 이 계획은 그 브랜치 위에서 진행한다.
2. **(16) A, PowerPoint를 미리보기에 맞춘다**: PowerPoint 차트의 값 축 주 눈금선을 끄고 주 단위를 최댓값으로 두어 눈금 글자를 0과 최댓값 둘만 보인다. 남는 차이인 값 축 글자의 위치(가로 막대에서 약 11pt, 가로 정렬)는 미리보기를 PowerPoint 실측 위치로 옮긴다. 내보내는 결과물은 PPTX이므로, 위치의 기준을 PowerPoint로 둔 C3 선례(세로 막대 범주 이름 기준선)를 따랐다.
3. **(17) A, 시안을 먼저 보인다**: 제목 글자 크기와 차트 영역 비율을 바꾼 시안 3개와 현행을 실제 PowerPoint로 렌더해 보인다. 크기, 비율, 적용 범위(차트 장만 또는 모든 템플릿)는 사용자가 시안을 본 뒤 정한다. 이 계획에서는 코드를 바꾸지 않는다.
4. **(18) A, 화면과 PPTX에는 소수 2자리로 보이고 원문은 보존한다**. 세부 해석:
   - 대상은 비교 차트의 값 글자(막대 끝 숫자)와 축 최댓값이다. 표 칸과 문장 속 숫자는 대상이 아니다. 수치 대조 게이트(`numeric_review`)는 텍스트 칸만 보므로 바뀌지 않는다.
   - 소수 자릿수가 2자리 이하인 값은 그대로 보인다(1200, 3.5). 3자리 이상인 값은 소수 셋째 자리에서 사사오입해 2자리로 보인다(123456789.123456 → 123456789.12, 2.999 → 3.00). "소수점 2자리까지만"을 "2자리까지 남긴다"로 읽었고, 정수나 1자리 값에 0을 채우지 않는다.
   - 원문 값은 덱의 근거, 렌더 계획의 `value`, PPTX 내장 데이터(PowerPoint "데이터 편집"에서 보이는 값), 차트 도형 설명 JSON에 그대로 남는다. 막대 길이도 원문 값으로 그린다.
   - 축 최댓값은 원문이 아니라 앱이 정하는 여유값이므로, 반올림해서 보이지 않고 값 자체를 소수 2자리로 올림해 정한다.
   - 반올림했다는 안내 문구는 슬라이드에 넣지 않는다. 슬라이드 하단 부연을 두지 않는 사용자 원칙과, 조건 문장 세 줄 상한 때문이다.
   - 0.004와 0.001이 둘 다 0.00으로 보이는 한계는 추천 때 알린 대로 받아들인다.
   - 유효숫자 15자리 거절(C3 Q3 A)은 유지한다. 2자리 표시로 바뀐 뒤 거절을 완화할지는 이월한다(6절).
5. **(19) 확인 질문**: "추천대로 승인"은 이 질문의 답이 되지 않는다. 사용자 확인 대기로 남긴다.

## 2. 지금 코드에서 확인한 사실 (기준 `e57853a`)

1. `export/pptx_writer.py` `_add_chart_shape`는 `major_unit=axis_maximum/5`를 쓰고, python-pptx 기본값으로 값 축 주 눈금선(`c:majorGridlines`)이 켜진다.
2. `layout/expression.py` `axis_maximum_text`는 다섯 눈금(최댓값의 k/5)을 모두 정확히 보일 소수 자릿수를 남긴다. 그래서 bar15의 축 최댓값이 `135802468.035810`(6자리)이다.
3. `ChartPoint.value`는 원문 값 문자열이고, 미리보기(`frontend/src/editor/ChartPreview.tsx`)와 PPTX 라벨 서식(`_number_format`)이 모두 이 글자의 자릿수를 따른다.
4. 미리보기는 0과 최댓값만 그린다. 가로 막대는 둘 다 `y0+font` 기준선에, 0은 시작 맞춤, 최댓값은 끝 맞춤이다. 세로 막대도 0을 그림 영역 아래 `y0+font`에, 최댓값을 그림 영역 왼쪽 `plot_y` 기준선에 그린다.
5. 회사 PC PowerPoint(16.0 build 20430)는 '0.00' 서식에서 1.005, 2.675, 0.125, 123456789.125를 1.01, 2.68, 0.13, 123456789.13으로 보였다(2026-10-20 실측, 표본 12개). 원문 값을 float로 넣어도 Decimal의 ROUND_HALF_UP과 같은 글자다.

## 3. 설계

### 3.1 표시 글자 (18)

`ChartPoint`에 표시 글자 `display`를 더한다. 레이아웃이 원문 Decimal에서 계산한다(소수 3자리 이상이면 `quantize(0.01, ROUND_HALF_UP)`). 미리보기는 `display`를 그리고, 레이아웃의 값 글자 폭도 `display`로 잰다. PPTX는 내장 데이터에 원문 값을 넣고, 라벨 서식을 `display`의 자릿수로 정한다(2절 5의 실측 근거).

축 최댓값은 `max(값)*1.1`을 소수 2자리로 올림한다. 눈금이 0과 최댓값 둘뿐이므로(3.2) 최댓값 자체의 자릿수만 남긴다. 값이 1조 이하라 최댓값은 정수 13자리와 소수 2자리, 15자리 안이다.

### 3.2 PowerPoint 눈금 (16)

값 축의 주 눈금선을 끄고 주 단위를 최댓값으로 둔다. 축 서식은 최댓값 글자의 자릿수를 따른다(0 눈금은 지금처럼 '0').

### 3.3 미리보기 축 글자 위치 (16)

PowerPoint에서 바뀐 차트를 렌더해 0과 최댓값 글자의 획 위치를 잰다. 미리보기 글자의 획 위치를 Noto Sans KR 글리프 경계로 계산해 1pt 안으로 맞춘다. 가로 막대는 기준선과 가로 정렬, 세로 막대는 0 글자를 그림 영역 왼쪽으로 옮기는 것까지 측정값에 따른다.

## 5. 수용 기준

1. 소수 3자리 이상인 차트 값은 미리보기와 PowerPoint에서 같은 소수 2자리 글자로 보이고, PPTX 내장 데이터에는 원문 값이 남는다.
2. PowerPoint 차트에 값 축 눈금선과 중간 눈금 글자가 없다.
3. 0과 최댓값 글자의 획 위치가 PowerPoint와 미리보기에서 1pt 안이다(회사 PC 실측).
4. 기존 수용 기준(가로 막대 그림 영역 1pt, 세로 막대 범주 이름)이 유지된다.
5. 백엔드와 프런트 전체 시험, 생성 파일 무변경, CI 두 OS 성공.
