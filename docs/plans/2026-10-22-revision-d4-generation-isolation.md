## 1. 사용자 결정

2026-10-22 사용자 결정 "1안으로 진행": D4의 다음 단위를 "생성 세션에서 스킬과 플러그인 빼기"로 정했다. 실제 생성 호출의 횟수와 대상은 승인되지 않았다. 구현과 생성 없는 확인을 마친 뒤 4절의 선택지로 묻는다. 지금까지 이 단위의 실제 AI 생성 호출은 0회다.

## 2. 전제 정정과 지금 사실 (기준 `eedab2a`, 생성 호출 없음)

1. 전제 정정: 2026-10-21 실측 기록(위 계획 11절)은 초기화 메시지의 개수만 보고 "`setting_sources=[]`인데도 사용자 스킬과 플러그인이 실린다"고 적었다. 2026-10-22 같은 옵션으로 초기화 응답의 이름을 읽어 보니, 명령 55개(동봉 CLI 50개)는 모두 Claude Code 내장 명령과 내장 스킬이고 에이전트 5개도 내장분이었다. 사용자가 설치한 스킬과 에이전트는 없었다. 사용자 설정은 이미 막혀 있다.
2. SDK 0.2.145는 `system_prompt`가 없으면 CLI에 `--system-prompt ""`를 넘긴다. Claude Code 기본 시스템 프롬프트에 들어가는 스킬 목록과 작업 폴더 정보는 실리지 않을 가능성이 크다. 다른 경로로 모델 입력에 들어가는지는 확인하지 못했다.
3. CLI 옵션 `--disable-slash-commands`("Disable all skills and commands")가 설치 CLI 2.1.306과 동봉 CLI 2.1.247에 모두 있다. SDK `extra_args={"disable-slash-commands": None}`로 넘기면 초기화 응답의 명령이 0개가 된다(두 판 모두 확인). 내장 에이전트 5개는 남지만 생성 경로는 도구가 없어(`tools=[]`) 부를 수 없다.
4. `--bare`는 OAuth와 키체인을 읽지 않아 구독 로그인 경로에서 쓸 수 없다.
5. 설치 CLI 실행의 초기화 메시지에 보인 플러그인 3개(동봉 0개)의 정체는 모른다. 관측 줄이 개수만 남겼기 때문이다.

## 3. 설계

1. `SubscriptionProvider.complete`의 옵션에 `extra_args={"disable-slash-commands": None}`를 넣는다. 목록 조회는 초기화 응답의 모델 항목만 읽으므로 바꾸지 않는다.
2. 응답 관측(`observed_fields`)의 개수 칸에 이름 목록을 더한다. 항목이 문자열이면 그 값, 객체면 `name` 칸만 쓴다. 이름마다 60자, 목록마다 40개까지 담고 경로 같은 다른 칸은 담지 않는다. 플러그인 3개의 정체를 다음 실제 호출에서 확인하려는 것이다.
3. 시험: 생성 옵션에 `disable-slash-commands`가 있는지, 관측 줄이 이름은 담고 경로는 담지 않는지.
4. 기록 정정: 2026-10-21 계획 11절 질문 3과 로드맵 D4a 이월표 행에 날짜 붙은 정정을 적는다.

## 4. 실제 호출 (승인 대상, 구현 뒤 묻는다)

같은 합성 장 하나를 `--disable-slash-commands`를 붙여 생성하고, 2026-10-21 L1(설치 CLI, `default`, `low`: 입력 5,607, 캐시 생성 6,388 토큰)과 비교한다. 입력이 같으므로 토큰이 줄면 내장 목록이 모델 입력에 들어가고 있었다는 뜻이고, 같으면 들어가지 않았다는 뜻이다. 어느 쪽이든 생성이 정상으로 끝나는지와 명령, 스킬, 플러그인 개수가 0이 되는지 확인한다.

- A(추천): 설치 CLI로 1회(L1과 같은 조건).
- B: A에 동봉 CLI 1회(L3와 같은 조건, `opus[1m]`). 2회.
- C: 실제 호출 없이 생성 없는 확인(명령 0개)만으로 마친다. 옵션이 생성에 주는 영향은 다음 실제 사용 때 드러난다.

판정과 기록은 2026-10-21 계획 3.5절과 5절을 따른다. 호출마다 상한 1회, 실패도 포함, 자동 재실행 없음.

## 6. 하지 않는 것과 이월

- 내장 에이전트를 끄는 일: 끄는 옵션이 없고, 도구가 없어 부를 수 없다. 방치 확정으로 둔다.
- 목록 조회 경로의 같은 옵션: 모델 항목만 읽으므로 넣지 않는다.
- Grok(xAI) 제공자 추가: 2026-10-22 사용자 질문에 대한 검토만 했다. Grok Build CLI는 세 번째 제공자로 붙일 수 있는 형태(비대화 실행, 모델 목록, 강도, 공식 로그인, 격리 옵션이 있음)이고, CLI에는 스키마 강제 출력이 없다. Grok Bot은 호스팅 컴퓨터에서 비동기로 일하고 외부 호출이 웹훅 접수뿐이라 생성 제공자 자리에 맞지 않는다. 출처는 docs.x.ai의 Grok Build CLI, 인증, 구조화 출력 문서다. 같은 커밋에서 로드맵 D4a 이월표에 담당(D4 제공자 확장)과 함께 올리고, 착수는 사용자 결정 뒤 계획서로 한다.
