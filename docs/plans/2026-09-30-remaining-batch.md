# 계획 잔여 일괄 개발

작성: 2026-09-30. 사용자 요청은 계획상 남은 개발을 묶어 처리하는 것이다. 기존 변경 322개 파일과 인덱스/HEAD를 저장소 밖 기준본에 보존했다. 이전 실호출 승인 8회는 소진됐다. 2026-09-30 새 승인에 따라 root만 비기밀 합성 입력의 LUNA `gpt-6-luna` 측정을 `provider.complete` 12/12회(생성 9회+분리된 검토 3회)로 완료했다. 실패/형식 재시도는 0회이고 비용은 null로 유지한다. 단일 페이지 3사례의 개선 우세는 입증하지 못했다. 구현자/독립 검토자는 실제 AI 호출 0회다. commit/push, 배포와 품질 자기 판정은 실행하지 않는다.

## 단위와 수용 조건

1. 게시 안전성: 잠금 symlink/reparse/교체와 출력 디렉터리 교체를 거절한다. 기존 파일을 덮거나 제3파일을 cleanup하지 않는다.
2. Q4b: 신규 출력 생산 provenance, 서버 주도 native PowerPoint 렌더, 설정된 독립 검수자 서명 receipt, 현재성/최신 실패/coverage 검사와 같은 바이트의 제출본 게시. 실행 환경/검수자 부재는 차단으로 남긴다. 기존 preflight/수동 기록은 그대로 유지한다.
3. DB-6/7: 신규4종 편집, 제한된 개수/선택 필드, 전체 템플릿 보존/손실 계약과 전환 전 영속 스냅샷. 충돌/늦은 응답/취소는 원래 편집을 보존한다.
4. Q4 수정: 호출 진입 전 상한/재시도/예약 검수 예산/시간/비용 결측/취소/기준 리비전 검사. 원래 초안을 덮지 않는 제한된 후보와 독립 재검수 흐름을 지원한다. 실제 외부 호출은 별도 승인 때만 실행한다.
5. Q5: 같은 자료/질문/환경의 세 비교군, 실패/보류 포함 분모, 눈가림 산출물과 사람 판정 폼/보고 도구. 3개 독립 자료를 요구하고 동일 자료 버전은 중복 사례로 세지 않는다. 결측 비용/수정 시간은 null로 보존한다. 개선량/합격 판정은 사용자 측정 전에 만들지 않는다.
6. Q2/Q3: 미등록 비교/산식 검수와 명시적 단위환산, 요약 의미검수, 부분 강조/차트/복합 표현, 기존 도식 교체와 보호 근거 이전의 남은 계약을 각 소유권으로 이어 구현한다. 이미 검증한 저장 버전/fingerprint를 조용히 바꾸지 않는다.

독립 검토자는 구현자의 파일에 생산 수정을 하지 않고 실패 반례와 발견을 전달한다. 이 역할 분리에는 위키의 구현자/독립 리뷰어/반영자 절차를 적용한다. [[wiki:Implementer-Reviewer-Applier-Pipeline]]

## 완료 기록

각 단위 계획, 변경 전 실패, 최종 검사와 독립 리뷰를 배치 증거 폴더에 남긴다. 전체 테스트/계약 왕복/화면 QA 뒤 이번 변경만 원본에 선택 반영하고 원본 기준 해시와 인덱스를 재검사한다. PowerPoint 실제 표시, Windows 실기기, 외부 모델 응답과 사람 블라인드 판정은 실행 여부를 따로 기록한다. 완료하지 않은 단위는 체크하지 않는다.

## 보존되는 staging과 저장 공간

`.slidecaptain-export-*` 비공개 staging 폴더는 성공/실패 뒤에도 보존한다. stat 이후 unlink까지의 경로 교체를 원자적으로 막을 수 없어 자동 cleanup을 없애 제3파일 삭제를 피했다. 잠금/게시 안전성 테스트는 이 보존 계약을 검사한다. 내보내기마다 파일과 공간이 누적되며 현재 자동 정리·용량 상한 기능은 없다. 안전한 유지보수 정리는 활성 작업과 소유권을 확인하는 별도 설계·승인 범위로 남긴다.


## root 최종 로컬 검증·실측 (2026-10-01)

root가 보고한 최종 결과는 백엔드 1,953개 통과/Windows 전용 1개 미실행, 프런트 532개 통과와 빌드 통과다. Chrome에서 차트/부분 강조, 문서 변경 미리보기→개별 손실 확인→적용, 검수 이력의 macOS native render 미수행 사유와 제출 게시 비활성화를 확인했다.

LUNA는 서로 다른 단일 본문 페이지 사례 3개의 세 비교군을 생성해 9개 PPTX와 눈가림 판정 폼을 만들었다. 분리된 AI 검토 문맥의 선호는 물류 사례의 일반 지침/기존 파이프라인 동률, 매출과 설문 사례는 일반 지침이었다. 개선 파이프라인의 우세를 입증하지 못했다. 이는 제한된 사례의 측정이며 독립된 사람 품질 수용이나 다장 보고서의 품질 통과가 아니다. 실제 호출은 root만 수행했으며 비용값이 없으므로 0으로 채우지 않는다. 세부 실행 증거는 root의 `docs/qa/2026-10-01-remaining-batch.md` 후속 기록을 따른다. Windows/native PowerPoint/독립 서명·사람 수용 항목은 계속 미완료다.
