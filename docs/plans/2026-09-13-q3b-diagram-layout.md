# Q3b 첫 단위: 결정론 도식 배치

작성: 2026-09-13. 사용자 요청은 SlideCaptain 개발 계속 진행이다. [Q3a 인계](../handoffs/2026-09-13-q3a-diagram-contract-handoff.md)의 다음 단위를 진행한다. 기존 누적 변경 239개 파일을 백업한 뒤 격리 작업 트리에서 구현한다.

## 목적과 종료 지점

검증한 DiagramSpec, 현재 Preset와 FontMetrics에서 공통 typed render 후보를 계산한다. 원본 노드/관계/근거/조건, 페이지 pt 좌표, 텍스트 줄바꿈, 연결선 끝점과 스타일을 함께 반환한다. 공간 부족이나 미지원 그래프를 내용 삭제나 글자 축소로 숨기지 않고 blocked와 항목별 사유로 반환한다.

이 단위는 독립 백엔드 어댑터다. Deck/저장본/API/OpenAPI/TypeScript, 생성/편집 화면, PPTX 라이터와 품질 기록은 바꾸지 않는다. 실제 원문/의미 검수, 브라우저/PowerPoint 렌더와 독자 판정은 not_run이다. computed는 계산 완료만 뜻한다.

## 입력과 계산 계약

1. `build_diagram_layout(payload, preset, metrics, *, evidence)`는 Q3a 파서로 입력과 Evidence를 매번 재검증한다. Preset도 중첩 검증 우회 편집을 다시 검사한다. 입력 오류는 ValueError 계열이며 정상이나 배치 불가인 입력은 typed blocked 결과다. 입력을 수정하거나 파일/AI를 호출하지 않는다.
2. report/flow_horizontal의 첫 배치는 한 줄의 노드다. flow의 위상 순서로 왼쪽에서 오른쪽으로 놓고 동률은 입력 노드 순서로 고정한다. reference/proposal은 순서를 정하지 않는다. 계산한 순서에서 인접하지 않은 두 노드의 관계는 unsupported_topology다. 유효한 Q3a 그래프라도 여러 줄, 노드 건너뛰기와 분기 자동 경로는 이번 배치 범위 밖이다.
3. Preset의 content_box를 사용한다. 제목/각주 예약 영역 안으로 침범하지 않는다. 노드 폭은 동일하며 간격은 내용 폭과 노드 수에서 계산하고 card_gap을 하한으로 둔다. 전용 수치는 새 프리셋 필드로 추가하지 않고 버전이 있는 배치 산식에 둔다. 공통 부제/분류 라벨이 있는 페이지 결합은 후속 어댑터의 책임이다.
4. 노드는 kind/role 안내, content와 모든 caveats를 같은 box_pt 본문 크기로 표시한다. 관계 라벨은 relation 안내를 포함해 body_pt로 표시한다. 기존 번들 폰트의 줄바꿈과 안전 여유를 사용하되 한 글자라도 폭을 초과하면 차단한다. 글자 축소와 말줄임은 없다. 줄 높이는 글자보다 작을 수 없다.
5. 한 간격의 여러 관계에는 서로 다른 세로 레인을 배정한다. 라벨 아래 수평 연결선과 노드 측면 앵커를 만들고 전체 높이는 노드 본문과 관계 레인의 최대 필요 높이다. flow만 도착점 화살표를 갖고 reference/proposal은 화살표 없이 구별되는 선 스타일과 명시적 라벨을 갖는다. 화살표의 실제 점도 백엔드가 계산한다.
6. 계산된 모든 상자, 라벨, 선, 화살표는 본문/페이지 경계와 유한값을 확인한다. computed에는 모든 입력 항목이 있어야 하고 blocked에는 부분 렌더 후보를 넣지 않는다. 출력에는 입력(도식/근거/프리셋/폰트 수치) fingerprint와 규칙 버전을 포함하며 검수 승인으로 쓰지 않는다.
7. 첫 단위는 번들 Noto Sans KR 폰트 이름만 지원한다. 다른 폰트의 폭 수치를 번들 폰트와 혼용하지 않고 사유를 반환한다. 폰트 수치 입력은 유한/양수 폭과 단위, 기본 구조를 검사한다. 실제 글리프 모양이나 OS 폰트 설치를 검증한 것은 아니다.

## 검증과 독립 리뷰

- 구현 전 실패 테스트: 합성 Q3a fixture의 결정론/입력 보존/의미와 근거 보존, 줄바꿈과 조건 보존, 흐름/참조/제안 앵커 및 화살표, 복수 관계의 레인 분리.
- 실패 경계: 좁은 폭/낮은 높이, 긴 한글/영문/라벨/조건, 단일 글자 폭, 비정상 Preset/폰트, 미지원 토폴로지, 검증 우회 편집과 근거 불일치, NaN/무한값.
- 왕복: typed JSON과 레거시/q2a/q2b/q2c 저장본, 기존 fingerprint/생성 스키마 무변경. 백엔드 전체, 프런트 검사/빌드, 공개 파일 감사와 원본 보존 대조.
- 계획을 독립 검토한 뒤 확정하고 구현 뒤에도 독립 리뷰의 재현 가능한 발견을 반영한다. 테스트 통과를 실제 보고서 품질로 올리지 않는다.

## 재심할 전제

단일 행과 인접 관계, 잠정 폭 배분, 현재 프로필/폰트 지원은 Q3b 첫 단위의 제한이다. 다음 렌더 단위에서 실제 텍스트와 관계 표현으로 재심한다. 글리프 폴백, 실제 PowerPoint 자동 줄바꿈, 공통 제목/부제 결합과 렌더 상태 저장/만료는 미구현이다. 이월은 로드맵에도 반영한다.

## 계획 독립 검토 반영 (2026-09-13)

- reference/proposal 라벨에는 주체와 대상의 표시명을 넣는다. content가 같은 노드는 표시명에 ID를 붙여 서로 구분하고 원래 content는 별도로 보존한다. 화살표 없는 연결에서 방향 정보가 사라진다는 발견을 반영했다.
- 기존 줄바꿈기는 연속/행 가장자리 공백을 축약한다. 이 입력과 탭/제어문자, 번들 폭에 없는 글리프는 `unsupported_text`로 차단한다. 지원 입력에서는 원문과 표시 문자를 보존하며 명시적 줄바꿈은 지원한다.
- 본문 경계 안쪽에 선 굵기 절반의 여유를 두고 라벨/노드 간 여유와 화살표 외곽까지 검사한다. 단순 중심선의 경계 통과로 전체 도형이 페이지 안에 있다고 간주하지 않는다.

## 구현 독립 검토 반영 (2026-09-13)

폰트 단위가 너무 커 정규화된 폭이 0으로 줄어드는 경우와 필수 속성 결손을 7개 실패 사례로 재현했다. 정규화한 폭의 유한/양수 검사와 필수 필드 구조 검증을 추가했다. 표시명에 붙인 ID가 다른 노드의 원래 내용과 충돌하는 경우도 별도 회귀로 확인해 모든 표시명을 ID 접두사로 구분한다. 빈 도식의 computed 직렬화는 출력 스키마에서 거절한다.

직렬화된 후보의 스키마 검사만으로 입력 fingerprint의 무결성, 실제 배치와 품질을 신뢰하지 않는다. 후속 렌더/저장 소비자는 원래 의미/근거/프리셋/폰트 입력에서 다시 계산해야 한다. 상세 결과와 다음 단위는 [인계](../handoffs/2026-09-13-q3b-diagram-layout-handoff.md)를 따른다.
