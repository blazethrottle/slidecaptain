# Claude 사용량의 부분 결측 보존

작성: 2026-09-28. SlideCaptain 개발 재개 요청에 따라 로드맵 이월 항목인 `build_call_usage`의 누락 토큰을 0으로 바꾸는 오류를 처리한다. [직전 인계](../handoffs/2026-09-28-quality-pilot-handoff.md)의 실제 AI 관통은 별도 동의가 필요한 상태다. 이번 단위는 기존 사용량 계약을 바로잡고 로컬 검증까지 수행한다.

## 범위와 계약

- Claude SDK의 모델별 토큰 네 필드는 명시된 음이 아닌 정수일 때만 값으로 받는다. 실제 0은 유지한다. 키 누락, null, 음수, 불리언, 문자열과 실수는 미확인으로 두며 숫자로 강제 변환하지 않는다. 설치된 SDK의 `ModelUsage` 타입은 정수지만 런타임 파서는 CLI 값을 그대로 전달하므로 어댑터에서 검사한다.
- 여러 모델 중 하나라도 해당 필드가 없거나 유효하지 않으면 그 필드의 합계는 `None`이다. 나머지 정상 필드는 합산한다. 모델 항목 자체가 잘못됐으면 그 모델의 모든 토큰을 모르므로 네 합계 모두 `None`이다. 유효 항목만 더한 부분 합계를 반환하지 않는다.
- 여러 호출의 `GenerationUsage`와 프런트 합산에서도 같은 결측 전파를 유지한다. 사용량 객체 자체가 없는 호출은 기존 `unmeasured_calls`로 별도 집계한다. `0 + null`은 null이고 `0 + 0`은 0이다.
- `model_usage` 최상위 값이 dict가 아니면 예외 없이 사용 불가로 처리한다. 하나 이상의 dict 항목이 있으면 출처는 `model_usage`이며, 전혀 없으면 기존 `usage`/`none` 출처 규칙을 유지한다. `usage`의 마지막 턴 토큰으로 빈칸을 채우지 않는다. 실제 모델은 Assistant 메시지를 우선하며, 모델 항목이 여럿이면 정상 항목 하나만 남았다는 이유로 모델을 추정하지 않는다.
- SDK가 주는 비용/시간/턴 수와 실패 응답의 사용량은 기존 계약대로 보존한다. 진단 로그의 모델별 합계에도 같은 결측 규칙을 적용한다. 인증정보, 프롬프트와 응답 본문을 사용량 로그에 추가하지 않는다.
- 화면은 알려진 입력/출력 값을 각각 표시하고 빠진 항목은 `미확인`으로 쓴다. 캐시 토큰이 0인 경우 생략하는 관례는 유지하지만 null인 경우에는 `캐시 읽기 토큰 미확인` 또는 `캐시 생성 토큰 미확인`을 표시한다. 토큰 네 값이 전부 없으면 `토큰 미확인`으로 묶는다.
- `CallUsage`/`GenerationUsage`의 nullable 필드를 사용하므로 모델이나 API 형태는 확장하지 않는다. 기존 JSONL이나 저장된 과거 0을 소급 수정하지 않는다. 값이 원래 없었는지는 기존 기록만으로 판단할 수 없다.

## 검증과 보존

실패 테스트로 단일/다중 모델의 누락과 null, 잘못된 값, 명시적 0, 잘못된 모델 항목을 재현한다. 고정 SDK 응답을 실제 제공자와 앱 API로 전달해 형식 재시도 뒤 응답과 JSONL에서 null 및 `missing`이 유지되는지 검사한다. 이 응답을 공통 픽스처로 프런트 합산/표시와 대조한다. 제공자 성공/실패와 진단 로그도 검사한다. 실제 AI 호출은 없다.

관련 회귀, 전체 백엔드/프런트 테스트, TypeScript/Vite 빌드, OpenAPI/생성 타입 대조와 공개 저장소 감사를 실행한다. 실제 브라우저에서는 합성 사용량 표시만 검사한다. 실제 AI, Windows 및 PowerPoint 검증은 별도다. 계획 적대 검토와 구현 검토의 수행 여부를 인계에 구분한다.

원본 `codex/phase-5b`, HEAD `a8c6d7a`의 290개 파일과 인덱스를 백업한 별도 작업본에서 수정한다. 반영 직전 원본 해시/경로/브랜치/HEAD/인덱스를 확인하고 이번 변경만 반영한다. 커밋/푸시/머지는 하지 않는다.

## 계획 리뷰 (2026-09-28)

독립 검토의 필수 수정은 0건이다. 선택 제안 2건에 따라 호출 간 결측 전파를 명시하고, 서로 다른 필드가 누락된 모델 및 0/null 혼합을 회귀 사례로 고정한다. 과거 기록의 0을 소급 정정하지 않는 경계도 유지한다.

신규 백엔드 40개/프런트 4개, 전체 백엔드 1,602개 통과/Windows 전용 1개 미실행, 프런트 406개 통과, TypeScript/Vite 빌드와 OpenAPI/생성 타입 동일성을 확인했다. 독립 리뷰의 필수 잔여는 0건이다. Chrome에서 일부 결측/명시적 0의 합성 생성 2개 흐름을 확인했으며 외부 AI 호출은 0회다. 인계와 이월표를 갱신했고 상세 검증 범위는 [인계](../handoffs/2026-09-28-usage-missing-values-handoff.md)에 있다.
