# Q2d 계산 문구 대조 최소 단위

작성: 2026-09-13. Q2c 이후 개발 재개 요청을 따른다.

## 범위와 종료 조건

Q2c의 근거와 산식으로 코드가 대상/기준, 부호, 단위, 기간, 분모와 반올림을 포함한 기준 문구를 만든다. 생성/축약 문맥에 기준 문구를 전달하고 현재 초안의 텍스트 칸 전체와 대조한다. 일치한 칸만 계산 ID와 두 근거 ID로 연결한다. 일부 숫자나 문장 일부의 일치로 연결하지 않는다. 다른 표현, 뒤집힌 기준, 누락된 단위와 연결되지 않은 원문 수치는 확인 필요로 남긴다.

읽기 전용 로컬 API와 편집 화면에서 현재 편집본을 검사한다. 저장/복원 후에는 다시 계산하며 결과를 덱에 저장하지 않는다. 편집 중 도착한 낡은 응답은 화면에 표시하지 않는다. 검사나 실패가 초안을 수정하거나 AI 호출을 추가하지 않는다. Deck/StoryPlan의 저장 버전과 Q1a 제출본 차단은 유지한다.

종료 조건은 합성 자료로 정상 문구/부호/단위/대상과 기준/반올림/숫자 일부/낡은 자료/계획 없음/대상 0건을 검증하고 API, 편집 화면, 저장과 복원 및 생성/축약의 왕복을 확인하는 것이다. 전체 회귀, 타입/빌드, 변경 보존 대조와 인계를 마친 뒤 다음 단위에서 멈춘다.

## 구현 전 반증 검토

- 같은 숫자가 자료 어디에 있다는 이유로 맞다고 할 수 없다. 문구 전체가 코드가 만든 명시적 비교 조건과 일치해야 한다.
- 같은 문구가 여러 산식에 대응하면 근거 연결을 임의 선택하지 않는다. 중복 연결은 확인 필요다.
- 원문이나 계획이 바뀌었으면 현재 자료로 fingerprint를 확인하고 대조를 미수행으로 남긴다. API/저장본의 계산 결과는 다시 계산한다.
- 숫자가 있는 텍스트 칸만 대상이며 표지 날짜와 간지 자동 번호는 제외한다. 한 자리 숫자와 비ASCII 숫자도 누락하지 않는다. 템플릿명과 색 역할은 텍스트 대상이 아니다.
- 문구 일치는 원문 해석이나 모델이 추출한 메타데이터의 진실성을 입증하지 않는다. 자유로운 자연어의 뜻, 숫자를 글자로 쓴 표현, 요약의 전체 정합성과 PowerPoint 표시는 미검수다.
- 기준 문구 방식은 지원 범위를 좁게 잡기 위한 선택이다. 자연스럽지만 다른 문구도 확인 필요가 될 수 있다. 사용자의 문장을 자동 교체하거나 이를 최종 보고서 문체로 강제하지 않는다.
- 서버에 저장된 덱만 읽으면 저장 대기 중인 편집본을 놓친다. 검사 요청에 편집기의 현재 덱을 담고 응답은 해당 덱에만 표시한다. 원문을 다른 앱에서 바꾸면 다시 검사해야 함을 표시한다.

구현자가 작성한 범위 검토이며 독립 에이전트 리뷰와 실제 AI 검증을 대신하지 않는다.
