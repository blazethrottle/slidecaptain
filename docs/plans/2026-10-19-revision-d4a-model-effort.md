# D4a: 모델 지원 정보와 ChatGPT 추론 강도 (2026-10-19)

## 범위와 근거

사용자의 GitHub 동기화/계속 진행 지시에 따라 C3 준비 PR #1을 main `1f1c4ef`에 병합하고, D4의 첫 구현 단위를 시작한다. C3 실제 PowerPoint 판정은 여전히 회사 PC에서 수행한다. 상위 계약은 [독립 앱 구현 설계](../architecture/2026-10-02-desktop-revision.md)의 AI 연결과 D4, [제품 설계](../design/2026-10-02-revision-product-ux.md)의 AI 연결이다.

이번 단위는 기존 공식 Codex `model/list`의 지원 Effort 정보를 보존하고, 사용자가 고른 값을 설정 파일부터 생성 lease와 `turn/start`까지 전달하는 것이다. 계정 프로필/영구 동의/Claude 공식 모델 조회/추천은 다음 D4 단위다. 실제 AI 호출 예산은 0회다.

2026-10-19 설치된 공식 Codex CLI `0.159.0-alpha.3`의 `app-server generate-json-schema`로 `Model.supportedReasoningEfforts[].reasoningEffort`, `defaultReasoningEffort`, `TurnStartParams.effort`를 확인했다. Effort는 열거형이 아닌 비어 있지 않은 문자열이다. 특정 모델명이나 지원 수준을 하드코딩하지 않는다. 이 확인은 로그인이나 생성 요청을 실행하지 않는다.

## 계약

1. `ModelOption`에 지원 Effort 목록, 지원 목록 안에 있는 기본값, 출처와 조회 시각을 추가한다. Codex 전체 페이지를 읽고 숨김/텍스트 미지원 모델은 제외한다. 잘못된 Effort 항목은 선택지로 내보내지 않는다. Claude의 기존 별칭에는 지원 수준을 추정하지 않는다. 정확한 모델 버전은 이번 응답만으로 확정하지 않는다.
2. `AISelection.effort`는 선택적 문자열이며 기본값은 null이다. null은 기존처럼 제공자 기본값을 사용하고 요청/설정 파일에서 생략한다. 구형 두 필드 설정은 그대로 읽는다. 명시 값은 ChatGPT의 현재 모델 지원 목록에 있어야 한다. 미지원 값은 저장과 생성 시작 전에 거절한다.
3. Effort 변경은 `selection_id`를 변경한다. 오래된 동의는 기존 충돌 관문에서 거절한다. 생성 lease는 모델과 Effort를 고정하고 재시도에도 같은 provider를 쓴다. 생성 중 설정 변경 금지는 유지한다. 공식 클라이언트의 도구 차단, 격리, 구독 확인은 그대로 적용한다.
4. 화면에는 모델이 제공하는 수준만 표시하고 기본값을 선택할 수 있다. 지원 정보가 사라진 기존 값은 조용히 대체하지 않고 다시 선택하도록 안내한다. 서비스/모델을 직접 바꾸면 Effort는 그 선택에 맞게 초기화한다. 빠른 선택으로 같은 모델을 다시 누르면 수동 Effort를 보존한다. 새로고침은 미저장 선택을 덮어쓰지 않는다.
5. API 계약/OpenAPI/프런트 타입을 함께 갱신한다. `/api/status`와 설정의 현재 적용, 생성 상태 줄, 전송 동의에 요청 추론 강도를 표시한다. null은 제공자 기본값으로 표시하며 실제 적용 확인으로 표현하지 않는다. 원장과 사용량의 기존 모델 기록을 실제 Effort 검증으로 해석하지 않는다. 실제 적용 강도 계측과 정확 버전 계약은 후속 D4 범위다.

## 작업과 검증

- T1: 계획 독립 리뷰, 지원 목록/설정/요청 전달의 실패 시험 작성, 백엔드 구현.
- T2: 화면 선택/보존/잘못된 값 차단의 실패 시험 작성, 화면과 생성 타입 구현.
- T3: 독립 코드 리뷰, 전체 백엔드/프런트 시험, 빌드/타입/공개 감사, 실제 브라우저에서 합성 응답으로 저장 흐름 확인.
- T4: 인계/로드맵 갱신, PR과 Windows/macOS CI 완료 확인. 이후 D4 단위로 자동 확장하지 않는다.

구체 회귀: 페이지 후반의 Effort, 잘못된/없는 메타데이터, 지원하지 않는 기본값, 구형 파일, 명시 값 재시작, 지원 목록 변경 후 호출 0, Effort만 바뀐 동의 충돌, `turn/start` 전달/기본값 생략, 서비스/모델 전환과 새로고침, 생성 중 잠금.

계획 독립 리뷰(2026-10-19): 사용 가능한 Codex 리뷰 에이전트가 생성 직전 Effort 표시 누락 1건을 지적했다. 계약 5와 상태/동의 회귀에 반영했다. Claude 전용 리뷰 도구로 수행했다고 주장하지 않는다.

## 호환성과 미완료

새 설정에서 Effort를 제공자 기본값으로 저장하면 이전 두 필드 형식으로 돌아간다. 명시 Effort가 든 설정은 구버전 앱이 알 수 없는 필드로 거절한다. 롤백 전에 기본값으로 저장한다. 파일을 삭제하거나 알 수 없는 필드를 무시하도록 완화하지 않는다.

후속 담당은 로드맵 D4a 이월표에 기록한다: D4b Claude 공식 모델/정확 버전/계정 범위와 계측, D4c 프로필/동의/공식 로그인/생성 중 다음 설정, D4d 추천과 릴리스 안내. 실제 AI 생성과 계정 격리 검증은 별도 실기기 단위이며 이번 시험 성공으로 완료 처리하지 않는다.

## 구현과 리뷰 기록

T1 백엔드 독립 리뷰는 Effort에 공식 규약에 없는 식별자 문법/길이 제한을 넣은 문제 1건을 발견했다. 문자열 규약을 그대로 보존하고 빈값/공백 전용 값만 거절하도록 수정했다. `adaptive.v2` 목록/전달과 `Future Level` 저장/재시작을 시험한다. T2 화면 독립 리뷰에서는 추가 결함이 없었다.

전체 검사에서 새 미지원 Effort 오류 경로의 `test_jobs_error_codes.py` 대응표 등록 누락을 발견해 보완했다. 선택 충돌 문구도 서비스/모델/추론 강도를 모두 설명하도록 맞췄고, 화면과 공유하는 `failure-bodies.json`을 실제 응답에 맞춰 갱신했다. 독립 리뷰어가 대응표와 실제 예외의 일치를 확인했다. 브랜치 전체 최종 리뷰의 차단 발견은 0건이다.

백엔드 초기 RED는 새 14개 실패/기존 27개 통과, 프런트 초기 RED는 새 8개 실패/기존 20개 통과였다. 이후 관련 백엔드/API 51개와 프런트 28개가 통과했다. 실제 Chromium의 합성 API 화면에서는 명시값 저장/재열기, 미저장 값 재조회 보존, 사라진 강도 저장 차단과 기본값 생략을 확인했다. 실제 AI 요청은 0회다.

전체 시험/브랜치 최종 리뷰의 확정 결과와 다음 행동은 [최신 인계](../handoffs/2026-10-19-d4a-model-effort.md)에 기록한다. 원장과 사용량은 기존 모델 범위를 유지하므로 요청 Effort의 감사 기록 또는 실제 적용 확인이 아니다.
