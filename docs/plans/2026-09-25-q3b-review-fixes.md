# Q3b 도식 작성과 보고 계획 연결 검토

작성: 2026-09-25. 개발 재개 요청에 따라 [최근 인계](../handoffs/2026-09-22-q3b-reconciliation-validation-handoff.md)의 작성/연결/저장 보호 경계를 검토한다. 기존 누적 변경을 별도 기준본으로 보존하고 확인된 결함만 수정한다.

## 범위와 완료 조건

- 작성 입력, 확인 후보, 저장된 덱과 저장본 식별값을 대조한다. 입력 변경, 창 닫기, 충돌 복구 뒤 늦은 응답이 현재 상태를 바꾸는 경우를 검사한다.
- 실패 테스트로 결함을 재현한 뒤 수정하고 관련 회귀, 전체 테스트와 빌드를 확인한다.
- 독립 리뷰는 별도 주체가 실제 수행한 범위와 결과만 기록한다. 사용자가 리뷰 에이전트 1명 사용을 승인했고 독립 리뷰와 수정 후 재검토를 수행했다. 2026-09-27 결과는 아래에 기록한다.
- 완료/미완료를 로드맵과 인계에 반영한다. 사용자 작업, 스테이징과 프로젝트 데이터를 보존하며 커밋/푸시/머지는 하지 않는다.

## 확인된 실패 경계

1. 도식 확인의 응답이 늦게 도착하면 그 사이 성공한 저장의 ETag를 과거 값으로 되돌린다. 확인 요청에는 기존 If-Match를 보내되 읽기 전용 확인 응답으로 저장용 ETag를 바꾸지 않는다.

확인 API가 반환하는 후보와 HTTP 계약은 유지한다. 전체 보고 계획 재생성, 도식 AI 생성, 지원 배치 확대, 실제 AI 호출과 PowerPoint/독자 품질 검수는 이번 범위에 포함하지 않는다.


## 구현과 자동 검증 결과

API 클라이언트의 ETag 수신 갱신 여부를 요청별로 지정하며 도식 연결 확인만 갱신하지 않는다. 기존 덱 읽기/저장/스냅샷 복구의 갱신 동작은 유지한다. 요청 순서를 고정한 새 회귀 1건은 수정 전 실패, 수정 후 통과했다. 백엔드 1,501개 통과/1개 미실행, 프런트 353개/34파일, 타입/빌드 및 생성 타입 대조를 확인했다. 별도 리뷰와 실제 앱 검증은 수행 여부를 [인계](../handoffs/2026-09-25-q3b-review-fixes-handoff.md)에 분리한다.


## 독립 리뷰 후속 결과 (2026-09-27)

이동 전 저장을 기다리는 동안 새 도식 초안을 열면, 시작 시점만 검사한 이탈 함수가 저장 성공 뒤 이동을 허용해 입력을 버리는 결함 1건을 재현했다. 현재 초안을 ref로 유지하고 저장 응답 뒤에도 다시 검사한다. 6개 이탈/복구/내보내기 경로의 수정 전 실패와 수정 후 통과를 확인하고, 이미 열린 초안의 차단을 대조군으로 유지했다.

독립 재검토는 관련 프런트 6파일 108건 중 실패 0건, 필수 수정 잔여 0건이다. 전체 프런트는 360건/35파일이며 타입/빌드가 통과했다. 백엔드 독립 교란 9건, 실제 Chrome 응답 순서 2개 시나리오도 확인했다. [최신 인계](../handoffs/2026-09-27-q3b-independent-review-handoff.md)에 코드 검토와 실제 앱/품질 검증 범위를 분리했다.
