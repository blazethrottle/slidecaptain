# MVP 구현 로드맵 (v0.1)

> 작성일 2026-08-27. [MVP 설계서](../specs/2026-08-27-mvp-design.md)를 구현 단계로 분해한 문서다.
> 각 단계는 독립적으로 동작하고 테스트되는 산출물을 낸다. 상세 계획서는 단계 착수 시점에 작성한다
> (앞 단계에서 확정된 실제 인터페이스를 근거로 쓰기 위해서다).

## 분해 원칙

설계서 1.3의 구축 순서(세로 관통 MVP)를 따르되, 관통 순서는 "결정론 코어부터"로 잡는다.
근거: 이 제품의 심장은 AI가 아니라 결정론적 레이아웃 엔진과 PPTX 내보내기다(핵심 원칙 "AI는 내용만, 배치는 코드가").
코어가 먼저 서야 AI 파이프라인의 분량 검증(용량 계약)과 편집 화면의 미리보기가 같은 수치를 공유할 수 있다.

## 단계를 가로지르는 아키텍처 결정 (로드맵 수준에서 확정)

1. **레이아웃 계산의 진본은 백엔드 하나**: 미리보기(화면)와 PPTX가 같은 수치를 공유해야 하므로,
   프런트엔드는 레이아웃을 직접 계산하지 않는다. 백엔드가 덱과 프리셋에서 계산한 렌더 계획
   (슬라이드별 프레임 좌표, 글자 크기, 줄바꿈 결과, 그리고 시각 스타일: 폰트, 색, 여백, 행간, 글머리표, 테두리 두께)을 JSON으로 내려주고, 화면은 그것을 그대로 그린다 (2026-08-28 단계 2에서 RenderStyle 내장으로 확정).
   로컬 서버라서 왕복 지연이 문제되지 않고, 레이아웃 논리의 언어 이원화(파이썬과 TS 중복 구현)를 차단한다.
2. **내부 좌표 단위는 pt**: 페이지는 16:9 = 960 x 540pt. 레이아웃 엔진은 pt(실수)로 계산하고,
   PPTX 라이터가 마지막에 EMU(PowerPoint 내부 단위, 1pt = 12,700EMU)로 변환한다.
3. **기본 폰트는 Noto Sans KR, 글자 폭은 추출 시점 1회 실측한 수치를 번들, 런타임은 항상 번들 사용**
   (2026-08-28 개정. 당초 "맑은 고딕 + 폰트 파일이 있으면 런타임 실측"에서 두 가지가 바뀜):
   ① 기본 폰트를 사용자의 실제 덱 관례에 맞춰 Noto Sans KR로 교체했다 (사용자 지시 2026-08-28). OFL 라이선스라
   맑은 고딕과 달리 폰트 파일 자체를 동봉할 수 있고, 실제로 동봉했다 (같은 날 사용자 승인: 정적 Regular와 Bold TTF와
   OFL.txt를 패키지에 포함, serve 기동 시 미설치 환경이면 사용자 권한으로 자동 설치. 코어의 OS 무관 동작 유지).
   ② 런타임 실측 분기를 제거하고 항상 번들 수치를 쓴다: Windows 배포본 Noto Sans KR은 가변 폰트(NotoSansKR-VF.ttf)라서
   무게 인스턴스화에 1회 약 14초가 걸려 런타임 실측이 비실용적이다 (내보내기 요청마다 14초, 테스트 스위트 9분 실측).
   실측은 추출 스크립트가 동봉 정적 파일에서 1회 수행하고, 번들 수치와 동봉 파일의 어긋남은 테스트가 감시한다
   (동봉 파일 기준이라 어느 환경에서나 동작. 당초 설치 폰트 기준이던 감시를 2026-08-28 폰트 동봉과 함께 이전).
   폭 데이터는 레귤러(wght 400)와 볼드(wght 700) 두 벌이다 (2026-08-28 실측: 한글 음절은 두 무게 모두
   920/1000 = 0.92em 균일, 영문은 비례폭에 볼드가 더 넓음. 맑은 고딕의 1.0em과 달라 같은 내용의 줄수 계산 결과가 바뀐다).
4. **역할 태깅은 도형 이름으로**: 내보낸 PPTX의 모든 도형에 "장ID:슬롯" 형식의 이름을 심는다.
   PowerPoint 선택 창에서 사람이 읽을 수 있고, 파일에 그대로 보존되며, 향후 양방향 재수입의 열쇠가 된다.

단계 2 방치 확정(2026-08-28 최종 리뷰 트리아지): create_project 중간 실패 시 deck.json 없는 반쪽 폴더 가능(1인 로컬이라 확률 낮고, 폴더 삭제로 수동 해소), 자료 이름의 연속 마침표(`..` 포함) 과차단(탈출 방지의 안전 쪽 오류), 엔진의 유령 장 백스톱 검사는 무테스트 유지(모델 검증이 앞단에서 차단하므로 방어선 성격), 스냅샷 타임스탬프의 나이브 로컬 시간(시계 역행 시 정렬만 어긋나고 충돌 백스톱이 덮어쓰기를 방지), 같은 마이크로초 스냅샷 충돌 파일(-1 접미사)의 정렬 역전(saved_at 동일, 실해 없음). 폰트 감시 테스트의 환경 의존(시스템 폰트 폴더 고정) 항목은 감시 기준을 동봉 파일로 이전하면서 해소됨(2026-08-28).

단계 3 방치 확정(2026-08-28 최종 리뷰 트리아지): 자료 없는 프로젝트에서는 cover와 divider 생성도 422로 막힘(결정 11과의 표면 모순이나 정상 흐름에서 도달 불가), 수치 게이트의 반복문 안 re.compile(re 내부 캐시가 흡수), CLINotFoundError 갈래의 로그 부재(예외 자체가 원인을 완결 설명), 스모크 1차의 콘솔 인코딩 판독 불가(UTF-8 강제로 해소, 스크립트는 정상).

단계 4 방치 확정(2026-08-29): CLI export는 전역 프리셋을 적용하지 않는다(서버 경로에만 적용되고, CLI에는 data-dir 맥락이 없어 어느 전역 프리셋을 읽어야 할지 정할 수 없음). 미리보기 표 경계선 색은 화면 전용 상수 #D0D7E2를 쓴다(렌더 계획이 내려주는 값이 아니라 화면 쪽 장식이라 백엔드 진본과 무관). 수치 경고(unverified_numbers)는 생성 응답에만 실리고 편집 화면에서 지속 표시되지 않는다(사용자가 편집 화면에서 직접 입력한 수치는 검증하지 않는다: 원저자가 사용자 본인이기 때문이다).

단계 4 방치 확정 추가(최종 리뷰 발견, 2026-08-29): TrustedHost 400은 영어 평문이다(정상 브라우저 사용자는 도달 불가한 경로라 한국어 안내로 다듬을 실익이 없음). 복구 목록 필터가 정형 스냅샷 파일명과 어긋나면 비정형 스냅샷만 남은 상태에서는 목록이 비게 되는데, 빈 목록 안내 문구가 이를 흡수한다. 생성 루프 중 저장 실패 시 해당 장의 진행 표시가 "생성 중"으로 잔존한다(실제 데이터는 실패로 처리되고 표시만 못 따라가는 문제라 실해가 없음). 같은 장을 A에서 B로 옮겼다가 다시 A로 돌아오는 왕복 편집에서는 낡은 AI 응답 결과 패널이 잠깐 표시될 수 있다(장 전환 시 결과를 리셋하므로 다른 장으로의 오귀속은 이미 차단되어 있고, 같은 장으로 돌아왔을 때 화면이 남는 것뿐이다).

파일럿 소형 묶음 방치 확정(태스크 리뷰 발견, 2026-09-01): 업로드 뒤 마지막 파일 열기가 실패하고 실패 목록도 있으면 열기 오류 문구가 실패 목록에 덮인다(방금 저장한 파일 읽기가 실패하는 상황 자체가 드물고, 기존 자료 추가 경로와 같은 유형). 상태 조회의 60초 캐시는 락으로 중복 호출을 막았지만 만료 후 재확인은 자동 테스트가 없다(캐시 적중만 검증, 만료는 코드 경로가 단순함). `claude auth status`를 `--json` 옵션 없이 호출한다(현재 기본 출력이 JSON이고 동봉 CLI 버전이 SDK에 고정되어 있어 옵션 미지원 위험을 피하는 쪽을 택함).

파일럿 소형 묶음 2 방치 확정(태스크 A 리뷰와 최종 리뷰 발견, 2026-09-01): 2026-09-01 이전 deck.json과 스냅샷의 표지 audience 값은 읽을 때 조용히 버려지고 안내가 없다. 버려지는 값은 새 규칙상 표지에 나오면 안 되는 피보고자이고, 피보고자 본값은 meta.audience에 그대로 남으며, 스냅샷 파일 원문은 유지된다(복원 시 무시만 됨). 영향 덱은 파일럿 덱 1개뿐이다. 자료 탭의 라벨 안 힌트가 라벨, 힌트, 입력의 세 줄로 놓이는 것은 브라우저 확인 결과 읽기에 무리가 없어 그대로 둔다.
