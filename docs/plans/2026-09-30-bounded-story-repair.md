# 제한된 계획 수정과 별도 재검수

기존 보고 계획 재작성은 본문/도식/보호 근거를 유지한다. Q4 수정 조정기를 이 경로에 연결하며 원래 Deck는 저장하지 않고 후보만 반환한다. 적용은 기존 apply의 자료 fingerprint/ETag/보존 검사를 다시 거친다.

## 계약

- 사용자가 문제 목록과 호출 상한(2~8), 수정 회차(1~3), 시간(10~300초)을 명시한다. 실패/형식 재시도도 전체 상한에 포함한다. 수정 한 회차 후 별도 호출 문맥에서 현재 자료/후보/본문을 재검수한다. 제공자와 모델은 사용자의 현재 선택 하나이며 자동 전환하지 않는다.
- 별도 호출 문맥은 같은 제공자를 쓰되 수정 대화/추론 기록을 공유하지 않는다. 검수 응답의 무결점 주장은 제출 승인이 아니다. 최소 한 번의 실제 성공 검수와 결과 형식 확인을 요구한다.
- 입력은 현재 원문(기존 100,000자 한도), Deck(60,000자 한도), 보고 질문과 문제 목록이다. 프롬프트의 입력은 자료로 취급한다. 검수는 서명 영수증이나 PowerPoint 검수를 대신하지 않는다.
- 자료/ETag 변경, 취소, 시간/호출 상한, 반복 결함, 잘못된 형식은 후보를 보존하고 중단한다. 서버는 각 호출 진입 전과 응답 뒤에 현재성을 검사한다. 늦은 응답은 저장하지 않는다.
- 사용량은 모든 호출을 기록하며 결측은 null로 유지한다. 비용 상한은 제공자가 검증 가능한 호출당 상한을 제공할 때만 지원한다. 확인할 수 없는 상한은 호출 전에 거절한다.
- UI는 자동 실행하지 않는다. 문제/상한/입력 범위를 보여준 뒤 기존 AI 동의 관문을 이용하고, 별도의 적용 확인을 요구한다. 취소는 요청 중단 신호를 서버로 전달하며 기존 초안과 입력을 지우지 않는다.

## 검증

오프라인 fake 제공자로 실패/재시도/예산 소진/성공 재검수/현재성 변경/형식 오류/취소를 재현한다. 실제 외부 호출은 별도 승인 전 0회다. 독립 계획/구현 리뷰와 UI의 이탈/중복/충돌 검사를 거친다.
