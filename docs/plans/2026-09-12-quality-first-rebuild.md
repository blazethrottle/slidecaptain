# 품질 중심 개선 개발 계획 Q0~Q5

작성: 2026-09-12, 갱신: 2026-10-01 (2026-09-30 일괄 개발 반영). 사용자 승인 범위는 제품/서비스/아키텍처 보완과 개선 개발이다. Q1b의 품질 기록/공통 게시 잠금/검수 이력 조회 다음으로 Q3a의 독립 도식 계약과 Q3b 배치/작성/계획 연결 및 편집 보존 재작성을 구현했다. 2026-09-28 승인된 합성 자료 실제 호출 5회에서 Sonnet의 장 생성/재작성/초안 PPTX와 LUNA의 장 생성을 확인했다. 당시 LUNA 재작성은 보존 계약 위반으로 차단됐다. 2026-09-29 보호 항목을 AI 출력에서 제외한 뒤 새 승인 3회로 LUNA도 장 생성/재작성/초안 PPTX를 완료했다. 회사 자료 외부 전송, 커밋/푸시와 배포는 수행하지 않았다.

진본 연결: [로드맵](2026-08-27-mvp-roadmap.md), [제품 기획](../specs/2026-09-12-quality-first-product.md), [아키텍처](../architecture/2026-09-12-quality-pipeline.md).

2026-09-30 이후 구현·검토와 미실행 수용 조건은 [일괄 개발 기록](2026-09-30-remaining-batch.md)을 따른다. 아래 날짜별 결과는 당시 이력이다. 새 LUNA 합성 측정은 root만 12/12회(생성 9회+분리된 검토 3회), 실패/재시도 0회로 완료했고 비용은 null이다. 단일 페이지 3사례의 개선 우세는 입증하지 못했다. 실제 Windows/PowerPoint/독립 서명/사람 품질 판정은 완료로 표시하지 않는다.

## 이번에 바뀐 결정

템플릿 개수와 렌더 가능 여부가 아니라 보고서의 논리, 근거, 표현과 읽기 품질을 완료 기준으로 삼는다. 기존 DA/DB 코드는 보존한다. UI 확장부터 재개하지 않고 작고 완결된 보고서 제작 흐름을 먼저 만든다. 30점 비교 자료를 골든 정답으로 고정하지 않는다.

## 단계와 의존성

| 단계 | 범위 | 완료 조건 | 현재 상태 |
|---|---|---|---|
| Q0 | 제품 정의, 서비스 흐름, 아키텍처, 기존 진본 정정 | 상충 원칙 정리, 범위와 검증 계획 연결 | 문서 반영 |
| Q1a | 생성 지침, 다른 장 초안 맥락, 구조/용량 사전 점검, 초안 표시 | 기존 경로에 연결, 빈 출력 거절, 미검수와 통과 구분, 아래 검증 항목 충족 | 구현과 로컬 자동화 검증 완료; 실제 보고서 품질 평가는 미수행 |
| Q1b | 검수 API/UI, 검수 이력, 공통 내보내기 잠금 | 현재 리비전 상세와 문제 목록, 낡은 판정 차단, 웹/CLI 동시 안전성 | 기록/API/UI, 공통 게시 잠금과 읽기 전용 전체 이력/조회 시점 대조 구현 및 macOS 검증 완료. Windows 실기기/새 CI는 미검증 |
| Q2 | 보고 질문, 근거 장부, 계산, 전체 보고 계획 | 비교 불가 지표 탐지, 사실/추정 구분, 주장별 출처, 요약 정합성 | 기존 Q2a~d와 계획 재작성에 명시적 단위 환산(Q2e), 미등록 비교/산식·요약 의심 휴리스틱(Q2f)을 추가해 로컬 검증했다. 의미 AI 검수는 not_run이며 자유 문장/원문 의미 정합성 수용은 미완료 |
| Q3 | 표현 중간 모델, 문장 일부 강조, 차트/관계도, 복합 배치 | 대표 보고서 하나에서 적절한 표현 선택과 편집 가능한 PPTX | 기존 도식 경로에 등록 비교 native 막대/열 차트와 원문 hash/문자 위치 부분 강조, DB-6/7을 연결했다. 수동 전체 후보 교체/보호 근거 이전/기존 도식 AI 교체의 guarded 경로 구현. 목표 앱·독자 품질과 지원 범위 확대는 미완료 |
| Q4 | 실제 렌더, 독립 검수, 제한된 수정, 제출 관문 | 필수 검수 누락/실패 시 통과하지 않음, 상한에서 초안 보존 | Q4a에 이어 Q4b provenance/native render 어댑터/서명 receipt 검증/동일 바이트 게시와 호출·시간·반복 상한 계획 수정 후보를 구현했다. 실제 Windows/native render/독립 서명·사람 검수는 미실행 |
| Q5 | 동일 조건 블라인드 비교와 반복 파일럿 | 운영 안전성과 다섯 품질 기준을 함께 충족, 미사용 사례로 확장 | 도구 구현·독립 검토. 단일 페이지 3개 합성 사례·9PPTX 측정 완료. 개선 우세를 입증하지 못했으며 전체 품질 수용·사람 판정은 미완료 |

순서: Q1a 검증 → Q1b/Q2 → 대표 보고서 한 개의 Q3/Q4 관통 → DB-6/7을 새 계약에 맞춰 통합 → Q5. 상세 계획은 앞 단계의 실제 계약을 기준으로 작성한다. 현재 다이어그램만으로 후속 단계가 구현됐다고 하지 않는다.

## Q1a 반영 내역

- models/quality.py: 점검별 대상/문제 수와 not_run, 초안 상태, 입력/출력 해시 계약.
- pipeline/quality.py: 빈 출력, 구조안 누락, 용량 경고 판정. 내용/시각/근거/표현/목표 앱 검수는 명시적 미수행.
- export/exporter.py: 현재 deck/preset/render plan을 점검한 뒤 초안 PPTX와 같은 버전의 sidecar를 기록한다. 빈 덱과 final 요청은 거절한다.
- pipeline/prompts.py: 보고 질문, 논리, 지표 비교 조건, 불확실성, 적절한 표현과 초안 맥락을 생성 지침에 연결한다. 다른 장 초안은 사실의 근거로 취급하지 않는다.
- server/app.py: 품질 관문 거절을 기존 문자열 detail의 422 응답으로 연결한다. HTTP 응답 모델은 유지한다.
- __main__.py: quality 명령과 export --final의 fail-closed 경로. quality는 현재 제출 가능하지 않아 종료 코드 2를 반환한다.
- ProjectView.tsx: 초안 내보내기와 미검수 안내, 점검 기록 경로 표시. 점검 상세 UI는 Q1b다.

추가 AI 호출을 자동 실행하지 않는다. 기존 생성 요청의 지침과 문맥을 보강한 것이며 독립 검수 호출을 구현한 것으로 간주하지 않는다. 생성 초안 맥락에는 장별/전체 한도가 있고 생략을 표시한다. 요약을 마지막에 자동 재검수하는 경로는 Q2/Q4다.

## Q1a 검증 결과

2026-09-12 사용자 승인 후 비기밀 합성 자료로 검증했다. 백엔드 회귀 사례 25개와 프런트 사례 2개를 추가했다. 초기 실패 6건은 빈 덱 성공 기대와 변경 전 버튼 문구에 해당하여 새 정책에 맞게 수정했다. 추가 UI 테스트에서 빈 덱의 비활성 버튼을 클릭하려던 설정 오류도 수정하여 클라이언트 차단과 서버 거절 경로를 분리했다.

| 검사 | 최종 결과 |
|---|---|
| 백엔드 전체 | 954개 중 실패 0개 |
| 프런트 전체 | 252개 중 실패 0개 |
| 프런트 프로덕션 빌드 | tsc와 Vite 빌드 통과 |
| 마지막 프런트 테스트 수정 후 타입 검사 | tsc --noEmit 통과 |
| OpenAPI | 저장된 스키마와 현재 앱의 일치 테스트 통과 |
| 생성 TypeScript 타입 | 임시 경로에 재생성한 타입과 기존 타입 파일이 바이트 단위로 일치 |

확인한 경계는 빈 출력/누락 장/용량 경고, 미검수를 통과로 표시하지 않는 상태, final 거절 시 무출력, 입력 fingerprint와 PPTX 해시, 버전별 기록과 게시 실패 시 기존 산출물 보존, API 422/기존 응답 계약, 프롬프트의 초안 제외/순서/길이 제한, 기존 저장/복구/잠금 경로다. 합성 PPTX를 생성하고 python-pptx로 다시 읽었지만 실제 PowerPoint 화면을 검사한 것은 아니다.

초기 실행에서도 관측된 React act 경고가 일부 기존 프런트 테스트에 남아 있다. 테스트 실패 0개와 경고 없음은 구분한다. 공개 저장소 감사기의 회귀 테스트는 백엔드 전체에 포함되지만 실제 저장소 추적 파일/이력 감사와 커밋/푸시는 이번 단계에서 실행하지 않았다.

Q1a 세션에서는 앱 서버 재시작, 실제 AI 생성과 배포를 하지 않고 [Q1a 인계](../handoffs/2026-09-12-q1a-validation-handoff.md)에서 멈췄다. 다음 사용자 요청으로 진행한 Q2a 결과는 아래와 같다.

## Q2a 첫 태스크 결과 (2026-09-12)

[단위 계획](2026-09-12-q2a-story-plan.md)대로 보고 질문 → 원문 위치와 주장 → 역할별 전체 흐름 → 승인 저장 → 장 생성/축약까지 연결했다. 선택적 `Structure.story_plan`을 API/저장/프런트 편집에서 보존한다. 코드가 원문 발췌와 자료 SHA-256을 만들고 존재하지 않는 참조와 낡은 계획의 재사용을 거절한다. 모델이 분류한 사실/추정/제안/미확인을 의미 검수 결과로 승격하지 않는다.

최종 검사: 백엔드 987개 중 실패 0개, 프런트 257개 중 실패 0개(24개 파일), tsc/Vite 빌드 통과. OpenAPI는 전체 백엔드 테스트에서 현재 앱과 일치했고 TypeScript 임시 재생성 결과도 저장 파일과 일치했다. 새 회귀 사례는 백엔드 33개와 프런트 5개다. 합성 자료만 사용했으며 실제 AI 호출과 PowerPoint 화면 검증은 하지 않았다.

자체 검토에서 발견한 보고 정보/Brief 지시 충돌과 표지에만 연결된 주장 누락 가능성을 실패 테스트로 확인한 뒤 수정했다. 독립 에이전트 리뷰는 수행하지 않았다. 사용자 요청대로 [Q2a 인계](../handoffs/2026-09-12-q2a-story-plan-handoff.md)를 남기고 다음 단위에 착수하기 전에 멈춘다.

## Q2b 비교 계약 결과 (2026-09-12)

[단위 계획](2026-09-12-q2b-metric-comparison.md)대로 근거의 지표 정의, 단위, 주체, 기간과 분모를 구조화하고 선언된 비교 쌍에 조건 일치/불가/정보 부족과 사유를 반환한다. 모델이 만든 판정은 받지 않으며 저장 후 재읽기에서도 코드가 다시 계산한다. 새 q2b-v1 계획은 저장/편집/복원/장 생성/축약과 화면에 전달하고 옛 q2a-v1 저장본의 fingerprint는 유지한다.

백엔드 1,033개 중 실패 0개, 프런트 265개 중 실패 0개(25개 파일), tsc/Vite 빌드와 OpenAPI/생성 타입 대조를 통과했다. 새 회귀 사례는 백엔드 46개, 프런트 8개다. 별도 임시 서버에서 빌드 파일 제공과 세 판정 응답을 확인했다(4건 중 문제 0건). 브라우저 연결이 없고 네이티브 앱 창 접근이 실패하여 실제 화면 조작은 미수행이다. 기존 사용 앱을 재시작하지 않았다.

자체 검토에서 결측끼리의 일치, 달력 기간의 일수 차이, 저장된 판정의 재사용, Q2a fingerprint 호환과 프런트 모의 데이터 계약을 확인했다. 독립 에이전트 리뷰와 실제 AI/PowerPoint/독자 평가는 미수행이다. [Q2b 인계](../handoffs/2026-09-12-q2b-metric-comparison-handoff.md)에서 다음 단위로 넘긴다.

## Q2c 근거 연결 계산 결과 (2026-09-13)

[단위 계획](2026-09-13-q2c-derived-values.md)대로 Q2b 비교와 원문 값에 차이/증감률 산식을 연결하고, 코드가 계산 결과와 불가 사유를 만든다. 퍼센트포인트, 양수 기준, 기간 방향과 반올림을 구분한다. 저장 후 재읽기에서도 결과를 다시 계산하며 q2a/q2b 저장본의 fingerprint를 보존한다. 계산을 화면과 생성/축약 문맥에 전달하고 해당 장의 computed 값만 수치 존재 경고의 근거에 추가했다.

백엔드 1,108개 중 실패 0개, 프런트 275개 중 실패 0개(26개 파일), tsc/Vite 빌드와 OpenAPI/생성 타입 대조를 통과했다. 새 회귀는 백엔드 75개/프런트 10개다. 하나의 합성 저장본을 실제 백엔드 계산과 프런트 표시 검사에서 함께 사용했다. 임시 서버의 HTTP 3개 사례와 Chrome의 정상 계산/계산 불가/반올림 3개 사례에서 문제 0건을 확인했다. 임시 서버에는 실제 AI 프로바이더를 연결하지 않았다.

자체 검토에서 생성 지침 충돌, 숫자 일부/공백 뒤 다른 단위 허용, 구두점 오거절과 계산 불가 안내 문구를 수정했다. 독립 에이전트 리뷰와 실제 AI/PowerPoint/독자 평가는 미수행이며 Q1a 품질 기록의 의미/근거/시각 검수는 계속 not_run이다. [Q2c 인계](../handoffs/2026-09-13-q2c-derived-values-handoff.md)에 다음 수치/문장 정합성 검수 단위를 남겼다.

## Q2d 계산 기준 문구 대조 결과 (2026-09-13)

## 새 도식 AI 후보와 전체 로컬 QA (2026-09-29)

## Q4a 수동 검수 기록과 현재성 (2026-09-29)

[계획](2026-09-29-q4a-review-records.md)에 따라 내보낸 PPTX에 사용자 판정/검수자/페이지/근거를 불변 추가하고 현재 입력 fingerprint와 실제 출력 해시를 재대조한다. 새 기록에 명시적 ETag를 요구하고 과거 통과보다 최신 기록을 우선한다. 손상/읽기 실패는 사용 불가이며 409/412와 내보내기 대기에서 입력을 보호한다. 같은 내용으로 정확히 복원되면 현재성은 다시 회복될 수 있다.

백엔드 1,772개 통과/Windows 전용 1개 미실행, 프런트 463개, 타입/빌드, 실제 HTTP 37개와 Chrome 합성 저장/충돌/만료/480px를 확인했다. 독립 리뷰의 저장 한도/실패 정리/비동기 경합 등을 수정하고 필수 잔여 0건을 확인했다. 기존 PPTX/품질 기록은 유지하며 모든 수동 통과도 제출본 승인이 아니다. 실제 AI 호출은 0회다. Q4b의 독립 검수 영수증/목표 렌더/제출 관문과 실제 독자 품질은 남는다. [인계](../handoffs/2026-09-29-q4a-review-records-handoff.md), [QA](../qa/2026-09-29-q4a-review-records.md).
