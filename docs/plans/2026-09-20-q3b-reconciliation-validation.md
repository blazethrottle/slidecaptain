# Q3b 도식 연결의 저장 충돌 처리와 화면 검증

작성: 2026-09-20. 개발 재개 요청으로 최근 연결 계약의 미검증 경로를 확인한다. 이전 [연결 계약](2026-09-20-q3b-story-plan-reconciliation.md)의 저장/근거/AI 경계를 유지한다.

2026-09-22 개정: 기존 장 재확인 시 계획 순서 변경과 실제 화면의 내부 검증 객체 노출을 실패 사례로 추가해 수정했다. 최종 결과와 남은 독립 리뷰는 [인계](../handoffs/2026-09-22-q3b-reconciliation-validation-handoff.md)에 기록했다.

## 범위와 실패 조건

- 연결 확인의 412 응답을 편집기의 저장 충돌 상태로 전달한다. 작성 입력을 남기고 적용/자동 저장을 차단하며, 닫은 뒤 기존 서버본 복구 경로를 제공한다.
- 연결 확인 전 기존 편집의 저장 대기와 진행 중 저장을 마친다. 저장 실패나 충돌이면 확인 API를 호출하지 않는다. 작성 창의 입력은 이 저장에 포함하지 않는다.
- 충돌을 관측한 뒤 이미 대기 중이던 저장도 요청하지 않는다. 진행 중 요청의 늦은 성공으로 충돌 표시를 지우지 않는다.
- 입력 변경/닫기/원본 변경 뒤 늦은 연결 응답을 적용하지 않는다. 낡은 자료와 저장본의 fingerprint 거절은 유지한다.
- 합성 자료로 기존 도식 수정, 새 장 연결, 저장/재열기, 다른 창 충돌과 자료 변경 거절을 실제 브라우저에서 확인한다.

## 검증과 종료

실패 테스트 재현 후 필요한 프런트 경로만 수정하고 API 거절/무변경 검사, 전체 회귀, 타입/빌드와 생성 계약 일치를 확인한다. 실제 화면의 저장본/스냅샷 보존을 대조한다. 기존 파일은 별도 baseline으로 보관하고 해시 대조 후 이번 차이만 원본에 반영한다.

자체 적대 검토의 초점은 저장을 기다리는 중 창이 닫히는 경우, 저장 412 뒤 대기하던 flush가 재저장하는 경우, 연결 412 뒤 복구 경로가 없는 경우다. 설치된 `engineering:code-review` 기준을 적용한다. 프로젝트가 참조한 superpowers 스킬 검색은 0건이었으며, 별도 주체의 독립 리뷰는 수행 여부를 인계에 분리한다.

도식 AI 생성/전체 재계획, 승인 저장/만료, 배치 범위 확대, 실제 AI 호출과 목표 PowerPoint/독자 품질 검수는 포함하지 않는다. 커밋/푸시/머지는 이번 누적 미커밋 작업에 적용하지 않는다.
