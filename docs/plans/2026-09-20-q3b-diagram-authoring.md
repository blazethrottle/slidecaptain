# Q3b 도식 작성과 검토 화면

작성: 2026-09-20. [이전 인계](../handoffs/2026-09-20-q3b-project-diagrams-handoff.md)의 다음 단위로, 사용자의 개발 재개 요청에 따라 도식 의미 입력 작성/수정과 저장 전 확인만 진행한다.

## 범위와 수용 기준

- 편집 화면에서 새 도식 장을 추가하거나 기존 도식을 별도 작성 창에서 수정한다. 제목/분류/부제/각주, 항목의 내용/역할/사실 구분/조건, 관계의 주체/대상/종류/라벨과 근거를 지정한다. 내부 ID와 좌표를 사용자가 입력하지 않는다.
- 근거는 현재 StoryPlan의 단일 Evidence 목록에서 선택한다. 출처 파일, 행과 등록된 발췌문을 표시한다. 근거가 없어도 명시적 제안은 작성할 수 있다. 사실과 관계의 원문 현재성/의미를 승인했다고 표시하지 않는다.
- 작성 중 입력은 Deck과 분리한다. 필수 입력을 확인하고 기존 POST /api/render-plan으로 전체 Deck의 구조/근거 ID/배치를 검사한다. 오류가 있으면 기존 저장본을 유지하며 구체적인 실패 사유를 보여 준다. 별도 AI 호출이나 저장 API를 추가하지 않는다.
- 확인된 결과만 '도식 적용'으로 기존 편집 상태에 한 번 반영하고 자동 저장/ETag/스냅샷/undo/redo 계약을 사용한다. 그 뒤 수정하면 확인 결과를 지우고 다시 확인하게 한다. 생성/템플릿 변환과 전체 구조안 재생성 제한은 유지한다.
- 작성 중 탭 이동/복원/내보내기/새로고침은 기존 dirty/flush 관문으로 보호한다. 명시적으로 취소하면 작성 중 입력만 버린다. 늦은 검사 응답, 닫힌 작성 창과 바뀐 원본 덱은 적용할 수 없다. 다른 편집을 덮어쓰지 않는다.
- AI 생성, 전체 StoryPlan 재계획, 검수 승인 저장, 분기 배치 확대와 목표 PowerPoint/독자 평가로 확장하지 않는다.

## 사전 반증 검토

1. 검사가 성공한 뒤 한 글자만 바뀌어도 성공 결과를 재사용할 수 없어야 한다. 입력별 요청 순번과 결과 무효화를 검사한다.
2. 원본 덱이 바뀐 뒤 작성 창을 적용하면 다른 편집을 잃을 수 있다. 시작 덱 동일성을 확인하고 충돌 시 내용을 보존한 채 적용을 막는다.
3. 작성 창이 닫힌 뒤 늦은 응답이 새 창의 상태를 바꾸거나 저장하면 안 된다. unmount와 요청 소유권을 검사한다.
4. 노드 삭제가 연결된 관계를 몰래 지우면 의미가 바뀐다. 연결된 항목은 관계를 먼저 삭제하도록 제한한다.
5. 등록된 발췌문 선택과 배치 성공은 사실 검증이 아니다. UI와 기존 품질 상태에서 미검수 표시를 유지한다.
6. 기존 장 추가로 StoryPlan fingerprint가 낡아질 수 있다. 재계산해 승인 상태를 만들지 않고 기존 장부/계획을 보존하며 기존 409 경계를 유지한다.

독립 에이전트 위임은 이번 세션에서 명시적으로 승인되지 않아 수행하지 않는다. 자체 계획/코드 검토와 독립 리뷰 미수행을 구분하고 후속 인계에 남긴다.

## 검증과 보존

실패 테스트를 먼저 작성해 무저장 작성/취소, 근거 선택, 오류/배치 실패, 늦은 응답과 변경 후 재확인, 저장/undo/redo/이탈 방지를 검증한다. 백엔드 기존 API 계약과 프런트 전체 회귀/빌드/타입 일치, 공개 저장소 감사, 실제 브라우저 합성 작성/재열기/배치 실패를 확인한다.

`~/Projects/slidecaptain-work/q3b-authoring-20260920/`의 baseline과 해시 목록에 기존 정규 파일 257개와 스테이징을 보존했다. 해당 폴더의 work에서 구현하고 시작 파일의 현재 해시를 대조한 뒤 이번 변경만 원본에 반영한다. 누적 변경 커밋/푸시/머지/배포는 수행하지 않는다.
