# 기존 보고 계획에 연결하는 AI 도식 초안

작성: 2026-09-29. 최신 재작성 인계 다음의 Q3b 개발 단위다. 사용자의 개발 및 QA 재개 요청에 따라 새 도식의 후보 생성부터 기존 작성/검사/적용까지 연결한다.

## 범위와 완료 조건

- 현재 저장본에 유효한 StoryPlan이 있을 때 새 도식 작성창에서 제목, 보고 역할과 기존 주장을 선택하고 AI 후보를 요청한다. 기존 도식 교체, 새 주장/근거 생성과 기존 본문 재생성은 포함하지 않는다.
- 후보는 작성 폼과 분리해 표시한다. 사용자가 명시적으로 불러온 뒤 수정할 수 있으며 기존 연결/배치 확인과 적용을 거쳐야 Deck에 반영된다. 생성과 후보 불러오기만으로 Deck이나 스냅샷을 저장하지 않는다.
- 현재 선택된 제공자와 모델, AI 전송 동의, 호출 잠금과 사용량 기록을 재사용한다. 자동 제공자 전환은 없다. 형식 재시도는 최대 1회다. 실제 모델 호출 예산은 소진돼 기본 QA는 합성 자료와 고정 응답으로 수행한다.

## API와 생성 계약

`POST /api/projects/{name}/generate/diagram`은 `chapter_id`, `topic`, `role`, `claim_ids`, `instructions`를 받는다. `X-Requested-With`, `X-AI-Consent`, 선택 ID와 명시적인 `If-Match`를 기존 관문으로 검증한다. 기존 장 ID, 빈/중복/미등록 주장, 일반 보고 역할 외의 값, 계획 부재와 낡은 계획/원문은 provider 진입 전에 거절한다.

AI 전용 응답은 `nodes`와 `edges`뿐이다. 서버가 도식 ID, 버전, 캔버스와 배치 종류를 구성한다. 선택한 주장에 연결된 근거만 허용하고 새 Evidence, 좌표, 전체 Deck과 보고 역할/주장 변경을 받지 않는다. 사실/추정/제안/미확인, 관계 자체의 근거와 조건을 기존 DiagramSpec 파서로 검증한다. 지원하지 않는 관계 배치를 조용히 변환하지 않는다.

프롬프트는 보고 정보/질문, 사용자가 선택한 주장과 연결 근거의 등록 발췌, 제목과 지시를 전달한다. 관계의 원문 의미를 확인하고 인과관계를 추정하지 않도록 지시한다. 한 줄/인접 연결 범위를 안내하되 유효한 비인접 관계를 임의로 순서화하지 않는다. 구조 통과 후 기존 배치 검사에서 거절된 후보는 입력 상태로 보존하며 Deck에는 적용하지 않는다.

응답 `DiagramGenerationResult`는 `status`, `diagram`, `raw_text`, `unverified_numbers`, `format_retried`, `usage`, `base_etag`, `sources_fingerprint`를 갖는다. `status`는 기존처럼 `ok` 또는 `format_error`다. 형식 통과는 의미/배치/제출 품질의 승인이 아니며 화면에서 그 범위를 표시한다.

잠금 안에서 저장본/ETag/전체 원문 집합 식별값을 읽고 AI await 동안 잠금을 놓는다. 응답 후 동일 저장본과 자료 집합을 재검사한다. 412/409에서는 후보를 적용하지 않고 기존 저장본을 보존한다. usage 종류에 diagram을 추가하고 OpenAPI/생성 타입을 함께 갱신한다.

## 화면의 보존 규칙

- 새 도식과 유효한 계획에서만 AI 후보 기능을 제공한다. 생성 전 대기 중인 기존 편집을 저장하고 실패하면 호출하지 않는다.
- 후보 요청의 ETag는 동의 대화 이전에 고정하며 응답으로 전역 ETag를 덮어쓰지 않는다.
- 후보가 도착해도 작성 입력을 바꾸지 않는다. 명시적 불러오기는 nodes/edges만 변경한다. 제목/역할/주장은 사용자의 선택을 유지한다.
- 편집, 원본 변경, 충돌과 창 닫기로 오래된 후보/응답을 무효화한다. 호출 중 중복 요청과 모델 변경을 막고 소유한 busy 상태만 해제한다. 동의 취소/실패 뒤 작성 입력을 보존한다.
- 도식 생성 busy를 작성창에서 편집 화면과 프로젝트 화면까지 전달해 AI 설정을 잠근다. AI 동의 overlay는 작성창 위에 표시하고 키보드 포커스는 동의창 안에 유지한다. 전송 고지에 도식 초안 생성과 실제 전송 범위를 추가한다.
- 수동 연결 확인/배치 미리보기/적용과 undo/저장 흐름은 유지한다. 미검수 초안과 제출본 거절도 유지한다.

## QA와 반영

구현 전 실패 회귀를 남긴다. 백엔드는 요청/근거/구조 검증, 선택 및 동의, 재시도/usage, 생성 중 저장/자료 변경, 후보 무저장과 API/PPTX 왕복을 검사한다. 프런트는 동의 취소, 후보 분리, 명시적 불러오기, 편집/늦은 응답/충돌, usage 및 기존 적용 경로를 검사한다.

전체 백엔드/프런트, 타입/빌드, OpenAPI/생성 타입 일치와 공개 저장소 감사를 실행한다. 실제 브라우저에서 합성 후보 생성/불러오기/검사/적용/저장/재열기와 좁은 화면을 확인한다. PowerPoint 설치/접근 가능 여부를 확인하되 미실행을 통과로 바꾸지 않는다. 실제 AI와 독자 품질은 별도 검증 상태다.

원본 `codex/phase-5b`의 HEAD `a8c6d7a`와 303개 파일, Git 인덱스를 기준으로 별도 작업본에서 구현한다. 계획과 구현은 독립 리뷰를 거친다. 검증 후 이번 변경만 원본에 반영하고 그 외 파일/스테이징/브랜치를 대조한다. 커밋/푸시는 하지 않는다.

계획 독립 리뷰는 동의창 표시 순서와 전송 고지의 두 필수 보완을 반영한 뒤 승인됐다. 구현에서는 이 두 동작을 다시 검증하며 계획 승인을 동작 통과로 대신하지 않는다.
