# Q4a: 내보낸 파일의 수동 검수 기록과 현재성

작성: 2026-09-29. 개발 재개 요청과 직전 도식 AI 후보 인계의 Q4 다음 항목을 따른다. Q4 첫 단위이며 목표 앱 렌더, 독립 AI 검수, 자동 수정 및 제출본 게시까지 완료하는 계획이 아니다.

## 범위와 가정

1. 기존 `preflight-v1/v2` 품질 기록과 PPTX는 불변으로 보존한다. 새 기록은 별도 서버 소유 파일에 추가한다. Deck와 StoryPlan 계약은 바꾸지 않는다.
2. 내보내기 이력 상세에서 보고 흐름, 근거, 표현, 시각, 목표 PowerPoint 표시의 수동 검수를 기록한다. 검수자, 항목, 판정, 확인한 페이지 번호와 판단 근거를 필수로 받는다. 사용자가 실제로 확인한 내용을 기록하는 기능이며 에이전트가 사용자의 품질 판정을 대신 입력하지 않는다.
3. `passed`와 `needs_revision`만 입력한다. 대상 0, 중복/범위 밖 페이지, 빈 검수자/근거는 거절한다. 통과는 해당 출력의 모든 페이지를 확인했다고 입력한 경우만 기록한다. 미입력 항목은 `not_run`이다. 자유문장과 자기 신고를 독립성/진실성의 자동 증명으로 취급하지 않는다.
4. 기록은 `export_id`, 게시 당시 input fingerprint, 실제 PPTX SHA-256, 서버 시각 및 규칙 버전에 묶는다. 판정은 사용자가 입력한 값이고 파일/현재성은 서버가 대조한 값으로 분리한다.
5. POST는 `X-Requested-With`, 명시적 `If-Match`, 사용자가 열어 본 fingerprint/PPTX hash를 요구한다. GET은 같은 입력 조회와 잠금에서 기준 ETag를 반환하며 별도 getDeck나 전역 캐시로 보완하지 않는다. readable preflight-v2, artifact matched, current input인 파일만 기록할 수 있다. 저장 직전에 현재 입력, 게시 기록과 실제 파일을 재대조한다. 낡은 deck은 412, 다른 자료/프리셋/출력 또는 손상 기록은 409로 거절한다. 다른 창의 최신 ETag로 검수 기준을 조용히 바꾸지 않는다.
6. GET은 덱/자료/프리셋/PPTX 변화와 읽기 실패에 따라 `current/stale/unavailable`을 반환한다. 과거 검수 기록은 삭제하지 않는다. 훼손된 검수 저장소는 모든 항목을 unavailable로 표시하고 새 기록도 차단한다. 손상된 최신 기록을 건너뛰어 예전 통과를 복원하지 않는다. 원래 입력과 출력이 정확히 복원되면 같은 기록을 다시 현재로 표시할 수 있다.
7. 최신 항목별 판정과 과거 기록을 표시한다. 서버가 OS 게시 잠금 안에서 배정한 순번으로 최신을 정하며 파일 시각이나 사용자 시각을 정렬 기준으로 쓰지 않는다. 새 실패 기록이 예전 통과 기록보다 우선한다. 독립 검수/실제 렌더 증거의 검증은 후속 단위이므로 `final_export_allowed=false`를 유지한다. 수동 통과를 제출 가능으로 표시하지 않는다. 기존 HTTP/CLI `--final`의 차단을 회귀 검사한다.
8. 새로고침/선택 변경/프로젝트 전환 후 늦은 응답은 무시한다. 409/412는 입력을 보존하고 재조회하기 전 저장을 막는다. 검수 폼의 미저장 입력을 버리는 이탈은 명시적으로 확인한다. 기존 편집 화면의 저장/이탈 계약은 유지한다. 복구/덱 읽기 실패 경로의 이력은 읽기 전용으로 두고 정상 이력 탭에만 입력과 이탈 보호를 연결한다.
9. 저장은 기존 프로젝트 잠금 다음에 exports의 OS 게시 잠금을 잡고, 고정한 디렉터리와 안전한 파일 경계를 사용한다. exports 직계 `<export_id>.review.<8자리 순번>.json`을 불변 추가하며 기존 파일을 교체하지 않는다. 경로 우회/심볼릭 링크/깨진 파일을 거절한다. 로컬 사용자가 파일을 직접 위조할 수 있다는 경계는 기존 로컬 앱과 같고, 이 단위가 인증된 서명이나 제3자 인증을 제공한다고 하지 않는다.

## 구현 단위와 검증

- 백엔드: 검수 요청/기록/조회 모델, 안전한 불변 추가 저장, 조회 및 현재성 대조, API와 경합/우회 회귀. AI 호출 없음.
- 프런트: 명시적 기준 토큰을 사용하는 API 클라이언트, 이력 상세의 검수 폼/조회/만료, 비동기 소유권/입력 보존 회귀.
- 같은 단위에서 OpenAPI/TypeScript를 재생성하고 기존 품질 이력/CLI 계약을 대조한다.
- 구현 전 계획 적대 리뷰, 구현 후 독립 코드 리뷰와 재검토를 수행한다. 전체 백엔드/프런트, 타입/빌드, 공개 저장소 감사 및 합성 Chrome 저장/만료 흐름을 확인한다.
- 실제 AI/PowerPoint/독자 품질 검수는 이 기능의 합성 QA로 완료 처리하지 않는다. 원본의 미커밋 변경/인덱스/브랜치를 해시로 보존하고 이번 경로만 반영한다. 커밋/푸시는 수행하지 않는다.

## 후속

Q4b에서 생성자와 분리한 검수 영수증, 실제 렌더와 환경 증거를 저장/검증하고, 모든 필수 항목을 만족하는 동일한 출력 바이트를 제출본으로 게시하는 공통 웹/CLI 관문을 설계한다. 페이지 영향별 선택적 만료, 제한된 수정과 Q5 비교는 별도로 남는다.
