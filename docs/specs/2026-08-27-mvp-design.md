# Slide Captain MVP 설계서 (v0.1)

> 작성일 2026-08-27. 브레인스토밍을 거쳐 합의된 설계다.
> 배경과 요구사항의 원천은 [방법론 히스토리](../background/methodology-history.md)를 본다.

## 1. 프로덕트 정의

### 1.1 문제와 목적

리서치 결과를 보고용 슬라이드(PPTX)로 만드는 과정에서 반복적으로 확인된 문제는 세 가지다.

1. 자료에서 덱까지 가는 조판 작업에 시간이 지나치게 든다.
2. AI 에이전트가 만드는 슬라이드의 품질과 규칙이 매번 달라, 수정에 다시 시간이 든다.
3. 화면 구성과 폰트 크기 조정을 텍스트 프롬프트로 주고받느라 시간과 토큰이 낭비된다.

이 앱의 목적은 다음과 같다.

1. 보고 슬라이드 작성의 효율화
2. 일관된 디자인과 화면 요소, 즉 일관된 품질의 산출물 보장
3. 세부 수정을 텍스트 프롬프트가 아니라 UI 조작으로 처리
4. 기본 템플릿과 사용자별 프리셋을 저장해, 보고의 맥락과 디자인 품질을 일정하게 유지
5. 내용 품질의 워크플로 강제: 결론부터 만들지 않도록, 구조 합의를 거친 뒤 채우는 순서를 화면 플로우로 강제

### 1.2 핵심 원칙

- **AI는 내용만, 배치는 코드가**: AI는 구조화된 콘텐츠(어느 장에 어떤 제목, 불릿, 표가 들어가는지)까지만 산출한다. 좌표, 폰트 크기, 여백은 결정론적 레이아웃 엔진이 프리셋에서 계산한다. 품질 비일관의 근본 원인(확률적으로 동작하는 LLM에 배치를 맡기는 구조)을 제거한다.
- **규격에 내용을 맞춘다**: 내용에 맞춰 규격을 줄이는 방향(자동 맞춤)은 균일성을 깨므로 쓰지 않는다. 고정 규격에서 용량을 역산해 생성 단계에서 계약으로 걸고, 넘치면 글자가 아니라 내용을 조정한다.
- **사용자 직접 수정은 최우선 신호**: 사용자가 UI에서 고친 프리셋 범위의 값은 "이번만 / 프리셋에 저장"으로 물어 규칙에 환류한다.

### 1.3 범위 결정 요약

| 항목 | 결정 |
|---|---|
| 배포 범위 | 1인 사용으로 시작하되, 향후 배포와 수익화 연계를 전제로 설계 (특정 환경 하드코딩 금지, 지침은 프리셋 데이터로 분리, AI 호출부 모듈화) |
| 진본 형식 | 구조화 데이터(JSON)가 진본, PPTX는 내보내기. 양방향(외부 수정 재수입)은 확장 목표 |
| 앱 형태 | 로컬 웹앱 (로컬 서버 + 브라우저 화면. 자료가 PC 밖으로 나가지 않음) |
| AI 호출 | 소유자 본인의 Claude 구독 호출로 시작, 배포 단계에 API 방식 추가 (2.4절) |
| 입력 범위 | 완성된 리서치 자료(마크다운, 텍스트) 입력. 리서치 자체는 범위 밖 |
| 생성 플로우 | 목적 입력 → AI 구조안 제시 → 화면에서 수정하고 승인 → 생성 |
| 편집 자유도 | 구조화된 수정만. 좌표 단위 드래그 없음 |
| 구축 순서 | 세로 관통 MVP: 입력부터 PPTX 내보내기까지 최소 기능으로 관통 후 각 단계를 보강 |

## 2. 아키텍처

### 2.1 기술 스택

| 층 | 선택 | 근거 |
|---|---|---|
| 백엔드 | Python + FastAPI | python-pptx가 PPTX 분야에서 읽기, 쓰기, 저수준 XML 접근을 모두 지원하는 사실상 표준. 한국어 어절 줄바꿈 주입과 역할 태깅 같은 핵심 기법이 저수준 접근을 요구하며, 양방향 목표(재수입)에는 읽기 능력이 필수. Node 진영 대안(pptxgenjs)은 생성 전용이라 부적합 |
| 프런트엔드 | React + TypeScript | 편집 UI(인라인 수정, 순서 변경)에 프레임워크가 필요. AI 코드 생성 지원이 가장 두터운 주류 기술 |
| 타입 공유 | OpenAPI 스키마에서 TS 타입 자동 생성 | 형식 정의의 진본을 백엔드 하나에 두고, 프런트 타입은 기계 생성해 언어 이원화의 어긋남을 도구로 차단 |
| 저장소 | 로컬 JSON 파일 | 1인 단계에는 파일로 충분. 저장 계층을 인터페이스로 추상화해 판매 단계에 DB(PostgreSQL JSONB 등) 구현으로 교체 가능하게 함 |
| AI 호출 | Claude Agent SDK (Python) | 공식 라이브러리. 프로바이더 인터페이스 뒤에 배치 (2.4절) |

되돌릴 수 있는 결정으로 설계한다: PPTX 내보내기를 독립 모듈로 분리해, 훗날 포장 단계에서 스택을 재평가할 여지를 남긴다.

### 2.2 구성 요소

1. **화면(브라우저)**: 프로젝트 목록 → 자료와 목적 입력 → 구조안 승인 → 덱 편집(미리보기 + 구조화 수정) → 내보내기
2. **덱 저장소**: 덱 JSON의 저장, 불러오기, 스냅샷. 저장소 인터페이스(목록, 불러오기, 저장, 스냅샷) 뒤에 파일 구현을 둔다
3. **AI 프로바이더**: 프롬프트 조립 → Claude 호출 → 응답 스키마 검증. 교체 가능한 부품
4. **프리셋 모듈**: 모든 시각 수치의 단일 진본. 미리보기와 PPTX 내보내기가 같은 수치를 공유
5. **PPTX 내보내기**: python-pptx 기반. 축적된 기법(어절 줄바꿈 속성, ASCII 경로, 역할 태깅) 내장

### 2.3 데이터 흐름

자료 + 목적 입력 → AI가 구조안(장 구성 표) 제안 → 화면에서 수정하고 승인 → AI가 장별 내용을 데이터로 채움 → 미리보기에서 구조화 수정(AI 호출 없음, 즉시 반영) → 필요한 장만 AI 재생성 → PPTX 내보내기

### 2.4 AI 프로바이더 구도

정책 근거(2026-08 확인): Anthropic 공식 문서 기준, 본인 구독으로 Agent SDK와 `claude -p`를 쓰는 것은 구독 사용량 한도에서 차감되는 허용 사용이다. 금지되는 것은 제3자 개발자가 자기 제품에 claude.ai 로그인을 제공하는 것(배포 시). 2026-06-15 시행 예정이던 Agent SDK 크레딧 제도는 일시 중지 상태다.

| 단계 | 프로바이더 | 상태 |
|---|---|---|
| 1단계 본인 전용 | 본인 구독 호출: Agent SDK(Python)로 로그인된 Claude Code를 구동. 구독 한도 내 처리 | v0.1 구현 |
| 배포 기본 | 앱 관리형: 앱이 자체 API 키로 호출하고 AI 비용을 포함한 이용료를 받음. 일반 사용자에게 API 키 개념을 요구하지 않음 | 판매 단계 |
| 배포 고급 옵션 | BYOK: 사용자가 자기 API 키를 입력해 원가 사용 | 판매 단계 |
| 미래 조건부 | 사용자 구독 연동: Anthropic이 일시 중지 중인 공식 프로그램을 재개하면 추가 | 정책 워치 |

## 3. 데이터 모델

### 3.1 프로젝트 폴더

```
projects/<프로젝트명>/
  deck.json      # 진본
  sources/       # 입력 자료 원문 (수치 대조의 기준)
  snapshots/     # 저장 시점 스냅샷
  exports/       # 내보낸 PPTX (버전 붙여 보존)
```

### 3.2 deck.json

세 덩어리로 구성한다. 스키마 버전 필드를 두어 형식 변경 시 마이그레이션한다.

1. **메타**: 제목, 보고 유형(연구분석 / 승인요청 / 전략기획), 피보고자, 사용 프리셋, 스키마 버전
2. **구조안**: 승인된 장 구성(순서, 장별 주제, 장별 결론 한 줄, 장별 템플릿 유형, 장별 근거 자료 매핑)
3. **슬라이드**: 장마다 "템플릿 유형 + 슬롯 내용"만 존재. **좌표와 글자 크기는 데이터에 없다.**

### 3.3 프리셋

- 글자: 역할별 크기(제목, 소제목, 본문, 각주), 하한 규칙(본문 12pt, 각주 9pt), 한글과 영문 폰트
- 색: 기본 텍스트, 강조, 표 머리글, 배경
- 여백과 간격, 표 스타일(균일 규격), 페이지 규격(16:9), 언어(ko-KR)
- 전역 프리셋이 기본이고, 덱별로 일부 값만 덮어쓰기 가능

### 3.4 템플릿 (v0.1 6종)

템플릿 하나 = 슬롯 정의(내용 칸의 형식) + 배치 계산 규칙의 쌍.

| 템플릿 | 용도 |
|---|---|
| 표지 | 제목, 부제, 날짜, 보고 대상 |
| 핵심 요약 | 결론 강조 박스 + 요점 목록 |
| 불릿 + 강조박스 | 가장 흔한 본문 장. 주제형 제목 + 불릿 + 결론 박스 |
| 표 중심 | 비교표, 데이터 표. 열 병합 규칙 내장 |
| 2단 비교 | 옵션 비교, 전후 대비 카드 2개 |
| 간지 | 섹션 구분 |

제목은 주제형(그 장이 무엇을 말하는지)만 쓴다. 결론은 강조 박스에 둔다. 본문과 불릿과 표 칸은 압축 문체(명사형 종결, 조사 생략 허용)를 쓴다.

## 4. AI 파이프라인

### 4.1 호출 2종

1. **구조안 생성**: 자료 전문 + 보고 유형 + 피보고자 + 목표 장수 → 구조안 JSON. 사용자가 승인해야 다음으로 간다.
2. **장별 내용 생성**: 승인된 구조안 + 그 장의 근거 자료 → 슬롯 내용 JSON. 장 단위로 따로 호출해 "이 장만 다시"가 저비용으로 가능하다. 슬롯별 분량 한도(5.1절)를 프롬프트에 계약 조건으로 명시한다.

### 4.2 검증 게이트 (코드가 수행, 호출마다 자동)

1. **형식 검증**: 응답이 슬롯 스키마에 맞는지. 실패 시 1회 자동 재시도, 재실패 시 원문을 보여주고 수동 처리
2. **분량 검증**: 실측 줄수(5.2절)로 한도 초과를 확인. 초과 시 축약 재생성 요청
3. **수치 대조**: 생성 문장의 숫자를 추출해 sources/ 원자료에 존재하는지 대조. 원자료에 없는 숫자에는 화면 경고 표지. "근거 없는 수치 금지"를 프롬프트 당부가 아니라 기계 검증으로 강제한다

## 5. 레이아웃 엔진과 오버플로 정책

### 5.1 용량 계약

폰트, 상자 폭, 상자 높이가 프리셋으로 확정되어 있으므로, 각 슬롯의 최대 분량(줄수, 불릿 수, 표 행수)을 사전에 역산할 수 있다. 이 한도를 AI 생성의 계약 조건으로 걸어 넘침을 생성 단계에서 차단한다.

### 5.2 실측 검증

글자수가 아니라 실제 폰트의 글자 폭 데이터로 줄바꿈 지점을 계산해 정확한 줄수를 잰다(결정론적). 안전 여유율을 두어 미리보기와 PowerPoint 실제 렌더의 미세 차이를 흡수하고, 최종 확인은 렌더 검증(7.3절)이 담당한다.

### 5.3 해소 사다리

초과 시 아래 순서로 해소한다. **글자 크기 축소는 사다리에 없다** (하한 규칙).

| 순서 | 조치 | 방식 |
|---|---|---|
| 1 | AI에 축약 재생성 요청 (요지 유지, 한도 명시) | 자동 |
| 2 | 구조 조정 제안: 표 열 병합, 불릿 수 축소, 장 분할 | 앱이 제안, 사용자 승인 |
| 3 | 내용 강등 선택: 각주나 발표자 노트로 내릴 문장 선택 | 사용자 |

### 5.4 좌표 계산 원칙

좌표는 조정 대상이 아니라 프리셋 수치(여백, 기준선, 간격)에서 나오는 수식의 결과다. 같은 역할 요소(제목, 본문 영역, 각주, 쪽번호)는 모든 장에서 같은 위치다. 내용이 적으면 위 기준선 정렬을 유지하고 아래를 여백으로 남긴다(장별 세로 중앙 정렬 금지). 시각 요소(표, 향후 차트)는 템플릿이 정한 고정 프레임 안에 생성되며, 요소 크기에 맞춰 페이지가 변형되지 않는다. 한 페이지의 글자 크기 단계는 2개 이하로 제한한다.

## 6. 편집 화면

세 구역: 왼쪽 장 목록(순서 변경), 가운데 미리보기(클릭 선택), 오른쪽 속성 패널.

### 6.1 즉시 반영 조작 (AI 호출 없음)

| 조작 | 동작 |
|---|---|
| 텍스트 직접 수정 | 미리보기에서 클릭해 타이핑. 즉시 분량 실측, 초과 시 경고와 해소 사다리 |
| 장 순서 변경 | 드래그(순서만 변경) |
| 템플릿 교체 | 호환되는 슬롯은 자동 이사, 갈 곳이 없는 내용은 버리지 않고 보류 영역에 보관해 수동 배치 |
| 프리셋 값 조정 | 덱 전체 일괄 반영. 특정 장만 예외로 두는 기능은 없다 |
| 표 조작 | 열 병합, 행 삭제, 값 수정 |
| 불릿 추가와 삭제, 강조박스 수정 | 즉시 반영 |

### 6.2 AI 재생성 조작 (명시적 버튼)

"이 장 다시 생성"(지시문 입력 가능), "이 장 축약". 장 단위 호출.

### 6.3 프리셋 환류

프리셋 범위의 값을 고치면 "이번 덱만 적용 / 프리셋에 저장"을 묻는다. 저장하면 다음 덱부터 기본값이 된다.

## 7. 내보내기와 파일 안전

### 7.1 PPTX 내보내기

- 모든 텍스트 run에 ko-KR 언어 속성을 주입해 어절 단위 줄바꿈을 보장한다
- 모든 요소에 역할 태깅(몇 번 장의 어떤 슬롯인지)을 심는다. 향후 양방향 재수입의 열쇠다
- 한글 경로에서도 안전하도록 ASCII 임시 경로로 변환 후 처리한다
- 재내보내기 시 기존 파일을 덮어쓰지 않고 새 버전 파일로 저장한다(사용자가 PowerPoint에서 직접 고친 수정분의 소실 방지)

### 7.2 오류 처리

| 상황 | 처리 |
|---|---|
| AI 응답 형식 불일치 | 1회 자동 재시도 → 원문 표시 + 수동 반영 경로 |
| AI 호출 실패(미로그인, 한도 소진) | 원인별로 쉬운 말 안내 |
| 저장 사고 | 원자적 쓰기(임시 파일 후 교체) + 저장마다 스냅샷 + 복구 메뉴 |
| 렌더 검증 오염 | 검증은 항상 사본으로만 열고 종료를 코드로 보장 |

### 7.3 렌더 검증

Windows에서는 내보내기 후 PowerPoint 자동화로 사본을 열어 확인하는 검증을 옵션으로 제공한다. 환경이 없으면 건너뛴다. macOS 렌더 검증은 로드맵.

## 8. 테스트 전략

TDD로 진행한다. 실측된 실패 목록이 회귀 테스트가 된다.

- **골든 테스트**: 같은 덱 데이터로 내보낸 PPTX를 코드로 다시 열어 좌표, 폰트, ko-KR 속성을 기준값과 대조
- **회귀 항목**: 어절 줄바꿈 속성 존재, 본문 12pt 하한, 페이지당 크기 단계 2개 이하, 역할 태깅 존재, 내보내기 전후 deck.json 불변
- **분량 실측기**: 알려진 문장이 예상 줄수로 계산되는지
- **AI 파이프라인**: 모의 응답으로 형식 검증, 재시도, 수치 대조를 검사(실호출 없음)
