# 단계 5B 반복 파일럿 관찰지 (3건, 2026-09-07 준비)

> 목적: 실제 업무 보고서 **3건**을 Slide Captain으로 끝까지 만들며 관찰을 기록한다. 이 기록이 5B 판정의 유일한 근거다.
> 채우는 사람: 사용자 본인. 형식을 지킬 필요는 없고 빈칸에 편하게 적으면 된다.
> 계획서: [2026-09-07-phase5b-repeatable-pilot.md](../plans/2026-09-07-phase5b-repeatable-pilot.md). 판정 기준 정본은 설계서 9.2절이다
>
> ⚠️ **회사 기밀 주의**: 이 파일은 공개 GitHub 저장소에 올라간다. 자료 내용, 회사 이름, 사람 이름, 파일 경로에 든 계정명을 적지 말고 **앱 사용 경험만** 적는다. 감사기가 계정 경로는 자동으로 막지만 회사 이름 자체는 막지 못한다.

## 시작 방법

1. macOS는 저장소 루트의 `SlideCaptain실행.command`를 더블클릭한다. Windows는 `SlideCaptain실행.bat`이다. 서버 창이 열리고 브라우저가 http://127.0.0.1:8765 로 열린다
2. 프로젝트를 만들고 실제 자료(마크다운, 텍스트, 엑셀)를 넣는다. 자료는 이 PC 밖으로 나가지 않는다. 단 AI 생성 시 자료 내용이 본인 Claude 구독 호출에 포함된다
3. 흐름: 자료 입력 → 보고 정보 저장 → 구조안 생성 → 표에서 수정 후 승인 → 장별 생성 → 편집 → PPTX 내보내기 → 실제로 열어 확인
4. **3건은 서로 다른 유형을 권장한다** (예: 텍스트 자료 중심 1건, 엑셀 포함 1건, 분량이 큰 1건). 유형이 겹치면 세 번 돌려도 같은 사실만 세 번 확인하게 된다
5. **도중에 고치지 않는다.** 불편한 것은 아래에 적기만 하고 끝까지 간다. 세 건이 같은 상태의 앱에서 돌아야 비교가 성립한다. 다만 **끝낼 수 없는 결함**을 만나면 거기서 멈추고 알려 주면 된다(고친 뒤 3건을 다시 센다)

## 판정 기준 (파일럿 시작 전 확정, 2026-09-07)

세 건을 다 마친 뒤 이 표를 채운다. **기준은 결과를 보고 고치지 않는다.**

| 축 | 기준 | 결과 | 통과 |
|---|---|---|---|
| 데이터 유실 | 0건 | | ☐ |
| 작업 완주 | 3건 전부 완주 | | ☐ |
| 수동 수정 시간 | 기존 방식 대비 "비슷하거나 빠름" | | ☐ |
| AI 재시도 | 구조안 1회 이하, 장별 평균 2회 이하 | | ☐ |
| 표시 결함 | 레이아웃 깨짐과 글자 잘림 0건 | | ☐ |
| 재사용 의사 | 3건 중 2건 이상 "예" | | ☐ |

**유실의 정의** (이 구분이 판정을 가른다):

- **유실로 센다**: 화면이 "저장됨"이라고 했는데 실제로 안 남았다. 또는 되돌리기, 새로고침, 브라우저나 앱 재시작으로 되돌아오지 않는 내용이 사라졌다
- **유실로 세지 않는다**: 강제종료나 정전으로 저장이 시도되기도 전에 끊겨서 마지막 자동저장 이후 몇 초에서 몇 분치가 날아갔다. 이건 아래 "자동저장 주기 한계" 칸에 따로 적는다
