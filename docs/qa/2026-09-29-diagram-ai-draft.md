## Chrome 실제 화면

합성 프로젝트 2개로 아래 경계를 직접 조작했다.

- 첫 동의창이 작성창 위에 표시된다. 480px에서 동의창 폭은 472px이고 Tab이 확인/취소 안에서 순환한다. 취소 시 해당 프로젝트의 생성 요청은 0회였다.
- 동의 취소와 승인 뒤 모두 작성창의 활성 입력으로 포커스가 돌아왔다. 생성 중 모델/이동 버튼은 잠긴다.
- 후보가 도착해도 기존 수동 입력을 유지한다. 후보는 사실/제안/조건/관계/근거와 usage 미확인을 보여 준다. 제목과 보고 역할/선택 주장을 유지한 채 명시적으로 nodes/edges만 불러온다.
- 불러오기 이후에도 도식 적용은 비활성이다. 기존 연결/배치 검사 후 적용할 수 있다. 후보 생성 및 검사 시 저장본 동일성과 스냅샷 0개를 확인했다.
- 적용/저장/새로고침/재열기 후 3장을 확인했다. 기존 두 슬라이드와 모든 주장/근거는 같고 새 도식의 역할은 evidence였다. 기존 도식 수정창에는 AI 교체 기능이 표시되지 않는다.
- 입력 변경은 후보를 무효화한다. 요청 중 작성창을 닫아도 요청 종료까지 모델 잠금을 유지하고 닫힌 후보는 저장하지 않는다.
- 480px의 기존 편집기에서 미리보기 폭 0px와 문서 폭 540px를 발견했다. 좁은 화면을 한 열로 바꾼 뒤 문서 폭은 480px, 미리보기와 holder는 모두 448×252px였다.
- 1440px에서는 기존 3열과 884×497.25px 미리보기를 확인했다. 다시 480px로 바꿔도 448×252px로 돌아왔으며 두 크기 모두 canvas와 holder의 하단 좌표가 같았다.

화면 증거는 `qa/480px-final.png`, `qa/desktop-final.png`, 수치는 `qa/browser-layout.json`, 포커스는 `qa/browser-focus.json`에 있다. 테스트 도구의 뷰포트 설정값과 실제 `innerWidth`를 함께 대조했다.
