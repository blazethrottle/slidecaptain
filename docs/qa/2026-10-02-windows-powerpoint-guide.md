# 2026-10-02 Windows PowerPoint 검수

최신 개발 브랜치는 `codex/phase-5b`다. 이 절차는 현재 버전의 표시·편집과 사용자가 직접 판정하는 품질 피드백을 준비한다. 회사 자료를 GitHub에 올리거나 외부 AI로 전송할 필요가 없다. 실제 Windows 검사와 사람 판정은 검수 당일 수행한다.

## 회사 PC에서 시작

1. 회사 PC의 SlideCaptain 폴더에서 Codex 또는 Claude에게 아래 재개 문장을 전달한다. 에이전트가 현재 변경과 브랜치를 먼저 확인하고 최신 개발 브랜치를 가져온다. 기존 프로젝트와 인증 프로필을 보존하며 reset/stash/clean을 사용하지 않는다. `main`에는 이번 개발본이 없으므로 브랜치를 반드시 확인한다.
2. 열려 있는 PowerPoint 문서의 수정분을 저장하고 PowerPoint를 닫는다. 앱의 새 글꼴 설치가 완료된 뒤 다시 연다. 이전 **SlideCaptain review server** 창이 있으면 그 창을 닫는다. 평소 앱은 8765, 이번 검수 앱은 8870을 사용한다.
3. 저장소 루트의 **Windows검수준비.bat**를 더블클릭한다. 현재 checkout의 백엔드를 설치하고 프런트를 빌드한 다음, 새로운 검수 폴더·PPTX·피드백 양식·합성 프로젝트를 만든다. Python 3.13 이상과 64비트 Node 22 이상/npm이 필요하다. 이미 설치돼 있지 않으면 에이전트가 README에 따라 환경을 먼저 준비한다. 준비 과정에는 의존성 다운로드가 있고 AI 호출은 없다.
4. 피드백 양식과 파일 폴더, `http://127.0.0.1:8870` 검수 앱이 열린다. 버전은 양식의 commit 값으로 확인한다. 폴더가 열리지 않으면 `projects/windows-review/latest-run.txt`에 적힌 폴더를 연다. 준비를 다시 실행할 때마다 새 회차가 생기며 이전 검수 결과를 덮지 않는다.

회사 PC 에이전트에게 전달할 문장:

> SlideCaptain 2026-10-02 Windows PowerPoint 검수를 시작해줘. 저장소와 미커밋 변경을 보존하고 origin의 codex/phase-5b 최신 버전을 별도 깨끗한 checkout 또는 안전한 fast-forward로 준비해줘. docs/qa/2026-10-02-windows-powerpoint-guide.md를 읽고 Windows검수준비.bat로 검수 앱과 피드백 폼을 열어줘. 기존 회사 프로젝트·인증정보는 옮기거나 덮지 말고, 실제 AI 호출 없이 먼저 합성 샘플의 PowerPoint 표시·편집·native render를 확인하자. 품질 판정과 피드백은 내가 직접 남길게. 피드백 JSON과 실제 검사 결과를 로컬에 보존해줘.

## 파일과 페이지 확인

준비된 샘플 5개, 총 15페이지를 모두 확인한다. 샘플은 결정론 렌더와 편집 기능 확인용이며 AI 보고서 품질의 우세를 측정하는 눈가림 비교가 아니다. 이전 Q5의 사람 비교 0/9 상태는 이 검사로 소급 변경하지 않는다.

| 샘플 | 페이지 | 확인할 내용 |
|---|---:|---|
| templates | 10 | 표지·요약·불릿·표·비교·구분·강조·카드·절차·행렬의 표시와 편집 |
| diagram | 2 | 노드·연결선·라벨, 사실과 제안 구분, 도식·표지 표시 |
| bar | 1 | 가로 막대, 값 1200/1000, 원 단위·기간·0축, 차트 데이터 편집 |
| column | 1 | 세로 막대와 같은 조건, 차트 데이터 편집 |
| emphasis | 1 | 첫 두 글자 굵게, 나머지 문장, 줄바꿈과 글자 폭 |

양식의 PPTX 링크를 눌러 다운로드되면 내려받은 파일을 PowerPoint로 연다. 또는 열린 검수 폴더의 `store/<샘플>/exports/`에서 PPTX를 더블클릭한다.

- **표시**: 모든 페이지를 일반 보기와 슬라이드 쇼에서 확인한다. 제목·본문·각주 잘림, 겹침, 한글 줄바꿈, 글꼴 대체, 글자 크기, 정렬, 강조·색, 페이지 균형과 가독성을 기록한다.
- **편집**: 텍스트·표 셀·차트 데이터·도식 노드를 직접 고쳐 본다. 원본 대신 `-edited.pptx`라는 별도 이름으로 저장하고 닫았다 다시 열어 수정이 유지되는지 확인한다. 앱이 만든 원본은 해시 대조와 native render에 쓰므로 보존한다.
- **흐름·근거·표현**: 의미를 이해할 수 있는지, 문구가 과도하게 단정하는지, 비교 조건·수치가 유지되는지 판정한다. 기능 샘플만으로 실제 업무 보고서 전체의 품질을 판정하지 않는다. 직접 만든 보고서의 추가 평가는 양식 마지막 칸에 페이지 번호와 문제를 적는다.

## 앱에서 실제 렌더와 검수 기록

1. 수정하지 않은 원본 PPTX를 사용한다. PowerPoint 문서를 저장하고 모두 닫는다. 앱에서 합성 프로젝트를 열고 **검수 이력**에서 준비된 출력 기록을 선택한다.
2. **PowerPoint 렌더 실행**을 누른다. 실제 설치본의 버전·빌드와 전체 페이지 렌더 결과가 기록된다. PowerPoint 미설치·실행 중·권한 차단이면 실패 사유를 기록한다. 에이전트가 사용자 문서를 강제로 닫거나 프로세스를 일괄 종료하지 않는다.
3. 전체 페이지를 직접 확인한 뒤 검수 기록의 다섯 기준과 페이지 범위, 근거를 채워 **검수 기록 저장**을 누를 수 있다. 피드백 양식과 앱의 수동 검수 기록은 별도이며 JSON이 자동으로 앱에 적용되지 않는다.
4. 실제 렌더가 끝나도 독립 서명 검수 없이는 제출본 게시가 차단된다. 이번 직접 피드백은 기능 개선 입력이며 서명 검수 영수증이나 최종 제출 승인으로 자동 승격되지 않는다.

## 피드백 저장

양식에서 환경과 파일별·페이지별 판정, 문제 위치·기대 결과·실제 결과·원하는 수정, 실제 수정 시간을 작성한다. 미평가·미측정은 빈칸으로 둔다. **피드백 JSON 저장**을 눌러 내려받은 파일을 보관한다. 중간에도 저장할 수 있고 같은 회차 양식의 **저장한 피드백 불러오기**로 이어 쓸 수 있다. 브라우저 임시 저장은 보조이며 최종 보관본은 다운로드한 JSON이다.

다음 개발 세션에는 JSON과 문제가 보이는 페이지 번호·민감정보를 가린 화면을 전달한다. 회사 원문·계약·내부 인명·비공개 수치를 개인 GitHub나 위키에 넣지 않는다. 검수 데이터와 인증정보는 공개 커밋에서 제외한다.

## 준비 검증과 남은 상태

검수 준비 스크립트는 현재 exporter로 파일을 만들고 PPTX 해시와 버전, 페이지 목록을 기록한다. 반복 실행은 새 폴더를 만들고 기존 프로젝트를 바꾸지 않는다. Windows 배치와 실제 PowerPoint 실행은 회사 PC에서 확인해야 하며 로컬 자동화·CI 결과로 실제 표시 통과를 대신하지 않는다. 추가 AI 생성은 이 준비에 포함하지 않는다.
