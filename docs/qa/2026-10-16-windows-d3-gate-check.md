# 회사 PC(Windows) D3 관문 확인 기록 (2026-10-16)

[회사 PC 재개 인계](../handoffs/2026-10-16-windows-resume.md) 4절과 5절에 따라 이 Mac이 판정할 수 없는 D3 관문 항목을 회사 PC에서 확인한 기록이다. 확인 대상은 main `688ad3b`이고, 확인 중 고친 것은 브랜치 `fix/windows-company-pc-20261016`에 있다(6절). 실제 자료 폴더와 8765 포트는 열지 않았고, 실제 AI 호출은 0회다. 사람의 판정은 사용자가 했고, 이 문서는 사용자의 판정과 에이전트의 관측을 구분해 적는다.

## 3. D3 관문 항목 (인계 4절 A)

### A1 실제 PowerPoint 표시 대조

에이전트 관측:

1. 표본 PPTX 5개 15쪽을 앱의 `render-export`(PowerPoint 렌더 어댑터)로 렌더했다. 15쪽 모두 렌더됐고 원본 SHA-256은 보존됐다. 남은 차단 사유는 독립 검수 영수증 없음(설계상 예상)이고, bar와 column은 10-02와 같이 사전 점검 실패 1건이 더 있다.
2. templates 프로젝트에서 직접 수정을 했다. 3쪽 결론 상자는 손잡이로 150px 끌어 위로 160.44pt 옮기고 글자를 12pt에서 14pt로 바꿨다. 4쪽 표는 본체를 끌었는데 가로는 슬라이드 오른쪽 끝에서 멈춰 50pt만 움직였다. 이어서 Shift+아래 방향키(10pt)와 왼쪽 방향키 3회(3pt)를 눌렀다. 저장값은 3쪽 `dy_pt -160.44`, `font_scale 1.1667`, 4쪽 `dx_pt 47`, `dy_pt 30.93`이다.
3. 내보낸 `_v002.pptx`를 원본과 EMU 단위로 비교했다. 도형 53개 중 고친 2개만 바뀌었고, 이동량은 저장값과 pt까지 같았다. 글자 크기도 12pt에서 14pt로 바뀌었다.
4. v002를 PowerPoint로 렌더해 앱 미리보기 캡처와 겹쳐 봤다. 옮긴 두 요소의 위치는 캡처 정밀도(약 1pt) 안에서 일치했다.
5. 차트 숫자 끝의 마침표(`1200.`, `1320.`)를 10-02와 같이 관측했다. 6절에서 고쳤다.

사용자 판정(PowerPoint 일반 보기와 슬라이드 쇼):

- v002 4쪽: 표가 오른쪽으로 지나치게 뻗어 그려져 있다.
- v001과 v002 9쪽(번호 단계): 내용과 글자가 좌우로 너무 넓게 떨어져 있고, 오른쪽 글자가 지나치게 작다.
- v001과 v002 10쪽(분류표): 오른쪽 글자와 글상자가 위쪽으로 치우쳐 있다.

세 지적 모두 앱 미리보기에서도 같은 모양이다. 따라서 PowerPoint 표시 차이가 아니라 템플릿과 직접 수정 규칙의 품질 문제다. 4쪽은 에이전트가 옮긴 결과이며, 앱이 요소를 본문 여백 밖, 슬라이드 끝까지 옮기도록 허용한다는 점이 드러났다(`clampOffset`, 설계 리뷰 RR3). 9쪽은 메모가 각주 크기(9pt)로 본문 영역 오른쪽 끝 140pt 칸에 오른쪽 정렬되는 설계 때문이다. 10쪽은 나열 칸에만 세로 정렬 지정이 빠져 있었다. 10쪽은 사용자 결정으로 고쳤고(6절), 9쪽과 이동 범위는 로드맵 이월표에 올렸다.

판정 근거 요약: 사용자가 옮긴 요소의 위치, 글자 크기, 표 모양은 앱 미리보기와 PowerPoint가 일치한다. 사람이 판정한 디자인 문제 3건은 PowerPoint와 무관하다.

### A2 한글 입력기 조합과 붙여넣기

사용자 판정: 문제 없음. 사용자가 Microsoft 한국어 입력기로 1쪽(표지) 제목에 한글을 입력하고 조합 중에 Enter, Tab, Esc를 눌렀으며, 메모장의 한글 문장을 부제에 붙여 넣었다.

에이전트 관측: 저장 파일의 제목은 "합성 요청 처리 보고 아아아아 테스트 입", 부제는 붙여 넣은 문장 그대로다(15:03 저장). 조합 중이던 글자가 Enter로 확정된 흔적이 있고, 글자가 두 번 들어가거나 빠진 곳은 없다. 사용자가 "수정 완료" 뒤 F5를 누르자 화면이 프로젝트 목록(첫 화면)으로 돌아갔다. 앱이 현재 프로젝트와 단계를 주소나 브라우저 저장소에 남기지 않기 때문이며, 설계 문서에 새로 고침 뒤 위치 복원 약속은 없다. 내용은 유지된다. 이월표에 올렸다.

### A3 Windows 150% 배율과 좌표 변환

사용자가 주 모니터의 Windows 배율을 150%로 바꿨고(devicePixelRatio 1.5, 창 1280x495 CSS px), 뒤이어 Chrome 확대를 125%로 바꿨다(1.875). 에이전트가 templates 5쪽 왼쪽 카드(420pt)를 옮겼다. 기대값은 화면에 그려진 카드 폭으로 1pt당 CSS 픽셀 수를 구해 계산했다.

| 조건 | 1pt당 CSS px | 조작 | 기대 | 저장값 |
|---|---|---|---|---|
| 150%, 확대 100% | 0.7844 | 손잡이 끌기 가로 +60px, 세로 +40px | +76.49pt, +51.00pt | +76.49pt, +51.00pt |
| 같은 조건 | 0.7844 | 오른쪽 방향키 5회, Shift+아래 1회 | +5pt, +10pt | +5pt, +10pt |
| 150%, 확대 125% | 0.5667 | 손잡이 끌기 가로 +34px, 세로 -17px | +60pt, -30pt | +60pt, -30pt |

저장 파일의 이동값은 `dx_pt 141.49`, `dy_pt 31`이다. 앱에서 내보낸 `_v003.pptx`를 v002와 비교하면 도형 53개 중 이 카드만 같은 거리를 옮겼다. 판정: 끌기 이동량은 배율과 확대에 관계없이 같은 pt로 저장되고, PPTX 위치도 저장값과 같다. 끝난 뒤 사용자가 확대와 배율을 원래 값(100%)으로 되돌렸다(devicePixelRatio 1 확인).

관측: 처음 요소를 옮기면 미리보기 위에 위치 안내 줄이 새로 생겨 미리보기 전체가 한 줄 아래로 밀린다. 이월표에 올렸다.

## 4. 기록용 항목 (인계 4절 B)

- B1 아이콘 글자: 화면 코드가 쓰는 기호 10종(체크, 빈 원, 엑스 두 종, 위아래 화살표, 오른쪽 화살표, 가운뎃점, 글머리 점, 짧은 줄표, 체크 상자)을 Windows Chrome에서 앱 글꼴 설정으로 40px로 띄워 확인했다. 모두 네모 없이 표시된다.
- B2 잠금 관련 건너뜀: `test_service_lock.py` 3건(POSIX 자식 상속, POSIX 권한 비트, 심볼릭 링크 권한), `test_export_lock_safety.py` 9건(링크 불가 2, POSIX 이름 바꾸기 경계 7), `test_process_restart.py` 5건(가짜 CLI와 SIGKILL이 POSIX 전용, 사유 문구가 "Windows는 회사 PC 확인"). 전체 건너뜀 46건의 사유 분포는 가짜 CLI 래퍼 13, 링크 생성 권한 8, POSIX 이름 바꾸기 경계 7, 가짜 CLI와 SIGKILL 5, 사용 중 디렉터리 이름 고정 3, 그 밖 10이다.
- B3 동기화 폴더: 사용자 결정으로 하지 않았다. 이 PC의 OneDrive 폴더는 있지만 OneDrive가 실행 중이 아니었다.
- B4 라우트 대조 도구의 인코딩: 2절의 두 결과. 6절에서 고쳤다.
- B5 데스크톱 앱: main 코드로 frozen 서비스를 빌드했고(`build_desktop_service.py`, 47초), smoke가 모든 항목을 통과했다(frozen, ui, 읽기와 저장과 내보내기와 재시작, 부모 EOF 종료, 무관한 서비스 보존, 같은 폴더의 두 번째 서비스 거부, 작업 원장 실패 시 닫힘, AI 호출 0). `npm run dist -- --dir`로 미서명 패키지를 만들었다. 출력은 모두 저장소 밖(`%USERPROFILE%\sc-b5`)이고, 자료 폴더는 `SLIDECAPTAIN_DATA_DIR`로 합성 자료 사본을 지정했다(서비스 명령줄 `--data-dir`로 확인).
  - 저장 전에 닫기: 사용자가 장 주제에 글자를 입력하고 곧바로 창을 닫았다. 경고 없이 닫혔지만 입력("표지ddd")은 저장됐다. 닫기 처리 중에 자동 저장이 먼저 끝난 것으로 보인다. 경고 대화 상자가 뜨는 조건(닫는 순간 저장되지 않은 변경이 남은 상태)은 재현하지 못했다.
  - 창 닫기와 자식 종료: 창을 닫으면 앱 프로세스와 서비스 프로세스가 모두 끝났다. 앱 본체를 강제 종료(Stop-Process)하면 서비스가 1초 안에 끝났고 남은 프로세스는 없었다.
  - 재시작: 이전 실행의 잠금 파일이 남아 있어도 서비스가 잠금을 얻고 떴으며, 입력이 유지됐다. Ctrl+R은 웹과 같이 첫 화면(프로젝트 목록)으로 돌아간다.
  - 확인하지 못한 것: AI 작업 중 닫기의 "계속 작업 / 취소 후 닫기" 대화 상자(실제 AI 호출 없이는 재현되지 않는다).

## 5. 확인 중 관측한 것

- 백엔드 시험이 실제 사용자 계정의 글꼴 등록을 바꾼다. 확인 당시 HKCU 글꼴 등록 2건(`Noto Sans KR`, `Noto Sans KR Bold`)이 그날 시험의 pytest 임시 폴더를 가리켰다. 격리 픽스처가 글꼴 폴더만 임시로 돌리고 레지스트리 쓰기, 세션 글꼴 추가, WM_FONTCHANGE 방송은 막지 않았기 때문이다. 앱이 사용자 폴더에 글꼴을 설치한 PC라면 정상 등록이 임시 경로로 덮이고, 임시 폴더가 지워지면 글꼴이 사라진다. 사용자 결정으로 두 항목을 백업한 뒤 지웠고(백업은 저장소 밖), 6절에서 고쳤다.
- 차트 축 서식이 PowerPoint의 그림 영역 배치를 바꾼다. 종전 서식(`0.##############`)에서 PowerPoint는 세로 막대 차트의 그림 영역을 계획보다 9pt 위로 줄여 그렸다(계획 x축 854.4px, 렌더 836px). 서식을 `0`으로 바꾸자 계획과 일치했고(854px), 그 대신 축 아래 24pt에 들어가지 않던 범주 이름의 아랫부분이 잘렸다. PowerPoint는 12pt 범주 이름을 축 아래 15.5~25.5pt에 그린다. 6절에서 고쳤다.
- 가로 막대 차트는 PowerPoint가 값 축을 위쪽에 그리고 그림 영역을 계획보다 약 15.5pt 아래에서 시작한다. 미리보기는 값 축 글자를 아래쪽에 그린다. 수정 전후가 같고 글자가 잘리지 않는다. 이월표에 올렸다.
- PowerPoint 렌더를 한 프로세스에서 연달아 실행하면, 앞 렌더의 PowerPoint가 바로 끝나지 않아 두 번째 렌더가 "실행 중인 PowerPoint" 오류로 거부된다. 잠시 뒤 다시 실행하면 통과한다. 이월표에 올렸다.

Windows 시간대는 이미 Korea Standard Time이어서, 사용자 결정으로 사용자 환경 변수 `TZ`를 지웠다(이전 값은 저장소 밖 백업에 기록). 지운 뒤 다시 띄운 앱은 `15:30:46+09:00`을 적었다. 앱 쪽 방어(Windows에서 POSIX 형식이 아닌 `TZ`를 서비스에 넘기지 않기)는 사용자 결정으로 이월표에 올렸다.
