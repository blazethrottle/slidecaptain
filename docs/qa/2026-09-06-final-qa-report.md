# Slide Captain 최종 QA 리포트 (단계 5A 완료 시점, 2026-09-06)

> 대상: 브랜치 `codex/phase-5a` (main 머지 직전), 실행 환경 Mac Mini(macOS). 실제 AI 호출은 사용자가 승인한 1회만 썼다.
> 이 리포트는 공개 저장소에 두므로 회사 자료와 식별 정보를 담지 않는다. 회사 자료는 한 건도 쓰지 않았고, 관통과 QA 의 입력은 전부 합성 문장이다.
> 구성: 1부 기획과 설계 대 구현 추적, 2부 코드 아키텍처와 테스트 지도, 3부 리뷰 이력 종합, 4부 QA 실행 결과(자동 검증, API 블랙박스, 실기기 관통), 5부 발견과 판정, 6부 다음 단계.

## 요약

**결론: 단계 5A 를 완료 상태로 판정하고 `codex/phase-5a` 를 `main` 에 머지해도 된다.** 근거는 네 가지다. ① 설계서 대응 34행 중 28이 구현됐고 부분 4 는 전부 로드맵이 명시적으로 유예한 항목이며 미확인은 없다. ② 백엔드 603 와 프런트 220 테스트가 worktree 와 GitHub 새 클론 양쪽에서 통과하고 패키지 소스 커버리지는 97.4% 다. ③ 실제 서버 API 블랙박스 47건 전부 통과, 실기기 관통(새 클론 환경 구성, 더블클릭 실행과 종료, 폰트 재설치, 업로드, 고지 취소와 동의, 실호출 1회, 편집과 저장과 스냅샷과 내보내기와 재열기)이 전부 성공했다. ④ 리뷰 이력의 critical 4건과 major 약 28건은 전부 처분이 확인되며, 분석가가 처분 불명으로 남긴 9건도 이번 QA 가 코드로 대조해 7건은 이미 해소, 2건은 이번 QA 안에서 닫혔다.

이번 QA 가 새로 찾은 것은 3건이다. 실호출 실측으로 드러난 **SDK `usage` dict 폴백이 마지막 턴 값이라 "대략" 토큰이 천 배 작을 수 있던 결함**(수정 완료), XLSX 업로드 직후 뜨는 불필요한 오류 문구(minor, 5B), 내보내기 안내 문구(nit, 5B). 판정을 바꾸는 결함은 없다.

남은 위험은 기능이 아니라 경계에 있다. 공개 저장소 감사기가 마크다운 본문의 회사 식별 문자열과 git 이력을 검사하지 않는 사각은 사용자 결정으로 후속 회차에 있고, Windows 는 실기기 없이 CI 로만 검증됐다. 5B 파일럿에 앞서 이 둘을 먼저 결정하는 것을 권한다.

## 1부. 기획과 설계 대 구현 추적

분석 대상은 배경 히스토리(요구사항 원천), MVP 설계서 1절부터 10절, 로드맵(단계 구성, 아키텍처 결정 9개, 확정 범위, 이월표, 진행 상태), 5A 마스터 플랜, 단계별 계획서의 완료 관문, README 와 CLAUDE.md 이고, 대조 수단은 코드 grep 과 파일 정독과 테스트 재실행이다.

**제품 정의**: 비개발자인 사용자 본인이 리서치 결과를 보고용 PPTX 로 만드는 과정을 돕는 1인 로컬 웹앱이다. 핵심 원칙은 "AI 는 내용만, 배치는 코드가" 이며, AI 는 장 구성과 슬롯 내용까지만 산출하고 좌표와 글자 크기는 결정론적 레이아웃 엔진이 프리셋에서 계산한다. 진본 데이터는 `deck.json` 이고 PPTX 는 내보내기 산출물이다.

**설계서 절 대 구현 대응 (34행)**: 구현됨 28, 부분 4, 미구현 1, 의도적 제외 1, 미확인 0.

## 2부. 코드 아키텍처와 테스트 지도

백엔드는 32개 파일 4,447줄, 프런트는 손으로 짠 코드 약 2,587줄(자동 생성 타입 1,926줄 제외)이다. 진입점은 `backend/slidecaptain/__main__.py`(export 와 serve)와 `frontend/src/main.tsx` 이고, 의존 방향은 models → metrics 와 layout → pipeline, storage 와 sources 는 models 만 의존, export 가 layout 과 metrics 를 묶고 server/app.py 가 전부를 조립한다. 순환 import 는 양쪽 다 없다.

**핵심 흐름 3개**는 코드로 끝까지 추적됐다. (a) 업로드는 `upload_source` 한 경로에서 경로 조각 제거, 확장자 분기, NFC 정규화, 이름 규칙, 크기 이중 검사, XLSX 상한 5종(로드 전 2종, 로드 후 3종), 잠금 안의 원본과 추출본 쓰기와 실패 시 원본 복원을 거친다. (b) 생성은 동의 관문(프런트 `ensureConsent` 와 서버 428)을 지나 `GenerationService` 의 단일 경유지 `_complete` 로 프로바이더를 부르고, 형식 게이트(재시도 1회)와 분량 게이트(축약 1회)와 수치 대조(경고만)를 거쳐 `finally` 에서 사용량을 기록한다. (c) 편집은 `useDeckEditor` 의 디바운스와 저장 체인 직렬화, `If-Match` ETag, 412 시 자동 저장 정지와 사용자 재개, 의미 시점 스냅샷, 원자적 쓰기, 버전 번호 내보내기로 이어진다.

**불변조건 20종**을 표로 정리했고 19종은 대응 테스트가 있으며 1종(CLI 자격 증명 파일을 읽지 않음)은 코드 검토로만 확인했다. 대표: 상태 변경 요청의 표식 헤더, Origin 루프백 검사, 생성 3종의 동의 헤더 428, `If-Match` 412, 프로젝트별 재진입 잠금, 원자적 쓰기와 고유 임시 파일, NFC 와 대소문자 충돌, 업로드 상한, 자료 합계 10만 자, 프로바이더 단일 경유, 없는 값은 None, 재시도와 축약 각 1회, 이메일 마스킹, 127.0.0.1 바인딩, 내보내기 버전 증가와 임시 위치 이동, 저장 직렬화, 충돌 시 덮어쓰기 금지.

**테스트 지도**: 백엔드 33개 파일 603개(최다 `test_file_store.py` 75, `test_public_repo_audit.py` 58, `test_generation_service.py` 46). 별도 환경에서 잰 패키지 소스 라인 커버리지 **97.4%**(2,328 문 중 61 미실행. 89% 미만 파일 없음). 미실행 줄은 대부분 재현이 어려운 경합과 손상 경로(임시 파일 삭제 실패, mkdir 경합, 스냅샷 이름 충돌, CLI 부재)다. 감사기 스크립트는 subprocess 로 테스트되어 계측이 27% 로 저평가된 것으로 추정한다. 프런트는 22개 파일 220개 전부 통과이나 커버리지 도구가 없어 파일 대응표로 갈음했고, 테스트 없는 소스는 `App.tsx`(3줄 조건문), `main.tsx`, `labels.ts`, 자동 생성 `types.ts`(CI 가 재생성 diff 로 검증) 뿐이다.

**코드 품질 관찰 9건**: 80줄 초과 함수는 `create_app`(386줄, FastAPI 관례), `upload_source`(93줄), `_build_extraction`(122줄)과 화면 컴포넌트 3개. 백엔드와 프런트가 같은 규칙을 두 번 구현한 곳은 사용량 합산 1곳(주석으로 상호 참조는 있음). 원인 로그 없이 예외를 삼키는 곳은 `fonts/installer.py` 의 Windows 즉시 반영 API 1곳뿐. TODO 0건. 시간 의존은 주입 가능한 구조로 격리. 하드코딩 상수의 정본은 명확하다(포트 1곳, 상한은 정의부).

**사용자 체감 위험 상위 5**: ① 감사기의 git 이력 미검사 ② 본문 식별 문자열 미검사 ③ 412 충돌 상태에서 창을 닫으면 그 사이 편집이 저장되지 않음(무결성 관점에서는 올바른 선택이나 체감은 유실) ④ 대용량 업로드의 클라이언트 사전 크기 검사 부재 ⑤ 폰트 즉시 반영 실패의 무로그.

## 3부. 리뷰 이력 종합

리뷰 문서 47건(계획서 적대 리뷰 8, 태스크 독립 리뷰 19, 묶음 최종 리뷰 12, 반박자 4, 기타 4)과 프런트 탐색 발견 17건, 각 계획서의 리뷰 반영 절, 로드맵 이월표, `fix:` 커밋 50건을 전수 확인했다.

**리뷰 체계**: 계획서 확정 전 세 관점 적대 리뷰 → 태스크마다 구현자와 독립 리뷰어 분리(리뷰어가 구현 직전 커밋에서 RED 재실증) → 묶음 최종 리뷰(세 관점 병렬, 실제 서버 재현) → major 는 반박자 3명. 판정 분포는 승인 약 13, 수정 후 승인 약 21, 재작업 1(B 계획 1차의 추출 관점). 심각도 총계(표기 방식이 섞여 근사치): critical 4, major 약 28, minor 약 37, nit 약 27. **critical 4건은 전부 구현 착수 전 계획 단계에서 나왔고 코드 배포 뒤 critical 로 격상된 사례는 없다.** 47건 중 28건 이상이 재현 스크립트, RED 재실증, 실제 서버 요청 같은 실행 증거를 남겼다.
