## 1. 실제 프로세스 재시작 관통 (5개 중 5개 통과)

`backend/tests/test_process_restart.py`가 데스크톱 서비스를 별도 프로세스로 띄워 2장 묶음을 등록하고, 장 처리의 한 지점에서 SIGKILL로 끊은 뒤 같은 폴더로 다시 띄운다. 끊는 지점은 시험 전용 실행기(`backend/tests/process_harness.py`)가 관문 파일로 멈춰 만든다. 제품 코드에는 시험 장치가 없다.

| 끊은 지점 (계획서 5.7) | 재시작 뒤 장 상태 | 덱 | 가짜 CLI 호출 |
|---|---|---|---|
| ①과 ② 사이: 호출이 나간 뒤 응답 전 | `remote_completion_unknown`, `interrupted` | 변화 없음 | 1회, 재시작 뒤 추가 0회 |
| ②와 ③ 사이: 결과를 원장에 쓴 뒤 적용 전 | `succeeded`, `interrupted` | 첫 장 적용 | 1회, 추가 0회 |
| ④와 ⑤ 사이: 적용 대상 ETag를 쓴 뒤 저장 전 | `succeeded`, `interrupted` | 첫 장 적용 | 1회, 추가 0회 |
| ⑤와 ⑥ 사이: 저장은 끝났고 성공 기록 전 | `succeeded`, `interrupted` | 첫 장 적용, 다시 저장하지 않음(ETag 불변) | 1회, 추가 0회 |
| 첫 장 형식 오류 뒤 둘째 장의 ②와 ③ 사이 | `failed`(`ai_output`), `succeeded` | 둘째 장만 적용 | 3회(형식 재시도 포함), 추가 0회 |

모든 경우에 부모는 `failed`, `partial`로 종결되고, 적용된 장의 적용 결과 ETag는 지금 덱의 ETag와 같다. 서비스를 끊은 뒤 가짜 CLI 프로세스가 남지 않는다(가짜 CLI는 부모가 바뀌면 끝난다. 이 보완 전에는 관문 모드의 가짜 CLI가 영구히 남았고, 이 세션의 시험 실행이 남긴 7개를 확인해 종료했다). 재시작 조정을 끄거나, 적용 재개를 끄거나, 원격 호출 시각이 있는 장을 `interrupted`로 바꾸는 변형을 이 시험이 잡는다. 적용 대상 ETag 기록 생략처럼 이 시험을 통과하는 다른 변형은 단위 시험(`test_jobs_batch.py`)이 잡는다. Windows는 가짜 CLI 래퍼와 SIGKILL이 POSIX 전용이라 건너뛴다. CI(`c937e05`, 실행 37756925732)에서 macOS는 이 시험을 돌렸고 Windows는 건너뛰었다.

## 4. 패키지 확인 (macOS)

빌드한 서비스 실행 파일(PyInstaller, `--onedir`)과 미서명 독립 앱(`npm run dist -- --dir`, `SlideCaptain.app`)을 저장소 밖 작업 폴더에 만들었다. 빌드는 `12d5b64` 기준이고 그 뒤 서비스 쪽 변경은 장 후보 처분 검사(`2ec570c`) 한 건이다. 서비스 시작 확인(`desktop/scripts/smoke-service.cjs`)은 빌드한 실행 파일(`mode: frozen`)로 모든 항목이 통과했다.

1. 독립 앱을 `SLIDECAPTAIN_CLAUDE_CLI=/nonexistent/claude`와 새 `SLIDECAPTAIN_DATA_DIR`로 실행했다. 앱이 띄운 서비스 프로세스의 환경(`ps eww`)에 두 값이 들어갔고, 서비스 인자 `--data-dir`가 그 새 폴더를 가리켰다. 앱을 끝내자 서비스도 끝났다. 창 안의 화면은 조작하지 않았다.
2. 창을 조작할 수 없어 생성 등록은 같은 서비스 실행 파일을 main 프로세스와 같은 환경 변수로 띄워서 했다. AI 연결 상태가 로그인이 아님(`logged_in: null`, 원인 문구는 CLI 파일 없음)을 확인한 뒤, 합성 자료 한 건을 넣은 프로젝트에 구조안 생성을 등록했다(202). 작업은 `failed`, `connection`, 503으로 끝났다. 첫 시도는 자료 없이 등록해 422(입력 자료 없음)로 거절됐고 자료를 넣어 다시 했다.
3. 서비스의 자식 프로세스는 등록 전후로 같았고 `claude` 프로세스는 없었다. `ai-usage.jsonl`은 0줄이다.

계획서와의 차이: ①은 독립 앱 실행과 서비스 직접 실행으로 나눠 했고, ⑤의 `claude` 프로세스 확인은 시스템 전체가 아니라 서비스의 자식 프로세스로 했다(이 Mac에서는 Claude Code 자체가 `claude` 이름으로 돈다).

관측: 서비스는 시작할 때 ChatGPT 연결 상태 확인용으로 `codex app-server`를 자식 프로세스로 띄운다. 자료 폴더 안의 별도 `CODEX_HOME`으로 뜨고 로그인이 없다. 생성 요청은 아니며 사용량 기록도 생기지 않았다. 이 프로세스가 외부 네트워크에 접속했는지는 관측하지 않았다. 이 동작은 D2b 이전부터 있었다.
