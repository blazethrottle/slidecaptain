## 1. 실제 프로세스 재시작 관통 (3개 중 3개 통과)

`backend/tests/test_process_restart.py`가 데스크톱 서비스를 별도 프로세스로 띄워 2장 묶음을 등록하고, 장 처리의 세 지점에서 SIGKILL로 끊은 뒤 같은 폴더로 다시 띄운다. 끊는 지점은 시험 전용 실행기(`backend/tests/process_harness.py`)가 관문 파일로 멈춰 만든다. 제품 코드에는 시험 장치가 없다.

| 끊은 지점 (계획서 5.7) | 재시작 뒤 첫 장 | 남은 장 | 덱 | 가짜 CLI 호출 |
|---|---|---|---|---|
| ①과 ② 사이: 호출이 나간 뒤 응답 전 | `remote_completion_unknown` | `interrupted` | 변화 없음 | 1회, 재시작 뒤 추가 0회 |
| ②와 ③ 사이: 결과를 원장에 쓴 뒤 적용 전 | `succeeded`, 후보 `applied` | `interrupted` | 첫 장 적용 | 1회, 재시작 뒤 추가 0회 |
| ④와 ⑤ 사이: 적용 대상 ETag를 쓴 뒤 저장 전 | `succeeded`, 후보 `applied` | `interrupted` | 첫 장 적용 | 1회, 재시작 뒤 추가 0회 |

재시작 조정을 끄거나, 적용 재개를 끄거나, 원격 호출 시각이 있는 장을 `interrupted`로 바꾸는 변형 3개를 이 시험이 모두 잡는다. Windows는 가짜 CLI 래퍼와 SIGKILL이 POSIX 전용이라 건너뛴다(회사 PC 확인 대상).

## 4. 패키지 확인 (macOS)

빌드한 서비스 실행 파일(PyInstaller, `--onedir`)과 미서명 독립 앱(`npm run dist -- --dir`, `SlideCaptain.app`)을 저장소 밖 작업 폴더에 만들었다. 서비스 시작 확인(`desktop/scripts/smoke-service.cjs`)은 빌드한 실행 파일(`mode: frozen`)로 모든 항목이 통과했다.

독립 앱 창은 이 셸에서 조작할 수 없으므로, main 프로세스가 서비스를 띄우는 방식(세션, 실행 식별자, 부모 연결 환경 변수)을 그대로 흉내 내 빌드한 서비스 실행 파일을 띄우고 계획서의 차단 절차를 따랐다.

1. `SLIDECAPTAIN_CLAUDE_CLI=/nonexistent/claude`와 새 자료 폴더로 실행했다.
2. `ps eww`로 서비스 프로세스 환경에 그 값이 들어간 것을 확인했다.
3. AI 연결 상태가 로그인이 아님(`logged_in: null`, 원인 문구는 CLI 파일 없음)을 확인했다.
4. 합성 자료 한 건을 넣은 프로젝트에 구조안 생성을 등록했다(202). 작업은 `failed`, `connection`, 503으로 끝났다.
5. 서비스의 자식 프로세스는 실행 전후로 같았고 `claude` 프로세스는 없었다. `ai-usage.jsonl`은 0줄이다.

관측: 서비스는 시작할 때 ChatGPT 연결 상태 확인용으로 `codex app-server`를 자식 프로세스로 띄운다. 생성 요청은 아니며 이 확인에서 사용량 기록은 생기지 않았다. 이 동작은 D2b 이전부터 있었다.
