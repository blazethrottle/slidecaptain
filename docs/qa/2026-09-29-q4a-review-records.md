## Chrome 실제 화면

합성 `browser-review` 한 프로젝트의 두 페이지 출력에서 다음을 확인했다.

1. 첫 조회의 다섯 항목은 미수행이며 폼의 항목/판정은 선택되지 않는다.
2. 한 페이지만 확인한 통과는 저장할 수 없다. 두 페이지를 명시적으로 선택한 뒤 저장하면 수동 입력임을 표시하고 폼이 비워진다.
3. 같은 시각 항목에 수정 필요를 추가하면 최신 판정이 바뀌고 이전 기록도 남는다.
4. 외부에서 합성 Deck를 바꾸고 저장하면 412를 표시하고 검수자/근거/페이지 입력을 보존한다. 기준을 다시 읽으면 기존 기록은 현재 출력에 적용할 수 없음으로 표시되고 새 저장이 차단된다.
5. Deck를 정확히 복원하면 현재성이 회복된다. 이후 원문만 바꿔 저장하면 409를 표시하고 입력을 보존한다. 원문 복원/기준 재확인 후 같은 입력을 저장했다.
6. 수동 기록 3개가 있어도 초안 안내와 독립 검수/제출 승인 아님을 유지한다. 480px에서 문서 폭은 480px였고 전체 폼/페이지 선택/저장 버튼의 잘림이나 겹침을 발견하지 못했다. 기본 1,920px 화면도 확인했고 임시 화면 크기를 복원했다.

자료 탭으로 이탈을 시도했을 때 확인 대화상자가 발생했고 입력이 남았다. 브라우저 자동화 도구의 대화상자 처리 오류가 있어 명시적 취소/수락 동작의 통과 근거는 자동화 회귀로 한정한다. 이 도구 오류를 제품 실패나 추가 통과로 세지 않았다. 스크린샷은 `qa/browser-stale.png`, `qa/browser-480.png`에 보관했다. QA 프로젝트만 변경하고 원본 사용자 프로젝트는 사용하지 않았다.

## 독립 리뷰와 수정

계획 검토에서 같은 조회의 ETag, 서버 순번, 손상 시 과거 통과 부활 금지, 안전한 잠금 파일 경계를 명시했다. 구현 검토에서 근거 길이 불일치, 누적 8MiB 한도를 넘기는 쓰기, fsync 실패 후 임시 파일 잔존, 잠금 오류의 422 분류를 수정했다. 새 파일을 더한 크기는 게시 전에 검사한다.

이후 내보내기 대기 중 새 검수 입력이 이력 재조회로 사라지는 경합을 재현하고 snapshot/export 대기 동안 입력을 잠갔다. 독립 재검토에서 늦은 상세 응답으로 처음 열린 폼이 busy 때문에 최초 GET을 건너뛰고, 내보내기 실패 뒤 영구 로딩에 남는 반례도 확인했다. 읽기 GET은 허용하고 입력만 잠그도록 수정해 두 독립 UI 회귀를 통과했다. 최종 필수 잔여는 0건이며 검토 파일 해시는 `review/final-review-files.json`, 판정은 `review/final-review.md`에 있다.

## 완료 범위와 한계

실제 AI 호출은 0회다. Windows 실기기/새 CI, 실제 PowerPoint 표시·편집, 생성자와 분리된 품질 검수, 독자 품질 평가는 미수행이다. 기존 로컬 사용자가 파일을 직접 위조하거나 기록 꼬리를 삭제하는 행위까지 인증하지 않으며 PowerPoint 실행 환경도 fingerprint에 포함하지 않는다. 수동 입력은 자기 신고이고 Q4b의 독립 검수 영수증과 제출본 게시를 대체하지 않는다.

원본 311개 파일 중 이번 작업으로 바뀐 14개와 신규 11개만 반영했다. 나머지 297개와 Git 인덱스/브랜치/HEAD를 보존했고 반영한 25개 경로는 검증 작업본과 같다. `logs/applied-preservation.json`을 따른다. Chrome 관측과 실제 요청 응답 코드는 `qa/browser-report.json`에 있으며 저장 요청은 200/200/412/409/200 순서였다. 추가 실제 AI 호출은 없었다.
