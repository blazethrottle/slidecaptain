# Windows 환경과 PowerPoint 실제 렌더 검증

2026-10-02 서울 기준 기록. 검수 대상은 `origin/codex/phase-5b`의 `8561b4e`이며 테스트 환경 수정은 `codex/windows-powerpoint-qa-20261002`에서 수행함. 기존 회사 프로젝트와 인증 프로필, 루트의 과거 미추적 핸드오프를 보존함. AI 생성 호출은 0회임.

## 실제 확인 결과

- Windows build 22631, Python 3.13.5 64비트, Node v22.17.1 x64에서 현재 checkout의 backend editable 설치와 frontend npm ci 및 빌드를 완료함. Noto Sans KR 설치 상태는 `already`로 확인함.
- `scripts/prepare_windows_review.py`로 별도 검수 회차를 생성함. templates 10장, diagram 2장, bar/column/emphasis 각 1장으로 총 5개 파일 15페이지임.
- 앱의 실제 `qualification` 및 `render-export` CLI로 Microsoft PowerPoint 16.0 build 20430에서 15페이지 전체를 1920 x 1080 PNG로 렌더함. 모든 파일의 원본 SHA-256이 manifest와 일치하며 렌더 이미지, 환경 fingerprint와 qualification 기록이 저장됨.
- 별도 포트 8870에서 합성 프로젝트만 담은 검수 앱을 실행함. Chrome에서 합성 프로젝트, 현재 입력/PPTX 일치와 렌더 `실행됨`, 독립 검수 `미수행`, 제출본 게시 차단 표시를 확인함.
- 전체 격자 이미지와 도식/막대 차트의 개별 이미지를 확인함. PPTX 재열기로 native 표 1개와 native 차트 2개를 확인함. 이는 사람이 PowerPoint에서 수정하고 저장한 뒤 다시 열어본 검증을 대신하지 않음.

## 테스트와 환경 보정

초기 최신 개발본 백엔드 전체 실행은 **1,938 통과 / 14 실패 / 16 건너뜀**, 프런트 전체 실행은 **529 통과 / 3 실패**였음. 실패를 숨기지 않고 아래 원인별로 보정 및 재검증함.

1. 심볼릭 링크 8건은 제품의 링크 차단 실패가 아니라 계정의 링크 생성 권한 부족인 `WinError 1314`였음. 공통 fixture로 해당 오류만 건너뛰고 다른 오류는 다시 발생시킴. 링크 생성 가능한 CI/기기에서 해당 검사 의무는 유지함.
2. 프로세스 게시 5건은 이벤트/응답 대기 15초 초과였음. 별도 파일 재현에서도 강제 종료 후 게시 검사 1건의 같은 대기 실패를 확인함. Windows 프로세스 대기만 60초로 조정하고 생산 잠금 시간과 0.3초 경합 단언, 자식 프로세스 종료 검사는 유지함. 수정 후 **14 통과 / 1 건너뜀**임. 자식 import만의 소요 시간은 따로 측정하지 않았음.
3. Bash 문법 검사 1건은 WSL Bash에 Windows 경로를 전달한 데서 실패함. stdin으로 전달하되 Windows의 text-mode LF→CRLF 변환도 재현하여 바이너리 입력으로 수정함. 수정 후 메타데이터 **37 통과**임.
4. history/reviews/metadata 묶음 재실행은 최종 Bash 보정 직전 **131 통과 / 1 실패 / 11 건너뜀**이었고, 남은 Bash 실패는 위 37건 재실행으로 해소함. 전체 백엔드를 수정 후 다시 실행하지 않았으며 원래 통과한 1,938건을 수정 후 전체 통과로 표현하지 않음.
5. 프런트 실패는 첫 테스트 5초 시간 초과와 후속 동의창 부재였음. 해당 파일 단독 **3 통과**, worker 2개 전체 재실행 **532 통과 / 52파일**임. 프런트 제품 코드는 변경하지 않음.

Windows metadata/qualification 별도 검사 **32 통과 / 1 건너뜀**, 공개 저장소 현재 파일 감사 0건, `git diff --check` 통과함. 지정한 테스트 5파일에 대한 독립 리뷰 및 binary stdin 후속 리뷰에서 필수 수정 사항 없음으로 승인됨.

## 발견과 남은 검수

- **표시 문제 미수정**: bar/column의 정수 값 및 축 눈금이 `1200.`처럼 끝에 소수점을 표시함. 현재 writer가 `0.##############`을 지정한 실제 PowerPoint 렌더에서 관측함. 차트 숫자 서식 후속 검토 대상으로 남김.
- **제출 조건 미충족**: bar/column 샘플의 `numeric_expressions`는 숫자 포함 칸 2개의 `unlinked_expression`으로 실패함. 1200/1000 차트 렌더 성공을 근거/수치 검수 통과로 승격하지 않음.
- **미수행**: 사람이 일반 보기/슬라이드 쇼에서 전 페이지를 직접 확인하고 텍스트/표/차트 데이터/도식 노드를 수정, 별도 파일 저장 후 재열기하는 검사, 사용자의 품질 피드백, 실제 독립 서명 검수, 제출본 게시임. 기존 Q5 사람 평가와 품질 우세 미입증 상태는 변경하지 않음.
- **배치 범위**: `Windows검수준비.bat`의 설치/빌드/준비/서버 단계에 해당하는 명령을 직접 수행함. 배치 파일 자체의 더블클릭, 새 콘솔/탐색기/피드백 HTML 자동 열기는 미검증임. 브라우저 도구는 file URL을 허용하지 않아 피드백 HTML 자동 열기는 실행하지 못함.
- `npm ci`가 기존 의존성에 high 3건을 보고함. 이번 회차에서 원인 감사나 의존성 갱신은 수행하지 않음.

## 로컬 증거와 재개

원본과 피드백 양식은 `projects/windows-review/latest-run.txt`가 가리키는 회차에 보존함. 이 회차의 `manifest.json`, `native-qa-summary.json`, 샘플별 `*-native.json`, `contact-sheet.png`와 `store/*/exports/`에 실제 렌더 증거가 있음. 테스트 로그는 `exports/windows-qa-20261002/`에 보존함. 모든 경로는 공개 저장소에서 제외함.

검수 앱은 `http://127.0.0.1:8870`이며 피드백은 해당 회차의 `index.html`을 직접 열어 JSON으로 저장할 수 있음. 파일 원문과 실제 판정은 로컬에 보존함. 사용자 피드백을 수동 통과나 독립 서명으로 자동 변환하지 않음.
