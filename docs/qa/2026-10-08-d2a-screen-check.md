# D2a 화면 확인 (계획서 7절)

작성: 2026-10-08 (서울 기준). 대상은 `feat/windows-feedback-revision`의 `a6b8005`까지다. 확인은 이 Mac(Apple M4, macOS 27.0.1)에서 헤드리스 Chromium(Playwright 1.59, Chromium 1234 빌드)으로 했다. **사람이 화면을 직접 본 확인이 아니다.** 실제 AI 호출은 0회다. 구조안 승인 루프의 생성 응답과 로그인 상태는 브라우저 안에서 흉내 냈다. 자료는 별도 `--data-dir`의 합성 프로젝트 2개만 썼고 사용자의 `~/slidecaptain-projects`에는 서버를 띄우지 않았다.

## 확인 범위의 분담

D2a-4와 D2a-5의 묶음 독립 리뷰(`7781169`에 반영)가 같은 방식으로 다음을 먼저 확인했다: 1440px, 1024px, 512px와 200% 확대에 해당하는 창에서 저장 상태가 첫 화면에 보임, 저장 중과 저장됨과 충돌의 구별, 버튼과 입력과 선택 상자 14개의 초점선, 움직임 감소 설정에서 회전 표시 정지, 되돌리기 뒤 초점 이동, 보존 건수 갱신. 이 기록은 그 리뷰가 확인하지 않았다고 밝힌 항목을 다룬다.

## 관측한 것과 한계

- 충돌 직후의 기존 서버 문구는 "화면을 새로고침한 뒤 다시 편집해 주세요"라고 안내한다. 새로고침은 미저장본 보존을 거치지 않으므로 D2a-2의 "서버 내용으로 되돌리기" 흐름과 어긋난다. 이월한다(로드맵 이월표).
- 되돌리기 직후 약 0.3초 동안 미리보기는 낡은 배치(흐린 표시)로 남고 그동안 편집이 열리지 않는다. 새 배치 계산이 오면 풀린다. 의도한 보호 동작이며 별도 재현 스크립트로 6초 동안 관찰해 확인했다.
- 확인하지 않은 것: 사람의 시각 판정, 실제 화면 낭독기, Windows에서의 표시(아이콘 글자 포함), 실제 AI 생성, 독립 앱 창 안의 화면(웹 모드로 확인했다).
