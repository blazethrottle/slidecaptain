# C3 후속 확인 기록: 차트 표시 맞춤과 소수 2자리 표기 (2026-10-20, 회사 PC)

계획: [C3 후속 계획](../plans/2026-10-20-c3-followup-chart-display.md). 브랜치 `feat/c3-chart-display`. 환경: Windows 11 Pro 10.0.22631, PowerPoint 16.0 build 20430(COM 자동화), 기본 프리셋(본문 12pt, Noto Sans KR). 실제 AI 호출 0회.

## 1. 결론

- (18) 소수 3자리 이상인 차트 값은 미리보기와 PowerPoint에서 같은 소수 2자리 글자로 보인다. PPTX 내장 데이터와 렌더 계획 `value`에는 원문 값이 남는다.
- (16) PowerPoint 차트에 값 축 눈금선과 중간 눈금 글자가 없다. 0과 최댓값 글자의 획 위치는 PowerPoint와 미리보기 계산값이 0.2pt 안에서 맞는다.
- 기존 수용 기준은 유지된다: 가로 막대 그림 영역 위쪽 12.000pt(계획 12.0), 세로 막대 그림 영역 24.000pt(계획 24.0), 막대 위치가 계획과 같다.
- (17) 현행과 시안 3개를 PowerPoint로 렌더했고, 크기와 비율, 적용 범위는 사용자 선택 대기다.

## 2. 방법

`scripts`의 스크립트로 작업 트리 코드에서 bar, bar15, column, column15 표본 PPTX를 만들고, PowerPoint COM으로 사본을 읽기 전용, 창 없이 열어 2880x1620 PNG(1pt = 3px)로 내보냈다. 차트 개체(`PlotArea`, `Axes(2)`, `Point`, `DataLabel.Text`)에서 값을 읽었다. COM의 `PlotArea.InsideTop`, `InsideLeft`는 차트 틀 기준보다 4pt 작게 나오므로 4pt를 더해 본다(2026-10-20 앞 세션의 운용 사실). 미리보기 글자의 획 위치는 번들 Noto Sans KR의 글리프 경계(PIL, fontTools)로 계산했다. 브라우저 화면 캡처는 하지 않았다.

증거(저장소 밖, `projects/`는 무시 대상): `projects/windows-review/run-20261019-112243-237724/c3-evidence/chart-display-20261020/`(render, mockup, rounding, scripts).

## 3. (18) PowerPoint의 소수 2자리 반올림

원문 값을 float로 넣고 라벨 서식 '0.00'을 준 표본 12개를 PowerPoint가 보인 글자다. 모두 원문 Decimal의 ROUND_HALF_UP과 같다. Python의 `'.2f'`(이진 float 기준)는 1.005를 1.00으로 보이므로 다르다.

| 원문 | PowerPoint |
|---|---|
| 1.005 | 1.01 |
| 2.675 | 2.68 |
| 0.125 | 0.13 |
| 1.015 | 1.02 |
| 0.004 | 0.00 |
| 0.005 | 0.01 |
| 123456789.125 | 123456789.13 |
| 123456789.123456 | 123456789.12 |
| 999999999999.995 | 1000000000000.00 |
| 8.345 | 8.35 |
| 1.345 | 1.35 |
| 0.285 | 0.29 |

바뀐 코드로 만든 bar15, column15에서 PowerPoint 라벨은 `123456789.12`, 축 최댓값은 `135802468.04`이고, 내장 데이터 값은 `123456789.123456`이다.

## 4. (16) 눈금과 축 글자 위치

PowerPoint `Axes(2)`: `HasMajorGridlines` False, `MajorUnit`과 `MaximumScale`이 같다(bar 1320, bar15 135802468.04). 눈금 글자는 0과 최댓값 둘이다.

축 글자 획 위치(12pt, 축 기준):

| 차트 | 글자 | PowerPoint | 미리보기(바꾼 뒤 계산) | 종전 미리보기 |
|---|---|---|---|---|
| 가로 막대 | 0, 최댓값 세로 | 축 아래 14.47~23.47pt | 14.45~23.56pt | 3.05~12.16pt |
| 가로 막대 | 0 가로 | 획 가운데가 눈금 +0.08pt | 눈금 +0.01pt(가운데 맞춤) | 시작 맞춤(획 가운데 눈금 +3.3pt) |
| 가로 막대 | 1320 가로 | 눈금 +0.30pt | 눈금 +0.23pt | 끝 맞춤(획 가운데 눈금 -13.1pt) |
| 세로 막대 | 0, 최댓값 세로 | 획이 눈금 -4.87~+4.13pt | -4.95~+4.16pt | 0은 그림 영역 아래, 최댓값은 기준선이 눈금 |
| 세로 막대 | 0 가로 | 획 오른쪽 끝이 축 왼쪽 13.97pt | 14.09pt | 0은 축 오른쪽 |
| 세로 막대 | 최댓값 가로 | 획 오른쪽 끝이 축 왼쪽 13.97pt | 13.87pt | 6.4pt |

미리보기 규칙: 가로 막대는 눈금에 가운데 맞춤, 기준선은 축 아래 글자 크기의 1.95배다. 세로 막대는 축 왼쪽 글자 크기의 1.125배에 끝 맞춤, 기준선은 눈금 아래 글자 크기의 1/3이다. 글자 크기에 비례한다는 것은 12pt 한 크기에서만 잰 가정이다.

## 5. (17) 시안

같은 bar 표본(A팀 1200, B팀 1000)을 코드 변경 없이 스크립트 안에서만 조정해 렌더했다. 차트 영역은 엔진이 주는 내용 영역의 폭과 높이를 비율만큼 줄여 그 가운데에 두었다. 네 장 모두 넘침 경고는 없었다.

| 이름 | 제목 | 차트 영역 |
|---|---|---|
| 현행 | 20pt | 100% |
| 시안 A | 24pt | 90% |
| 시안 B | 24pt | 80% |
| 시안 C | 28pt | 80% |

사용자에게는 비교 페이지(비공개 게시)로 보였다. 남은 결정은 시안, 적용 범위(차트 장만 또는 모든 템플릿), 차트 배치(가운데 또는 왼쪽 맞춤)다.

## 7. 영향과 미확인

- 차트가 있는 덱은 렌더 계획이 바뀐다(`display` 필드, 축 최댓값 글자 `1357.40`→`1357.4` 등). 업데이트 뒤 기존 내보내기가 "현재 저장본과 다름"으로 표시된다. 로드맵 회사 PC 이월표 (6)과 같은 D4 릴리스 안내에 더했다.
- 미리보기 위치는 글리프 계산값이다. 실제 브라우저(Chrome, 독립 앱) 화면의 픽셀 대조는 하지 않았다.
- PowerPoint 쪽 축 글자 간격이 글자 크기에 비례하는지는 재지 않았다.
