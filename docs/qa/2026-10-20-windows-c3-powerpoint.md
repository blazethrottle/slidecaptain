# Windows C3 PowerPoint 대조와 사용자 판정 (2026-10-20)

## 1. 결론

- 회사 PC의 PowerPoint 16.0 build 20430으로 합성 회차 `run-20261019-112243-237724`의 bar, bar15, column 1쪽과 templates 9쪽을 열어 렌더 계획 및 미리보기와 대조했다. 실제 AI 호출은 0회다.
- 사용자가 C3 여섯 항목을 모두 통과로 판정했다(2026-10-20 09:51 서울 저장).
- 에이전트 측정에서 bar-axis의 수용 기준 "그림 영역 위쪽 시작이 계획과 1pt 안"은 불합격이었다. PowerPoint가 그림 영역을 계획보다 4.2pt 위에 그렸다. 원인을 실험으로 확인하고 브랜치 `fix/c3-bar-axis-room`에서 고쳤다. 고친 코드로 만든 PPTX는 계획과 0.00pt 차이로 일치한다(3절).
- 사용자가 디자인 요청 두 가지를 남겼다(5절). C3 항목 밖에서 미리보기와 PowerPoint의 차이 세 가지를 새로 관측했다(4절). 셋 다 사용자 결정 대기다.
- 사람 판정은 서명 검수나 제출 승인이 아니다. 회차의 `human_status`와 manifest는 바꾸지 않았다.

기준: [C3 확인 목록](2026-10-18-c3-check.md) 4절, [10-19 Windows 재개 기록](2026-10-19-windows-c3-check.md).

## 2. 방법

- 10-19 세션은 화면 조작 도구의 PowerPoint 사용 승인이 거절되어 멈췄다. 이번에는 화면 조작 대신 PowerShell의 PowerPoint COM 자동화를 썼다. 승인 설정을 바꾸거나 거절을 우회하지 않았다.
- 회차 PPTX의 사본을 임시 폴더에 만들고 읽기 전용, 창 없이 열었다. 원본 4개의 SHA-256은 manifest와 일치했다. 사용자가 Downloads에서 직접 열어 둔 PPTX 창은 건드리지 않았다.
- 측정은 두 가지다. 하나는 차트 개체(`PlotArea`, `Point`, `Axis`)의 pt 값이고, 다른 하나는 `Slide.Export` 2880x1620 PNG(1pt가 3px)의 픽셀 위치다.
- COM 좌표 주의: `PlotArea.InsideTop`과 `InsideLeft`는 차트 틀 기준보다 4pt 작게 나온다(`ChartArea.Left`, `Top`이 4). `Point.Top`과 PNG 픽셀은 차트 틀 기준으로 서로 맞는다. 판정은 PNG 픽셀과 `Point` 값으로 했다.
- 미리보기 글자의 세로 위치는 브라우저 캡처(약 1.13px/pt)가 거칠어서, 미리보기 SVG가 쓰는 기준선과 앱 글꼴(`NotoSansKR-Regular.ttf`)의 글리프 경계로 계산했다.
- 증거: 회차 `c3-evidence/powerpoint-20261020/` (PNG 10개, `measure.json`, 측정 스크립트 5개).

## 4. bar 그림 영역: 원인과 수정

원인: 가로 막대 레이아웃은 그림 영역 아래에 글자 크기의 2배(12pt에서 24pt)를 남긴다. PowerPoint의 값 축 글자 칸은 28pt(`Axis.Height`)다. 모자란 4pt를 맞추려고 PowerPoint는 그림 영역 높이는 그대로 두고 위치만 위로 올린다.

확인 실험: 같은 PPTX에서 그림 영역 높이만 바꾼 사본 세 개를 PowerPoint로 열었다.

| 그림 영역 아래 여유 | 그림 영역 위쪽의 계획 대비 차이 |
|---|---|
| 24pt(현재) | -4.16pt |
| 26pt | -2.16pt |
| 28pt | -0.16pt |
| 30pt | 0.00pt |

수정(`backend/slidecaptain/layout/expression.py`): 가로 막대의 `plot_h`를 `height-font*3`에서 `height-font*3.5`로 바꿔 아래 여유를 글자 크기의 2.5배로 둔다. 세로 막대와 같은 배수다. 시험 `test_bar_chart_leaves_room_below_the_plot_for_powerpoint_value_axis_labels`는 고치기 전에 실패하는 것을 확인했다.

고친 코드로 만든 bar, bar15 PPTX의 PowerPoint 측정:

- 그림 영역 위쪽 12.000pt(계획 12.0pt), 막대 1 위쪽 51.650pt(계획 51.65pt).
- PNG 픽셀도 계획과 1px(0.33pt) 안에서 같다.
- 값 축 글자 아래 끝은 444.7pt로 차트 틀(451.2pt) 안이다.
- column 차트의 계획과 PowerPoint 표시는 바뀌지 않았다.

영향: 가로 막대 차트 덱의 렌더 계획이 바뀐다. 그림 영역 높이가 6pt 줄고, 기본 템플릿에서 막대 두께가 80.8pt에서 79.3pt가 된다. 기존 내보내기는 "현재 저장본과 다름"으로 표시된다. 로드맵 회사 PC 확인 이월표 (6)과 같은 D4 릴리스 안내에 더한다.

가정: 12pt에서만 쟀다. 글자 칸이 글자 크기에 비례한다고 가정한다(세로 막대와 같은 가정).

## 5. 사용자 요청 (결정 대기)

1. 차트 장의 제목과 차트 크기 비율(bar, bar15 메모): "탬플릿의 페이지 제목 폰트크기를 조금 더 키우고, 차트 영역 비율을 조금 줄이는 것이 더 보기 좋을 듯". 지금 제목은 20pt이고 차트 틀은 본문 영역 전체(860 x 359.2pt)를 쓴다. 제목 글자 크기는 프리셋 값이라 모든 템플릿의 덱에 영향이 있다.
2. 소수 2자리 기본 표기(bar15 메모): "소수점 2자리까지만 표기하는 것을 default 로 설정하기 바람". 지금 계약은 차트가 원문 수치를 그대로 보이고, 수치 대조 게이트가 원문과 화면 숫자를 대조하며, 미리보기와 PowerPoint가 같은 글자를 보이는 것이다. 표시를 반올림하면 이 계약을 다시 정해야 한다.

## 6. 새로 관측한 차이 (C3 항목 밖, 결정 대기)

1. 눈금선과 중간 눈금 글자: PowerPoint는 값 축에 주 눈금선(그림 영역을 가로지르는 선 5개)과 중간 눈금 글자 4개(bar는 264, 528, 792, 1056)를 그린다. 미리보기는 눈금선 없이 0과 최댓값만 그린다. python-pptx 기본 차트가 값 축 주 눈금선을 켜고, 내보내기가 주 단위를 최댓값의 1/5로 둔다(`pptx_writer.py`의 `major_unit`). 저장소 문서에서 이 차이를 기록한 곳은 찾지 못했다.
2. bar15에서 PowerPoint의 데이터 값 `123456789.123456`이 최댓값 눈금선과 겹친다. 값 글자가 그림 영역 오른쪽 끝을 넘어가기 때문이다. 미리보기에는 눈금선이 없어 겹치지 않는다.
3. 가로 막대 값 축 글자 위치: PowerPoint는 축 아래 약 14~23pt에 그리고, 미리보기는 축 아래 3.0~12.2pt(기준선 `y0+font`)에 그린다. 약 11pt 차이다. 가로 위치도 다르다. PowerPoint는 글자를 눈금 가운데에 맞추고, 미리보기는 0을 왼쪽 끝, 최댓값을 오른쪽 끝에 맞춘다.
