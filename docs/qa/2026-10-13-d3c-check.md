| 묶음의 낡은 후보 | 내용이 있는 장의 묶음 결과를 구성 화면 비교에서 반영. 묶음 실행 중에는 반영이 막힘 | 가장 최근 묶음에 한해 통과(`s3-batch`, 가짜 CLI 관문 모드로 실제 작업 경로). 새 묶음이 생긴 뒤 이전 묶음의 낡은 후보는 앱 안에서 반영할 길이 없다(6절 C1, 미해결). 묶음 등록은 빈 장만 받으므로, 시험과 같이 묶음 중 다른 창의 편집으로 사슬을 끊어 10장 결과를 낡은 후보로 남기고, 묶음 뒤 사용자가 10장에 직접 문구를 쓴 상태를 만들었다. 구성 화면의 "10번 장 후보 비교 보기"에서 반영하자 묶음 결과가 저장되고 그 장의 처분이 `applied`가 됐다. 묶음 실행 중에는 세 겹으로 막혔다: 구성 화면에 후보 비교 버튼이 없고(0개), 편집 화면은 읽기 전용이라 누르기와 키보드 모두 비교 화면을 열지 못하며, 반영 요청은 409 `batch_active`다. 비교 화면을 연 채 묶음이 시작되면 다음 미리 보기가 "장 생성 묶음이 진행 중이라 지금은 반영할 수 없습니다."를 보이고 반영 버튼을 끈다. 묶음을 취소하자 반영이 다시 열렸다 |
| 부분 강조 | 강조가 있는 장의 후보 반영이 저장되고 강조가 규칙대로 남음 | 통과(`s4-spans`). 첫 불릿과 결론에 강조를 둔 장에서 기본 선택은 "부분 강조 2개가 지워집니다", 결론을 지금 문구로 두면 1개로 바뀌었다. 반영은 오류 없이 저장되고 결론의 강조만 남았다 |

## 6. 확인 중 발견한 것

- C1(β 리뷰와 랩업에서 판단): 구성 화면은 원장의 장 생성 묶음 가운데 가장 최근 것 하나만 따라간다(`StructureScreen.tsx`의 `latest`). 그래서 새 묶음이 끝나면, 이전 묶음에서 반영하지 않은 낡은 후보는 구성 화면에 비교 버튼이 없다. 재현(`s3b-older`): 첫 묶음의 10장 후보가 원장에 `stale`로 남은 채 둘째 묶음(9장)이 끝나자 구성 화면의 후보 비교 버튼이 0개였다. 복구 화면은 그 후보를 "장 내용 생성 (10장 강조)"로 보이고 "보기", "구성 단계로 옮겨 다시 생성", "버리기"를 주며 "반영은 해당 화면에서 합니다"라고 안내한다. AI가 만든 내용은 보기로 읽을 수 있고 편집 단계의 "이 장 다시 생성"으로 다시 만들 수 있으므로 내용 유실은 아니지만(복구 화면의 "구성 단계로 옮겨 다시 생성"은 내용이 있는 장에서 누를 버튼이 없는 행으로 보낸다), 계획 4.8의 "구성 화면의 비교에서 반영한다"는 경로가 새 묶음 뒤에는 닫힌다. β 묶음 리뷰(S1, major)는 같은 세션 안에서도 일어남을 jsdom으로 보였다: 묶음 뒤 실패한 빈 장을 구성 화면의 "이 장 다시 생성"으로 다시 만들면 그 단일 장 묶음이 가장 최근 묶음이 되어, 옆 장의 "후보 비교 보기"가 사라진다. 편집 화면의 생성 패널도 장 생성과 장 축약 작업만 보므로 묶음 하위 행의 후보를 보이지 않는다. 처리 방향은 β 랩업에서 사용자와 정한다.

  > 2026-10-16 정정: C1은 C1 계획([2026-10-15-revision-d3-wrapup-c1](../plans/2026-10-15-revision-d3-wrapup-c1.md))의 W1(`b7d4363`, 리뷰 반영 `bd59027`)으로 닫았다. 복구 화면이 미처분 장 후보의 공통 반영 입구다(구현 설계 6절 2026-10-15 결정 1). 같은 모양의 도식 후보(SC-02)는 W2(`1eb3647`, `441fced`, 리뷰 반영 `f1074e7`)로 닫았다.
- 묶음 실행 중의 반영 막힘은 비교 화면의 안내보다 화면 잠금이 먼저다(2절). 비교 화면의 "묶음 진행 중" 안내는 비교 화면을 연 채 묶음이 시작될 때만 나온다.
