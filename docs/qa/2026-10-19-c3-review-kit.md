# C3 T4 검수 기록 준비 확인 (2026-10-19, Linux)

## 범위와 기준

GitHub main `5b006009fe8f7335a1db55cb58142d0f18d8db46`을 기준으로 최신 인계와 실제 코드를 대조했다. 기준 커밋의 [CI 255](https://github.com/blazethrottle/slidecaptain/actions/runs/39126701122)는 Windows와 macOS 모두 성공했다. 조회 시 PR과 이슈는 없었다. 작업 브랜치는 `feat/c3-review-checklist`다.

사용자의 개발 재개 요청으로 [C3 계획 10절](../plans/2026-10-18-revision-d3-wrapup-c3.md)의 T4 준비를 구현했다. 여섯 검수 항목을 양식에 연결한 것이며 PowerPoint 표시를 확인한 결과가 아니다. 실제 AI 호출은 0회다.

## 변경과 검증

- 검수 manifest와 HTML에 [C3 확인 기록 4절](2026-10-18-c3-check.md)의 여섯 항목을 넣었다. 대상 표본과 페이지, 확인 방법, 기대 결과를 함께 표시한다. 합성 표본은 종전과 같은 6개, 16쪽이다.
- 항목별 판정과 관찰 메모를 JSON 다운로드, 불러오기, 브라우저 임시 저장에 연결했다. 준비 직후 판정과 메모는 모두 null이다. 이전 JSON에는 새 항목이 없으므로 불러올 때 새 항목을 미평가로 초기화한다.
- 회차, 확인 목록 버전, 항목 ID, 표본 SHA-256, 대상 페이지를 DOM 입력 변경 전에 검사한다. 불일치와 중복, 누락, 잘못된 판정은 현재 입력을 보존한 채 거절한다. 제출 승인과 manifest의 `human_status=not_run`은 바꾸지 않는다.
- 백엔드 검수 도구 시험은 구현 전 `targeted_review` 부재로 실패했고 구현 후 통과했다. 원래 HTML로 교체한 변형에서 새 프런트 시험 13개가 모두 실패했다. 작업 중 파일은 별도 바이트 백업으로 복구했다.
- 프런트 전체 86파일 1,325개, 디자인 토큰 검사(96개), TypeScript와 Vite 빌드 통과. 기존 번들 크기 경고는 동일하다.
- 백엔드 전체 2,931 통과, 플랫폼 관련 5 건너뜀(237.91초). 첫 실행은 `v0.2.0` 태그가 이 클론에 없어 호환성 시험 8개가 준비 단계에서 실패했다(2,923 통과, 5 건너뜀). `git fetch origin --tags`로 환경을 보완한 뒤 전체를 다시 실행해 통과했다.
- Chromium에서 실제 생성된 HTML의 여섯 항목 모두 미평가 시작, 메모 입력 뒤 새로고침 복원, JSON 다운로드와 파일 불러오기를 확인했다. 시험으로 입력한 '측정 2pt'는 저장 왕복용 합성 문구이며 PowerPoint 측정값이 아니다. 캡처와 생성물은 저장소 밖 세션 임시 폴더에 있다.
- 독립 리뷰 1명: 계획 보완 1건(아이콘 검수 대상 명시)을 반영했고 코드 리뷰에서 조치할 결함 없음. 리뷰어도 프런트 13개 시험과 생성된 6항목 HTML의 별도 왕복/불일치 검증을 실행했다. 구현자와 다른 제공자 모델의 리뷰는 아니며 Claude 리뷰로 기록하지 않는다.
- 공개 저장소 이력 감사, diff 공백 검사 통과. OpenAPI와 프런트 타입 재생성 결과도 무변경이다. 변경 브랜치의 양 OS CI 결과는 해당 커밋의 GitHub PR Checks가 진본이며, push 뒤 둘 다 끝날 때까지 확인한다.

## 미완료와 회사 PC 재개

1. 실제 PowerPoint 표시와 C3R-05 라벨 이동/선택 테두리의 사용자 판정은 미완료다. 새 회차는 `Windows검수준비.bat`로 만들고 여섯 항목을 확인한 뒤 JSON을 저장한다. 기존 회차와 업무 자료는 그대로 보존한다.
2. 아이콘 항목은 정확히 U+203C U+FE0E를 실제 앱의 '반영 결과 확인 필요' 상태에서 확인한다. 양식에 적힌 문자만으로 통과 처리하지 않는다. AI 없이 해당 상태를 재현하는 절차는 아직 확정하지 않았고, 재현하지 못하면 미평가로 남긴다. 담당은 로드맵 회사 PC 이월표 (15)의 다음 회사 PC 세션이다.
3. C3R-08 실제 AI 생성, D4 릴리스 안내와 개발은 기존 이월 상태를 유지한다. D4에 배정된 표본의 `unlinked_expression`(회사 PC 이월표 (14))도 바꾸지 않았다.

되돌리기는 이 준비 기능의 커밋을 revert한다. 새 검수 회차가 별도 폴더에 생성되므로 기존 피드백을 덮어쓰지 않는다. 이전 양식은 새 항목을 표시하지 못하므로 새 JSON은 해당 회차의 양식과 함께 보관한다.
