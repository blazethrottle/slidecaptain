# slidecaptain

보고 슬라이드(PPTX) 제작을 돕는 로컬 웹앱이다.

비개발자가 자료와 요청을 제시하면, 읽는 사람이 핵심 판단과 근거를 쉽게 이해할 수 있는 편집 가능한 보고서를 만드는 것이 목표다. 핵심 원칙은 "AI는 보고 논리와 표현을 설계하고, 코드는 배치를 계산하며, 완성본 검수로 제출 가능 여부를 판단한다"이다. 서식의 균일성과 PPTX 생성 성공을 보고서 품질 보장으로 간주하지 않는다.

2026-09-12에 품질 중심으로 설계를 전환했다. 현재 구현은 검수 전 초안을 생성한다. 2026-09-30 잔여 개발에서 명시적 단위 환산, 비교 의심 문구 탐지, 근거에 연결된 편집 가능한 막대/열 차트와 부분 강조, DB-6/7 편집·전환 보존, 제한된 보고 계획 수정과 보호된 문서 교체를 추가했다. Q4b의 렌더·서명 검수·같은 바이트 게시 경로도 구현했으나 실제 Windows/PowerPoint 렌더, 독립 검수자 서명과 사람 품질 판정은 미실행이다. 현재 상태와 검증 경계는 [일괄 개발 기록](docs/plans/2026-09-30-remaining-batch.md)을 따른다.

## 실행

- **macOS**: 저장소 루트의 `SlideCaptain실행.command`를 더블클릭한다. 이 창이 서버 창이며, 창을 닫거나 Ctrl+C를 누르면 서버가 멈춘다.
- **Windows**: 저장소 루트의 `SlideCaptain실행.bat`를 더블클릭한다. 별도 서버 창이 뜬다.

두 스크립트 모두 서버가 이미 떠 있으면 새로 켜지 않고 브라우저만 연다. 서버 주소는 `http://127.0.0.1:8765`이며 이 PC에서만 접근할 수 있다. 처음 실행하는 PC라면 먼저 아래 "개발 환경 구성"을 마쳐야 한다.

### Windows PowerPoint 검수 준비 (2026-10-02)

검수용 최신 개발 브랜치는 `codex/phase-5b`다. 이 브랜치를 받은 뒤 **Windows검수준비.bat**를 더블클릭하면 합성 샘플 5개(15페이지), 별도 검수 프로젝트 폴더, 페이지별 품질 피드백 양식과 포트 8870의 앱을 준비한다. 추가 AI 호출은 없다. 양식에서 **피드백 JSON 저장**을 눌러 판정과 수정 요청을 보관한다. 자세한 절차와 회사 PC 에이전트에게 전달할 문장은 [Windows PowerPoint 검수 가이드](docs/qa/2026-10-02-windows-powerpoint-guide.md)에 있다. 실제 PowerPoint 표시와 사람 품질 판정은 회사 PC에서 별도로 수행한다.

## AI 서비스 연결

프로젝트 목록 또는 프로젝트 안에서 **AI 연결 및 모델**을 연다.

1. **Claude Sonnet** 또는 **Codex LUNA** 빠른 선택을 누르거나, 아래 서비스와 모델 목록에서 직접 선택한다. 빠른 선택은 현재 설치된 모델 목록에 해당 모델이 있을 때만 활성화된다.
2. **로그인 시작**을 누른다. Claude는 공식 Claude Code가 브라우저를 연다. ChatGPT는 **공식 로그인 페이지 열기**로 이동한다. 로그인은 제공자의 화면에서 직접 완료한다.
3. 연결 상태를 확인하고 언어모델을 골라 **선택 저장**을 누른다. 서버를 재시작하지 않아도 다음 생성부터 적용된다.

Claude는 이 PC의 본인 Claude Code 구독 계정을 사용한다. ChatGPT는 [Codex CLI](https://developers.openai.com/codex/cli/)가 필요하며 SlideCaptain 전용 프로필로 연결한다. 기존 Codex 로그인은 복사하거나 변경하지 않는다. 로그인 대기 취소와 상태 재확인을 지원한다. 모델·서비스가 바뀌면 생성 전에 전송 대상을 다시 확인한다.

빠른 선택도 **선택 저장**으로 확정해야 다음 생성부터 적용된다. 저장한 선택은 앱을 다시 열어도 유지된다. 실패하면 사용자가 연결과 모델을 확인한 뒤 다시 선택하며, 다른 서비스로 자동 전환하지 않는다. Codex LUNA의 정확한 모델 ID는 `gpt-6-luna`다. 목록에 없거나 연결 확인에 실패하면 안내를 표시한다.

선택은 프로젝트 저장 폴더의 `ai-settings.json`에 남으며 인증 토큰은 담지 않는다. ChatGPT 인증은 공식 CLI가 같은 폴더의 `.slidecaptain-codex/`에 관리한다. 해당 프로필은 개인 인증정보이므로 공유하지 않는다. 네이티브 CLI를 찾지 못하면 `SLIDECAPTAIN_CODEX_CLI`에 실행 파일 경로를 지정할 수 있다. Windows의 `.cmd`/`.bat` 대신 네이티브 `codex.exe`를 사용한다.

현재 구독 연결은 본인용 로컬 프로필이다. 웹 채팅과 Agent SDK/Codex 사용 한도, API 결제는 다를 수 있다. 타인에게 배포하는 서비스의 제공자별 조건은 [연결 설계](docs/architecture/2026-09-13-ai-connections.md)에 명시했다.

## 개발 환경 구성

### macOS

저장소를 iCloud와 동기화되는 폴더(`~/Documents`, `~/Desktop` 등) 밖에 둔다. 예를 들어 `~/Projects/`에 둔다. iCloud 폴더 안에 두면 가상환경의 `.pth` 파일에 hidden 플래그가 붙어 Python 3.13이 editable 설치를 조용히 무시한다(2026-09-02 실측).

uv와 fnm이 없으면 먼저 설치한다.
```
brew install uv fnm
```

`backend` 폴더에서 Python 3.13 가상환경을 만든다.
```
uv venv --python 3.13
```

같은 폴더에서 백엔드를 의존성과 함께 설치한다. uv가 만든 가상환경에는 pip가 없어 `uv pip`를 쓴다.
```
uv pip install --python .venv/bin/python -e ".[dev]"
```

`.nvmrc`가 지정한 Node 버전을 설치하고 사용한다.
```
fnm install 22.17.1
fnm use 22.17.1
```

fnm을 처음 설치했다면 셸 설정 파일(`~/.zshrc`)에 `eval "$(fnm env --use-on-cd)"` 한 줄을 추가하고 터미널을 새로 연 뒤 `node -v`가 v22.17.1인지 확인한다. 이 연동이 없으면 `fnm use`가 Node 버전을 실제로 바꾸지 못한다(환경에 따라 연동 안내 오류가 뜨거나 성공처럼 보여도 `node -v`가 그대로다. 2026-09-05 두 리뷰어가 각각 실측).

`frontend` 폴더에서 화면 의존성을 설치하고 빌드한다. 빌드된 화면을 서버가 함께 제공한다.
```
npm ci
npm run build
```

### Windows

`backend` 폴더에서 가상환경을 만들고 의존성과 함께 설치한다(`python --version`이 3.13 이상이어야 한다).
```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

`frontend` 폴더에서 화면 의존성을 설치하고 빌드한다(최초 1회).
```
npm install
npm run build
```

## 개발 명령

- 테스트: `backend` 폴더에서 실행한다. macOS `.venv/bin/python -m pytest tests -q` (Windows `.venv\Scripts\python.exe -m pytest tests -q`)
- 로컬 서버: `backend` 폴더에서 실행한 뒤 `http://127.0.0.1:8765/docs`를 연다. macOS `.venv/bin/python -m slidecaptain serve` (Windows `.venv\Scripts\python.exe -m slidecaptain serve`)
- CLI 내보내기: `backend` 폴더에서 실행한다. macOS `.venv/bin/python -m slidecaptain export <deck.json>` (Windows `.venv\Scripts\python.exe -m slidecaptain export <deck.json>`)
- 타입 재생성: `backend`에서 OpenAPI 스키마를 뽑고 `frontend`에서 타입으로 바꾼다. macOS `.venv/bin/python scripts/dump_openapi.py` 뒤 `npm run generate-types` (Windows `.venv\Scripts\python.exe scripts\dump_openapi.py`)
- 프런트 테스트: `frontend` 폴더에서 `npm test`
- 프런트 개발 서버: `frontend` 폴더에서 `npm run dev` (백엔드 `serve`와 병행 실행)
- 화면 빌드: `frontend` 폴더에서 `npm run build`

## 주의 (macOS)

- 클론을 iCloud와 동기화되는 폴더(`~/Documents`, `~/Desktop` 등)에 두지 않는다. `.pth` 파일에 hidden 플래그가 붙어 editable 설치가 조용히 무시된다.
- uv가 만든 가상환경에는 pip가 없다. 패키지를 설치하거나 갱신할 때는 `pip` 대신 `uv pip`를 쓴다.
- git worktree(`~/Projects/slidecaptain-5a` 등)에서 백엔드 테스트를 돌릴 때는 `PYTHONPATH=<worktree>/backend`를 앞에 붙인다. main 클론의 가상환경을 빌려 쓰면 editable 설치가 main 클론 패키지를 가리켜 worktree 코드가 검증되지 않는다.

## 폰트

첫 `serve` 실행이 Noto Sans KR 두 파일(Regular, Bold)을 사용자 폰트 폴더(macOS `~/Library/Fonts`, Windows 사용자 폰트 폴더)에 자동으로 설치한다. 설치에 실패하면 안내 문구와 함께 수동 설치 파일 경로(`backend/slidecaptain/fonts/assets/`)를 출력한다. 화면 폭 계산은 폰트가 없어도 번들 수치로 동작한다.

## 데이터 폴더

기본 데이터 폴더는 `~/slidecaptain-projects`이며 `serve --data-dir <경로>`로 바꿀 수 있다. 프로젝트마다 `deck.json`, `uploads/`, `sources/`, `snapshots/`, `exports/`, `ai-usage.jsonl`(AI 사용량 기록, 내용은 담지 않는다) 폴더와 파일이 생긴다.

## 검증과 CI

- 백엔드 테스트, 프런트 테스트, 타입 재생성 무변경 확인은 위 "개발 명령"과 같다.
- 푸시 전에 공개 저장소 감사기를 돌린다. 이 저장소는 공개 GitHub에 올라가므로 회사 자료, 오피스 파일, 인증정보가 추적되면 안 된다. 저장소 루트에서 macOS `backend/.venv/bin/python scripts/audit_public_repo.py` (Windows `backend\.venv\Scripts\python.exe scripts\audit_public_repo.py`). 과거 이력까지 보려면 `--history`를 붙인다.
- `.github/workflows/ci.yml`이 push와 pull request마다 Windows와 macOS에서 같은 순서로 실행한다: 줄바꿈 검사, 감사기, 백엔드 테스트, OpenAPI와 타입 재생성 뒤 무변경 확인, 프런트 테스트, 화면 빌드.
- CI가 보증하지 않는 것: 실제 AI 로그인 완료와 호출(Claude 또는 ChatGPT 연결을 선택하며, 첫 호출과 연결 변경 후 전송 범위를 확인하고 호출별 사용량을 표시한다), PowerPoint 표시, 폰트 설치 실증. 이것들은 실기기 관통의 몫이다.

## 화면을 갱신할 때 (배포 순서)

서버 종료 → `frontend` 폴더에서 `npm run build` → 실행 스크립트(`SlideCaptain실행.command` 또는 `SlideCaptain실행.bat`)로 재실행 → 브라우저 새로고침. 서버를 먼저 끄지 않으면 옛 서버와 새 화면이 섞여 저장 유실 창이 생길 수 있다(로드맵 실측 기록).

## 품질 사전 점검

웹과 CLI 내보내기는 PPTX 옆에 같은 버전의 `.quality.json`과 신규 출력의 `.provenance.json`을 기록한다. 생산 기록은 실행 ID, 입력 fingerprint와 실제 PPTX 해시를 연결한다. 구형 산출물은 소급 변경하지 않는다. 내보내는 초안과 현재 원문으로 계산 문구를 다시 대조하며, 웹에서는 게시한 기록의 검사 수와 확인 필요 문구를 보여 준다. `export --final`과 API의 `?final=true`로 새 제출본을 생성하는 요청은 거절한다. 별도 Q4b 검수 경로와 `publish-final`은 실제 렌더 증거, 설정된 독립 검수자 서명, 전체 페이지 coverage와 현재성을 통과한 기존 출력의 같은 바이트만 게시한다. 필요한 환경이나 검수 증거가 없으면 차단한다. 수동 통과 기록만으로 이 관문을 통과하지 않는다.

`backend`에서 운영체제별 가상환경 Python으로 `-m slidecaptain quality <deck.json>`을 실행하면 AI 호출과 파일 수정 없이 점검 JSON을 출력한다. CLI의 `quality`와 `export`는 덱 옆 `sources/`를 읽으며, 계획이나 자료가 없거나 낡으면 수치 대조를 미수행으로 기록한다. 종료 코드 2는 아직 제출 가능하지 않음을 뜻한다. CLI는 기본 프리셋과 덱 덮어쓰기를 사용하므로 웹앱의 전역 프리셋과 다를 수 있다.

웹과 CLI가 같은 폴더에 동시에 내보내면 버전 선택과 저장을 순서대로 처리한다. 저장 대기가 5초를 넘으면 잠시 후 다시 시도하라는 안내를 제공한다. 출력 폴더에는 `.slidecaptain-export.lock`이 남으며, 앱을 사용하는 동안 이 파일을 삭제하지 않는다. PPTX 게시에 실패해 품질 기록만 남은 버전은 다음 내보내기에서 건너뛴다. 파일 잠금과 hard link를 지원하는 로컬 파일 시스템이 필요하며 미지원 위치에서는 오류를 반환한다. 잠금 파일은 링크를 따라가지 않고 고정 핸들로 검사하며, 게시 뒤 출력 identity와 해시를 다시 확인한다. `.slidecaptain-export-*` 비공개 staging 폴더는 경로 교체 중 제3파일을 삭제하는 cleanup 경합을 피하기 위해 성공/실패 뒤에도 보존한다. 자동 정리 기능은 없으며 반복 내보내기만큼 저장 공간이 누적된다. 앱 실행 중 경로 기반으로 일괄 삭제하지 않는다.

프로젝트의 **검수 이력**에서 이전 내보내기의 점검 기록을 다시 열 수 있다. 기록 상태, 실제 PPTX와의 일치, 현재 저장된 덱/프리셋/원문과의 일치를 각각 표시한다. 파일 누락/손상과 구형 기록을 숨기지 않으며, 덱이 깨져 복구가 필요한 프로젝트에서도 과거 기록을 조회한다. 다른 창이나 앱에서 수정했다면 이력을 새로고침한다. 자료 탭의 미저장 본문은 먼저 `자료 저장`으로 저장해야 이동할 수 있다. 파일 일치는 제출 승인이나 내용/시각 검수 통과가 아니다.

2026-09-29 개정: 이력 상세에서 **수동 검수 기록**을 추가한다. 실제로 확인한 항목과 페이지, 검수자, 판정과 근거를 입력한다. 통과 기록에는 모든 페이지 확인이 필요하다. 현재 덱/자료/프리셋 또는 PPTX가 바뀌면 과거 기록은 보존하고 만료를 표시한다. 충돌 시 입력을 유지하며 기준을 다시 확인해야 한다. 이 기록은 사용자가 입력한 확인 내용이며 독립 검수나 제출 승인을 자동으로 증명하지 않는다. 모든 수동 항목에 통과를 기록해도 제출본 내보내기는 아직 차단된다.

## 개발 이력 (2026-09-13 기록)

## 도식을 직접 작성하기

편집 탭의 **도식 추가**로 시작합니다. 항목의 내용/구분/조건과 관계를 입력하고, 사실이나 흐름/참조에는 등록된 근거를 선택합니다. **입력과 배치 확인**으로 오류와 미리보기를 확인한 뒤 **도식 적용**을 누르면 덱에 반영하고 자동 저장합니다. 기존 도식은 **도식 내용 수정**에서 고칠 수 있습니다. 적용한 변경은 되돌리기와 스냅샷 복구를 사용할 수 있습니다.

보고 계획이 있으면 도식 장의 역할과 연결할 주장을 선택합니다. 핵심 답변을 담당하는 장은 적어도 하나 유지해야 합니다. 확인할 때 기존 편집 내용을 먼저 저장합니다. 다른 창의 저장과 충돌하면 작성 내용을 확인한 뒤 창을 닫고 **서버 내용으로 되돌리기**로 최신본을 불러올 수 있습니다. 2026-09-22 개정: 보고 계획 연결과 충돌 복구 동작을 반영했습니다.

작성 중에는 도식 입력을 기존 덱에 반영하지 않으며 **변경 버리고 닫기**는 이 창의 변경만 버립니다. 현재 배치는 한 줄의 인접한 항목 연결을 지원합니다. 도식이 있는 덱의 전체 구조안 AI 재생성은 아직 지원하지 않으며, 자료나 보고 정보가 바뀌어 계획이 낡으면 연결 확인도 거절합니다. 배치 성공과 근거 선택은 내용/PowerPoint/제출 품질의 검수 통과를 뜻하지 않습니다.

## 기존 편집을 보존하며 보고 계획 재작성하기

저장된 보고 계획이 있으면 구조안 탭에서 **기존 편집을 보존하며 계획 재작성**을 사용할 수 있습니다. 재작성 보고 질문과 지시사항을 넣고 **재작성 미리보기**를 누릅니다. 후보를 읽고 본문 재검토가 필요함을 확인한 뒤 **이 계획 적용**을 누르면 저장합니다. 2026-09-27 개정: 기존 장을 유지하는 재작성 기능을 추가했습니다.

장 수, 제목, 본문과 도식은 유지하고 장 순서와 일반 장의 주장/근거를 다시 계획합니다. 도식이 의존하는 원자료가 바뀌면 재작성을 중단합니다. 다른 창의 저장이나 자료 변경이 있으면 적용을 막고, 미적용 후보는 현재 화면에서만 유지합니다. 재작성은 기존 본문의 수치와 논리를 자동으로 고치지 않으므로 적용 뒤에도 새 계획과 본문을 대조해야 합니다.


## 2026-09-30 추가 편집과 검수 경로

편집 탭에서 등록된 비교를 표의 막대/열 차트로 표시하고, 원문 해시와 문자 위치에 연결된 부분 강조를 추가할 수 있다. 비교 조건과 단위를 보존하며 기존 차트의 조건 문구를 인라인으로 덮어쓰지 않는다. 비교/요약 의심 문구는 사람이 확인할 후보이며 의미 검수 통과가 아니다. 단위 환산은 명시적으로 지원한 등록 단위만 처리한다.

구조안에서는 문제 목록과 호출·시간·반복 상한을 정한 보고 계획 수정 후보를 만들 수 있다. 같은 선택 제공자의 분리된 검토 문맥을 사용하며 형식 재시도도 호출 상한에 포함한다. 후보는 자동 저장하거나 제출 승인으로 바꾸지 않는다. 전체 문서 후보 JSON 교체와 기존 보호 근거의 명시적 이전은 손실 항목 확인, ETag와 원문 현재성 재검사 후 스냅샷을 남겨 적용한다. 기존 도식 AI 교체도 이 보호된 적용 경로를 사용한다. 이는 전체 본문 자동 재생성이나 새 의미의 정확성을 보증하지 않는다.

Q5에는 같은 조건의 세 비교군을 준비하고 눈가림·사람 판정·보고를 만드는 도구가 있다. 단일 페이지 3개 합성 사례의 측정은 제한된 기능 관통이며 전체 보고서 품질 수용이나 사람 판정을 대신하지 않는다.
